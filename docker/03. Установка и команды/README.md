# 03. Установка и команды

## О чём этот раздел

Теперь, когда мы разобрали, как устроен контейнер изнутри и как работает OCI, переходим к практической работе с Docker. Здесь разберём:

| Тема | Что даёт |
|------|----------|
| **Установка** | Как поставить Docker на разные дистрибутивы |
| **Архитектура** | Из чего состоит Docker: CLI, dockerd, containerd, runc |
| **Основные команды** | Работа с образами, контейнерами, сетями, томами |

> **Ключевая мысль:** Docker — это не монолит. Это набор компонентов, каждый из которых делает свою работу. Понимание архитектуры помогает отлаживать проблемы и понимать, что происходит «под капотом».

## 01. Установка Docker

### Варианты установки

Docker можно установить несколькими способами:

| Способ | Когда использовать |
|--------|-------------------|
| **Официальный репозиторий Docker** | Для production, всегда свежая версия |
| **Репозиторий дистрибутива** | Для быстрого старта, но версия может быть старой |
| **Скрипт get.docker.com** | Для быстрой установки на тестовых стендах |
| **Docker Desktop** | Для macOS и Windows |

> **Рекомендация:** для production используйте официальный репозиторий Docker. Для обучения подойдёт и версия из репозитория дистрибутива.

### Установка на Ubuntu/Debian

**Шаг 1: Удалить старые версии**

```bash
sudo apt remove docker docker-engine docker.io containerd runc
```

**Что происходит:** удаляются старые версии Docker, которые могли быть установлены из репозитория дистрибутива. Это нужно, чтобы избежать конфликтов.

**Шаг 2: Установить зависимости**

```bash
sudo apt update
sudo apt install -y ca-certificates curl gnupg lsb-release
```

**Что происходит:** устанавливаются утилиты, необходимые для добавления репозитория и проверки подписей.

**Шаг 3: Добавить GPG-ключ Docker**

```bash
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
```

**Что происходит:** скачивается GPG-ключ Docker и сохраняется в `/etc/apt/keyrings/docker.gpg`. Этот ключ используется для проверки подлинности пакетов.

**Шаг 4: Добавить репозиторий**

```bash
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
```

**Что происходит:** в `/etc/apt/sources.list.d/docker.list` добавляется запись о репозитории Docker. Теперь `apt` будет искать пакеты Docker в этом репозитории.

**Шаг 5: Установить Docker**

```bash
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

**Что происходит:** устанавливаются:

| Пакет | Что это |
|-------|---------|
| `docker-ce` | Docker Engine (демон) |
| `docker-ce-cli` | Docker CLI (командная строка) |
| `containerd.io` | containerd (среда выполнения контейнеров) |
| `docker-buildx-plugin` | BuildKit (современная сборка образов) |
| `docker-compose-plugin` | Docker Compose (управление многоконтейнерными приложениями) |

**Шаг 6: Добавить пользователя в группу docker**

```bash
sudo usermod -aG docker $USER
newgrp docker
```

**Что происходит:** пользователь добавляется в группу `docker`. Это позволяет запускать команды Docker без `sudo`. Без этого каждая команда требует прав root.

**Шаг 7: Проверить установку**

```bash
docker --version
docker run hello-world
```

**Что происходит:** Docker скачивает образ `hello-world`, запускает его и выводит приветственное сообщение. Это первый контейнер в вашей жизни.

### Проверка установки

```bash
# Версия Docker
docker --version

# Информация о системе
docker info

# Запуск тестового контейнера
docker run hello-world
```

**Что происходит:** `docker info` показывает информацию о Docker: версию, количество контейнеров, образов, драйверы, хранилище, cgroups. Это полезно для отладки.

## 02. Архитектура Docker

### Компоненты Docker

Docker — это не один процесс, а набор компонентов:

```
┌─────────────────────────────────────────────────────────────┐
│                      Docker CLI                             │
│                   (docker command)                          │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      dockerd                                │
│                 (Docker Daemon)                             │
│  - Управляет образами                                       │
│  - Управляет контейнерами                                   │
│  - Управляет сетями                                         │
│  - Управляет томами                                         │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                     containerd                              │
│              (Container Runtime)                            │
│  - Управляет жизненным циклом контейнеров                   │
│  - Работает с образами                                      │
│  - Вызывает runc                                            │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                       runc                                  │
│              (OCI Runtime)                                  │
│  - Читает config.json                                       │
│  - Настраивает namespaces, cgroups, capabilities            │
│  - Запускает процесс                                        │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    Контейнер                                │
│                  (изолированный процесс)                    │
└─────────────────────────────────────────────────────────────┘
```

### Docker CLI

**Docker CLI** — это командная строка, с которой работает пользователь. Она отправляет команды демону `dockerd` через REST API.

```bash
docker run nginx
```

**Что происходит:** CLI отправляет запрос демону, демон выполняет команду, CLI показывает результат.

### dockerd (Docker Daemon)

**dockerd** — это фоновый процесс, который управляет всем: образами, контейнерами, сетями, томами. Он слушает Unix-сокет `/var/run/docker.sock`.

**Что делает dockerd:**

- Принимает команды от CLI
- Скачивает образы из реестров
- Собирает образы из Dockerfile
- Создаёт и запускает контейнеры
- Управляет сетями и томами

**Где работает:** dockerd запускается как systemd-сервис. Его можно перезапустить:

```bash
sudo systemctl restart docker
```

### containerd

**containerd** — это среда выполнения контейнеров. Она управляет жизненным циклом контейнеров: создание, запуск, остановка, удаление.

**Что делает containerd:**

- Управляет образами (скачивание, хранение)
- Управляет контейнерами (создание, запуск, остановка)
- Вызывает `runc` для запуска контейнера
- Предоставляет API для dockerd

**Зачем разделили dockerd и containerd:** containerd — это более низкоуровневый компонент, который может использоваться без Docker. Например, Kubernetes использует containerd напрямую, без dockerd.

### runc

**runc** — это OCI Runtime. Он читает `config.json` и запускает контейнер. Мы разбирали его в предыдущем разделе.

**Что делает runc:**

- Читает `config.json`
- Настраивает namespaces, cgroups, capabilities
- Монтирует rootfs
- Запускает процесс

### Взаимодействие компонентов

Когда вы запускаете `docker run nginx`:

1. **Docker CLI** отправляет запрос демону `dockerd`
2. **dockerd** проверяет, есть ли образ `nginx` локально. Если нет — скачивает из Docker Hub
3. **dockerd** формирует OCI Bundle (config.json + rootfs)
4. **dockerd** передаёт Bundle в **containerd**
5. **containerd** вызывает **runc** с этим Bundle
6. **runc** настраивает изоляцию и запускает контейнер
7. **containerd** следит за жизненным циклом контейнера
8. **dockerd** возвращает результат CLI

### Где что хранится

| Компонент | Где хранится |
|-----------|--------------|
| Образы | `/var/lib/docker/image/` |
| Слои образов | `/var/lib/docker/overlay2/` |
| Контейнеры | `/var/lib/docker/containers/` |
| Тома | `/var/lib/docker/volumes/` |
| OCI Bundle (временный) | `/run/containerd/io.containerd.runtime.v2.task/moby/<id>/` |

### Ключевые моменты

1. **Docker — это не монолит.** Это набор компонентов, каждый из которых делает свою работу.
2. **dockerd управляет всем.** Он принимает команды от CLI и координирует работу остальных компонентов.
3. **containerd управляет жизненным циклом.** Он может использоваться без Docker (например, в Kubernetes).
4. **runc запускает контейнер.** Это низкоуровневый инструмент, который делает одну вещь и делает её хорошо.

## 03. Основные команды

### Работа с образами

| Команда | Что делает |
|---------|------------|
| `docker images` | Список локальных образов |
| `docker pull ubuntu:22.04` | Скачать образ |
| `docker build -t myapp:1.0 .` | Собрать образ из Dockerfile |
| `docker rmi <image>` | Удалить образ |
| `docker image prune` | Удалить неиспользуемые образы |
| `docker history <image>` | История слоёв образа |

**Пример: скачиваем образ**

```bash
docker pull ubuntu:22.04
```

**Что происходит:** Docker скачивает образ `ubuntu:22.04` из Docker Hub. Образ состоит из слоёв, которые сохраняются в `/var/lib/docker/overlay2/`.

**Пример: смотрим список образов**

```bash
docker images
```

**Что происходит:** вывод показывает список локальных образов:

```
REPOSITORY   TAG       IMAGE ID       CREATED       SIZE
ubuntu       22.04     abc123def456   2 weeks ago   77.8MB
nginx        latest    def456abc123   1 week ago    187MB
```

**Пример: удаляем образ**

```bash
docker rmi ubuntu:22.04
```

**Что происходит:** образ удаляется. Если на его основе есть контейнеры (даже остановленные), удаление не произойдёт — нужно сначала удалить контейнеры.

### Работа с контейнерами

| Команда | Что делает |
|---------|------------|
| `docker run -it ubuntu bash` | Запустить контейнер интерактивно |
| `docker run -d -p 8080:80 nginx` | Запустить в фоне с пробросом порта |
| `docker ps` | Список запущенных контейнеров |
| `docker ps -a` | Список всех контейнеров (включая остановленные) |
| `docker start <container>` | Запустить остановленный |
| `docker stop <container>` | Остановить |
| `docker rm <container>` | Удалить |
| `docker exec -it <container> bash` | Войти в запущенный контейнер |
| `docker logs <container>` | Логи контейнера |
| `docker inspect <container>` | Детальная информация (JSON) |
| `docker stats` | Статистика в реальном времени |

**Пример: запускаем контейнер**

```bash
docker run -it ubuntu bash
```

**Что происходит:**

- `docker run` — создать и запустить контейнер
- `-it` — интерактивный терминал
- `ubuntu` — образ
- `bash` — команда, которая запустится в контейнере

Вы попадаете внутрь контейнера. Процесс `bash` работает в изолированном окружении. Выход — команда `exit`.

**Пример: запускаем контейнер в фоне**

```bash
docker run -d -p 8080:80 nginx
```

**Что происходит:**

- `-d` — запуск в фоне (detached)
- `-p 8080:80` — проброс порта: порт 8080 на хосте → порт 80 в контейнере
- `nginx` — образ

Теперь можно открыть `http://localhost:8080` в браузере и увидеть страницу Nginx.

**Пример: смотрим список контейнеров**

```bash
docker ps
```

**Что происходит:** вывод показывает запущенные контейнеры:

```
CONTAINER ID   IMAGE   COMMAND   CREATED   STATUS   PORTS                  NAMES
abc123def456   nginx   "nginx"   5 min ago Up 5 min 0.0.0.0:8080->80/tcp   happy_tesla
```

**Пример: входим в запущенный контейнер**

```bash
docker exec -it happy_tesla bash
```

**Что происходит:** вы попадаете внутрь уже запущенного контейнера. Это удобно для отладки: можно посмотреть файлы, логи, процессы.

**Пример: смотрим логи**

```bash
docker logs happy_tesla
```

**Что происходит:** вывод показывает логи контейнера (то, что процесс пишет в stdout/stderr).

**Пример: смотрим детальную информацию**

```bash
docker inspect happy_tesla
```

**Что происходит:** вывод показывает JSON с полной информацией о контейнере: конфигурация, состояние, network, mounts, namespaces и многое другое.

**Пример: смотрим статистику**

```bash
docker stats
```

**Что происходит:** вывод показывает статистику в реальном времени:

```
CONTAINER ID   NAME          CPU %   MEM USAGE / LIMIT   MEM %   NET I/O       BLOCK I/O
abc123def456   happy_tesla   0.00%   1.5MiB / 1GiB       0.15%   1.2kB / 0B    0B / 0B
```

### Полезные флаги `docker run`

| Флаг | Значение |
|------|----------|
| `-d` | Запуск в фоне (detached) |
| `-it` | Интерактивный терминал |
| `-p 8080:80` | Проброс порта (хост:контейнер) |
| `-v /host:/container` | Монтирование тома |
| `--name myapp` | Имя контейнера |
| `--rm` | Удалить после остановки |
| `-e VAR=value` | Переменная окружения |
| `--network mynet` | Подключить к сети |
| `--memory 512m` | Лимит памяти |
| `--cpus 1.5` | Лимит CPU |
| `--cap-drop=ALL` | Убрать все capabilities |

**Пример: запуск с лимитами**

```bash
docker run -d \
  --name myapp \
  --memory 512m \
  --cpus 1.5 \
  --cap-drop=ALL \
  -p 8080:80 \
  nginx
```

**Что происходит:** контейнер запускается с лимитом памяти 512 МБ, лимитом CPU 1.5 ядра, без capabilities. Порт 8080 на хосте пробрасывается на порт 80 в контейнере.

### Работа с сетями

| Команда | Что делает |
|---------|------------|
| `docker network ls` | Список сетей |
| `docker network create mynet` | Создать сеть |
| `docker network inspect mynet` | Информация о сети |
| `docker network connect mynet <container>` | Подключить контейнер к сети |
| `docker network disconnect mynet <container>` | Отключить контейнер от сети |

**Пример: создаём сеть**

```bash
docker network create mynet
```

**Что происходит:** создаётся пользовательская bridge-сеть. В ней работает встроенный DNS, который позволяет контейнерам обращаться друг к другу по имени.

**Пример: запускаем контейнеры в одной сети**

```bash
docker run -d --network mynet --name app1 nginx
docker run -d --network mynet --name app2 nginx
```

**Что происходит:** оба контейнера подключены к сети `mynet`. Теперь `app1` может обращаться к `app2` по имени `app2`.

### Работа с томами

| Команда | Что делает |
|---------|------------|
| `docker volume ls` | Список томов |
| `docker volume create mydata` | Создать том |
| `docker volume inspect mydata` | Информация о томе |
| `docker volume rm mydata` | Удалить том |
| `docker volume prune` | Удалить неиспользуемые тома |

**Пример: создаём том**

```bash
docker volume create mydata
```

**Что происходит:** создаётся именованный том. Docker управляет им и хранит данные в `/var/lib/docker/volumes/mydata/`.

**Пример: монтируем том в контейнер**

```bash
docker run -d -v mydata:/data nginx
```

**Что происходит:** том `mydata` монтируется в контейнер по пути `/data`. Все данные, которые контейнер пишет в `/data`, сохраняются в томе и не теряются при удалении контейнера.

### Очистка

| Команда | Что делает |
|---------|------------|
| `docker system df` | Использование места |
| `docker system prune` | Удалить всё неиспользуемое |
| `docker system prune -a` | Удалить все неиспользуемые образы |
| `docker container prune` | Удалить остановленные контейнеры |
| `docker image prune` | Удалить неиспользуемые образы |
| `docker volume prune` | Удалить неиспользуемые тома |

**Пример: смотрим использование места**

```bash
docker system df
```

**Что происходит:** вывод показывает, сколько места занимают образы, контейнеры, тома:

```
TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          5         2         1.2GB     800MB (66%)
Containers      3         1         50MB      40MB (80%)
Local Volumes   2         1         100MB     50MB (50%)
Build Cache     0         0         0B        0B
```

**Пример: очищаем всё неиспользуемое**

```bash
docker system prune -a
```

**Что происходит:** удаляются все остановленные контейнеры, неиспользуемые образы, неиспользуемые сети и build cache. **Осторожно:** это необратимо.
