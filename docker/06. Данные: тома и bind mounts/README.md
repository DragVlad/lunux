# 06. Данные: тома и bind mounts

## О чём этот раздел

Контейнер эфемерен: удалили — данные внутри потеряны. Но приложениям нужно хранить данные: базы данных, логи, конфигурации, загруженные файлы. Для этого в Docker есть **тома (volumes)** и **bind mounts**.

| Тема | Что даёт |
|------|----------|
| **Проблема эфемерности** | Почему данные в контейнере теряются |
| **Тома** | Управляемые Docker хранилища |
| **Bind mounts** | Монтирование директорий хоста |
| **tmpfs** | Хранение в памяти |
| **Сравнение** | Что когда использовать |

> **Ключевая мысль:** контейнер — это процесс. Его файловая система — временная. Для сохранения данных нужны внешние хранилища.

---

## 01. Проблема эфемерности

### Что происходит с данными в контейнере

Когда вы запускаете контейнер, Docker создаёт верхний слой (diff) через OverlayFS. Всё, что приложение пишет внутри контейнера, попадает в этот слой.

**Что происходит при удалении контейнера:**

```bash
docker run -d --name test nginx
docker exec test sh -c "echo 'important data' > /data.txt"
docker rm -f test
```

**Что происходит:** контейнер удалён. Верхний слой (diff) удалён. Файл `/data.txt` потерян навсегда.

> **Важно:** данные внутри контейнера живут ровно столько, сколько живёт контейнер. Удалили контейнер — потеряли данные.

### Почему это проблема

| Сценарий | Что теряется |
|----------|--------------|
| База данных | Все данные |
| Логи | История логов |
| Загруженные файлы | Контент пользователей |
| Конфигурации | Настройки |

### Решение: внешние хранилища

Docker предлагает три способа хранения данных вне контейнера:

| Способ | Где хранится | Управление |
|--------|--------------|------------|
| **Volume** | `/var/lib/docker/volumes/` | Docker |
| **Bind mount** | Любая директория хоста | Пользователь |
| **tmpfs** | Память (RAM) | Ядро |

---

## 02. Тома (Volumes)

### Что это

**Том (volume)** — это хранилище, управляемое Docker. Он хранится в `/var/lib/docker/volumes/` и не зависит от жизненного цикла контейнера.

### Создание тома

```bash
docker volume create mydata
```

**Что происходит:** Docker создаёт директорию `/var/lib/docker/volumes/mydata/_data/`.

### Просмотр томов

```bash
docker volume ls
```

**Что происходит:** вывод показывает список томов:

```
DRIVER    VOLUME NAME
local     mydata
local     db-data
```

```bash
docker volume inspect mydata
```

**Что происходит:** вывод показывает информацию:

```json
[
  {
    "CreatedAt": "2024-01-01T00:00:00Z",
    "Driver": "local",
    "Mountpoint": "/var/lib/docker/volumes/mydata/_data",
    "Name": "mydata",
    "Scope": "local"
  }
]
```

### Монтирование тома

```bash
docker run -d --name app -v mydata:/data nginx
```

**Что происходит:** том `mydata` монтируется в контейнер по пути `/data`. Всё, что приложение пишет в `/data`, сохраняется в томе.

**Синтаксис:**

```
-v <имя-тома>:<путь-в-контейнере>
```

### Пример: база данных с томом

```bash
docker run -d \
  --name postgres \
  -e POSTGRES_PASSWORD=secret \
  -v pgdata:/var/lib/postgresql/data \
  postgres:16
```

**Что происходит:** данные PostgreSQL сохраняются в томе `pgdata`. Даже если контейнер удалить — данные останутся.

**Проверка:**

```bash
docker rm -f postgres
docker run -d \
  --name postgres \
  -e POSTGRES_PASSWORD=secret \
  -v pgdata:/var/lib/postgresql/data \
  postgres:16
```

**Что происходит:** новый контейнер использует тот же том. Данные на месте.

### Анонимные тома

```bash
docker run -d -v /data nginx
```

**Что происходит:** Docker создаёт анонимный том (без имени) и монтирует его в `/data`. Имя тома — случайный хеш.

```bash
docker volume ls
```

**Что происходит:** вывод показывает:

```
DRIVER    VOLUME NAME
local     abc123def456...
```

**Зачем это нужно:** для данных, которые не нужно сохранять между запусками, но нужно вынести из контейнера.

### Удаление томов

```bash
docker volume rm mydata
```

**Что делает:** удаляет том. Данные теряются.

```bash
docker volume prune
```

**Что делает:** удаляет все неиспользуемые тома.

> **Важно:** `docker volume prune` удаляет только тома, которые не используются ни одним контейнером. Будьте осторожны.

### Тома в Dockerfile

```dockerfile
FROM postgres:16
VOLUME /var/lib/postgresql/data
```

**Что делает:** объявляет том. При запуске контейнера Docker создаст анонимный том, если не указан явный.

> **Важно:** `VOLUME` в Dockerfile — это документация. Он не монтирует том, а объявляет, что данные должны храниться вне контейнера.

### Преимущества томов

| Преимущество | Что даёт |
|--------------|----------|
| **Управление Docker** | Docker создаёт, удаляет,备份 |
| **Не зависит от хоста** | Работает на любой ОС |
| **Изоляция** | Не конфликтует с файлами хоста |
| **Производительность** | Оптимизированы для Docker |
| **Безопасность** | Не требуют прав root |

## 03. Bind mounts

### Что это

**Bind mount** — это монтирование директории или файла с хоста в контейнер. Вы сами управляете этой директорией.

### Монтирование

```bash
docker run -d -v /host/path:/container/path nginx
```

**Что происходит:** директория `/host/path` на хосте монтируется в `/container/path` в контейнере. Всё, что пишется в `/container/path`, попадает в `/host/path`.

**Синтаксис:**

```
-v <путь-на-хосте>:<путь-в-контейнере>
```

### Пример: монтирование конфигурации

```bash
docker run -d \
  --name nginx \
  -v /etc/nginx/nginx.conf:/etc/nginx/nginx.conf:ro \
  nginx
```

**Что происходит:** файл конфигурации с хоста монтируется в контейнер. `:ro` — только для чтения.

### Пример: монтирование логов

```bash
docker run -d \
  --name app \
  -v /var/log/myapp:/app/logs \
  myapp
```

**Что происходит:** логи приложения пишутся в `/var/log/myapp` на хосте.

### Пример: монтирование с UUID

Если у вас есть отдельный диск с UUID:

```bash
sudo mkdir -p /mnt/logs
sudo mount UUID="2874bb04-4132-4d84-9c7f-af1212c7693b" /mnt/logs
```

**Что происходит:** диск монтируется в `/mnt/logs`.

**Добавляем в `/etc/fstab`:**

```
UUID="2874bb04-4132-4d84-9c7f-af1212c7693b" /mnt/logs    ext4  defaults  0 2
```

**Что происходит:** при загрузке диск автоматически монтируется.

**Монтируем в контейнер:**

```bash
docker run -d \
  --name app \
  -v /mnt/logs:/app/logs \
  myapp
```

**Что происходит:** логи пишутся на отдельный диск.

### Read-only bind mount

```bash
docker run -d -v /host/config:/app/config:ro nginx
```

**Что происходит:** `:ro` — контейнер может только читать. Это защищает от случайного изменения.

### Преимущества bind mounts

| Преимущество | Что даёт |
|--------------|----------|
| **Прямой доступ** | Файлы видны на хосте |
| **Гибкость** | Любая директория |
| **Совместимость** | Работает с любыми инструментами |
| **Контроль** | Вы управляете данными |

### Недостатки bind mounts

| Недостаток | Почему |
|------------|--------|
| **Зависимость от хоста** | Пути разные на разных ОС |
| **Права** | Могут быть проблемы с UID/GID |
| **Безопасность** | Контейнер может изменить файлы хоста |
| **Портативность** | Не работает на macOS/Windows так же |

## 04. tmpfs

### Что это

**tmpfs** — это монтирование в память (RAM). Данные не сохраняются на диск и теряются при остановке контейнера.

### Монтирование

```bash
docker run -d --tmpfs /tmp nginx
```

**Что происходит:** `/tmp` в контейнере хранится в памяти.

### С параметрами

```bash
docker run -d --tmpfs /tmp:size=100m,mode=1777 nginx
```

**Что происходит:** `/tmp` ограничен 100 МБ, права 1777.

### Когда использовать

| Сценарий | Почему |
|----------|--------|
| **Временные файлы** | Не нужны после остановки |
| **Секреты** | Не попадают на диск |
| **Кэш** | Быстрый доступ |
| **Тесты** | Быстро и чисто |

> **Важно:** tmpfs использует RAM. Не монтируйте большие объёмы — это может привести к OOM.

## 05. Сравнение

### Таблица сравнения

| Характеристика | Volume | Bind mount | tmpfs |
|----------------|--------|------------|-------|
| **Где хранится** | `/var/lib/docker/volumes/` | Любая директория | RAM |
| **Управление** | Docker | Пользователь | Ядро |
| **Сохраняется** | Да | Да | Нет |
| **Портативность** | Высокая | Низкая | Высокая |
| **Производительность** | Высокая | Средняя | Очень высокая |
| **Безопасность** | Высокая | Средняя | Высокая |
| **Использование** | Production | Development | Временные данные |

### Когда что использовать

| Сценарий | Рекомендация |
|----------|--------------|
| **База данных** | Volume |
| **Логи** | Volume или bind mount |
| **Конфигурация** | Bind mount (read-only) |
| **Временные файлы** | tmpfs |
| **Разработка** | Bind mount |
| **Production** | Volume |
| **Секреты** | tmpfs или Docker secrets |

## 06. Практические примеры

### Пример: PostgreSQL с томом

```bash
docker volume create pgdata

docker run -d \
  --name postgres \
  -e POSTGRES_PASSWORD=secret \
  -e POSTGRES_DB=mydb \
  -v pgdata:/var/lib/postgresql/data \
  -p 5432:5432 \
  postgres:16
```

**Что происходит:** данные PostgreSQL сохраняются в томе `pgdata`.

**Проверка:**

```bash
docker exec -it postgres psql -U postgres -d mydb -c "CREATE TABLE test (id int);"
docker rm -f postgres
docker run -d \
  --name postgres \
  -e POSTGRES_PASSWORD=secret \
  -e POSTGRES_DB=mydb \
  -v pgdata:/var/lib/postgresql/data \
  -p 5432:5432 \
  postgres:16
docker exec -it postgres psql -U postgres -d mydb -c "\dt"
```

**Что происходит:** таблица `test` на месте.

### Пример: nginx с конфигурацией и логами

```bash
mkdir -p /mnt/logs/nginx
mkdir -p /mnt/config/nginx

cat > /mnt/config/nginx/default.conf << 'EOF'
server {
    listen 80;
    location / {
        root /usr/share/nginx/html;
        index index.html;
    }
}
EOF

docker run -d \
  --name nginx \
  -p 80:80 \
  -v /mnt/config/nginx/default.conf:/etc/nginx/conf.d/default.conf:ro \
  -v /mnt/logs/nginx:/var/log/nginx \
  nginx
```

**Что происходит:**

- Конфигурация монтируется из `/mnt/config/nginx/default.conf`
- Логи пишутся в `/mnt/logs/nginx`

### Пример: приложение с логами на отдельном диске

```bash
# Монтируем диск
sudo mount UUID="2874bb04-4132-4d84-9c7f-af1212c7693b" /mnt/logs

# Запускаем приложение
docker run -d \
  --name app \
  -v /mnt/logs:/app/logs \
  myapp

# Смотрим логи
cat /mnt/logs/monitor.log
```

### Пример: Docker Compose с томами

```yaml
services:
  app:
    build: .
    volumes:
      - app-logs:/app/logs
      - ./config:/app/config:ro

  db:
    image: postgres:16
    environment:
      - POSTGRES_PASSWORD=secret
    volumes:
      - db-data:/var/lib/postgresql/data

volumes:
  app-logs:
  db-data:
```

**Что происходит:**

- `app-logs` — именованный том для логов
- `./config` — bind mount для конфигурации
- `db-data` — именованный том для базы данных

### Пример: tmpfs для секретов

```bash
docker run -d \
  --name app \
  --tmpfs /run/secrets:size=1m \
  -e SECRET_KEY=mysecret \
  myapp
```

**Что происходит:** `/run/secrets` хранится в памяти. При остановке контейнера данные теряются.

## Итог раздела

| Тема | Что даёт |
|------|----------|
| **Эфемерность** | Понимание, почему данные теряются |
| **Тома** | Управляемое Docker хранилище |
| **Bind mounts** | Монтирование директорий хоста |
| **tmpfs** | Хранение в памяти |
| **Сравнение** | Выбор подходящего способа |

> **Главный вывод:** контейнер — эфемерен. Для сохранения данных используйте тома (production) или bind mounts (development). Для временных данных — tmpfs.

**Ключевые правила:**

1. **База данных** → всегда том
2. **Конфигурация** → bind mount с `:ro`
3. **Логи** → том или bind mount
4. **Секреты** → tmpfs или Docker secrets
5. **Не храните данные в контейнере** — потеряете
