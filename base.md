# Общее представление о процессе загрузки

BIOS > POST > MBR > RAM(ОЗВУ) > CRUB2 > Kernel(ядро) > Systemd(Init)

биос - базовая система ввода вывода

POST(POWER ON SELF TEST) - самотест системы

MBR(MASTER BOOT RECORD) - биос ищет и определяет главные загрузочные записи и после этого помещает их в оперативную память(RAM-ОЗВУ)

CRUB2 - позволяет загружать все OS на системе и так же позволяет выбрать ядро для загрузки.
Т.е. его основная функция загрузить ядро linux в RAM
/boot/grub/grub.conf

Kernel(ядро) - после того как граб загрузил ядро в RAM, он передает процесс загрузки системы ядру.
Далее ядро использует временную файловую систему из файла initrd.img. После полной загрузки ядро передает управление Systemd(с).
initrd.img - это временная корневая файловая система, загружаемая в оперативную память во время загрузки Linux. Она используется ядром для начальной инициализации системы, в частности, для монтирования реальной корневой файловой системы, на которой находится основная операционная система
/boot - здесь находятся все доступные ядра в системе

Init - легаси загрузчик, при загрузке системы смотрит в файл inittab, чтобы определить уровень выполнения, всего их 6.
Для работы достаточно уровня 3 или 5:
- Уровень 0 — Остановка системы (Halt)
- Уровень 1 — Однопользовательский режим (Single-User Mode)
- Уровень 2 — Многопользовательский режим без сети (Multi-User, без NFS)
- Уровень 3 — Многопользовательский режим с сетью (Full Multi-User Mode)
- Уровень 4 — Не используется (User-Definable)
- Уровень 5 — Графический режим (X11, GUI)

- Уровень 6 — Перезагрузка (Reboot) (Доп. режим)
```bash
# Проверка уровня
runlevel
> N 5

systemctl get-default
> graphical.target
```
Важно заметить что systemd использует targets, вместо runlevels, т.е.:
```bash
multi-user.target ≈ уровень 3

graphical.target ≈ уровень 5.
```

Systemd - монтирует файловую систему /etc/fstab(тут описано что монтировать и куда), получает доступ к файлам конфигурации в /etc/ и после этих стартовых работ мы можем увидеть графический интерфейс 

- Питание поступает на материнскую плату > материнская плата подает питание на процессор
- После поступления питания на процессор, он выполняет базовые инструкции BIOS/UEFI(код которого постоянно хранится в ПЗУ)
- Базовая система(BIOS/UEFI) проверяет оборудование(процессор, диски, оперативку). Обычно процесс начинается с жесткого диска(флешка, диск, сетевая карта) и далее передает управление другому загрузчику(CRUB2)
    - Основное предназначение Базовой системы, проверка аппаратного обеспечения т.е. POST(Power-On Self-Test — самотестирование)
- После получения управления от базовой системы, загрузчик выполняет загрузку OS

# Разметка дисков MBR/GPT
- MBR (Master Boot Record) — старый стандарт (с 1983 года), работает даже на древних компьютерах.
    - Диски до 2 ТераБайт
    - 4 основных раздела
- GPT (GUID Partition Table) — современный стандарт (с 2000-х), требует UEFI (но некоторые системы с BIOS тоже поддерживают).
    - Диски до 9.4 ЗетаБайт
    - >= 128 разделов
```bash

Таблица разделов: gpt
...
```

# CRUB2

Чтобы попасть в его меню нужно зажать при включении `SHIFT/ESC`
Принимает управление от Базовой системы и позволяет загружать OS с выбранными параметрами т.е.:
- Меню выбора OS
- Позволяет выбрать версию ядра Linux
- Монтирует диск с модулями ядра или другими системными файлами в оперативную память
- Запускает ядро из файла `boot/vmlinuz-5.15.0-70-generic`
- Монтирует диск с модулями ядра, файлами системы в оперативную память из файла `boot/vmlinuz-5.15.0-70-generic`
- Изменить параметры загрузки ядра
