# 02. Troubleshooting: диагностика типовых проблем

Мы научились обновлять кластер, делать бэкапы, управлять сертификатами. Но что делать, когда **что-то сломалось**? Pod не запускается, Service не отвечает, узел NotReady. В этой лекции разберём **системный подход к диагностике** и типовые проблемы.

> **Troubleshooting** — это не гадание, а методичный процесс: собрать данные, сузить область, найти причину, исправить, проверить.

---

## Методология диагностики

### Системный подход

```
1. Определить симптом       → Что именно не работает?
2. Собрать данные           → Логи, события, метрики
3. Сузить область           → Сеть? Ресурсы? Конфигурация?
4. Найти причину            → Корень проблемы
5. Исправить                → Минимальное изменение
6. Проверить                → Убедиться, что работает
7. Задокументировать        → Чтобы не повторилось
```

### Инструменты диагностики

| Инструмент | Назначение |
|------------|------------|
| `kubectl get` | Список объектов |
| `kubectl describe` | Детали + события |
| `kubectl logs` | Логи контейнера |
| `kubectl exec` | Зайти в контейнер |
| `kubectl debug` | Эфемерный контейнер |
| `kubectl events` | События кластера |
| `kubectl top` | Метрики ресурсов |
| `kubectl auth can-i` | Проверка прав |
| `kubectl port-forward` | Проброс порта |
| `kubectl cp` | Копирование файлов |

### Универсальная команда

```bash
kubectl describe pod <pod-name> | grep -A20 "Events:"
```

**90% проблем видны в Events.**

## Часть 1: Pod не запускается

### Симптом: Pod в Pending

**Что означает:** Pod создан, но не назначен на узел.

**Диагностика:**

```bash
kubectl describe pod <pod-name>
kubectl get events --sort-by=.metadata.creationTimestamp
```

**Причины и решения:**

| Причина | Сообщение в Events | Решение |
|---------|-------------------|---------|
| Недостаточно ресурсов | `Insufficient cpu/memory` | Уменьшить requests, добавить узлы |
| Нет подходящего узла | `didn't match node selector` | Проверить labels, nodeSelector |
| Taints без tolerations | `had taint {dedicated: gpu}` | Добавить tolerations |
| PVC не Bound | `pod has unbound immediate PersistentVolumeClaims` | Проверить PVC, StorageClass |
| PodAntiAffinity | `didn't match pod anti-affinity rules` | Использовать `preferred` |
| Недостаточно IP | `no IP addresses available` | Проверить CNI, IP pool |

**Пример:**

```bash
kubectl describe pod my-pod
# Events:
#   Warning  FailedScheduling  ...  0/5 nodes are available: 2 Insufficient cpu, 3 node(s) had taint {dedicated: gpu}
```

**Решение:**

```bash
# Проверить ресурсы узлов
kubectl describe node <node> | grep -A10 "Allocated resources"
kubectl top nodes

# Проверить taints
kubectl describe node <node> | grep Taints

# Проверить labels
kubectl get nodes --show-labels
```

### Симптом: ImagePullBackOff / ErrImagePull

**Что означает:** не удалось скачать образ.

**Диагностика:**

```bash
kubectl describe pod <pod-name> | grep -A5 "Events:"
```

**Причины:**

| Причина | Решение |
|---------|---------|
| Неверное имя/тег образа | Проверить `image:` в манифесте |
| Приватный registry без секрета | Добавить `imagePullSecrets` |
| Неверные credentials | Проверить Secret |
| Registry недоступен | Проверить сеть с узла |
| Rate limit (Docker Hub) | Использовать другой registry |

**Решение:**

```bash
# Проверить образ
kubectl get pod my-pod -o jsonpath='{.spec.containers[*].image}'

# Проверить imagePullSecrets
kubectl get pod my-pod -o jsonpath='{.spec.imagePullSecrets}'

# Проверить Secret
kubectl get secret regcred -o yaml

# Проверить доступ с узла
kubectl debug node/<node> -it --image=busybox -- wget -qO- https://registry.example.com/v2/
```

### Симптом: CrashLoopBackOff

**Что означает:** контейнер запускается и сразу падает. kubelet перезапускает, снова падает.

**Диагностика:**

```bash
# Логи текущего запуска
kubectl logs <pod-name>

# Логи предыдущего запуска (важно!)
kubectl logs <pod-name> --previous

# События
kubectl describe pod <pod-name> | grep -A10 "Events:"

# Код выхода
kubectl get pod <pod-name> -o jsonpath='{.status.containerStatuses[*].lastState.terminated.exitCode}'
```

**Причины:**

| Exit Code | Причина | Решение |
|-----------|---------|---------|
| 0 | Контейнер завершился успешно, но Pod не Job | Проверить `command`, `restartPolicy` |
| 1 | Общая ошибка | Смотреть логи |
| 137 | OOMKilled или SIGKILL | Увеличить limits.memory |
| 139 | Segfault | Проблема с приложением |
| 143 | SIGTERM | Graceful shutdown |

**Решение:**

```bash
# OOMKilled
kubectl describe pod my-pod | grep -i oom
# Увеличить limits.memory

# Ошибка в command
kubectl get pod my-pod -o jsonpath='{.spec.containers[*].command}'
kubectl get pod my-pod -o jsonpath='{.spec.containers[*].args}'

# Проверить ConfigMap/Secret
kubectl get configmap my-config
kubectl get secret my-secret
```

### Симптом: CreateContainerConfigError

**Что означает:** не удалось создать контейнер из-за конфигурации.

**Причины:**

| Причина | Решение |
|---------|---------|
| ConfigMap не найден | Создать ConfigMap |
| Secret не найден | Создать Secret |
| ServiceAccount не найден | Создать ServiceAccount |
| Неверный ключ в ConfigMap | Проверить ключи |

**Решение:**

```bash
kubectl describe pod my-pod | grep -A5 "Events:"
# Error: configmap "my-config" not found

kubectl get configmap -n <namespace>
kubectl get secret -n <namespace>
kubectl get serviceaccount -n <namespace>
```

### Симптом: RunContainerError

**Что означает:** контейнер не может быть запущен.

**Причины:**
- Неверный `command`.
- Нет исполняемого файла.
- Проблемы с volume mount.

**Решение:**

```bash
kubectl describe pod my-pod | grep -A5 "Events:"
kubectl logs my-pod --previous
```

### Симптом: Terminating (застрял)

**Что означает:** Pod не может завершиться.

**Причины:**
- Finalizers.
- Проблемы с узлом.
- Graceful shutdown не завершается.

**Решение:**

```bash
# Проверить finalizers
kubectl get pod my-pod -o jsonpath='{.metadata.finalizers}'

# Удалить finalizer
kubectl patch pod my-pod -p '{"metadata":{"finalizers":[]}}' --type=merge

# Форсированное удаление
kubectl delete pod my-pod --grace-period=0 --force
```

> [!warning]
> Форсированное удаление может оставить «зомби»-процессы на узле.

### Симптом: Evicted

**Что означает:** Pod вытеснен с узла из-за нехватки ресурсов.

**Причины:**
- MemoryPressure.
- DiskPressure.
- PIDPressure.

**Решение:**

```bash
kubectl describe pod my-pod | grep -A5 "Status:"
kubectl describe node <node> | grep -A5 "Conditions:"

# Увеличить resources
# Очистить диск
# Добавить узлы
```

## Часть 2: Service не работает

### Симптом: Service не отвечает

**Диагностика:**

```bash
kubectl get svc my-service
kubectl get endpoints my-service
kubectl describe svc my-service
```

**Причины:**

| Причина | Решение |
|---------|---------|
| Endpoints пуст | Проверить selector Service и labels Pod |
| Pod не Ready | Проверить readinessProbe |
| Неверный targetPort | Проверить порт контейнера |
| NetworkPolicy блокирует | Проверить политики |

**Пример:**

```bash
kubectl get endpoints my-service
# NAME         ENDPOINTS   AGE
# my-service   <none>      5m
```

**Что делать:**

```bash
# Проверить selector Service
kubectl get svc my-service -o jsonpath='{.spec.selector}'

# Проверить labels Pod
kubectl get pods --show-labels

# Проверить readiness
kubectl get pods -o wide
kubectl describe pod <pod-name> | grep -A5 "Readiness"
```

### Симптом: DNS не резолвится

**Диагностика:**

```bash
kubectl run -it --rm debug --image=busybox:1.36 --restart=Never -- nslookup my-service
kubectl run -it --rm debug --image=busybox:1.36 --restart=Never -- cat /etc/resolv.conf
```

**Причины:**

| Причина | Решение |
|---------|---------|
| CoreDNS не работает | Проверить Pod CoreDNS |
| NetworkPolicy блокирует DNS | Разрешить DNS |
| Неверное имя | Проверить namespace |
| ndots:5 | Использовать FQDN |

**Решение:**

```bash
# Проверить CoreDNS
kubectl get pods -n kube-system -l k8s-app=kube-dns
kubectl logs -n kube-system -l k8s-app=kube-dns

# Проверить Service kube-dns
kubectl get svc -n kube-system kube-dns

# Проверить resolv.conf в Pod
kubectl exec -it my-pod -- cat /etc/resolv.conf
```

### Симптом: Ingress не работает

**Диагностика:**

```bash
kubectl get ingress
kubectl describe ingress my-ingress
kubectl logs -n ingress-nginx deploy/ingress-nginx-controller
```

**Причины:**

| Причина | Решение |
|---------|---------|
| Ingress Controller не установлен | Установить |
| Неверный ingressClassName | Проверить |
| Service не существует | Создать Service |
| TLS Secret не найден | Создать Secret |
| DNS не настроен | Настроить DNS |

**Решение:**

```bash
# Проверить Ingress Controller
kubectl get pods -n ingress-nginx
kubectl get ingressclass

# Проверить Service
kubectl get svc my-service

# Проверить TLS
kubectl get secret my-tls-secret

# Проверить DNS
nslookup app.example.com
```

## Часть 3: Узел NotReady

### Симптом: Node NotReady

**Диагностика:**

```bash
kubectl get nodes
kubectl describe node <node>
```

**Причины:**

| Причина | Решение |
|---------|---------|
| kubelet не работает | Проверить kubelet |
| Сеть недоступна | Проверить сеть |
| Диск заполнен | Очистить диск |
| Память закончилась | Добавить память |
| Сертификат просрочен | Обновить сертификат |
| Container runtime упал | Перезапустить |

**Решение:**

```bash
# Проверить kubelet
systemctl status kubelet
journalctl -u kubelet -f

# Проверить runtime
systemctl status containerd
journalctl -u containerd -f

# Проверить ресурсы
df -h
free -h
top

# Проверить сертификаты
kubeadm certs check-expiration

# Проверить условия узла
kubectl describe node <node> | grep -A10 "Conditions:"
```

### Симптом: Node Pressure

```
MemoryPressure   True
DiskPressure     True
PIDPressure      True
```

**Решение:**

```bash
# MemoryPressure
kubectl describe node <node> | grep -A5 "Allocated resources"
kubectl top pods --all-namespaces --sort-by=memory

# DiskPressure
df -h
du -sh /var/lib/docker/*
du -sh /var/log/*
# Очистить: docker system prune, logrotate

# PIDPressure
ps aux | wc -l
# Увеличить pid_max
```

### Симптом: Node NotReady после upgrade

**Решение:**

```bash
# Проверить kubelet
systemctl status kubelet
journalctl -u kubelet -f

# Проверить версию
kubelet --version
kubectl version --short

# Проверить CNI
ls /etc/cni/net.d/
kubectl get pods -n kube-system | grep -E "calico|cilium|flannel"
```

## Часть 5: Проблемы с хранилищем

### Симптом: PVC в Pending

**Диагностика:**

```bash
kubectl get pvc
kubectl describe pvc my-pvc
kubectl get storageclass
```

**Причины:**

| Причина | Решение |
|---------|---------|
| Нет StorageClass | Создать StorageClass |
| Нет provisioner | Установить CSI |
| WaitForFirstConsumer | Создать Pod |
| Недостаточно capacity | Увеличить |

**Решение:**

```bash
kubectl describe pvc my-pvc | grep -A5 "Events:"
kubectl logs -n kube-system <csi-provisioner-pod>
```

### Симптом: Pod не монтирует PVC

**Диагностика:**

```bash
kubectl describe pod my-pod | grep -A10 "Events:"
# Unable to attach or mount volumes
```

**Решение:**

```bash
kubectl get volumeattachments
kubectl describe volumeattachment <name>
kubectl logs -n kube-system <csi-node-pod>
```

### Симптом: VolumeAttachment застрял

**Решение:**

```bash
kubectl get volumeattachments
kubectl describe volumeattachment <name>
# Если узел удалён — удалить вручную
kubectl delete volumeattachment <name>
```

| Причина | Решение |


## Часть 7: Проблемы с RBAC

### Симптом: Forbidden

```
Error from server (Forbidden): pods is forbidden:
User "system:serviceaccount:default:my-sa" cannot list resource "pods"
```

**Диагностика:**

```bash
kubectl auth can-i list pods --as=system:serviceaccount:default:my-sa
kubectl auth can-i --list --as=system:serviceaccount:default:my-sa
```

**Решение:**

```bash
# Создать Role/ClusterRole и Binding
kubectl create role pod-reader --verb=get,list,watch --resource=pods
kubectl create rolebinding pod-reader --role=pod-reader --serviceaccount=default:my-sa
```

### Симптом: Unauthorized

```
Error from server (Unauthorized): Unauthorized
```

**Причины:**
- Просроченный токен.
- Неверный kubeconfig.
- Сертификат невалиден.

**Решение:**

```bash
kubectl config view
kubectl config current-context
kubeadm certs check-expiration
```

## Практический пример: полный цикл диагностики

### Проблема: Pod не запускается

**Шаг 1: Проверить статус**

```bash
kubectl get pods
# NAME       READY   STATUS             RESTARTS   AGE
# my-pod     0/1     CrashLoopBackOff   5          5m
```

**Шаг 2: Собрать данные**

```bash
kubectl describe pod my-pod
kubectl logs my-pod --previous
```

**Шаг 3: Сузить область**

```bash
# Проверить events
kubectl get events --sort-by=.metadata.creationTimestamp

# Проверить ресурсы
kubectl top pods

# Проверить конфигурацию
kubectl get pod my-pod -o yaml
```

**Шаг 4: Найти причину**

```bash
# В логах: "Cannot connect to database"
# Причина: БД недоступна
```

**Шаг 5: Исправить**

```bash
# Проверить Service БД
kubectl get svc postgres
kubectl get endpoints postgres
```

**Шаг 6: Проверить**

```bash
kubectl get pods
kubectl logs my-pod
```

## Итог

1. **Системный подход:** симптом → данные → сузить → причина → исправить → проверить.
2. **Events —最重要.** 90% проблем видны в `kubectl describe pod`.
3. **Pending:** ресурсы, taints, PVC, affinity.
4. **ImagePullBackOff:** образ, registry, credentials.
5. **CrashLoopBackOff:** логи previous, exit code, OOMKilled.
6. **Service не работает:** Endpoints, selector, targetPort.
7. **Node NotReady:** kubelet, runtime, ресурсы.
8. **OOMKilled:** увеличить limits.memory.
9. **PVC Pending:** StorageClass, provisioner.
10. **RBAC:** `kubectl auth can-i`.

> [!tip]
> **Правило диагностики:**
> - Pod не запускается → `kubectl describe pod` → Events
> - Pod падает → `kubectl logs --previous`
> - Service не работает → `kubectl get endpoints`
> - Node NotReady → `journalctl -u kubelet`
> - API недоступен → `crictl ps` + логи
> - Сеть → `netshoot` + `tcpdump`
> - RBAC → `kubectl auth can-i`

> [!warning]
> **Не удаляйте Pod сразу.** Сначала соберите данные: `describe`, `logs`, `exec`. После удаления логи и события исчезнут.
