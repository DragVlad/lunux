# 01. CRD и Operators: расширение Kubernetes

Мы разобрали, как Kubernetes управляет Pod, Deployment, Service. Но что, если вам нужно управлять **чем-то своим**? Например, базами данных, очередями, сертификатами, кластерами Kafka? Kubernetes позволяет **расширять себя** через **Custom Resource Definitions (CRD)** и **Operators**.

> **Главная идея:** Kubernetes — это не просто оркестратор контейнеров. Это **платформа для построения платформ**. CRD и Operators позволяют добавлять новые типы объектов и логику их обработки.

---

## Часть 1: Custom Resource Definition (CRD)

> **CRD** — это способ определить **свой тип объекта** в Kubernetes. После создания CRD вы можете создавать объекты этого типа через `kubectl`, API, YAML.

### Зачем нужны CRD

Kubernetes имеет встроенные объекты: Pod, Service, Deployment. Но что, если вам нужно:
- Управлять базами данных (`kind: PostgreSQL`).
- Управлять сертификатами (`kind: Certificate`).
- Управлять кластерами Kafka (`kind: Kafka`).
- Управлять политиками (`kind: Policy`).

CRD позволяют добавить эти типы **без изменения кода Kubernetes**.

### Пример: CRD для PostgreSQL

```yaml
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  name: postgresqls.database.example.com
spec:
  group: database.example.com
  names:
    kind: PostgreSQL
    listKind: PostgreSQLList
    plural: postgresqls
    singular: postgresql
    shortNames:
      - pg
  scope: Namespaced
  versions:
    - name: v1
      served: true
      storage: true
      schema:
        openAPIV3Schema:
          type: object
          properties:
            spec:
              type: object
              properties:
                version:
                  type: string
                  enum: ["13", "14", "15", "16"]
                storage:
                  type: string
                  pattern: "^[0-9]+Gi$"
                replicas:
                  type: integer
                  minimum: 1
                  maximum: 5
              required:
                - version
                - storage
            status:
              type: object
              properties:
                phase:
                  type: string
                ready:
                  type: boolean
      subresources:
        status: {}
      additionalPrinterColumns:
        - name: Version
          type: string
          jsonPath: .spec.version
        - name: Storage
          type: string
          jsonPath: .spec.storage
        - name: Phase
          type: string
          jsonPath: .status.phase
```

### Разбор CRD

| Поле | Назначение |
|------|------------|
| `group` | API-группа (`database.example.com`) |
| `names.kind` | Тип объекта (`PostgreSQL`) |
| `names.plural` | Множественное число (`postgresqls`) |
| `names.shortNames` | Короткие имена (`pg`) |
| `scope` | `Namespaced` или `Cluster` |
| `versions` | Версии API |
| `schema` | OpenAPI-схема (валидация) |
| `subresources.status` | Включает `/status` subresource |
| `additionalPrinterColumns` | Колонки в `kubectl get` |

### Создание CRD

```bash
kubectl apply -f postgresql-crd.yaml
kubectl get crds
kubectl get crd postgresqls.database.example.com
```

### Создание Custom Resource

```yaml
apiVersion: database.example.com/v1
kind: PostgreSQL
metadata:
  name: my-postgres
  namespace: default
spec:
  version: "16"
  storage: "10Gi"
  replicas: 3
```

```bash
kubectl apply -f my-postgres.yaml
kubectl get postgresqls
kubectl get pg
kubectl describe pg my-postgres
```

> [!note]
> **CRD сам по себе ничего не делает.** Он только определяет тип объекта. Чтобы объект **работал** (создавал Pod, Service, PVC), нужен **Controller** (Operator).

### Валидация через OpenAPI Schema

CRD schema валидирует объекты:

```yaml
schema:
  openAPIV3Schema:
    type: object
    properties:
      spec:
        type: object
        properties:
          version:
            type: string
            enum: ["13", "14", "15", "16"]      # только эти значения
          storage:
            type: string
            pattern: "^[0-9]+Gi$"                # формат 10Gi
          replicas:
            type: integer
            minimum: 1
            maximum: 5
        required:
          - version
          - storage
```

**Что произойдёт:** если создать PostgreSQL с `version: "17"` — Kubernetes отклонит.

### Версионирование CRD

```yaml
spec:
  versions:
    - name: v1
      served: true
      storage: true
      schema:
        # ...
    - name: v2
      served: true
      storage: false
      schema:
        # ...
```

| Поле | Описание |
|------|----------|
| `served` | Версия доступна через API |
| `storage` | Версия для хранения в etcd (только одна) |

**Conversion Webhook** — для конвертации между версиями:

```yaml
spec:
  conversion:
    strategy: Webhook
    webhook:
      clientConfig:
        service:
          name: conversion-webhook
          namespace: default
          path: /convert
      conversionReviewVersions: ["v1"]
```

### Categories

```yaml
names:
  categories:
    - all
    - database
```

Теперь `kubectl get all` покажет PostgreSQL.

### Scale subresource

```yaml
spec:
  versions:
    - name: v1
      subresources:
        scale:
          specReplicasPath: .spec.replicas
          statusReplicasPath: .status.replicas
          labelSelectorPath: .status.selector
```

Теперь работает:

```bash
kubectl scale pg my-postgres --replicas=5
```

### Finalizers

```yaml
metadata:
  finalizers:
    - database.example.com/cleanup
```

**Finalizer** — блокирует удаление объекта, пока контроллер не выполнит очистку.

**Логика:**
1. Пользователь удаляет объект.
2. Kubernetes ставит `deletionTimestamp`, но не удаляет.
3. Controller видит finalizer, выполняет очистку.
4. Controller удаляет finalizer.
5. Kubernetes удаляет объект.

## Часть 2: Operators

> **Operator** — это **Controller**, который управляет Custom Resource. Он знает, как развернуть, масштабировать, обновлять и восстанавливать приложение.

### Что такое Controller

**Controller** — это цикл:

```
for {
    desired_state := get_desired_state()      // из CR
    current_state := get_current_state()      // из кластера
    if current_state != desired_state {
        take_action_to_fix()                  // создать/обновить/удалить
    }
    sleep()
}
```

**Operator** — это Controller для конкретного приложения, который знает **domain-specific** логику.

### Operator vs CRD

| CRD | Operator |
|-----|----------|
| Определяет **тип** объекта | Управляет **жизненным циклом** |
| Не делает ничего сам | Создаёт Pod, Service, PVC |
| Статичный | Активный |

**Аналогия:** CRD — это «чертёж». Operator — это «инженер», который по чертежу строит.

### Что умеет Operator

| Задача | Описание |
|--------|----------|
| **Provisioning** | Создаёт Pod, Service, PVC, ConfigMap |
| **Scaling** | Реагирует на изменение `replicas` |
| **Upgrade** | Обновляет версию приложения |
| **Backup** | Создаёт резервные копии |
| **Restore** | Восстанавливает из бэкапа |
| **Failover** | Переключает на реплику при сбое |
| **Configuration** | Применяет настройки |

### Пример: PostgreSQL Operator

**CR:**

```yaml
apiVersion: database.example.com/v1
kind: PostgreSQL
metadata:
  name: my-postgres
spec:
  version: "16"
  storage: "10Gi"
  replicas: 3
  backup:
    schedule: "0 3 * * *"
    retention: 7
```

**Operator:**

1. Создаёт StatefulSet с 3 репликами.
2. Создаёт Headless Service.
3. Создаёт PVC для каждого Pod.
4. Настраивает репликацию (master-replica).
5. Настраивает бэкапы через CronJob.
6. Следит за здоровьем.
7. При сбое master — делает failover.

**Reconciler (упрощённо):**

```go
func (r *PostgreSQLReconciler) Reconcile(ctx context.Context, req ctrl.Request) (ctrl.Result, error) {
    // 1. Получить CR
    pg := &databasev1.PostgreSQL{}
    if err := r.Get(ctx, req.NamespacedName, pg); err != nil {
        return ctrl.Result{}, client.IgnoreNotFound(err)
    }

    // 2. Проверить, существует ли StatefulSet
    sts := &appsv1.StatefulSet{}
    err := r.Get(ctx, types.NamespacedName{Name: pg.Name, Namespace: pg.Namespace}, sts)
    if apierrors.IsNotFound(err) {
        // 3. Создать StatefulSet
        sts = r.buildStatefulSet(pg)
        if err := r.Create(ctx, sts); err != nil {
            return ctrl.Result{}, err
        }
        return ctrl.Result{Requeue: true}, nil
    }

    // 4. Обновить статус
    pg.Status.Phase = "Running"
    pg.Status.Ready = true
    if err := r.Status().Update(ctx, pg); err != nil {
        return ctrl.Result{}, err
    }

    return ctrl.Result{}, nil
}
```

### Kopf: пример на Python

**Установка:**

```bash
pip install kopf kubernetes
```

**Operator:**

```python
import kopf
import kubernetes

@kopf.on.create('database.example.com', 'v1', 'postgresqls')
def create_fn(spec, name, namespace, logger, **kwargs):
    logger.info(f"Creating PostgreSQL {name}")

    # Создать StatefulSet
    api = kubernetes.client.AppsV1Api()
    sts = kubernetes.client.V1StatefulSet(
        metadata=kubernetes.client.V1ObjectMeta(name=name),
        spec=kubernetes.client.V1StatefulSetSpec(
            service_name=name,
            replicas=spec.get('replicas', 1),
            selector=kubernetes.client.V1LabelSelector(
                match_labels={"app": name}
            ),
            template=kubernetes.client.V1PodTemplateSpec(
                metadata=kubernetes.client.V1ObjectMeta(
                    labels={"app": name}
                ),
                spec=kubernetes.client.V1PodSpec(
                    containers=[
                        kubernetes.client.V1Container(
                            name="postgres",
                            image=f"postgres:{spec['version']}",
                            env=[
                                kubernetes.client.V1EnvVar(
                                    name="POSTGRES_PASSWORD",
                                    value="secret"
                                )
                            ]
                        )
                    ]
                )
            )
        )
    )
    api.create_namespaced_stateful_set(namespace, sts)

    return {'phase': 'Creating'}
```

### Best practices для Operators

| Практика | Почему |
|----------|--------|
| Один Operator — одно приложение | Изоляция |
| Idempotent Reconciler | Можно вызывать многократно |
| Finalizers для очистки | Не оставлять мусор |
| Status subresource | Отделить статус от spec |
| Admission webhooks | Валидация CR |
| OwnerReferences | Каскадное удаление |
| Metrics | Prometheus metrics |
| Логирование | Structured logs |
| Тесты | Unit + integration |
| Документация | README, examples |

### Anti-patterns

| Anti-pattern | Почему плохо |
|--------------|--------------|
| Operator для простого Deployment | Избыточно |
| Слишком много логики в CRD schema | Сложно поддерживать |
| Игнорирование status | Нет обратной связи |
| Отсутствие finalizers | Мусор в кластере |
| Синхронные операции | Блокирует Reconciler |
| Хардкод значений | Нет гибкости |

### Шаг 2: Operator на Python (kopf)

**Файл `operator.py`:**

```python
import kopf
import kubernetes
from kubernetes import client, config

# Загрузить конфигурацию
config.load_incluster_config()  # или config.load_kube_config() для локальной разработки

@kopf.on.create('example.com', 'v1', 'websites')
def create_website(spec, name, namespace, logger, **kwargs):
    logger.info(f"Creating Website {name}")

    replicas = spec.get('replicas', 1)
    image = spec['image']

    # Создать Deployment
    apps_api = client.AppsV1Api()
    deployment = client.V1Deployment(
        metadata=client.V1ObjectMeta(name=f"{name}-deployment"),
        spec=client.V1DeploymentSpec(
            replicas=replicas,
            selector=client.V1LabelSelector(
                match_labels={"app": name}
            ),
            template=client.V1PodTemplateSpec(
                metadata=client.V1ObjectMeta(
                    labels={"app": name}
                ),
                spec=client.V1PodSpec(
                    containers=[
                        client.V1Container(
                            name="web",
                            image=image,
                            ports=[client.V1ContainerPort(container_port=80)]
                        )
                    ]
                )
            )
        )
    )

    try:
        apps_api.create_namespaced_deployment(namespace, deployment)
    except kubernetes.client.exceptions.ApiException as e:
        if e.status != 409:  # Already exists
            raise

    # Создать Service
    core_api = client.CoreV1Api()
    service = client.V1Service(
        metadata=client.V1ObjectMeta(name=f"{name}-service"),
        spec=client.V1ServiceSpec(
            selector={"app": name},
            ports=[client.V1ServicePort(port=80, target_port=80)],
            type="ClusterIP"
        )
    )

    try:
        core_api.create_namespaced_service(namespace, service)
    except kubernetes.client.exceptions.ApiException as e:
        if e.status != 409:
            raise

    return {'phase': 'Running', 'url': f"http://{name}-service.{namespace}.svc.cluster.local"}


@kopf.on.update('example.com', 'v1', 'websites')
def update_website(spec, name, namespace, logger, **kwargs):
    logger.info(f"Updating Website {name}")

    replicas = spec.get('replicas', 1)
    apps_api = client.AppsV1Api()

    # Обновить replicas
    apps_api.patch_namespaced_deployment_scale(
        name=f"{name}-deployment",
        namespace=namespace,
        body={'spec': {'replicas': replicas}}
    )


@kopf.on.delete('example.com', 'v1', 'websites')
def delete_website(name, namespace, logger, **kwargs):
    logger.info(f"Deleting Website {name}")

    apps_api = client.AppsV1Api()
    core_api = client.CoreV1Api()

    try:
        apps_api.delete_namespaced_deployment(f"{name}-deployment", namespace)
    except kubernetes.client.exceptions.ApiException as e:
        if e.status != 404:
            raise

    try:
        core_api.delete_namespaced_service(f"{name}-service", namespace)
    except kubernetes.client.exceptions.ApiException as e:
        if e.status != 404:
            raise
```

### Шаг 3: RBAC для Operator

**Файл `rbac.yaml`:**

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: website-operator
  namespace: default
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: website-operator
rules:
  - apiGroups: ["example.com"]
    resources: ["websites", "websites/status"]
    verbs: ["get", "list", "watch", "create", "update", "patch", "delete"]
  - apiGroups: ["apps"]
    resources: ["deployments"]
    verbs: ["get", "list", "watch", "create", "update", "patch", "delete"]
  - apiGroups: [""]
    resources: ["services"]
    verbs: ["get", "list", "watch", "create", "update", "patch", "delete"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: website-operator
subjects:
  - kind: ServiceAccount
    name: website-operator
    namespace: default
roleRef:
  kind: ClusterRole
  name: website-operator
  apiGroup: rbac.authorization.k8s.io
```

## Troubleshooting

### CRD не создаётся

```
Error: CustomResourceDefinition.apiextensions.k8s.io "postgresqls.database.example.com" is invalid
```

**Причины:**
- Неверная схема OpenAPI.
- Дублирование версий.
- Некорректный `group`.

**Решение:**

```bash
kubectl apply -f crd.yaml --dry-run=server
kubectl describe crd postgresqls.database.example.com
```

### CR не создаётся

```
Error: error validating data: ValidationError(PostgreSQL.spec): unknown field "storageSize"
```

**Причины:**
- Поле не в схеме.
- Опечатка.

**Решение:**

```bash
kubectl explain postgresqls.spec
kubectl explain postgresqls.spec.version
```

### Operator не реагирует

**Причины:**
- RBAC недостаточно.
- Operator не запущен.
- Ошибка в Reconciler.

**Решение:**

```bash
kubectl logs -l app=my-operator
kubectl describe clusterrole my-operator
kubectl auth can-i create deployments --as=system:serviceaccount:default:my-operator
```

### Finalizer блокирует удаление

```
Error: object is being deleted: customresource "my-cr" is being deleted
```

**Причины:**
- Operator не удалил finalizer.
- Operator не работает.

**Решение:**

```bash
# Временно удалить finalizer вручную
kubectl patch pg my-postgres -p '{"metadata":{"finalizers":[]}}' --type=merge
```

> [!warning]
> Удаление finalizer вручную может оставить мусор. Используйте только в крайнем случае.

### Conversion Webhook не работает

```
Error: conversion webhook for database.example.com/v1, Kind=PostgreSQL failed
```

**Решение:**

```bash
kubectl logs -n default deploy/conversion-webhook
kubectl get crd postgresqls.database.example.com -o yaml | grep -A10 conversion
```

## Итог

1. **CRD** — определение своего типа объекта. Не делает ничего сам.
2. **Operator** — Controller для CR. Управляет жизненным циклом.
3. **CRD + Controller = Operator.**
4. **OpenAPI Schema** — валидация CR.
5. **Finalizers** — очистка при удалении.
6. **Status subresource** — отделить статус от spec.
7. **Фреймворки:** Operator SDK (Go), Kubebuilder (Go), Kopf (Python).
8. **OLM** — менеджер Operators.
9. **Популярные Operators:** Prometheus, cert-manager, Strimzi, Rook.
10. **Best practices:** idempotent Reconciler, OwnerReferences, metrics, tests.

> [!tip]
> **Правило выбора:**
> - Нужен свой тип объекта → **CRD**
> - Нужна логика управления → **Operator**
> - Простой Operator → **Kopf (Python)**
> - Мощный Operator → **Kubebuilder / Operator SDK (Go)**
> - Готовый Operator → **OperatorHub**
> - Управление Operators → **OLM**

> [!warning]
> **Не пишите Operator, если можно обойтись Helm-чартом или Kustomize.** Operator нужен, когда есть **domain-specific** логика: репликация, failover, backup, upgrade.
