# 02. Безопасность глубже: Pod Security, Admission Controllers, secrets

В прошлой лекции мы разобрали RBAC, ServiceAccount и NetworkPolicy — базовый уровень безопасности. Но Kubernetes — это **глубоко настраиваемая система**, и безопасность не заканчивается на RBAC. Есть ещё несколько слоёв: **Pod Security**, **Admission Controllers** и правильная работа с **секретами**.

В этой лекции разберём продвинутые темы безопасности.

> **Безопасность — это слоёный пирог.** Каждый слой защищает от разных угроз. RBAC защищает API. NetworkPolicy — сеть. Pod Security — runtime. Admission Controllers — политики. Secrets — данные.

---

## Часть 1: Pod Security Standards (PSS)

> **Pod Security Standards** — три предопределённых уровня безопасности для Pod, определённых Kubernetes.

### Три уровня

| Уровень | Описание | Для кого |
|---------|----------|----------|
| **Privileged** | Без ограничений | Системные компоненты (CNI, CSI) |
| **Baseline** | Минимальные ограничения | Обычные приложения |
| **Restricted** | Строгие ограничения | Критичные приложения |

### Privileged

**Нет ограничений.** Pod может делать всё:
- `privileged: true`
- `hostNetwork: true`
- `hostPID: true`
- `hostPath` volumes
- Все capabilities

**Использование:** только для системных компонентов (kube-proxy, CNI, CSI).

### Baseline

**Минимальные ограничения.** Запрещает:
- `privileged: true`
- `hostNetwork`, `hostPID`, `hostIPC`
- `hostPath` volumes
- Добавление опасных capabilities (`SYS_ADMIN`, `NET_ADMIN`)
- `allowPrivilegeEscalation: true` без причины

**Разрешает:**
- Запуск от root
- Запись в root FS
- Обычные capabilities

### Restricted

**Строгие ограничения.** Дополнительно к Baseline запрещает:
- Запуск от root (`runAsNonRoot: true` обязательно)
- `allowPrivilegeEscalation: true`
- Все capabilities кроме `NET_BIND_SERVICE`
- Запись в root FS (`readOnlyRootFilesystem: true`)
- Требует `seccompProfile: RuntimeDefault`

### Реализация: Pod Security Admission

> **Pod Security Admission (PSA)** — встроенный admission-контроллер для PSS (с v1.23, стабильный с v1.25).

**Namespace labels:**

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: production
  labels:
    pod-security.kubernetes.io/enforce: restricted
    pod-security.kubernetes.io/enforce-version: v1.28
    pod-security.kubernetes.io/audit: restricted
    pod-security.kubernetes.io/audit-version: v1.28
    pod-security.kubernetes.io/warn: restricted
    pod-security.kubernetes.io/warn-version: v1.28
```

### Три режима

| Режим | Поведение |
|-------|-----------|
| `enforce` | Отклоняет Pod, нарушающие политику |
| `audit` | Логирует нарушения, но не отклоняет |
| `warn` | Показывает предупреждение пользователю |

**Best practice:** использовать все три режима:

```yaml
labels:
  pod-security.kubernetes.io/enforce: baseline       # Отклонять
  pod-security.kubernetes.io/audit: restricted       # Логировать
  pod-security.kubernetes.io/warn: restricted        # Предупреждать
```

### Исключения

Можно исключить конкретные namespace или пользователей:

```yaml
# В конфигурации API-сервера (--admission-control-config-file)
apiVersion: apiserver.config.k8s.io/v1
kind: AdmissionConfiguration
plugins:
  - name: PodSecurity
    configuration:
      apiVersion: pod-security.admission.config.k8s.io/v1
      kind: PodSecurityConfiguration
      defaults:
        enforce: "baseline"
        enforce-version: "latest"
      exemptions:
        usernames: []
        runtimeClasses: []
        namespaces:
          - kube-system
          - istio-system
```

### Пример: Restricted Pod

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: restricted-pod
  namespace: production
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 1000
    runAsGroup: 3000
    fsGroup: 2000
    seccompProfile:
      type: RuntimeDefault
  containers:
    - name: app
      image: myapp:1.0
      securityContext:
        allowPrivilegeEscalation: false
        readOnlyRootFilesystem: true
        capabilities:
          drop:
            - ALL
      volumeMounts:
        - name: tmp
          mountPath: /tmp
        - name: cache
          mountPath: /var/cache
  volumes:
    - name: tmp
      emptyDir: {}
    - name: cache
      emptyDir: {}
```

> [!important]
> **`readOnlyRootFilesystem: true` требует writable volumes** для `/tmp`, `/var/cache`, `/var/run`. Иначе приложение упадёт.

### Что делать, если Pod не соответствует Restricted

1. **Проверить логи:** `kubectl describe pod` покажет причину.
2. **Добавить securityContext.**
3. **Использовать writable volumes** для временных файлов.
4. **Сменить базовый образ** на non-root (например, `nginxinc/nginx-unprivileged`).
5. **Если нельзя** — использовать `baseline` вместо `restricted`.

### Проверка

```bash
# Labels namespace
kubectl get namespaces --show-labels

# Проверить, соответствует ли Pod
kubectl label --dry-run=server --overwrite namespace production pod-security.kubernetes.io/enforce=restricted

# События
kubectl get events --field-selector reason=FailedCreate
```

## Часть 2: Admission Controllers

> **Admission Controllers** — плагины API-сервера, которые перехватывают запросы **после аутентификации и авторизации**, но **до сохранения** в etcd.

### Два типа

| Тип | Действие | Пример |
|-----|----------|--------|
| **Mutating** | Изменяет объект | Добавляет labels, sidecar, limits |
| **Validating** | Проверяет и отклоняет | Проверяет Pod Security, квоты |

**Порядок:** сначала Mutating, потом Validating.

### Встроенные Admission Controllers

| Контроллер | Тип | Роль |
|------------|-----|------|
| **NamespaceLifecycle** | Validating | Не даёт создавать объекты в удалённых namespace |
| **LimitRanger** | Mutating + Validating | Применяет LimitRange |
| **ResourceQuota** | Validating | Проверяет ResourceQuota |
| **PodSecurity** | Validating | Проверяет Pod Security Standards |
| **NodeRestriction** | Validating | Ограничивает kubelet |
| **ServiceAccount** | Mutating | Автоматически добавляет ServiceAccount |
| **DefaultStorageClass** | Mutating | Добавляет default StorageClass |
| **MutatingAdmissionWebhook** | Mutating | Внешние webhooks |
| **ValidatingAdmissionWebhook** | Validating | Внешние webhooks |

**Просмотр включённых:**

```bash
kubectl get pods -n kube-system kube-apiserver-<node> -o yaml | grep enable-admission-plugins
```

### Dynamic Admission Webhooks

> **Admission Webhook** — HTTP-сервер, который вызывается API-сервером для мутации или валидации объектов.

**Архитектура:**

```
kubectl apply → API-сервер → Mutating Webhook → Validating Webhook → etcd
```

**Пример: MutatingWebhookConfiguration**

```yaml
apiVersion: admissionregistration.k8s.io/v1
kind: MutatingWebhookConfiguration
metadata:
  name: sidecar-injector
webhooks:
  - name: sidecar-injector.example.com
    clientConfig:
      service:
        name: sidecar-injector
        namespace: default
        path: /mutate
      caBundle: <base64-ca>
    rules:
      - operations: ["CREATE"]
        apiGroups: [""]
        apiVersions: ["v1"]
        resources: ["pods"]
    failurePolicy: Fail
    sideEffects: None
    admissionReviewVersions: ["v1"]
```

**Пример: ValidatingWebhookConfiguration**

```yaml
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingWebhookConfiguration
metadata:
  name: policy-validator
webhooks:
  - name: policy-validator.example.com
    clientConfig:
      service:
        name: policy-validator
        namespace: default
        path: /validate
      caBundle: <base64-ca>
    rules:
      - operations: ["CREATE", "UPDATE"]
        apiGroups: ["apps"]
        apiVersions: ["v1"]
        resources: ["deployments"]
    failurePolicy: Fail
    sideEffects: None
    admissionReviewVersions: ["v1"]
```

### failurePolicy

| Значение | Поведение |
|----------|-----------|
| `Fail` | Если webhook недоступен — запрос отклоняется |
| `Ignore` | Если webhook недоступен — запрос проходит |

> [!warning]
> `failurePolicy: Fail` может **заблокировать весь кластер**, если webhook упадёт. Используйте `Ignore` для некритичных webhooks.

### OPA Gatekeeper

> **OPA Gatekeeper** — admission webhook для политик на основе **Open Policy Agent (OPA)**.

**Установка:**

```bash
helm repo add gatekeeper https://open-policy-agent.github.io/gatekeeper/charts
helm install gatekeeper gatekeeper/gatekeeper -n gatekeeper-system --create-namespace
```

**ConstraintTemplate:**

```yaml
apiVersion: templates.gatekeeper.sh/v1
kind: ConstraintTemplate
metadata:
  name: k8srequiredlabels
spec:
  crd:
    spec:
      names:
        kind: K8sRequiredLabels
      validation:
        openAPIV3Schema:
          type: object
          properties:
            labels:
              type: array
              items:
                type: string
  targets:
    - target: admission.k8s.gatekeeper.sh
      rego: |
        package k8srequiredlabels
        violation[{"msg": msg}] {
          provided := {label | input.review.object.metadata.labels[label]}
          required := {label | label := input.parameters.labels[_]}
          missing := required - provided
          count(missing) > 0
          msg := sprintf("Missing labels: %v", [missing])
        }
```

**Constraint:**

```yaml
apiVersion: constraints.gatekeeper.sh/v1beta1
kind: K8sRequiredLabels
metadata:
  name: require-team-label
spec:
  match:
    kinds:
      - apiGroups: [""]
        kinds: ["Namespace"]
  parameters:
    labels:
      - "team"
```

**Что произойдёт:** все namespace без label `team` будут отклонены.

### Kyverno

> **Kyverno** — альтернатива OPA Gatekeeper. Политики на YAML, без Rego.

**Установка:**

```bash
helm repo add kyverno https://kyverno.github.io/kyverno/
helm install kyverno kyverno/kyverno -n kyverno --create-namespace
```

**ClusterPolicy:**

```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: require-labels
spec:
  validationFailureAction: Enforce
  rules:
    - name: check-team-label
      match:
        any:
          - resources:
              kinds:
                - Namespace
      validate:
        message: "Namespace must have a 'team' label"
        pattern:
          metadata:
            labels:
              team: "?*"
```

**Mutation:**

```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: add-default-labels
spec:
  rules:
    - name: add-team-label
      match:
        any:
          - resources:
              kinds:
                - Pod
      mutate:
        patchStrategicMerge:
          metadata:
            labels:
              managed-by: kyverno
```

### OPA Gatekeeper vs Kyverno

| OPA Gatekeeper | Kyverno |
|----------------|---------|
| Политики на Rego | Политики на YAML |
| Мощнее, гибче | Проще, интуитивнее |
| Крутая кривая обучения | Легко освоить |
| Для сложных политик | Для типовых задач |
| CNCF graduated | CNCF incubating |

### Admission Controllers: best practices

| Практика | Почему |
|----------|--------|
| Начинать с `audit` | Не сломать кластер |
| Использовать `warn` | Обучить команду |
| `failurePolicy: Ignore` для некритичных | Избежать блокировки |
| Тестировать политики | Можно заблокировать себя |
| Версионировать политики | GitOps |
| Мониторить webhooks | Latency, failures |
| Исключения для системных namespace | kube-system, istio-system |

## Часть 3: Secrets — глубоко

> **Secret** — объект для хранения конфиденциальных данных. Но **base64 — не шифрование**. Разберём, как защитить Secrets по-настоящему.

### Проблемы стандартных Secrets

1. **base64 — не шифрование.** Любой с доступом к etcd или API читает.
2. **Хранятся в etcd в открытом виде** (по умолчанию).
3. **Видны в `kubectl get secret -o yaml`.**
4. **Могут попасть в логи, CI/CD, Git.**

### Encryption at rest

> **Encryption at rest** — шифрование Secrets в etcd.

**EncryptionConfiguration:**

```yaml
apiVersion: apiserver.config.k8s.io/v1
kind: EncryptionConfiguration
resources:
  - resources:
      - secrets
      - configmaps
    providers:
      - aescbc:
          keys:
            - name: key1
              secret: <base64-encoded-32-byte-key>
      - identity: {}
```

**Запуск API-сервера с флагом:**

```
--encryption-provider-config=/etc/kubernetes/encryption-config.yaml
```

**Проверка:**

```bash
# Создать Secret
kubectl create secret generic test --from-literal=key=value

# Прочитать напрямую из etcd (должно быть зашифровано)
ETCDCTL_API=3 etcdctl get /registry/secrets/default/test \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key
```

> [!important]
> Encryption at rest защищает только от **прямого доступа к etcd**. Если у атакующего есть доступ к API — он прочитает Secret.

### KMS Provider

Для production используйте **KMS Provider** — ключи хранятся во внешнем KMS (AWS KMS, Azure Key Vault, GCP KMS).

```yaml
apiVersion: apiserver.config.k8s.io/v1
kind: EncryptionConfiguration
resources:
  - resources:
      - secrets
    providers:
      - kms:
          name: aws-kms
          endpoint: unix:///var/run/kmsplugin/socket.sock
          cachesize: 1000
          timeout: 3s
      - identity: {}
```

### External Secrets Operator

> **External Secrets Operator (ESO)** — синхронизация секретов из внешних хранилищ (Vault, AWS Secrets Manager, Azure Key Vault, GCP Secret Manager) в Kubernetes.

**Установка:**

```bash
helm repo add external-secrets https://charts.external-secrets.io
helm install external-secrets external-secrets/external-secrets -n external-secrets --create-namespace
```

**SecretStore:**

```yaml
apiVersion: external-secrets.io/v1beta1
kind: SecretStore
metadata:
  name: vault-backend
  namespace: default
spec:
  provider:
    vault:
      server: "https://vault.example.com"
      path: "secret"
      version: "v2"
      auth:
        kubernetes:
          mountPath: "kubernetes"
          role: "my-role"
```

**ExternalSecret:**

```yaml
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: db-credentials
  namespace: default
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: vault-backend
    kind: SecretStore
  target:
    name: db-secret
    creationPolicy: Owner
  data:
    - secretKey: username
      remoteRef:
        key: database/creds/myapp
        property: username
    - secretKey: password
      remoteRef:
        key: database/creds/myapp
        property: password
```

**Что произойдёт:** ESO создаст Secret `db-secret` с данными из Vault. Каждый час — обновление.

### Sealed Secrets

> **Sealed Secrets** — шифрование Secret для безопасного хранения в Git.

**Установка:**

```bash
helm repo add sealed-secrets https://bitnami-labs.github.io/sealed-secrets
helm install sealed-secrets sealed-secrets/sealed-secrets -n kube-system
```

**Создание SealedSecret:**

```bash
# Создать Secret
kubectl create secret generic my-secret --from-literal=password=secret --dry-run=client -o yaml > secret.yaml

# Зашифровать
kubeseal --format yaml < secret.yaml > sealed-secret.yaml
```

**SealedSecret:**

```yaml
apiVersion: bitnami.com/v1alpha1
kind: SealedSecret
metadata:
  name: my-secret
  namespace: default
spec:
  encryptedData:
    password: AgBy3i4OJSWK+PiTySYZZA9rO43cGDEq...
  template:
    metadata:
      name: my-secret
      namespace: default
```

**Что произойдёт:** SealedSecret безопасно хранить в Git. В кластере контроллер расшифрует его в обычный Secret.

> [!warning]
> SealedSecret **привязан к namespace**. Нельзя скопировать в другой namespace.

### SOPS

> **SOPS (Secrets OPerationS)** — шифрование файлов (YAML, JSON, ENV) с помощью GPG, AWS KMS, GCP KMS, Azure Key Vault.

**Использование:**

```bash
# Зашифровать
sops --encrypt --kms arn:aws:kms:us-east-1:123456789012:key/abc-123 secrets.yaml > secrets.enc.yaml

# Расшифровать
sops --decrypt secrets.enc.yaml > secrets.yaml
```

**Интеграция с Flux:**

```yaml
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: my-app
spec:
  decryption:
    provider: sops
    secretRef:
      name: sops-gpg
```

### Vault

> **HashiCorp Vault** — централизованное хранилище секретов с динамическими credentials.

**Интеграция:**

| Способ | Описание |
|--------|----------|
| **Vault Agent Injector** | Sidecar-контейнер монтирует секреты в Pod |
| **Vault CSI Provider** | CSI-драйвер монтирует секреты как volume |
| **External Secrets Operator** | Синхронизация в Kubernetes Secret |

**Vault Agent Injector:**

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-app
  annotations:
    vault.hashicorp.com/agent-inject: "true"
    vault.hashicorp.com/role: "my-app"
    vault.hashicorp.com/agent-inject-secret-db: "database/creds/myapp"
spec:
  containers:
    - name: app
      image: myapp:1.0
```

**Что произойдёт:** Vault Agent Injector добавит sidecar, который смонтирует секреты в `/vault/secrets/db`.

### Best practices для Secrets

| Практика | Почему |
|----------|--------|
| Encryption at rest | Защита etcd |
| KMS Provider | Ключи во внешнем KMS |
| External Secrets Operator | Секреты не в Git |
| Sealed Secrets / SOPS | Безопасное хранение в Git |
| Vault | Динамические credentials |
| RBAC на Secrets | Ограничить доступ |
| Не логировать Secrets | Могут попасть в логи |
| Ротация секретов | Минимизировать ущерб |
| Аудит доступа к Secrets | Audit logging |
| Не монтировать все Secrets | Только нужные |

> [!warning]
> **Никогда не коммитьте Secrets в Git.** Даже в приватный репозиторий. Используйте Sealed Secrets, SOPS или External Secrets.

## Часть 4: Аудит и мониторинг безопасности

### Audit Logging

> **Audit Logging** — запись всех запросов к API-серверу.

**Audit Policy:**

```yaml
apiVersion: audit.k8s.io/v1
kind: Policy
rules:
  - level: RequestResponse
    resources:
      - group: ""
        resources: ["secrets", "configmaps"]
  - level: Metadata
    resources:
      - group: ""
        resources: ["pods", "deployments"]
  - level: None
    users: ["system:kube-proxy"]
    verbs: ["watch"]
    resources:
      - group: ""
        resources: ["endpoints", "services"]
```

**Уровни:**

| Уровень | Описание |
|---------|----------|
| `None` | Не логировать |
| `Metadata` | Метаданные запроса |
| `Request` | Метаданные + тело запроса |
| `RequestResponse` | Метаданные + тело + ответ |

**Запуск API-сервера:**

```
--audit-policy-file=/etc/kubernetes/audit-policy.yaml
--audit-log-path=/var/log/kubernetes/audit.log
--audit-log-maxage=30
--audit-log-maxbackup=10
--audit-log-maxsize=100
```

### Falco

> **Falco** — runtime security. Обнаруживает подозрительную активность в контейнерах.

**Установка:**

```bash
helm repo add falcosecurity https://falcosecurity.github.io/charts
helm install falco falcosecurity/falco -n falco --create-namespace
```

**Пример правила:**

```yaml
- rule: Terminal shell in container
  desc: A shell was spawned in a container
  condition: >
    spawned_process and container
    and proc.name in (bash, sh, zsh)
  output: >
    Shell spawned in container
    (user=%user.name container=%container.name shell=%proc.name)
  priority: WARNING
```

**Что обнаружит:** запуск shell в контейнере — потенциальная атака.

### Trivy

> **Trivy** — сканер уязвимостей для контейнеров и Kubernetes.

**Сканирование образа:**

```bash

```

**Сканирование кластера:**


**Trivy Operator:**


## Практический пример: полный стек безопасности

### 1. Namespace с Pod Security

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: production
  labels:
    pod-security.kubernetes.io/enforce: restricted
    pod-security.kubernetes.io/audit: restricted
    pod-security.kubernetes.io/warn: restricted
```

### 2. Kyverno Policy

```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: require-labels
spec:
  validationFailureAction: Enforce
  rules:
    - name: check-team-label
      match:
        any:
          - resources:
              kinds:
                - Namespace
      validate:
        message: "Namespace must have a 'team' label"
        pattern:
          metadata:
            labels:
              team: "?*"
```

### 3. ExternalSecret

## Troubleshooting

### Pod отклонён Pod Security

```
Error: pods "my-pod" is forbidden: violates PodSecurity "restricted:latest":
  allowPrivilegeEscalation != false,
  unrestricted capabilities,
  runAsNonRoot != true,
  seccompProfile
```

**Решение:**

```bash
kubectl describe namespace production
# Добавить securityContext
# Использовать non-root образ
# Добавить writable volumes
```

### Webhook блокирует кластер

```
Error: Internal error occurred: failed calling webhook "policy-validator.example.com"
```

**Причина:** webhook недоступен, `failurePolicy: Fail`.

**Решение:**

```bash
# Временно удалить webhook
kubectl delete validatingwebhookconfiguration policy-validator
# Или изменить failurePolicy на Ignore
kubectl patch validatingwebhookconfiguration policy-validator --type=json -p='[{"op":"replace","path":"/webhooks/0/failurePolicy","value":"Ignore"}]'
```

### Secret не расшифровывается

```
Error: cannot decrypt secret: cipher: message authentication failed
```

**Причина:** неверный ключ шифрования.

**Решение:**

```bash
# Проверить EncryptionConfiguration
kubectl get pods -n kube-system kube-apiserver-<node> -o yaml | grep encryption
# Убедиться, что ключ правильный
```

### ExternalSecret не синхронизируется

```
Status:
  Conditions:
    - Type: Ready
      Status: "False"
      Reason: SecretSyncedError
```

**Решение:**

```bash
kubectl describe externalsecret db-credentials
kubectl logs -n external-secrets deploy/external-secrets
# Проверить доступ к Vault/AWS
```

## Итог

1. **Pod Security Standards:** Privileged, Baseline, Restricted.
2. **Pod Security Admission** — встроенный admission-контроллер.
3. **Admission Controllers:** Mutating и Validating.
4. **OPA Gatekeeper** — политики на Rego. **Kyverno** — политики на YAML.
5. **base64 — не шифрование.** Secrets в etcd открыты по умолчанию.
6. **Encryption at rest** + **KMS Provider** — защита etcd.
7. **External Secrets Operator** — синхронизация из Vault/AWS.
8. **Sealed Secrets / SOPS** — безопасное хранение в Git.
9. **Vault** — динамические credentials.
10. **Falco** — runtime security. **Trivy** — сканер уязвимостей.

> [!tip]
> **Правило выбора:**
> - Pod Security → `baseline` для большинства, `restricted` для критичных
> - Политики → **Kyverno** (просто) или **OPA Gatekeeper** (мощно)
> - Secrets → **External Secrets Operator** + **Vault**
> - GitOps → **Sealed Secrets** или **SOPS**
> - Runtime → **Falco**
> - Сканирование → **Trivy**

> [!warning]
> **Безопасность — это процесс, а не состояние.** Регулярно обновляйте, аудируйте, сканируйте. Новые уязвимости появляются каждый день.
