# 01. Пакетный менеджер Helm: от манифестов к чартам

Мы научились писать манифесты: Deployment, Service, ConfigMap, Ingress. Но представьте, что у вас **20 микросервисов**, каждый с 10 манифестами. И это нужно развернуть в **3 окружениях** (dev, staging, prod). Вручную — это сотни YAML-файлов, которые нужно копировать, менять и поддерживать.

**Helm** решает эту проблему.

> **Helm** — пакетный менеджер для Kubernetes. Позволяет **шаблонизировать** манифесты, **управлять релизами**, **откатывать** изменения и **распространять** приложения как пакеты (charts).

---

## Проблема: дублирование манифестов

### Без Helm

```
manifests/
├── dev/
│   ├── deployment.yaml    # image: myapp:dev
│   ├── service.yaml       # replicas: 1
│   └── configmap.yaml     # log_level: debug
├── staging/
│   ├── deployment.yaml    # image: myapp:staging
│   ├── service.yaml       # replicas: 3
│   └── configmap.yaml     # log_level: info
└── prod/
    ├── deployment.yaml    # image: myapp:1.0
    ├── service.yaml       # replicas: 10
    └── configmap.yaml     # log_level: warn
```

**Проблемы:**
- Дублирование.
- Рассинхронизация.
- Сложно поддерживать.
- Нет версионирования.

### С Helm

```
my-app/
├── Chart.yaml
├── values.yaml            # дефолтные значения
├── values-dev.yaml        # переопределения для dev
├── values-staging.yaml
├── values-prod.yaml
└── templates/
    ├── deployment.yaml    # шаблон с {{ .Values.image }}
    ├── service.yaml
    └── configmap.yaml
```

**Преимущества:**
- Один шаблон — много окружений.
- Версионирование через Git.
- Откат через `helm rollback`.
- Распространение через chart repository.

## Архитектура Helm

```
┌─────────────────────────────────────────────────────────────┐
│                         Helm CLI                             │
│                                                              │
│  helm install → Chart + Values → Rendered Manifests → K8s  │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                      Kubernetes API                          │
│                                                              │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │
│  │  Release     │  │  Release     │  │  Release     │      │
│  │  (v1)        │  │  (v2)        │  │  (v3)        │      │
│  └──────────────┘  └──────────────┘  └──────────────┘      │
│                                                              │
│  Secrets в namespace: sh.helm.release.v1.my-app.v1          │
└─────────────────────────────────────────────────────────────┘
```

### Ключевые понятия

| Понятие | Описание |
|---------|----------|
| **Chart** | Пакет с манифестами и шаблонами |
| **Release** | Экземпляр chart, развёрнутый в кластере |
| **Values** | Параметры для шаблонов |
| **Revision** | Версия релиза (для отката) |
| **Repository** | Хранилище charts |

## Chart.yaml

```yaml
apiVersion: v2
name: my-app
description: A Helm chart for my application
type: application
version: 1.0.0
appVersion: "1.0.0"
icon: https://example.com/icon.png
home: https://example.com
sources:
  - https://github.com/example/my-app
maintainers:
  - name: John Doe
    email: john@example.com
keywords:
  - web
  - nginx
dependencies:
  - name: postgresql
    version: "12.x.x"
    repository: https://charts.bitnami.com/bitnami
    condition: postgresql.enabled
  - name: redis
    version: "17.x.x"
    repository: https://charts.bitnami.com/bitnami
    condition: redis.enabled
annotations:
  category: Web
```

### Разбор

| Поле | Описание |
|------|----------|
| `apiVersion` | `v2` для Helm 3 |
| `name` | Имя chart |
| `version` | Версия chart (SemVer) |
| `appVersion` | Версия приложения |
| `type` | `application` или `library` |
| `dependencies` | Зависимости (subcharts) |
| `condition` | Условие включения зависимости |

### Переопределение values

**Через файл:**

```bash
helm install my-app ./my-app -f values-prod.yaml
```

**Через --set:**

```bash
helm install my-app ./my-app \
  --set replicaCount=3 \
  --set image.tag=1.2.3 \
  --set config.logLevel=debug
```

**Приоритет:**

```
values.yaml (дефолт)
  ↓
values-prod.yaml (-f)
  ↓
--set (высший приоритет)
```

## Шаблоны

### Синтаксис Go Templates

| Синтаксис | Описание |
|-----------|----------|
| `{{ .Values.key }}` | Значение из values |
| `{{ .Release.Name }}` | Имя релиза |
| `{{ .Release.Namespace }}` | Namespace |
| `{{ .Chart.Name }}` | Имя chart |
| `{{ .Chart.Version }}` | Версия chart |
| `{{ include "my-app.fullname" . }}` | Хелпер |
| `{{ .Files.Get "file.txt" }}` | Файл из chart |
| `{{- ... }}` | Trim left whitespace |
| `{{ ... -}}` | Trim right whitespace |
| `{{ if .Values.enabled }}...{{ end }}` | Условие |
| `{{ range .Values.list }}...{{ end }}` | Цикл |
| `{{ with .Values.foo }}...{{ end }}` | Контекст |
| `{{ default "value" .Values.key }}` | Дефолт |
| `{{ required "msg" .Values.key }}` | Обязательное |
| `{{ quote .Values.key }}` | В кавычки |
| `{{ toYaml .Values.key \| nindent 4 }}` | В YAML с отступом |

### _helpers.tpl

```yaml
{{/*
Expand the name of the chart.
*/}}
{{- define "my-app.name" -}}
{{- default .Chart.Name .Values.nameOverride | trunc 63 | trimSuffix "-" }}
{{- end }}

{{/*
Create a default fully qualified app name.
*/}}
{{- define "my-app.fullname" -}}
{{- if .Values.fullnameOverride }}
{{- .Values.fullnameOverride | trunc 63 | trimSuffix "-" }}
{{- else }}
{{- $name := default .Chart.Name .Values.nameOverride }}
{{- if contains $name .Release.Name }}
{{- .Release.Name | trunc 63 | trimSuffix "-" }}
{{- else }}
{{- printf "%s-%s" .Release.Name $name | trunc 63 | trimSuffix "-" }}
{{- end }}
{{- end }}
{{- end }}

{{/*
Common labels
*/}}
{{- define "my-app.labels" -}}
helm.sh/chart: {{ include "my-app.chart" . }}
{{ include "my-app.selectorLabels" . }}
{{- if .Chart.AppVersion }}
app.kubernetes.io/version: {{ .Chart.AppVersion | quote }}
{{- end }}
app.kubernetes.io/managed-by: {{ .Release.Service }}
{{- end }}

{{/*
Selector labels
*/}}
{{- define "my-app.selectorLabels" -}}
app.kubernetes.io/name: {{ include "my-app.name" . }}
app.kubernetes.io/instance: {{ .Release.Name }}
{{- end }}
```

### deployment.yaml

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "my-app.fullname" . }}
  labels:
    {{- include "my-app.labels" . | nindent 4 }}
spec:
  {{- if not .Values.autoscaling.enabled }}
  replicas: {{ .Values.replicaCount }}
  {{- end }}
  selector:
    matchLabels:
      {{- include "my-app.selectorLabels" . | nindent 6 }}
  template:
    metadata:
      {{- with .Values.podAnnotations }}
      annotations:
        {{- toYaml . | nindent 8 }}
      {{- end }}
      labels:
        {{- include "my-app.selectorLabels" . | nindent 8 }}
    spec:
      {{- with .Values.imagePullSecrets }}
      imagePullSecrets:
        {{- toYaml . | nindent 8 }}
      {{- end }}
      serviceAccountName: {{ include "my-app.serviceAccountName" . }}
      securityContext:
        {{- toYaml .Values.podSecurityContext | nindent 8 }}
      containers:
        - name: {{ .Chart.Name }}
          securityContext:
            {{- toYaml .Values.securityContext | nindent 12 }}
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
          imagePullPolicy: {{ .Values.image.pullPolicy }}
          ports:
            - name: http
              containerPort: {{ .Values.service.port }}
              protocol: TCP
          env:
            - name: LOG_LEVEL
              value: {{ .Values.config.logLevel | quote }}
            - name: DB_HOST
              value: {{ .Values.config.dbHost | quote }}
            - name: DB_PORT
              value: {{ .Values.config.dbPort | quote }}
          livenessProbe:
            httpGet:
              path: /
              port: http
          readinessProbe:
            httpGet:
              path: /
              port: http
          resources:
            {{- toYaml .Values.resources | nindent 12 }}
      {{- with .Values.nodeSelector }}
      nodeSelector:
        {{- toYaml . | nindent 8 }}
      {{- end }}
      {{- with .Values.affinity }}
      affinity:
        {{- toYaml . | nindent 8 }}
      {{- end }}
      {{- with .Values.tolerations }}
      tolerations:
        {{- toYaml . | nindent 8 }}
      {{- end }}
```

### ingress.yaml

```yaml
{{- if .Values.ingress.enabled -}}
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: {{ include "my-app.fullname" . }}
  labels:
    {{- include "my-app.labels" . | nindent 4 }}
  {{- with .Values.ingress.annotations }}
  annotations:
    {{- toYaml . | nindent 4 }}
  {{- end }}
spec:
  {{- with .Values.ingress.className }}
  ingressClassName: {{ . }}
  {{- end }}
  {{- if .Values.ingress.tls }}
  tls:
    {{- range .Values.ingress.tls }}
    - hosts:
        {{- range .hosts }}
        - {{ . | quote }}
        {{- end }}
      secretName: {{ .secretName }}
    {{- end }}
  {{- end }}
  rules:
    {{- range .Values.ingress.hosts }}
    - host: {{ .host | quote }}
      http:
        paths:
          {{- range .paths }}
          - path: {{ .path }}
            pathType: {{ .pathType }}
            backend:
              service:
                name: {{ include "my-app.fullname" $ }}
                port:
                  number: {{ $.Values.service.port }}
          {{- end }}
    {{- end }}
{{- end }}
```

## Команды Helm

### Установка

```bash
# Из локальной директории
helm install my-app ./my-app

# С values
helm install my-app ./my-app -f values-prod.yaml

# С --set
helm install my-app ./my-app --set replicaCount=3

# С namespace
helm install my-app ./my-app -n production --create-namespace

# Dry-run
helm install my-app ./my-app --dry-run --debug

# Из репозитория
helm repo add bitnami https://charts.bitnami.com/bitnami
helm install my-postgres bitnami/postgresql
```

### Просмотр

```bash
# Список релизов
helm list
helm list -A
helm list -n production

# Статус
helm status my-app

# Values
helm get values my-app
helm get values my-app -n production

# Манифесты
helm get manifest my-app
helm get all my-app

# История
helm history my-app
```

### Обновление

```bash
# Обновить values
helm upgrade my-app ./my-app -f values-prod.yaml

# Обновить с --set
helm upgrade my-app ./my-app --set image.tag=1.2.3

# Install or upgrade
helm upgrade --install my-app ./my-app

# Атомарно (откат при ошибке)
helm upgrade my-app ./my-app --atomic

# С таймаутом
helm upgrade my-app ./my-app --timeout 10m
```

### Откат

```bash
# Откатить к предыдущей версии
helm rollback my-app

# Откатить к конкретной ревизии
helm rollback my-app 2

# С --wait
helm rollback my-app --wait
```

### Удаление

```bash
# Удалить релиз
helm uninstall my-app

# С сохранением истории
helm uninstall my-app --keep-history

# Удалить namespace
helm uninstall my-app -n production
```

### Тестирование

```bash
# Запустить тесты
helm test my-app

# Lint
helm lint ./my-app

# Template (рендер без установки)
helm template my-app ./my-app

# Template с values
helm template my-app ./my-app -f values-prod.yaml
```

### Упаковка

```bash
# Упаковать chart
helm package ./my-app

# С версией
helm package ./my-app --version 1.2.3

# С appVersion
helm package ./my-app --app-version 1.2.3
```

### Репозитории

```bash
# Добавить репозиторий
helm repo add bitnami https://charts.bitnami.com/bitnami

# Обновить
helm repo update

# Список
helm repo list

# Поиск
helm search repo postgresql

# Удалить
helm repo remove bitnami
```

## Зависимости (Subcharts)

### dependencies в Chart.yaml

```yaml
dependencies:
  - name: postgresql
    version: "12.x.x"
    repository: https://charts.bitnami.com/bitnami
    condition: postgresql.enabled
  - name: redis
    version: "17.x.x"
    repository: https://charts.bitnami.com/bitnami
    condition: redis.enabled
```

### Обновление зависимостей

```bash
helm dependency update ./my-app
helm dependency build ./my-app
```

**Что произойдёт:** в `charts/` появятся `.tgz` файлы зависимостей.

### Values для subcharts

```yaml
# values.yaml
postgresql:
  enabled: true
  auth:
    username: myuser
    password: mypassword
    database: mydb
  primary:
    persistence:
      size: 10Gi

redis:
  enabled: false
```

### Условия

```yaml
condition: postgresql.enabled
```

Если `postgresql.enabled: false` — subchart не устанавливается.

### Tags

```yaml
dependencies:
  - name: postgresql
    version: "12.x.x"
    repository: https://charts.bitnami.com/bitnami
    tags:
      - database
```

```yaml
# values.yaml
tags:
  database: true
```

## Helm Hooks

> **Hooks** — манифесты, выполняемые на определённых этапах жизненного цикла релиза.

| Hook | Когда выполняется |
|------|-------------------|
| `pre-install` | До установки |
| `post-install` | После установки |
| `pre-delete` | До удаления |
| `post-delete` | После удаления |
| `pre-upgrade` | До обновления |
| `post-upgrade` | После обновления |
| `pre-rollback` | До отката |
| `post-rollback` | После отката |
| `test` | При `helm test` |

### Пример: Job для миграции БД

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: {{ include "my-app.fullname" . }}-migrate
  annotations:
    "helm.sh/hook": pre-upgrade,pre-install
    "helm.sh/hook-weight": "-5"
    "helm.sh/hook-delete-policy": before-hook-creation,hook-succeeded
spec:
  template:
    spec:
      restartPolicy: OnFailure
      containers:
        - name: migrate
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
          command: ["python", "manage.py", "migrate"]
```

### Hook weights

```yaml
annotations:
  "helm.sh/hook-weight": "-5"    # выполняется раньше
```

### Hook delete policy

```yaml
annotations:
  "helm.sh/hook-delete-policy": before-hook-creation,hook-succeeded
```

| Политика | Описание |
|----------|----------|
| `before-hook-creation` | Удалить старый hook перед созданием нового |
| `hook-succeeded` | Удалить после успеха |
| `hook-failed` | Удалить после ошибки |

## Helm в GitOps

### Argo CD + Helm

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: my-app
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/example/my-app
    targetRevision: main
    path: charts/my-app
    helm:
      valueFiles:
        - values-prod.yaml
  destination:
    server: https://kubernetes.default.svc
    namespace: production
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
```

### Flux + Helm

```yaml
apiVersion: source.toolkit.fluxcd.io/v1beta2
kind: HelmRepository
metadata:
  name: bitnami
  namespace: flux-system
spec:
  interval: 1h
  url: https://charts.bitnami.com/bitnami

  name: my-app
  namespace: production

  interval: 5m
  chart:
    spec:
      chart: my-app
      version: "1.0.0"
      sourceRef:
        kind: HelmRepository
        name: my-charts
        namespace: flux-system
  values:
    replicaCount: 3
    image:
      tag: "1.2.3"
```

## Best practices

| Практика | Почему |
|----------|--------|
| SemVer для version | Совместимость |
| values.schema.json | Валидация values |
| _helpers.tpl для общих labels | DRY |
| Не хардкодить значения | Гибкость |
| Использовать `required` | Обязательные values |
| `--atomic` при upgrade | Откат при ошибке |
| `helm lint` | Проверка chart |
| `helm template` | Рендер без установки |
| Тесты (`helm test`) | Проверка работоспособности |
| README.md | Документация |
| .helmignore | Не паковать мусор |
| Hooks для миграций | Порядок операций |
| Subcharts для зависимостей | Переиспользование |
| Git для charts | Версионирование |
| Chart repository | Распространение |

### Anti-patterns

| Anti-pattern | Почему плохо |
|--------------|--------------|
| Хардкод значений | Нет гибкости |
| Слишком много values | Сложно поддерживать |
| Нет values.schema.json | Нет валидации |
| Игнорирование `helm lint` | Ошибки в шаблонах |
| `--set` для всего | Невоспроизводимо |
| Нет версионирования | Нет отката |
| Мутация существующих ресурсов | Конфликты |

## Практический пример: полный цикл

### 1. Создать chart

```bash
helm create my-app
cd my-app
```

### 2. Настроить values.yaml

```yaml
replicaCount: 2

image:
  repository: nginx
  tag: "1.25"
  pullPolicy: IfNotPresent

service:
  type: ClusterIP
  port: 80

ingress:
  enabled: true
  className: nginx
  hosts:
    - host: my-app.example.com
      paths:
        - path: /
          pathType: Prefix

resources:
  limits:
    cpu: 200m
    memory: 256Mi
  requests:
    cpu: 100m
    memory: 128Mi

config:
  logLevel: info
```

### 3. Проверить

```bash
helm lint .
helm template my-app . --debug
```

### 4. Установить

```bash
helm install my-app . -n production --create-namespace
```

### 5. Проверить

```bash
helm list -n production
kubectl get all -n production
kubectl get ingress -n production
```

### 6. Обновить

```bash
helm upgrade my-app . -n production --set image.tag=1.26 --atomic
```

### 7. Откатить

```bash
helm history my-app -n production
helm rollback my-app 1 -n production
```

### 8. Удалить

```bash
helm uninstall my-app -n production
```

## Troubleshooting

### Error: cannot re-use a name that is still in use

```
Error: cannot re-use a name that is still in use
```

**Причина:** релиз с таким именем уже существует.

**Решение:**

```bash
helm list -A | grep my-app
helm uninstall my-app -n production
# Или использовать другое имя
```

### Error: UPGRADE FAILED: another operation is in progress

**Причина:** предыдущая операция не завершилась.

**Решение:**

```bash
helm history my-app -n production
helm rollback my-app -n production
# Или
kubectl delete secret -n production -l owner=helm,name=my-app
```

### Error: rendered manifests contain a resource that already exists

**Причина:** ресурс существует, но не управляется Helm.

**Решение:**

```bash
# Добавить аннотации
kubectl annotate <resource> meta.helm.sh/release-name=my-app
kubectl annotate <resource> meta.helm.sh/release-namespace=production
kubectl label <resource> app.kubernetes.io/managed-by=Helm
```

### Error: values don't meet the specifications of the schema

**Причина:** values не соответствуют `values.schema.json`.

**Решение:**

```bash
# Проверить схему
cat values.schema.json
# Исправить values
```

### Helm не видит values

**Причина:** неверный порядок `-f`.

**Решение:**

```bash
# Правильно: последний -f имеет приоритет
helm install my-app . -f values.yaml -f values-prod.yaml
```

### Timeout

**Причина:** ресурсы не готовы.

**Решение:**

```bash
helm install my-app . --timeout 10m --wait
helm status my-app
kubectl get pods -n production
```

## Итог

1. **Helm** — пакетный менеджер для Kubernetes.
2. **Chart** — пакет с манифестами и шаблонами.
3. **Release** — экземпляр chart в кластере.
4. **Values** — параметры для шаблонов.
5. **Go Templates** — синтаксис шаблонов.
6. **_helpers.tpl** — общие хелперы.
7. **Subcharts** — зависимости.
8. **Hooks** — lifecycle-хуки.
9. **helm rollback** — откат к предыдущей версии.
10. **GitOps** — Argo CD, Flux + Helm.

> [!tip]
> **Правило выбора:**
> - Простое приложение → **kubectl apply**
> - Много окружений → **Helm**
> - Публикация → **Chart repository**
> - GitOps → **Argo CD / Flux + Helm**
> - Сложные зависимости → **Subcharts**
> - Миграции → **Hooks**

> [!warning]
> **Не используйте `--set` для всего.** Это невоспроизводимо. Используйте `values-*.yaml` в Git.
