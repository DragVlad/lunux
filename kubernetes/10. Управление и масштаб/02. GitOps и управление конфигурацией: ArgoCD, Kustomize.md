# 02. GitOps и управление конфигурацией: ArgoCD, Kustomize

В прошлой лекции мы освоили Helm — шаблонизацию манифестов. Но остаётся вопрос: **как доставлять изменения в кластер?** Вручную запускать `helm upgrade`? А если изменения внёс кто-то другой? А если кластер «дрейфует» от желаемого состояния?

Ответ — **GitOps**.

> **GitOps** — это методология, при которой **Git является единственным источником правды** для состояния кластера. Все изменения вносятся через коммиты в Git, а специальный агент (Argo CD, Flux) синхронизирует кластер с Git.

---

## Часть 1: Что такое GitOps

### Принципы GitOps

1. **Декларативность** — всё состояние описано декларативно (YAML).
2. **Git как источник правды** — желаемое состояние хранится в Git.
3. **Автоматическая синхронизация** — агент приводит кластер к состоянию в Git.
4. **Непрерывное согласование** — агент постоянно проверяет расхождения.

### Как это работает

```
┌─────────────────────────────────────────────────────────────┐
│                         Developer                            │
│                                                              │
│  1. Изменяет YAML в Git                                     │
│  2. Коммитит и пушит                                        │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                          Git                                 │
│                                                              │
│  manifests/                                                  │
│  ├── deployment.yaml                                        │
│  ├── service.yaml                                           │
│  └── configmap.yaml                                         │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           │ 3. Агент опрашивает Git
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                       Argo CD / Flux                         │
│                                                              │
│  4. Сравнивает desired (Git) с actual (кластер)             │
│  5. Если расхождение — применяет изменения                  │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                       Kubernetes                             │
│                                                              │
│  6. Кластер приведён к состоянию в Git                      │
└─────────────────────────────────────────────────────────────┘
```

### Push vs Pull

| Модель | Описание | Пример |
|--------|----------|--------|
| **Push** | CI/CD пушит изменения в кластер | Jenkins, GitLab CI |
| **Pull** | Агент в кластере pulls из Git | Argo CD, Flux |

**Pull-модель безопаснее:** не нужно давать CI/CD доступ к кластеру. Агент сам читает Git.

### Преимущества GitOps

| Преимущество | Описание |
|--------------|----------|
| **Аудит** | Все изменения в Git — кто, когда, что |
| **Откат** | `git revert` — и кластер откатился |
| **Воспроизводимость** | Один Git — много кластеров |
| **Безопасность** | Нет прямого доступа к кластеру |
| **Согласованность** | Кластер всегда соответствует Git |
| **DR** | Восстановление кластера из Git |

## Часть 2: Kustomize

> **Kustomize** — инструмент для управления конфигурацией через **overlays**. Встроен в `kubectl` (с v1.14).

### Зачем Kustomize

Helm использует **шаблоны**. Kustomize использует **патчи**. Это разные подходы:

| Helm | Kustomize |
|------|-----------|
| Шаблоны Go | Патчи YAML |
| Values | Overlays |
| Мощный | Простой |
| Кривая обучения | Легко освоить |
| Пакеты | Конфигурация |

**Kustomize** хорош, когда:
- У вас есть базовые манифесты.
- Нужно переопределить их для разных окружений.
- Вы не хотите шаблонизировать.

### Структура Kustomize

```
my-app/
├── base/
│   ├── kustomization.yaml
│   ├── deployment.yaml
│   ├── service.yaml
│   └── configmap.yaml
└── overlays/
    ├── dev/
    │   ├── kustomization.yaml
    │   ├── replica-patch.yaml
    │   └── configmap-patch.yaml
    ├── staging/
    │   ├── kustomization.yaml
    │   └── replica-patch.yaml
    └── prod/
        ├── kustomization.yaml
        ├── replica-patch.yaml
        ├── resources-patch.yaml
        └── hpa.yaml
```

### base/kustomization.yaml

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

resources:
  - deployment.yaml
  - service.yaml
  - configmap.yaml

commonLabels:
  app: my-app

commonAnnotations:
  managed-by: kustomize
```

### base/deployment.yaml

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 1
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
        - name: app
          image: nginx:1.25
          ports:
            - containerPort: 80
          resources:
            requests:
              memory: "64Mi"
              cpu: "100m"
            limits:
              memory: "128Mi"
              cpu: "200m"
```

### overlays/prod/kustomization.yaml

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

resources:
  - ../../base
  - hpa.yaml

replicas:
  - name: my-app

  - name: nginx

  - path: replica-patch.yaml
  - path: resources-patch.yaml

  - name: my-app-config
    behavior: merge
    literals:
      - LOG_LEVEL=warn
      - ENV=production
```

```yaml
  replicas: 5
```

### Патчи: стратегии

**Strategic Merge Patch:**

```yaml
patches:
  - path: patch.yaml
```

**JSON Patch (RFC 6902):**

```yaml
patches:
  - target:
      kind: Deployment
      name: my-app
    patch: |-
      - op: replace
        path: /spec/replicas
        value: 5
      - op: add
        path: /spec/template/spec/containers/0/env
        value:
          - name: NEW_VAR
            value: "new"
```

**JSON Merge Patch:**

```yaml
patches:
  - target:
      kind: Deployment
      name: my-app
    patch: |-
      - op: replace
        path: /spec/replicas
        value: 5
```

### ConfigMapGenerator

```yaml
configMapGenerator:
  - name: my-app-config
    files:
      - config.properties
    literals:
      - LOG_LEVEL=info
    envs:
      - config.env
```

**Что произойдёт:** Kustomize создаст ConfigMap с хешем в имени (`my-app-config-abc123`). При изменении — новый хеш, Pod перезапустится.

### SecretGenerator

```yaml
secretGenerator:
  - name: my-app-secret
    literals:
      - password=secret
    files:
      - tls.crt
      - tls.key
    type: kubernetes.io/tls
```

### Components

**Components** — переиспользуемые фрагменты:

```yaml
# components/monitoring/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1alpha1
kind: Component

resources:
  - servicemonitor.yaml

patches:
  - path: add-annotations.yaml
```

```yaml
# overlays/prod/kustomization.yaml
components:
  - ../../components/monitoring
```

### Команды Kustomize

```bash
# Просмотр
kubectl kustomize overlays/prod

# Применение
kubectl apply -k overlays/prod

# Diff
kubectl diff -k overlays/prod

# Standalone
kustomize build overlays/prod
kustomize build overlays/prod | kubectl apply -f -
```

### Kustomize vs Helm

| Kustomize | Helm |
|-----------|------|
| Патчи | Шаблоны |
| Нет версионирования | Версионирование релизов |
| Нет отката | `helm rollback` |
| Встроен в kubectl | Требует установки |
| Простой | Мощный |
| Для конфигурации | Для пакетов |

> [!tip]
> **Kustomize + Helm = мощь.** Helm рендерит шаблоны, Kustomize патчит результат. Argo CD поддерживает оба.

## Часть 3: Argo CD

> **Argo CD** — декларативный GitOps-инструмент для Kubernetes. Pull-модель.

### Архитектура

```
┌─────────────────────────────────────────────────────────────┐
│                         Argo CD                              │
│                                                              │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │
│  │  API Server  │  │  Repository  │  │  Application │      │
│  │              │  │   Server     │  │  Controller  │      │
│  │  UI, CLI     │  │  Git, Helm   │  │  Sync        │      │
│  └──────────────┘  └──────────────┘  └──────────────┘      │
│                                                              │
│  ┌──────────────┐  ┌──────────────┐                        │
│  │  Dex         │  │  Redis       │                        │
│  │  (SSO)       │  │  (cache)     │                        │
│  └──────────────┘  └──────────────┘                        │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                      Kubernetes                              │
│                                                              │
│  Application CRD → Sync → Cluster                           │
└─────────────────────────────────────────────────────────────┘
```

### Установка

```bash
kubectl create namespace argocd
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

# Или через Helm
helm repo add argo https://argoproj.github.io/argo-helm
helm install argocd argo/argo-cd -n argocd --create-namespace
```

### Доступ к UI

```bash
kubectl port-forward svc/argocd-server -n argocd 8080:443

# Пароль admin
kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d
```

### CLI

```bash
# Установка
brew install argocd

# Логин
argocd login localhost:8080

# Список приложений
argocd app list
argocd app get my-app
argocd app sync my-app
argocd app history my-app
argocd app rollback my-app 1
```

### Application CRD

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: my-app
  namespace: argocd
  finalizers:
    - resources-finalizer.argocd.argoproj.io
spec:
  project: default
  source:
    repoURL: https://github.com/example/my-app
    targetRevision: main
    path: manifests/overlays/prod
  destination:
    server: https://kubernetes.default.svc
    namespace: production
  syncPolicy:
    automated:
      prune: true          # удалять ресурсы, удалённые из Git
      selfHeal: true       # восстанавливать при дрейфе
      allowEmpty: false
    syncOptions:
      - CreateNamespace=true
      - PrunePropagationPolicy=foreground
    retry:
      limit: 5
      backoff:
        duration: 5s
        factor: 2
        maxDuration: 3m
```

### Разбор spec

| Поле | Назначение |
|------|------------|
| `source.repoURL` | Git-репозиторий |
| `source.targetRevision` | Ветка, тег, коммит |
| `source.path` | Путь к манифестам |
| `source.helm` | Helm-параметры |
| `source.kustomize` | Kustomize-параметры |
| `destination.server` | Кластер |
| `destination.namespace` | Namespace |
| `syncPolicy.automated` | Автосинхронизация |
| `syncPolicy.automated.prune` | Удалять ресурсы, удалённые из Git |
| `syncPolicy.automated.selfHeal` | Восстанавливать при дрейфе |

### Sync Policy

| Политика | Описание |
|----------|----------|
| **Manual** | Синхронизация только вручную |
| **Automated** | Автоматически при изменениях в Git |
| **Automated + prune** | Удалять ресурсы, удалённые из Git |
| **Automated + selfHeal** | Восстанавливать при ручных изменениях |

### ApplicationSet: много приложений

> **ApplicationSet** — генерация Application из шаблона.

```yaml
apiVersion: argoproj.io/v1alpha1
kind: ApplicationSet
metadata:
  name: my-apps
  namespace: argocd
spec:
  generators:
    - list:
        elements:
          - cluster: dev
            namespace: dev
            values: values-dev.yaml
          - cluster: staging
            namespace: staging
            values: values-staging.yaml
          - cluster: prod
            namespace: production
            values: values-prod.yaml
  template:
    metadata:
      name: 'my-app-{{cluster}}'
    spec:
      project: default
      source:
        repoURL: https://github.com/example/my-app
        targetRevision: main
        path: charts/my-app
        helm:
          valueFiles:
            - '{{values}}'
      destination:
        server: 'https://kubernetes.default.svc'
        namespace: '{{namespace}}'
      syncPolicy:
        automated:
          prune: true
          selfHeal: true
```

### Generators

| Generator | Описание |
|-----------|----------|
| **List** | Статический список |
| **Cluster** | Все кластеры |
| **Git** | Директории в Git |
| **Matrix** | Комбинация генераторов |
| **Merge** | Объединение |

**Git Generator:**

```yaml
generators:
  - git:
      repoURL: https://github.com/example/my-app
      revision: main
      directories:
        - path: apps/*
```

**Cluster Generator:**

```yaml
generators:
  - clusters:
      selector:
        matchLabels:
          env: production
```

### Sync Waves

> **Sync Waves** — порядок применения ресурсов.

```yaml
metadata:
  annotations:
    argocd.argoproj.io/sync-wave: "-1"   # раньше
```

| Wave | Ресурсы |
|------|---------|
| -5 | Namespace, CRD |
| -1 | ConfigMap, Secret |
| 0 | Deployment, Service (по умолчанию) |
| 1 | Ingress, HPA |
| 5 | Job, CronJob |

### Sync Hooks

```yaml
metadata:
  annotations:
    argocd.argoproj.io/hook: PreSync
    argocd.argoproj.io/hook-delete-policy: HookSucceeded
```

| Hook | Когда |
|------|-------|
| `PreSync` | До синхронизации |
| `Sync` | Во время |
| `PostSync` | После |
| `SyncFail` | При ошибке |
| `Skip` | Пропустить |

## Часть 4: Flux

> **Flux** — альтернатива Argo CD. Более модульный, следует Unix-философии.

### Компоненты

| Компонент | Роль |
|-----------|------|
| **source-controller** | Git, Helm repositories |
| **kustomize-controller** | Kustomize |
| **helm-controller** | Helm |
| **notification-controller** | Уведомления |
| **image-reflector-controller** | Образы |
| **image-automation-controller** | Автообновление |

### Установка

```bash
flux bootstrap github \
  --owner=example \
  --repository=fleet-infra \
  --branch=main \
  --path=clusters/production \
  --personal
```

### GitRepository

```yaml
apiVersion: source.toolkit.fluxcd.io/v1
kind: GitRepository
metadata:
  name: my-app
  namespace: flux-system
spec:
  interval: 1m
  url: https://github.com/example/my-app
  ref:
    branch: main
```

### Kustomization

```yaml
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: my-app
  namespace: flux-system
spec:
  interval: 10m
  targetNamespace: production
  sourceRef:
    kind: GitRepository
    name: my-app
  path: ./overlays/prod
  prune: true
  healthChecks:
    - apiVersion: apps/v1
      kind: Deployment
      name: my-app
      namespace: production
```

### HelmRelease

```yaml
apiVersion: helm.toolkit.fluxcd.io/v2beta1
kind: HelmRelease
metadata:
  name: my-app
  namespace: production
spec:
  interval: 5m
  chart:
    spec:
      chart: my-app
      version: "1.0.0"
      sourceRef:
        kind: HelmRepository
        name: my-charts
        namespace: flux-system
  values:
    replicaCount: 3
    image:
      tag: "1.2.3"
  install:
    remediation:
      retries: 3
  upgrade:
    remediation:
      retries: 3
```

### Image Automation

```yaml
apiVersion: image.toolkit.fluxcd.io/v1beta2
kind: ImageRepository
metadata:
  name: my-app
  namespace: flux-system
spec:
  image: myregistry/my-app
  interval: 5m
---
apiVersion: image.toolkit.fluxcd.io/v1beta2
kind: ImagePolicy
metadata:
  name: my-app
  namespace: flux-system
spec:
  imageRepositoryRef:
    name: my-app
  policy:
    semver:
      range: ">=1.0.0"
---
apiVersion: image.toolkit.fluxcd.io/v1beta2
kind: ImageUpdateAutomation
metadata:
  name: flux-system
  namespace: flux-system
spec:
  interval: 30m
  sourceRef:
    kind: GitRepository
    name: flux-system
  git:
    checkout:
      ref:
        branch: main
    commit:
      author:
        name: flux
        email: flux@example.com
    push:
      branch: main
  update:
    path: ./clusters/production
    strategy: Setters
```

### Argo CD vs Flux

| Argo CD | Flux |
|---------|------|
| UI из коробки | CLI-first |
| Application CRD | Kustomization, HelmRelease |
| Монолитный | Модульный |
| SSO, RBAC | Простой |
| ApplicationSet | Множество controllers |
| Популярнее | Легче |
| Для больших команд | Для маленьких |

```yaml
      containers:
        - name: app
          image: nginx:1.25
          ports:
            - containerPort: 80
          envFrom:
            - configMapRef:
                name: my-app-config
```

### 4. overlays/prod/kustomization.yaml

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

namespace: production

resources:
  - ../../base
  - hpa.yaml

replicas:
  - name: my-app
    count: 5

images:
  - name: nginx
    newTag: "1.26"

configMapGenerator:
  - name: my-app-config
    behavior: merge
    literals:
      - LOG_LEVEL=warn
      - ENV=production
```

### 5. Argo CD Application

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: my-app
  namespace: argocd
  finalizers:
    - resources-finalizer.argocd.argoproj.io
spec:
  project: default
  source:
    repoURL: https://github.com/example/my-app
    targetRevision: main
    path: overlays/prod
  destination:
    server: https://kubernetes.default.svc
    namespace: production
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
```

### 6. Применение

```bash
kubectl apply -f application.yaml

# Проверка
argocd app list
argocd app get my-app
argocd app sync my-app
```

### 7. Обновление

```bash
# Изменить values в Git
vim overlays/prod/kustomization.yaml

git push

# Argo CD автоматически синхронизирует
argocd app get my-app
```

### 8. Откат

```bash
# Через Git
git revert HEAD
git push

# Через Argo CD
argocd app rollback my-app 1
```

## Часть 6: Best practices

### GitOps

| Практика | Почему |
|----------|--------|
| Один репозиторий на окружение | Изоляция |
| Или монорепо с директориями | Централизация |
| Ветки: main → prod, develop → dev | Промоушен |
| Pull-модель | Безопасность |
| Автосинхронизация | Консистентность |
| Self-heal | Защита от дрейфа |
| Prune | Удаление мусора |
| Notifications | Уведомления |
| RBAC | Доступ |
| SSO | Аутентификация |

### Kustomize

| Практика | Почему |
|----------|--------|
| base + overlays | DRY |
| commonLabels | Консистентность |
| ConfigMapGenerator | Автоматический хеш |
| Components | Переиспользование |
| Не патчить всё | Только нужное |
| Тестировать `kustomize build` | Проверка |

### Argo CD

| Практика | Почему |
|----------|--------|
| AppProject на команду | Изоляция |
| RBAC | Доступ |
| SSO | Аутентификация |
| Sync Waves | Порядок |
| Hooks | Миграции |
| Notifications | Уведомления |
| ApplicationSet | Много приложений |
| Мониторинг | Prometheus |

### Anti-patterns

| Anti-pattern | Почему плохо |
|--------------|--------------|
| Ручные изменения в кластере | Дрейф |
| Нет self-heal | Дрейф сохраняется |
| Нет prune | Мусор |
| Один репозиторий для всего | Сложно |
| Секреты в Git | Безопасность |
| Нет RBAC | Все могут всё |
| Нет уведомлений | Не знаете о проблемах |

## Troubleshooting

### Argo CD не синхронизирует

```bash
argocd app get my-app
argocd app diff my-app
argocd app sync my-app --force
kubectl logs -n argocd deploy/argocd-application-controller
```

### OutOfSync

```bash
argocd app get my-app
# Status: OutOfSync

# Причины:
# - Ручные изменения в кластере
# - Изменения в Git
# - Проблемы с RBAC

argocd app sync my-app
argocd app diff my-app
```

### Kustomize build fails

```bash
kustomize build overlays/prod
kubectl kustomize overlays/prod --enable-helm
```

### Argo CD не видит Git

```bash
argocd repo list
argocd repo add https://github.com/example/my-app --username user --password pass
kubectl logs -n argocd deploy/argocd-repo-server
```

### Self-heal не работает

```yaml
syncPolicy:
  automated:
    selfHeal: true
```

Проверить, что `automated` включён.

## Итог

1. **GitOps** — Git как источник правды. Pull-модель.
2. **Kustomize** — патчи YAML. base + overlays.
3. **Argo CD** — GitOps-инструмент. Application CRD.
4. **Flux** — альтернатива Argo CD. Модульный.
5. **ApplicationSet** — генерация приложений.
6. **Sync Waves** — порядок применения.
7. **Hooks** — lifecycle-хуки.
8. **AppProject** — изоляция команд.
9. **SSO, RBAC** — безопасность.
10. **Notifications** — уведомления.

> [!tip]
> **Правило выбора:**
> - Простое приложение → **kubectl apply**
> - Много окружений → **Kustomize**
> - Пакеты → **Helm**
> - GitOps → **Argo CD** (UI) или **Flux** (CLI)
> - Много приложений → **ApplicationSet**
> - Секреты → **Sealed Secrets**, **SOPS**, **External Secrets**

> [!warning]
> **Никогда не храните секреты в Git в открытом виде.** Используйте Sealed Secrets, SOPS или External Secrets Operator.
