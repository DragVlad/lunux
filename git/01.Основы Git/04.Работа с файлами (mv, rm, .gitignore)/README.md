# 04. Работа с файлами (mv, rm, .gitignore)

Управление файлами в Git — это не просто их добавление и коммит. Важно уметь корректно удалять, переименовывать и перемещать файлы, а также исключать ненужные файлы из отслеживания. Неправильное удаление или переименование может привести к потере истории или проблемам при слиянии.

## git rm: Удаление файлов и папок

Команда `git rm` удаляет файлы из вашей рабочей директории и индекса. В отличие от обычного `rm`, `git rm` автоматически обновляет индекс, что делает удаление частью следующего коммита.

### Удаление отслеживаемого файла

```bash
# Удалить файл из рабочей директории и индекса
git rm file.txt
git commit -m "Remove file.txt"
```

### Удаление нескольких файлов

```bash
# Удалить все .log файлы
git rm *.log

# Удалить папку рекурсивно
git rm -r logs/
```

### Удаление файла из индекса (перестать отслеживать)

Если вы случайно добавили файл в индекс и хотите, чтобы Git перестал его отслеживать, но оставить файл в рабочей директории:

```bash
# Удалить из индекса, но оставить файл на диске
git rm --cached file.txt
```

Этот прием часто используется, когда файл был закоммичен по ошибке, и его нужно добавить в `.gitignore`.

### Сравнение способов удаления

| Команда | Рабочая директория | Индекс | История |
| :--- | :--- | :--- | :--- |
| `rm file.txt` | Удаляет | Оставляет (помечает как удаленный) | Не меняет |
| `git rm file.txt` | Удаляет | Удаляет | Готовит коммит с удалением |
| `git rm --cached file.txt` | Оставляет | Удаляет | Готовит коммит с удалением |

## git mv: Переименование и перемещение

Команда `git mv` — это удобный способ переименовать или переместить файл. Она делает три вещи за один раз:
1. Переименовывает/перемещает файл в файловой системе.
2. Удаляет старый файл из индекса.
3. Добавляет новый файл в индекс.

```bash
# Переименовать файл
git mv old_name.txt new_name.txt

# Переместить файл в другую папку
git mv file.txt src/new_file.txt

# Переместить и переименовать
git mv old_name.txt src/new_name.txt
```

**Эквивалент `git mv` с обычными командами:**

```bash
# Ручное перемещение/переименование
mv old_name.txt new_name.txt
git rm old_name.txt
git add new_name.txt
```

Git достаточно умен, чтобы сам определить переименование, даже если вы используете обычные команды `mv` + `git add`/`rm`, но `git mv` делает это в одной команде и упрощает процесс.

### Почему важно использовать git mv

| Проблема | Решение |
| :--- | :--- |
| Потеря истории | `git mv` сохраняет связь между старым и новым именем |
| Сложности с merge | Git лучше обрабатывает переименования, если они зафиксированы правильно |
| Упрощение работы | Одна команда вместо трех |

## .gitignore: Исключение файлов из отслеживания

Файл `.gitignore` позволяет указать Git, какие файлы и директории он должен игнорировать. Это необходимо для того, чтобы не засорять репозиторий временными файлами, файлами сборки, секретами и конфиденциальными данными.

### Структура .gitignore

```bash
# Комментарии начинаются с решетки

# Игнорировать файлы с расширением .log
*.log

# Игнорировать папку node_modules на любом уровне
node_modules/

# Игнорировать папку .env в корне
/.env/

# Игнорировать все .pyc файлы
*.pyc

# Но не игнорировать специальный файл
!special.pyc

# Игнорировать временные файлы ОС
.DS_Store
Thumbs.db

# Игнорировать все в папке temp
temp/

# Но не игнорировать важный файл внутри temp
!temp/important.txt
```

### Шаблоны для .gitignore

| Шаблон | Описание | Пример |
| :--- | :--- | :--- |
| `*.ext` | Игнорировать все файлы с расширением `.ext` | `*.log` |
| `folder/` | Игнорировать папку `folder` и всё её содержимое | `node_modules/` |
| `/folder/` | Игнорировать папку только в корне репозитория | `/build/` |
| `!file.ext` | Не игнорировать файл `file.ext` (переопределение) | `!important.log` |
| `**/temp` | Игнорировать все папки `temp` на любом уровне | `**/temp` |
| `file?` | Игнорировать файлы с одним любым символом | `file?.txt` |
| `[abc]` | Игнорировать файлы, начинающиеся с a, b или c | `[abc]*.log` |

### Игнорирование уже отслеживаемых файлов

Если файл уже отслеживается Git, добавление его в `.gitignore` не сработает. Нужно сначала удалить его из индекса:

```bash
# Удалить из индекса (файл останется на диске)
git rm --cached file.txt

# Добавить в .gitignore
echo "file.txt" >> .gitignore
git add .gitignore

# Закоммитить изменения
git commit -m "Stop tracking file.txt and add to gitignore"
```

### Полезные готовые .gitignore

Разные языки и фреймворки имеют свои стандартные наборы игнорируемых файлов. Готовые шаблоны можно найти на [github.com/github/gitignore](https://github.com/github/gitignore).

**Пример для Python:**

```bash
# Python
__pycache__/
*.py[cod]
*.so
.Python
env/
venv/
.venv/
pip-log.txt
pip-delete-this-directory.txt
.pytest_cache/
.coverage
htmlcov/
.tox/
.mypy_cache/
.dmypy.json
dmypy.json
```

**Пример для Node.js:**

```bash
# Node.js
node_modules/
npm-debug.log*
yarn-debug.log*
yarn-error.log*
.env
dist/
build/
*.log
.DS_Store
```

### Глобальный .gitignore

Можно создать глобальный `.gitignore` для файлов, которые вы не хотите отслеживать ни в одном проекте (например, файлы редактора):

```bash
# Создать глобальный .gitignore
git config --global core.excludesfile ~/.gitignore_global

# Добавить в него файлы
echo ".DS_Store" >> ~/.gitignore_global
echo "*.swp" >> ~/.gitignore_global
echo "Thumbs.db" >> ~/.gitignore_global
```

## Итоговая таблица команд

| Команда | Назначение | Пример |
| :--- | :--- | :--- |
| `git rm` | Удалить файл из рабочей директории и индекса | `git rm file.txt` |
| `git rm --cached` | Удалить файл из индекса, оставить на диске | `git rm --cached file.txt` |
| `git rm -r` | Удалить папку рекурсивно | `git rm -r folder/` |
| `git mv` | Переименовать или переместить файл | `git mv old new` |
| `.gitignore` | Исключить файлы из отслеживания | См. примеры выше |

> [!tip]
> Всегда проверяйте статус (`git status`) после удаления или перемещения файлов, чтобы убедиться, что все изменения корректно зафиксированы в индексе.

> [!warning]
> Будьте осторожны с `git rm`, особенно с рекурсивным удалением (`-r`). Удаление файлов из репозитория — это необратимая операция (хотя их можно восстановить из истории).
