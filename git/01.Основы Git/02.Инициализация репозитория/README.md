# 02. Инициализация репозитория

Чтобы начать использовать Git для управления версиями вашего проекта, вам необходимо создать репозиторий. Это можно сделать двумя основными способами: создать новый репозиторий с нуля или скопировать (клонировать) существующий.

## git init: Создание нового репозитория

Команда `git init` используется для создания нового пустого репозитория Git в текущей директории.

```bash
# Переходим в папку с проектом
cd /path/to/your/project

# Инициализируем репозиторий
git init
```

После выполнения этой команды в корне вашего проекта появится скрытая директория `.git`. Именно в ней Git хранит всю историю, настройки и объекты вашего репозитория. **Эту папку удалять нельзя, если вы хотите сохранить историю.**

```bash
# Проверяем, что папка .git появилась
ls -la | grep .git
```

### Что происходит при git init?

| Действие | Описание |
| :--- | :--- |
| Создание `.git/` | Создается скрытая папка со всей внутренней структурой Git |
| Создание ветки по умолчанию | Создается ветка `master` или `main` (зависит от настроек `init.defaultBranch`) |
| Подготовка к коммитам | Репозиторий готов к добавлению файлов и созданию коммитов |

### Настройка ветки по умолчанию

В современных версиях Git ветка по умолчанию — `main`. Если вы хотите использовать `master`, можно изменить настройку:

```bash
# Проверить текущую ветку по умолчанию
git config --global init.defaultBranch

# Установить main как ветку по умолчанию
git config --global init.defaultBranch main

# Установить master как ветку по умолчанию
git config --global init.defaultBranch master
```

### Первый коммит в новом репозитории

После `git init` ваш репозиторий пуст. Обычно перед первым коммитом нужно создать файл, например, `README.md`, и добавить его в индекс.

```bash
# Создаем файл README
echo "# My Project" > README.md

# Добавляем файл в индекс
git add README.md

# Создаем первый коммит
git commit -m "Initial commit"
```

## git clone: Копирование существующего репозитория

Команда `git clone` создает локальную копию удаленного репозитория на вашем компьютере. Это самый распространенный способ начать работу над существующим проектом.

### Протоколы клонирования

| Протокол | Ссылка для клонирования | Особенности |
| :--- | :--- | :--- |
| **HTTPS** | `https://github.com/user/repo.git` | Простой в использовании, требует ввода логина/пароля или токена. Работает через стандартный порт 443. |
| **SSH** | `git@github.com:user/repo.git` | Более безопасный и быстрый. Требует предварительной настройки SSH-ключей. Не требует ввода пароля при каждом пуше. |
| **Git** | `git://github.com/user/repo.git` | Устаревший протокол, обычно не используется. |

### Синтаксис git clone

```bash
# Базовое клонирование
git clone https://github.com/user/project.git

# Клонирование в папку с другим именем
git clone https://github.com/user/project.git my-project-folder

# Клонирование только последнего коммита (экономит время и место)
git clone --depth 1 https://github.com/user/project.git

# Клонирование конкретной ветки
git clone -b develop https://github.com/user/project.git
```

### Что происходит при git clone?

| Действие | Описание |
| :--- | :--- |
| Создание папки | Создается директория с именем репозитория (или указанным именем) |
| Инициализация Git | Внутри создается папка `.git` |
| Загрузка данных | Скачиваются все объекты и история (если не указан `--depth`) |
| Настройка remote | Автоматически настраивается удаленный репозиторий `origin` |
| Переключение на ветку | Вы переключаетесь на ветку по умолчанию (обычно `main` или `master`) |

> [!note]
> После клонирования вы автоматически перейдете в директорию проекта (или в указанную вами директорию), и Git настроит связь с удаленным репозиторием под именем `origin`.

### Проверка после клонирования

```bash
# Проверить статус
git status

# Проверить удаленные репозитории
git remote -v

# Проверить историю
git log --oneline
```

## Инициализация в существующей папке

Если у вас уже есть папка с файлами, и вы хотите начать использовать Git:

```bash
# Переходим в папку проекта
cd /path/to/existing/project

# Инициализируем Git
git init

# Добавляем все файлы в индекс
git add .

# Создаем первый коммит
git commit -m "Initial commit with existing files"
```

## Сравнение git init и git clone

| Характеристика | git init | git clone |
| :--- | :--- | :--- |
| **Когда использовать** | Начало нового проекта | Подключение к существующему проекту |
| **История** | Создается новая, пустая | Копируется существующая |
| **Удаленные репозитории** | Нет (можно добавить позже) | Автоматически настраивается `origin` |
| **Ветки** | Только локальная ветка по умолчанию | Все ветки из удаленного репозитория |

> [!tip]
> Если вы только начинаете проект, используйте `git init`. Если вы подключаетесь к уже существующему проекту, используйте `git clone`. Для новых проектов на GitHub/GitLab обычно создают пустой репозиторий на сайте, а затем клонируют его локально.

> [!warning]
> Никогда не инициализируйте Git внутри уже существующего репозитория (где уже есть папка `.git`). Это может привести к проблемам.
