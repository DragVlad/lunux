# 00. Введение в Git

## Что такое Git?

**Git** — это распределенная система контроля версий (Distributed Version Control System, DVCS), созданная Линусом Торвальдсом в 2005 году для разработки ядра Linux. Она предназначена для отслеживания изменений в файлах, координации работы нескольких разработчиков над одним проектом и обеспечения целостности истории изменений.

В отличие от централизованных систем (например, Subversion или CVS), где вся история хранится на сервере, Git предоставляет каждому разработчику полную копию репозитория. Это означает, что большинство операций (просмотр истории, создание веток, сравнение изменений) выполняются локально, без необходимости подключения к сети, что делает их невероятно быстрыми.

## Почему Git важен для разработчика и администратора?

Для системного администратора и DevOps-инженера Git — это не просто инструмент для хранения кода приложений. Это основа для:

1.  **Инфраструктура как код (IaC):** Хранение конфигураций серверов, манифестов Ansible, Terraform-скриптов и Dockerfile в Git позволяет отслеживать каждое изменение, быстро откатываться к рабочей версии и обеспечивать воспроизводимость среды.
2.  **Автоматизация и CI/CD:** Git является триггером для пайплайнов непрерывной интеграции и доставки (CI/CD). Каждый `push` в определенную ветку может автоматически запускать сборку, тестирование и развертывание вашего приложения или инфраструктуры.
3.  **Совместная работа:** Позволяет нескольким инженерам одновременно работать над одними и теми же файлами, не мешая друг другу, а затем объединять свои изменения.
4.  **Аудит и отслеживание:** Вы всегда можете посмотреть, кто, когда и зачем изменил критически важный файл (например, конфигурацию веб-сервера или политики безопасности).

## Ключевые концепции

| Концепция | Описание |
| :--- | :--- |
| **Репозиторий (Repository)** | Хранилище вашего проекта. Содержит все файлы и всю историю их изменений. |
| **Коммит (Commit)** | «Снимок» состояния вашего репозитория в определенный момент времени. Каждый коммит имеет уникальный хеш-идентификатор (SHA-1). |
| **Ветка (Branch)** | Изолированная линия разработки. Позволяет работать над новыми функциями или исправлениями, не затрагивая стабильную версию кода (например, `main` или `master`). |
| **Тег (Tag)** | Метка, указывающая на конкретный коммит. Обычно используется для маркировки версий релизов (например, `v1.0.0`). |
| **HEAD** | Указатель на текущий коммит, который вы просматриваете или над которым работаете. Обычно это последний коммит в вашей текущей ветке. |
| **Рабочая директория (Working Directory)** | Файлы на вашем компьютере, с которыми вы работаете в данный момент. |
| **Индекс / Staging Area (Область подготовленных файлов)** | Промежуточная область перед созданием коммита. Вы добавляете файлы в индекс, а затем создаете коммит из содержимого индекса. Это позволяет вам разделить изменения и сгруппировать их в логические коммиты. |

## Жизненный цикл состояния файлов в Git

Файлы в вашем репозитории могут находиться в одном из четырех состояний:

```mermaid
graph LR
    A[Untracked<br>(Неотслеживаемый)] --> B[Staged<br>(Подготовленный)]
    B --> C[Commited<br>(Закоммиченный)]
    D[Unmodified<br>(Неизмененный)] --> B
    D --> E[Modified<br>(Измененный)]
    E --> B
    C --> D
```

1.  **Untracked (Неотслеживаемый):** Новый файл, который Git еще не отслеживает. Чтобы Git начал его отслеживать, его нужно добавить в индекс (staged).
2.  **Unmodified (Неизмененный):** Файл уже есть в репозитории и с момента последнего коммита не изменялся.
3.  **Modified (Измененный):** Файл был изменен, но еще не подготовлен к коммиту.
4.  **Staged (Подготовленный):** Измененный файл помечен для включения в следующий коммит.

## Git vs. Другие системы контроля версий

| Особенность | Git (DVCS) | SVN (CVCS) |
| :--- | :--- | :--- |
| **Архитектура** | **Распределенная.** У каждого разработчика полная копия истории. | **Централизованная.** Один центральный сервер с историей. |
| **Работа без сети** | Почти все операции локальны (коммиты, просмотр истории, ветки). | Требуется подключение к серверу для большинства операций. |
| **Ветвление и слияние** | **Сильная и гибкая.** Ветки — это легковесные указатели. Слияние — ключевая возможность. | **Слабая.** Ветки создавать сложно и дорого. Слияние часто проблематично. |
| **Производительность** | Очень высокая благодаря локальным операциям. | Зависит от скорости соединения с сервером. |
| **Целостность данных** | Каждый файл и коммит проверяется по контрольной сумме (SHA-1). Подделка истории практически невозможна. | Менее надежная защита от потери или подделки данных. |

> [!note]
> Git — это стандарт де-факто в современной разработке ПО. Независимо от того, работаете ли вы с микросервисами, конфигурациями Kubernetes или просто пишете скрипты на Bash, знание Git — это обязательный навык.

> [!tip]
> Начните изучение Git с базовых команд (`add`, `commit`, `push`, `pull`, `branch`), а затем переходите к более сложным, таким как `rebase`, `cherry-pick` и `reflog`. Практика — единственный способ освоить его по-настоящему.
