# 02. JVM, JRE, JDK — архитектура

## О чём этот раздел

Этот раздел посвящён фундаментальной архитектуре Java-платформы. Многие новички путают понятия JVM, JRE и JDK, а без чёткого понимания этих компонентов сложно двигаться дальше. Мы разберём, из чего состоит каждый элемент, как они взаимодействуют друг с другом и с операционной системой, и зачем вообще нужны эти абстракции. Это знание станет вашей опорой при настройке окружения, сборке проектов и понимании того, как Java-программа живёт внутри системы.

---

## JVM (Java Virtual Machine): сердце платформы

**JVM (Java Virtual Machine)** — это исполнительный движок, который запускает Java-приложения. Она отвечает за:

1. **Загрузку кода** — находит и загружает `.class`-файлы.
2. **Проверку кода (Bytecode Verifier)** — убеждается, что байт-код безопасен, не нарушает ограничений и не содержит вредоносных конструкций.
3. **Интерпретацию и компиляцию** — превращает байт-код в понятные процессору инструкции.
4. **Управление памятью (Garbage Collection)** — автоматически очищает неиспользуемую память.
5. **Обработку потоков и синхронизацию** — управляет выполнением нескольких потоков.

## JRE (Java Runtime Environment): среда исполнения

**JRE (Java Runtime Environment)** — это то, что необходимо для **запуска** уже готовых Java-программ. Она содержит JVM и основные библиотеки классов, но в ней **нет инструментов для разработки** (компилятора, отладчика и т.д.).

**Когда нужна JRE?**
- Если вы обычный пользователь и хотите просто запустить `.jar`-файл или игру.
- Если на сервере уже есть собранное приложение, и его нужно только выполнить.

> [!tip]
> Начиная с Java 11, отдельная установка JRE перестала распространяться. Теперь JRE является частью JDK. Команды типа `jlink` позволяют создать кастомный минимальный образ JRE для вашего приложения.

## JDK (Java Development Kit): инструментарий разработчика

**JDK (Java Development Kit)** — это полноценный набор для **разработки** Java-приложений. Он включает в себя всё, что есть в JRE, а также инструменты для компиляции, отладки, документирования и анализа кода.

**Ключевые инструменты JDK (из папки `bin/`):**

| Инструмент | Назначение |
| :--- | :--- |
| `javac` | Компилятор. Превращает `.java` в `.class` (байт-код) |
| `java` | Запускает приложение (интерпретирует байт-код через JVM) |
| `jar` | Упаковывает файлы в архив `.jar` (Java Archive) |
| `javadoc` | Генерирует HTML-документацию из комментариев в коде |
| `jdb` | Отладчик для поиска ошибок в коде |
| `jps` | Показывает список запущенных Java-процессов |
| `jcmd` | Отправляет диагностические команды Java-процессам |
| `jstack` | Получение дампа потоков для анализа зависаний |
| `jmap` | Работа с дампами памяти для поиска утечек |
| `jhat` | Анализ дампов памяти (устаревший, заменён на VisualVM) |
| `jstat` | Статистика JVM (сборщик мусора, классы и т.д.) |
| `jinfo` | Просмотр и изменение настроек JVM |

**Когда нужен JDK?**
- Когда вы пишете код и хотите его скомпилировать.
- Когда вы отлаживаете или профилируете приложение.
- Когда вы собираете проект с помощью систем сборки (Maven, Gradle).

> [!important]
> **Главное правило:**
> - Хотите **разрабатывать** → ставьте **JDK**.
> - Хотите только **запускать** готовые программы → достаточно **JRE** (но помните, что в новых версиях JRE идёт в комплекте с JDK).

## Краткая шпаргалка

| Компонент | Содержит | Для чего |
| :--- | :--- | :--- |
| **JVM** | Исполнительный движок (интерпретатор, JIT), Runtime Data Areas, Class Loader | Выполняет байт-код. Абстрагирует программу от ОС. |
| **JRE** | JVM + стандартные библиотеки классов (API) + конфигурации | Запуск Java-программ. Не содержит инструментов разработки. |
| **JDK** | JRE (JVM + API) + инструменты разработки (javac, jar, jdb, ...) | Разработка, компиляция, отладка и запуск Java-приложений. |

---

## Итог

- **JVM** — это «двигатель», который запускает байт-код.
- **JRE** — это JVM + библиотеки, среда для запуска готовых приложений.
- **JDK** — это JRE + инструменты для разработчика, полный набор для создания ПО.

Понимание этой иерархии помогает не запутаться в терминах, правильно настраивать окружение и осознанно выбирать, что именно вы устанавливаете на свой компьютер или сервер.

> [!tip]
> Разница между JDK и JRE видна невооружённым глазом: в папке `bin` JDK вы найдёте `javac`, а в JRE — только `java`. Попробуйте открыть эти папки на своей системе, чтобы закрепить материал.
