# 01. Что такое Java: история, версии, LTS (8, 11, 17, 21)

## О чём этот раздел

Этот раздел открывает знакомство с миром Java. Мы начнем с самого начала: узнаем, как появился этот язык, почему он стал таким популярным, и как он эволюционировал до современного состояния. Вместо сухого перечня фактов, мы заложим понимание ключевых вех в истории Java, важности долгосрочной поддержки (LTS) и того, что отличает разные версии. Это фундамент, на котором строится всё дальнейшее изучение — от синтаксиса до сложных корпоративных приложений.

## Как появилась Java

История Java началась в начале 1990-х годов в компании Sun Microsystems. Группа инженеров, включая Джеймса Гослинга, Майка Шеридана и Патрика Нотона, работала над проектом **Green**. Их целью было создание платформы для управления бытовыми электронными устройствами (умные ТВ, пульты ДУ, приставки). Изначально язык, который они разрабатывали, назывался **Oak** (в честь дуба, росшего за окном Гослинга).

Однако проект Oak не имел коммерческого успеха на рынке бытовой электроники. Настоящий прорыв случился, когда команда поняла, что их технология идеально подходит для новой, только зарождающейся тогда сети — **Интернета**. В 1995 году язык был переименован в **Java** (в честь любимого сорта кофе, который пили разработчики) и представлен широкой публике с лозунгом **"Write Once, Run Anywhere" (WORA)**. Этот принцип, обещающий, что однажды написанный код будет работать на любой платформе, стал главным двигателем популярности Java.

> Ключевым прорывом стала архитектура **Java Virtual Machine (JVM)**, которая позволила изолировать программный код от конкретной аппаратной платформы. Вместо того чтобы компилироваться в машинный код для конкретного процессора, Java-код компилируется в **байт-код**, который затем интерпретируется JVM, установленной на целевой системе.

К концу 1990-х Java уже использовалась в веб-приложениях, на серверах и в корпоративной среде, быстро став одной из доминирующих платформ для разработки ПО.

## Эволюция версий и LTS

Изначально Sun Microsystems (а затем и Oracle, купившая Sun в 2010 году) выпускала новые версии Java нерегулярно. Однако в 2017 году был принят новый **релизный цикл**: теперь новые версии Java выходят **каждые шесть месяцев** (в марте и сентябре). Это позволяет сообществу быстрее получать новые функции и улучшения.

Однако не все хотят обновлять свои системы так часто. Поэтому Oracle ввела понятие **LTS (Long-Term Support) — версии с долгосрочной поддержкой**.

| Версия LTS | Год выпуска | Ключевые особенности |
| :--- | :--- | :--- |
| **Java 8** | 2014 | **Lambda-выражения, Stream API, новый API для работы с датой и временем (`java.time`).** Язык стал функциональным. На протяжении многих лет оставалась самой популярной версией. |
| **Java 11** | 2018 | **Модульная система (Project Jigsaw), новый HTTP Client, улучшения в API.** Заменила Java 8 в качестве стандартной LTS версии для большинства проектов. |
| **Java 17** | 2021 | **Sealed Classes, Pattern Matching for `switch`, Foreign Function & Memory API (в инкубаторе).** Новая актуальная LTS-версия, принесшая значительные улучшения производительности и языка. |
| **Java 21** | 2023 | **Virtual Threads (Project Loom), Sequenced Collections, Record Patterns, Pattern Matching for `switch` (final).** Революционная версия, значительно упрощающая работу с многопоточностью и высоконагруженными приложениями. |

> [!note]
> Версии, выходящие между LTS-релизами (например, Java 12, 13, 14, 15, 16, 18, 19, 20), называются **Feature Releases**. Они содержат новые функции, но поддержка для них прекращается сразу после выхода следующей Feature Release.

## Почему это важно знать?

Понимание различий между версиями критично по нескольким причинам:

- **Выбор версии для проекта**: Для новых проектов рекомендуется использовать последнюю LTS-версию (на данный момент Java 21 или 17), чтобы иметь доступ к самым новым и производительным функциям и получать долгосрочную поддержку.
- **Поддержка legacy-кода**: Многие корпоративные приложения до сих пор работают на Java 8. Знание особенностей этой версии необходимо для поддержки и миграции старых систем.
- **Экосистема**: Многие библиотеки и фреймворки (например, Spring Boot) активно развиваются и постепенно отказываются от поддержки устаревших версий.

## Философия Java

Успех Java во многом определяется её ключевыми принципами:

- **"Write Once, Run Anywhere"**: Программы, написанные на Java, могут работать на любой платформе, имеющей JVM.
- **Объектно-ориентированность**: Всё в Java (почти) является объектом. Это способствует созданию гибкого, модульного и переиспользуемого кода.
- **Безопасность и надёжность**: Язык спроектирован так, чтобы предотвращать многие распространенные ошибки программирования (например, проблемы с управлением памятью) и обеспечивать безопасное выполнение кода.
- **Автоматическое управление памятью (Garbage Collection)**: Разработчик не должен вручную выделять и освобождать память — за этим следит специальный механизм JVM (сборщик мусора), что резко снижает количество ошибок, связанных с утечками памяти.
- **Обратная совместимость**: Старый код, написанный для более старых версий Java, почти всегда гарантированно будет работать на новых версиях. Это ценное свойство обеспечивает стабильность огромной экосистемы.
