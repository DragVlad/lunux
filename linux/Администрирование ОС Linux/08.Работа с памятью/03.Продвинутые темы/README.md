# Страничный кэш, грязные страницы, Memory Overcommit и Swapping

## Страничный кэш (Page Cache)

> Page cache в Linux играет важную роль в оптимизации производительности системы, используя оперативную память для хранения данных, считываемых с диска.

Linux всегда старается использовать оперативную память для ускорения операций с диском, используя доступную память для буферов и кэша (страницы с фактическим содержимым файлов или блочных устройств). Это помогает системе работать быстрее, потому что информация с диска уже находится в памяти, что экономит операции ввода-вывода. Если программам или приложениям потребуется больше памяти, Linux освободит буферы и кэш, чтобы предоставить память для этих приложений.

### Как работает page cache

1. **Чтение данных** — когда программа запрашивает данные с диска, система сначала проверяет, есть ли эти данные в page cache. Если данные уже находятся в кэше (это называется *cache hit*), они немедленно возвращаются программе, избегая операции ввода-вывода (I/O) с диска. Если данных в кэше нет (*cache miss*), они считываются с диска и помещаются в кэш для последующего использования.

2. **Запись данных** — когда программа записывает данные на диск, эти данные сначала записываются в page cache. Это называется отложенной записью (*write-back*). Фактическая запись на диск выполняется позже, что позволяет сгруппировать несколько операций записи и уменьшить количество операций I/O, улучшая производительность.

3. **Освобождение памяти** — если системе требуется больше оперативной памяти для выполнения программ, она может освободить место в page cache, удаляя старые или редко используемые данные.

### Мониторинг использования page cache

> Использование page cache можно мониторить с помощью команды `free` или `vmstat`.

**Команда `free`:**

```bash
free -hw
```

Флаги `-h` и `-w` дают вывод в удобочитаемом формате и разделяют статистику для кэшей и буферов.

**Файл `/proc/meminfo`:**

```bash
grep "^Cach|^Buff" -E /proc/meminfo
```

**Команда `vmstat`:**

```bash
vmstat -s
```

> `vmstat` — мощный инструмент для сбора информации об использовании виртуальной памяти.

**Основные поля вывода `vmstat -s`:**

| Поле | Описание |
|------|----------|
| total memory | Общее количество физической оперативной памяти в системе |
| used memory | Количество используемой памяти (активная + неактивная) |
| active memory | Память, активно используемая процессами |
| inactive memory | Память, которая не используется, но может быть быстро использована |
| free memory | Свободная память, не используемая ни для каких целей |
| buffer memory | Память для буферов файловой системы (метаданные) |
| swap cache | Память, ранее бывшая на свопе и возвращённая в RAM |
| total swap | Общее количество пространства свопа |
| used swap | Используемое пространство свопа |
| free swap | Свободное пространство свопа |
| pages paged in | Страницы, загруженные в RAM с диска |
| pages paged out | Страницы, выгруженные из RAM на диск |
| pages swapped in | Страницы, загруженные из свопа в RAM |
| pages swapped out | Страницы, выгруженные из RAM в своп |

### Управление page cache

Для управления кэшем используется интерфейс ядра `/proc/sys/vm/drop_caches`, который позволяет администратору вручную сбрасывать кэши:

```bash
sudo sh -c 'echo 1 > /proc/sys/vm/drop_caches'   # Сбросить только page cache
sudo sh -c 'echo 2 > /proc/sys/vm/drop_caches'   # Сбросить только dentry и inode кэши
sudo sh -c 'echo 3 > /proc/sys/vm/drop_caches'   # Сбросить все кэши
```

**Пример эмуляции интенсивного дискового ввода-вывода:**

```bash
# Смотрим состояние кэша до эксперимента
free -mw

# Генерируем файл со случайными данными (эмуляция интенсивного вывода)
dd if=/dev/random of=./data_file count=1400000

# Читаем файл и записываем в новый файл 10 раз (эмуляция чтения и записи)
for i in `seq 1 10`; do echo $i; cat data_file >> large_file; done

# Читаем получившийся файл и смотрим статистику
cat large_file > /dev/null
free -mw
```

## «Грязные» страницы (Dirty Pages)

> «Грязные» страницы памяти (*dirty pages*) в Linux — это страницы в оперативной памяти, которые были изменены программами, но ещё не записаны обратно на диск или в постоянное хранилище. Эти страницы содержат данные, отличающиеся от тех, что находятся на диске.

Когда программа записывает данные в файл, операционная система сначала вносит изменения в оперативную память (а не сразу на диск). Это делается для повышения производительности: запись в память намного быстрее, чем запись на диск. В результате эти страницы становятся «грязными» (dirty), так как они теперь содержат изменённые данные, которые ещё не были синхронизированы с их версией на диске.

### Управление «грязными» страницами

Операционная система должна управлять «грязными» страницами, чтобы избежать потери данных и обеспечить согласованность между содержимым оперативной памяти и данными на диске. Для этого используются следующие механизмы:

1. **Фоновая запись (*write-back*)** — операционная система периодически записывает «грязные» страницы на диск. Это может происходить, когда система простаивает или в определённые интервалы времени.

2. **Жёсткие лимиты и пороги** — существуют параметры, контролирующие количество «грязных» страниц:

   - `/proc/sys/vm/dirty_background_ratio` — процент от общей оперативной памяти, который может быть занят «грязными» страницами до начала фонового сброса на диск.
   - `/proc/sys/vm/dirty_ratio` — максимальный процент от общей оперативной памяти для «грязных» страниц. При достижении этого лимита новые записи блокируются до сброса части страниц.
   - `/proc/sys/vm/dirty_expire_centisecs` — интервал сброса грязных страниц на диск в сотых долях секунды (100 = 1с).

**Просмотр текущих значений:**

```bash
cat /proc/sys/vm/dirty_background_ratio
cat /proc/sys/vm/dirty_ratio
cat /proc/sys/vm/dirty_expire_centisecs

# или
sudo sysctl vm.dirty_background_ratio
sudo sysctl vm.dirty_ratio
sudo sysctl vm.dirty_expire_centisecs
```

**Просмотр количества «грязных» страниц:**

```bash
grep Dirty /proc/meminfo
```

**Принудительный сброс на диск:**

```bash
sync
grep Dirty /proc/meminfo
```

### Настройка параметров управления «грязными» страницами

```bash
sudo su -c "echo 150 > /proc/sys/vm/dirty_expire_centisecs"
sudo su -c "echo 20 > /proc/sys/vm/dirty_ratio"
sudo su -c "echo 20 > /proc/sys/vm/dirty_background_ratio"
```

> **Важно:** «Сброс» страниц на диск — это операция ввода-вывода, которая достаточно дорога, так как диск является самой медленной частью системы. Необходимо найти золотую середину между обеспечением консистентности данных и тратой системных ресурсов.

**Правильное управление «грязными» страницами критично для поддержания производительности и целостности данных:**

- Если система позволяет накапливаться слишком большому количеству «грязных» страниц, могут случиться внезапные пики записи на диск, что замедлит работу системы.
- В случае сбоя системы данные в «грязных» страницах могут быть потеряны, если они не были сброшены на диск.

## Memory Overcommit

> Memory Overcommit — это механизм в Linux, который позволяет системе выделять больше виртуальной памяти, чем физически доступно. Этот механизм основан на предположении, что приложения *не используют всю запрашиваемую память одновременно*. В результате Linux может более эффективно использовать доступные ресурсы, но также это может привести к ситуации, когда памяти не хватает для выполнения всех запрошенных операций.

### Как работает Memory Overcommit

В Linux есть несколько режимов управления политикой overcommit, которые определяются с помощью параметра `vm.overcommit_memory`:

| Режим | Значение | Описание |
|-------|----------|----------|
| **Strict Overcommit** (строгая политика) | `2` | Система разрешает выделение памяти только в пределах физически доступной памяти и swap пространства. При превышении лимита `malloc` возвращает ошибку. |
| **Heuristic Overcommit** (эвристическая политика) | `0` | Система использует эвристический алгоритм для определения, сколько памяти можно выделить, основываясь на типичном поведении приложений. |
| **Always Overcommit** (всегда разрешать) | `1` | Система всегда разрешает выделение памяти. При нехватке памяти срабатывает OOM killer. |

### Конфигурация Memory Overcommit

```bash
# Установить строгую политику overcommit
echo "vm.overcommit_memory = 2" >> /etc/sysctl.conf
sysctl -p
```

### Memory Overcommit и OOM Killer

Когда система Linux сталкивается с недостатком памяти из-за overcommit, запускается **OOM killer** — механизм, который завершает один или несколько процессов, чтобы освободить память и предотвратить крах системы.

**Выбор процесса для завершения:** OOM killer выбирает процесс на основе метрики `oom_score`, которая учитывает потребление памяти и важность процесса.

**Конфигурация OOM killer:** можно настроить поведение, установив значение `oom_score_adj` для процесса, определяющее приоритет для завершения.

### Преимущества и недостатки Memory Overcommit

**Преимущества:**
- Лучшее использование ресурсов — приложения часто запрашивают больше памяти, чем используют.
- Улучшенная производительность — для некоторых типов нагрузок overcommit может улучшить общую производительность.

**Недостатки:**
- Риск неожиданного завершения процессов — если система столкнётся с нехваткой памяти, процессы могут быть внезапно завершены OOM killer-ом.
- Непредсказуемость поведения — особенно в режиме «всегда разрешать overcommit».

## Swapping (Подкачка)

> Swapping (своппинг) — это процесс передачи данных между оперативной памятью (RAM) и областью подкачки на жёстком диске (swap space). Когда оперативная память начинает исчерпываться, Linux может временно сохранять часть неиспользуемых данных на диск, освобождая оперативную память для более активных процессов.

Когда процесс нуждается в данных, которые были перемещены в область подкачки, операционная система перемещает их обратно в оперативную память, что может занимать время и влиять на производительность. Swapping является важным механизмом для управления памятью и позволяет системе работать с более объёмными данными, чем фактически доступно в оперативной памяти.

### Нужен ли своп?

Ответ зависит от типа системы:

- **Система с равномерной нагрузкой, использующая меньше памяти, чем есть** — своп в принципе не нужен.
- **Система с памятью впритык** — в свопе появляется смысл.

Если свопа нет, а память нужна, ядро будет сбрасывать файловые кэши. При этом с кэшами кто-то мог работать, и в результате даже при выключенном свопе наблюдается высокое IO.

Если же своп есть, настроен и достаточен, туда вытесняются редко используемые страницы, а файловый кэш остаётся на месте, что повышает среднюю производительность.

### Основные концепции свопинга

**Swap пространство:**
- **Swap раздел** — специальный раздел на диске, выделенный под своп.
- **Swap файл** — обычный файл, используемый как swap пространство (удобно, если нет возможности создать отдельный раздел).

**Когда используется swap:**
- При нехватке физической оперативной памяти система перемещает наименее используемые страницы в swap пространство.
- Свопинг помогает предотвратить сбои системы и замедления, обеспечивая дополнительное виртуальное пространство памяти.

### Управление swap пространством

**Просмотр текущего состояния swap:**

```bash
swapon --show
# или
swapon -s
```

Команда `free -h` также показывает использование swap:

```bash
free -h
```

### Настройка swappiness

**Swappiness** — параметр ядра Linux, определяющий, как агрессивно система будет использовать swap пространство. Значение варьируется от 0 до 100:

- **Низкое значение** (например, 10) — система реже использует swap, предпочитая сохранять данные в оперативной памяти.
- **Высокое значение** (например, 60 и выше) — система более склонна к использованию swap.

**Просмотр текущего значения:**

```bash
cat /proc/sys/vm/swappiness
```

**Временное изменение:**

```bash
sudo sysctl vm.swappiness=10
```

**Постоянное изменение** — добавьте строку в `/etc/sysctl.conf`:

```text
vm.swappiness = 10
```

### Важные моменты

- **Производительность** — чрезмерное использование swap может значительно замедлить систему, так как доступ к диску намного медленнее, чем к оперативной памяти. Оптимальное значение swappiness помогает избежать этого.

- **SSD и swap** — использование swap на SSD может улучшить производительность по сравнению с HDD, но также может ускорить износ SSD. Следует внимательно выбирать значение swappiness и размер swap пространства.
