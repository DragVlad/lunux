# Утечки памяти и OOM Killer

## Утечки памяти

> Утечка памяти (Memory Leak) — ситуация, когда программа продолжает выделять память в течение своего выполнения, но не освобождает её после использования. Это приводит к постепенному истощению доступной памяти, что может привести к снижению производительности и даже к краху системы или приложения.

### Основные причины утечек памяти

1. **Неосвобождённые указатели** — программа выделяет память с помощью функций, таких как `malloc` в C или `new` в C++, но не освобождает её с помощью `free` или `delete`.

2. **Ссылочные циклы** — в языках с автоматическим управлением памятью (Python, Java) ссылки между объектами могут образовывать циклы, которые сборщик мусора не может разорвать, что приводит к утечке памяти.

3. **Забытие ссылок** — программа перестаёт использовать некоторые объекты, но ссылки на них продолжают существовать, что предотвращает их сбор сборщиком мусора.

4. **Ошибки логики** — программа может иметь логические ошибки, из-за которых она неправильно управляет памятью, например, несколько раз выделяет память без соответствующего освобождения.

### Примеры утечек памяти

**Пример на C:**

```c
#include <stdlib.h>

void create_leak() {
    int *ptr = malloc(sizeof(int) * 10); // Память выделена, но не освобождена
}

int main() {
    for (int i = 0; i < 1000; ++i) {
        create_leak(); // Вызываем функцию, создающую утечку памяти
    }
    return 0;
}
```

В этом примере в цикле многократно вызывается функция, которая запрашивает память и не освобождает её. Картина становится ещё более критичной при замене конечного цикла `for` на бесконечный `while`.

**Пример на Python:**

```python
class Node:
    def __init__(self):
        self.next = None

def create_cycle():
    a = Node()
    b = Node()
    a.next = b
    b.next = a  # Создаём циклическую ссылку

while True:
    create_cycle()  # Создаём циклы, которые сборщик мусора не может удалить
```

В этом примере используется бесконечный цикл, в котором вызываемая функция создаёт объекты со взаимными ссылками, что приводит к накоплению неудаляемых объектов.

### Влияние утечек памяти

1. **Снижение производительности** — постепенное истощение доступной памяти может замедлить выполнение программы, так как операционная система начинает активно использовать свопинг и другие механизмы управления памятью.

2. **Крахи программы** — когда память заканчивается, программы могут завершаться с ошибками (OutOfMemoryError).

3. **Увеличение использования ресурсов** — утечки памяти приводят к увеличению использования оперативной памяти и могут негативно повлиять на другие приложения и общую производительность системы.

### Методы обнаружения и предотвращения утечек памяти

#### Инструменты для обнаружения утечек

**Valgrind** — популярный инструмент для анализа памяти в программах на C и C++. Может обнаруживать утечки памяти, использование неинициализированной памяти и другие ошибки.

```bash
valgrind --leak-check=full ./your_program
```

**AddressSanitizer** — инструмент для обнаружения ошибок памяти в C/C++. Включается при компиляции с флагами:

```bash
gcc -fsanitize=address -g your_program.c -o your_program
./your_program
```

**Pympler** — библиотека для анализа использования памяти в Python-программах.

```python
from pympler import tracker
tr = tracker.SummaryTracker()
tr.print_diff()
```

#### Практики для предотвращения утечек

**Правильное управление памятью:**
- В языках с ручным управлением памятью (C, C++) всегда освобождайте память, если она больше не нужна.
- Используйте умные указатели (`std::shared_ptr`, `std::unique_ptr` в C++), которые автоматически управляют временем жизни объектов.

**Избегайте циклических ссылок:**
- В языках с автоматическим управлением памятью избегайте циклических ссылок или используйте слабые ссылки (*weak references*).

**Использование инструментов анализа:**
- Регулярно используйте инструменты анализа памяти для проверки и отладки программ.

**Проверка кода:**
- Регулярные ревью кода и тестирование могут помочь обнаружить и устранить утечки памяти на ранних стадиях разработки.

> Утечки памяти представляют серьёзную проблему для стабильности и производительности программного обеспечения. Понимание причин, использование инструментов для обнаружения и применение лучших практик для управления памятью могут значительно уменьшить риск утечек памяти и улучшить общую надёжность программ.

## OOM Killer

> OOM Killer (Out-Of-Memory Killer) — это механизм в операционной системе Linux, предназначенный для завершения процессов при нехватке памяти. Его основная задача — предотвратить крах системы, когда все доступные ресурсы памяти (физическая память и swap) исчерпаны.

Если система сталкивается с ситуацией, когда память заполнена почти до отказа, и нет возможности сбросить кэши или выгрузить страницы, OOM Killer активируется для «спасения» системы радикальным способом — завершением процесса с наибольшим потреблением памяти.

Механизм OOM Killer выбирает по определённому алгоритму процесс, которым наиболее целесообразно пожертвовать в текущий момент, освобождая используемую им память для перераспределения между остальными процессами. Основной критерий выбора — **текущее потребление физической памяти и других ресурсов**. Существует также специальный коэффициент, который позволяет ядру подсказать, кого в спорной ситуации лучше завершить, а кого пощадить.

Если отключить OOM Killer полностью, системе в случае полного дефицита памяти ничего не останется, кроме как перезагрузиться.

### Как работает OOM Killer

Когда система сталкивается с недостатком памяти, активируется OOM Killer для освобождения памяти. OOM Killer выбирает один или несколько процессов для завершения, основываясь на различных факторах.

#### Критерии выбора процесса

**OOM Score:**
- Каждый процесс в системе имеет значение `oom_score`, которое используется для определения «ценности» процесса.
- Чем выше `oom_score`, тем больше вероятность, что процесс будет завершён при нехватке памяти.
- Значение `oom_score` рассчитывается на основе нескольких факторов, включая потребление памяти процессом и его приоритет.

**oom_score_adj:**
- Значение может быть использовано для корректировки `oom_score` процесса.
- Позволяет администратору системы или программам изменять приоритет завершения процесса.
- Значение варьируется от -1000 до 1000:
  - `-1000` — процесс никогда не должен быть завершён OOM Killer.
  - `1000` — процесс становится наиболее вероятным кандидатом на завершение.

```bash
echo -1000 > /proc/<pid>/oom_score_adj
```

**Потребление памяти:**
- OOM Killer учитывает общее потребление памяти процессом, включая физическую память и swap.

**Приоритет процесса (nice value):**
- Процессы с более высоким приоритетом (меньшее значение `nice`) имеют меньший шанс быть завершёнными.

### Настройка поведения OOM Killer

Администраторы могут управлять поведением OOM Killer через различные настройки и параметры.

**vm.overcommit_memory:**
- `0` — эвристическая политика. Система пытается угадать, сколько памяти можно выделить.
- `1` — всегда разрешать выделение памяти. Система всегда позволяет выделять больше памяти, чем доступно.
- `2` — строгая политика. Система выделяет память только в пределах доступной физической памяти и swap.

```bash
echo 2 > /proc/sys/vm/overcommit_memory
```

**vm.overcommit_ratio:**
- Если `vm.overcommit_memory` установлено в `2`, этот параметр определяет процент памяти, который система может выделить сверх доступной памяти.

```bash
echo 50 > /proc/sys/vm/overcommit_ratio
```

**vm.panic_on_oom:**
- Определяет, должна ли система паниковать (перезагружаться) при возникновении OOM ситуации.

```bash
echo 1 > /proc/sys/vm/panic_on_oom
```

**oom_adj и oom_score_adj:**
- Процессы могут управлять своим приоритетом для OOM Killer с помощью `oom_adj` (устаревший) и `oom_score_adj` (современный аналог).

```bash
echo -17 > /proc/<pid>/oom_adj          # Устаревший способ
echo -1000 > /proc/<pid>/oom_score_adj  # Современный способ
```

### Пример настройки OOM Killer

**Защита процесса от завершения:**

```bash
#!/bin/bash
# Пример: защищаем процесс с PID 12345
PID=12345
echo -1000 > /proc/$PID/oom_score_adj
```

**Понижение приоритета завершения для процесса:**

```bash
#!/bin/bash
# Пример: понижаем приоритет завершения для процесса с PID 12345
PID=12345
echo 1000 > /proc/$PID/oom_score_adj
```

OOM Killer — это важный механизм в Linux, предназначенный для защиты системы от краха при нехватке памяти. Он завершает процессы с высоким потреблением памяти, основываясь на `oom_score` и других факторах, чтобы освободить ресурсы. Настройка поведения OOM Killer позволяет администраторам системы определять, какие процессы должны быть защищены, а какие могут быть завершены при критической нехватке памяти, обеспечивая стабильную работу системы даже в условиях интенсивного использования ресурсов.
