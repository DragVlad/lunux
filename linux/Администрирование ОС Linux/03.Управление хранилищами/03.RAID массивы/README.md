# Программные RAID массивы и управление с помощью mdadm

RAID — технология, без которой трудно представить работу любого физического сервера. Для виртуальных серверов она менее актуальна, так как они полагаются на отказоустойчивость нижележащего физического оборудования.

> **RAID** (Redundant Array of Independent Disks) — технология объединения нескольких физических дисков в один логический массив для повышения надёжности, производительности и/или ёмкости хранения данных.

---

## Программные и аппаратные RAID

| Тип | Реализация | Преимущества | Недостатки |
|-----|------------|--------------|-------------|
| **Аппаратный RAID** | Выделенный RAID-контроллер | Высокая производительность, прозрачность для ОС, дополнительные функции (кеширование, батареи) | Высокая стоимость, зависимость от конкретного контроллера |
| **Программный RAID** | Уровень ОС (mdadm в Linux) | Низкая стоимость, гибкость настройки | Нагрузка на ЦП, ограниченный функционал |

---

## Уровни RAID

| Уровень | Описание | Минимум дисков | Отказоустойчивость | Эффективность места |
|---------|----------|----------------|-------------------|---------------------|
| **RAID 0** | Стрипинг (чередование) | 2 | Нет | 100% |
| **RAID 1** | Зеркалирование | 2 | Да (1 диск) | 50% |
| **RAID 5** | Стрипинг + чётность | 3 | Да (1 диск) | (n-1)/n |
| **RAID 6** | Стрипинг + двойная чётность | 4 | Да (2 диска) | (n-2)/n |
| **RAID 10** | RAID 1 + RAID 0 | 4 | Да (до 2 дисков) | 50% |

## mdadm и ядро Linux

> **mdadm** — утилита пользовательского пространства, взаимодействующая с ядром Linux для создания и управления программными RAID массивами. Основную работу выполняет **модуль ядра md** (multiple devices).

### Роль ядра:
- Обработка всех операций ввода-вывода
- Распределение данных по дискам согласно конфигурации RAID
- Вычисление контрольных сумм и паритетных данных (RAID 5/6)
- Управление синхронизацией и восстановлением

---

## Практический пример: создание RAID 1

### Исходные данные
- Диски: `/dev/sdc`, `/dev/sdd`, `/dev/sde`
- Цель: создать RAID 1 массив, смонтировать его, симулировать сбой и замену диска

### Шаг 1: Создание RAID 1 массива

```bash
sudo mdadm --create --verbose /dev/md0 --level=1 --raid-devices=2 /dev/sdc /dev/sdd
```

**Параметры:**
- `--create` — создание нового массива
- `--verbose` — подробный вывод
- `--level=1` — уровень RAID 1
- `--raid-devices=2` — количество устройств

### Шаг 2: Проверка состояния

```bash
cat /proc/mdstat
sudo mdadm --detail /dev/md0
```

### Шаг 3: Форматирование и монтирование

```bash
# Создание файловой системы
sudo mkfs.ext4 /dev/md0

# Точка монтирования
sudo mkdir -p /mnt/raid1

# Монтирование
sudo mount /dev/md0 /mnt/raid1

# Проверка
df -h | grep /mnt/raid1
```

### Шаг 4: Симуляция сбоя диска

```bash
# Пометка диска как сбойного
sudo mdadm --manage /dev/md0 --fail /dev/sdc

# Просмотр состояния (один диск faulty)
sudo mdadm --detail /dev/md0

# Удаление сбойного диска из массива
sudo mdadm --manage /dev/md0 --remove /dev/sdc

# Добавление нового диска /dev/sde
sudo mdadm --manage /dev/md0 --add /dev/sde
```

### Шаг 5: Наблюдение за реконструкцией

```bash
# Во время восстановления
cat /proc/mdstat
sudo mdadm --detail /dev/md0

# После завершения — оба диска active sync
```

## Сохранение конфигурации RAID

Чтобы массив автоматически собирался при загрузке с тем же именем `/dev/md0`:

```bash
# Сохранение конфигурации
sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf

# Обновление initramfs
sudo update-initramfs -u

# Перезагрузка для проверки
sudo reboot
```

---

## Удаление программного RAID

### Полное безопасное удаление

```bash
# 1. Размонтирование
sudo umount /dev/md0

# 2. Остановка RAID массива
sudo mdadm --stop /dev/md0

# 3. Удаление из конфигурации
sudo mdadm --remove /dev/md0
sudo update-initramfs -u

# 4. Очистка метаданных с дисков
sudo mdadm --zero-superblock /dev/sdc
sudo mdadm --zero-superblock /dev/sdd
sudo mdadm --zero-superblock /dev/sde
```

## Основные команды mdadm

| Задача | Команда |
|--------|---------|
| Создание RAID | `mdadm --create /dev/md0 --level=1 --raid-devices=N /dev/sdX...` |
| Просмотр деталей | `mdadm --detail /dev/md0` |
| Быстрый статус | `cat /proc/mdstat` |
| Пометка диска как failed | `mdadm --manage /dev/md0 --fail /dev/sdX` |
| Удаление диска | `mdadm --manage /dev/md0 --remove /dev/sdX` |
| Добавление диска | `mdadm --manage /dev/md0 --add /dev/sdX` |
| Остановка массива | `mdadm --stop /dev/md0` |
| Сохранение конфигурации | `mdadm --detail --scan >> /etc/mdadm/mdadm.conf` |
| Очистка метаданных | `mdadm --zero-superblock /dev/sdX` |

## Сравнение: RAID, LVM и обычные разделы

| Характеристика | Обычные разделы | LVM | RAID (mdadm) |
|----------------|-----------------|-----|--------------|
| Объединение дисков | Нет | Да (VG) | Да |
| Изменение размера | Нет (только пересоздание) | Да (on-the-fly) | Да (только увеличение) |
| Отказоустойчивость | Нет | Нет (только через RAID) | Да (RAID 1/5/6/10) |
| Производительность | Базовая | Базовая | + (RAID 0/10) |
| Снапшоты | Нет | Да | Нет |
| Сложность | Низкая | Средняя | Средняя |

> [!tip]
> В реальной практике часто комбинируют LVM поверх RAID: сначала создают RAID массив (отказоустойчивость), затем на нём создают LVM (гибкость управления пространством и снапшоты).

---

## Итог

Программный RAID в Linux — мощное и бесплатное решение для отказоустойчивости и повышения производительности хранения данных.

1. **RAID 1** — для критичных данных (зеркало)
2. **RAID 5/6** — баланс между ёмкостью и надёжностью (min 3/4 диска)
3. **RAID 10** — для высокой производительности и надёжности (4+ диска)
4. Всегда сохраняйте конфигурацию mdadm в `/etc/mdadm/mdadm.conf`
5. Для виртуальных сред RAID обычно не нужен — используйте возможности гипервизора

> [!warning]
> RAID не заменяет резервное копирование! Он защищает от отказа диска, но не от случайного удаления файлов, вирусов или логических ошибок.
