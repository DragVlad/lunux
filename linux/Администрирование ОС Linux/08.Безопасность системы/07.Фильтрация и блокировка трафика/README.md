# Фильтрация трафика

Фильтрация трафика — один из важнейших механизмов защиты сервера, позволяющий контролировать, какой сетевой трафик разрешён к прохождению на сервер или от него, а какой должен быть заблокирован. Для реализации этой задачи существует класс решений, называемых межсетевыми экранами или фаерволами (брандмауэрами).

## Stateful и Stateless фаерволы

Фаерволы делятся на 2 основных вида: stateful (с контролем состояния) и stateless (без контроля состояния).

- **Stateful** — фаервол имеет представление о такой абстракции, как установленное соединение. Обработав согласно своим правилам первый пакет из установленного соединения, остальные он пропускает на основании их принадлежности разрешенному соединению. Это экономит вычислительные ресурсы, система работает быстрее, и её обслуживание выглядит более логично.
  - *Пример:* при запрете всего трафика из интернета, кроме веб-сервера на порту 80/TCP, достаточно одного правила, разрешающего входящий трафик на этот порт. Фаервол сам пропускает ответные пакеты в рамках установленного соединения.

- **Stateless** — обрабатывает каждый пакет независимо. Всё, что не описано явно, работать не будет. Для того же примера нужно два правила: разрешить входящий трафик на порт 80 и разрешить исходящий трафик с порта 80. Количество правил удваивается, каждый пакет проверяется как первый, что на больших объемах трафика может сильно нагружать систему.

## Netfilter

Ядро Linux содержит встроенный сетевой стек и механизм фильтрации трафика, называемый **Netfilter**. Netfilter — это встроенный механизм ядра Linux, предназначенный для фильтрации и управления сетевым трафиком. Он представляет собой набор модулей, которые позволяют проверять, изменять, перенаправлять или блокировать сетевые пакеты. Сам по себе Netfilter не является отдельной программой; это компонент ядра, который управляется через пользовательские утилиты, такие как `iptables`, `nftables`, `firewalld` или `UFW`.

### Обработка пакетов

Когда сетевой пакет попадает в Linux-сервер, он проходит через последовательность этапов обработки внутри ядра. На каждом этапе ядро передаёт пакет Netfilter, который:

1. **Проверяет пакет** на соответствие заданным пользователем правилам.
2. **Принимает решение**, что делать с пакетом:
   - разрешить (ACCEPT),
   - заблокировать (DROP или REJECT),
   - изменить (NAT),
   - записать событие в логи (LOG),
   - перенаправить дальше по цепочке проверок.

Решения принимаются на основе заранее заданных правил фильтрации, которые могут проверять: адреса источника и назначения, номера портов, используемые протоколы (TCP, UDP, ICMP), состояния соединения и другие параметры.

### Таблицы и цепочки

Правила фильтрации группируются в **таблицы (tables)**, которые делятся на логические **цепочки (chains)**.

По умолчанию Netfilter содержит несколько основных таблиц:

- **filter** — таблица для фильтрации пакетов (принять, заблокировать).
- **nat** — таблица для трансляции адресов и портов (NAT).
- **mangle** — изменение заголовков пакетов (для QoS, маркировки).
- **raw** — низкоуровневая таблица для предварительной обработки пакетов.
- **security** — специальные политики безопасности (используется редко, обычно SELinux).

Каждая таблица содержит цепочки, определяющие точку обработки пакета. Основные цепочки:

- **INPUT** — пакеты, идущие на сам сервер.
- **OUTPUT** — пакеты, исходящие с самого сервера.
- **FORWARD** — пакеты, проходящие транзитом через сервер (маршрутизация).
- **PREROUTING** — предварительная обработка пакета (до принятия решения о маршрутизации).
- **POSTROUTING** — окончательная обработка пакета (после решения о маршрутизации).

### Возможности и ограничения Netfilter

**Возможности Netfilter:**

- Блокировка и разрешение сетевых соединений по IP-адресам, портам, протоколам.
- Stateful-фильтрация — различение состояний подключений (новое, установленное, связанное).
- Трансляция адресов и портов (NAT).
- Логирование событий для анализа безопасности.
- Модификация пакетов (маркировка, QoS, изменение заголовков).
- Перенаправление пакетов между интерфейсами и сетями.

**Что Netfilter не умеет (ограничения):**

- Netfilter работает на уровне сетевых пакетов и не может глубоко анализировать содержимое (не поддерживает DPI, Deep Packet Inspection). Для этого требуются специализированные решения (Suricata, Snort, WAF).
- Не может защищать напрямую от сложных атак на уровне приложений (SQL-инъекции, XSS, вредоносный код).
- Netfilter не шифрует и не защищает трафик, а только управляет его прохождением.

## Инструменты управления Netfilter

В Linux существует несколько инструментов для управления Netfilter и создания правил фильтрации трафика:

| Инструмент | Описание |
|------------|----------|
| **iptables** | Классический, исторически основной инструмент управления Netfilter. Работает на уровне отдельных сетевых пакетов. Мощный, гибкий, но сложный в настройке, особенно при большом количестве правил. |
| **nftables** | Современная замена iptables. Более простой, логичный и производительный синтаксис. Поддерживает атомарное обновление правил. Рекомендуется для новых серверов. |
| **firewalld** | Высокоуровневый инструмент, чаще используется в Fedora/CentOS/RHEL. Имеет концепцию зон и сервисов, работает поверх nftables или iptables. |
| **UFW (Uncomplicated Firewall)** | Простая, интуитивно понятная обёртка над iptables/nftables. Используется в Ubuntu по умолчанию. Подходит для простых задач. |

**Краткие рекомендации по выбору:**

- **iptables** — если нужна максимальная совместимость или привычка к классическому подходу.
- **nftables** — для новых серверов, современных систем, сложных правил и высокой производительности.
- **firewalld** — если нужна простая и удобная абстракция для сложных правил.
- **UFW** — для простых и понятных задач без сложных требований.

### Сравнение инструментов

| Инструмент | Преимущества | Недостатки |
|------------|--------------|-------------|
| **iptables** | Широкое распространение, обширная документация | Сложность управления большими наборами правил, отсутствие атомарных изменений |
| **nftables** | Упрощённый и гибкий синтаксис, атомарные изменения, объединение функциональности | Относительная новизна, меньше готовых решений |
| **UFW** | Простота и удобство, быстрая настройка | Ограниченная гибкость для сложных конфигураций |
| **firewalld** | Динамическое управление, зональная модель, поддержка iptables и nftables | Сложность для новичков |

## Синтаксис и примеры использования

### iptables

Основной синтаксис команды:

```bash
iptables [-t таблица] команда [цепочка] [условия] [действие]
```

**Основные таблицы:**

- `filter` — основная таблица для фильтрации пакетов (цепочки: INPUT, FORWARD, OUTPUT)
- `nat` — для трансляции адресов (цепочки: PREROUTING, POSTROUTING, OUTPUT)
- `mangle` — для модификации пакетов

**Основные команды:**

- `-A, --append` — добавить правило в конец цепочки
- `-I, --insert` — вставить правило в указанную позицию
- `-D, --delete` — удалить правило
- `-L, --list` — отобразить правила
- `-F, --flush` — удалить все правила

**Основные параметры условий:**

- `-p, --protocol` — протокол (tcp, udp, icmp)
- `-s, --source` — IP-адрес источника
- `-d, --destination` — IP-адрес назначения
- `-i, --in-interface` — входящий интерфейс
- `-o, --out-interface` — исходящий интерфейс
- `--sport, --source-port` — порт источника
- `--dport, --destination-port` — порт назначения

**Основные действия:**

- `ACCEPT` — разрешить
- `DROP` — отбросить без уведомления
- `REJECT` — отбросить с уведомлением
- `LOG` — зарегистрировать в системном журнале

**Пример добавления правила:**

```bash
iptables -A INPUT -p tcp --dport 22 -j ACCEPT
```

### nftables

Основной синтаксис команды:

```bash
nft [опции] команда [аргументы]
```

**Основные команды:**

- `add table` — создаёт таблицу
- `delete table` — удаляет таблицу
- `list tables` — отображает список таблиц
- `add chain` — создаёт цепочку
- `delete chain` — удаляет цепочку
- `add rule` — добавляет правило
- `delete rule` — удаляет правило
- `list ruleset` — отображает все правила

**Пример создания таблицы, цепочки и добавления правила:**

```bash
# Создаём таблицу 'filter' в семействах протоколов 'inet' (IPv4 и IPv6)
nft add table inet filter

# Создаём цепочку 'input' с типом 'filter', привязкой к hook 'input', приоритетом 0 и политикой 'accept'
nft add chain inet filter input { type filter hook input priority 0 \; policy accept \; }

# Добавляем правило, разрешающее входящие TCP-соединения на порт 22
nft add rule inet filter input tcp dport 22 accept
```

### UFW

Основной синтаксис:

```bash
sudo ufw [команда] [параметры]
```

**Основные команды:**

- `enable` — включить брандмауэр
- `disable` — отключить брандмауэр
- `status` — статус и список правил
- `allow` — разрешить трафик
- `deny` — запретить трафик
- `reject` — отклонить с уведомлением
- `limit` — ограничить количество подключений
- `delete` — удалить правило

**Примеры использования:**

```bash
# Включение брандмауэра
sudo ufw enable

# Разрешение входящих соединений на порт 22 (SSH)
sudo ufw allow 22
sudo ufw allow 22/tcp
sudo ufw allow OpenSSH

# Запрещение входящих соединений на порт 80
sudo ufw deny 80

# Ограничение частоты подключений к SSH
sudo ufw limit ssh

# Удаление правила для порта 80
sudo ufw delete allow 80

# Просмотр статуса и активных правил
sudo ufw status verbose
```

### firewalld

Основной синтаксис:

```bash
sudo firewall-cmd [опции]
```

**Основные опции:**

- `--get-zones` — список доступных зон
- `--get-services` — список предопределённых сервисов
- `--zone=зона` — указание зоны
- `--add-service=сервис` — добавить сервис в зону
- `--remove-service=сервис` — удалить сервис из зоны
- `--add-port=порт/протокол` — добавить порт в зону
- `--remove-port=порт/протокол` — удалить порт из зоны
- `--list-all` — отобразить все настройки зоны
- `--permanent` — сохранить изменения постоянно
- `--reload` — перезагрузить конфигурацию

**Концепция зон firewalld:**

- `drop` — все входящие пакеты отбрасываются
- `block` — входящие соединения отклоняются с сообщением
- `public` — для общественных сетей, минимальное доверие
- `external` — для внешних сетей с включённым NAT
- `dmz` — для демилитаризованной зоны
- `work` — для рабочих сетей
- `home` — для домашних сетей
- `internal` — для внутренних сетей
- `trusted` — все сетевые подключения принимаются

**Примеры использования:**

```bash
# Просмотр активных зон и интерфейсов
sudo firewall-cmd --get-active-zones

# Просмотр настроек текущей зоны
sudo firewall-cmd --list-all

# Установка зоны по умолчанию
sudo firewall-cmd --set-default-zone=home

# Привязка интерфейса к зоне
sudo firewall-cmd --zone=work --change-interface=eth0

# Добавление сервиса в зону (временно)
sudo firewall-cmd --zone=public --add-service=http

# Добавление сервиса в зону (постоянно)
sudo firewall-cmd --zone=public --permanent --add-service=http
sudo firewall-cmd --reload

# Добавление порта в зону
sudo firewall-cmd --zone=public --add-port=8080/tcp

# Удаление сервиса из зоны
sudo firewall-cmd --zone=public --remove-service=http
```

## Типовые кейсы управления трафиком

### Блокировка всего входящего трафика

| Инструмент | Команды |
|------------|---------|
| iptables | `sudo iptables -P INPUT DROP`<br>`sudo iptables -P FORWARD DROP`<br>`sudo iptables -P OUTPUT ACCEPT` |
| nftables | `sudo nft add table inet filter`<br>`sudo nft add chain inet filter input { type filter hook input priority 0 \; policy drop \; }`<br>`sudo nft add chain inet filter forward { type filter hook forward priority 0 \; policy drop \; }`<br>`sudo nft add chain inet filter output { type filter hook output priority 0 \; policy accept \; }` |
| UFW | `sudo ufw default deny incoming`<br>`sudo ufw default allow outgoing`<br>`sudo ufw enable` |
| firewalld | `sudo firewall-cmd --set-default-zone=drop`<br>`sudo firewall-cmd --reload` |

### Разрешение только SSH (порт 22)

| Инструмент | Команда |
|------------|---------|
| iptables | `sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT` |
| nftables | `sudo nft add rule inet filter input tcp dport 22 accept` |
| UFW | `sudo ufw allow ssh` |
| firewalld | `sudo firewall-cmd --zone=public --add-service=ssh --permanent`<br>`sudo firewall-cmd --reload` |

### Разрешение только веб-сервера (HTTP и HTTPS)

| Инструмент | Команды |
|------------|---------|
| iptables | `sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT`<br>`sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT` |
| nftables | `sudo nft add rule inet filter input tcp dport { 80, 443 } accept` |
| UFW | `sudo ufw allow http`<br>`sudo ufw allow https` |
| firewalld | `sudo firewall-cmd --zone=public --add-service=http --permanent`<br>`sudo firewall-cmd --zone=public --add-service=https --permanent`<br>`sudo firewall-cmd --reload` |

## Специфические и неочевидные случаи настройки

### Использование наборов (sets) в nftables

**Пример 1: Создание именованного набора IP-адресов**

```bash
# Создаём таблицу 'filter' в семействах протоколов 'inet'
sudo nft add table inet filter

# Создаём именованный набор 'blackhole' для хранения IPv4-адресов
sudo nft add set inet filter blackhole { type ipv4_addr\; comment "drop all packets from these hosts" \; }

# Добавляем IP-адреса в набор 'blackhole'
sudo nft add element inet filter blackhole { 192.168.1.100, 192.168.1.101 }

# Создаём цепочку 'input' с политикой 'accept'
sudo nft add chain inet filter input { type filter hook input priority 0 \; policy accept \; }

# Добавляем правило, блокирующее пакеты от IP-адресов из набора 'blackhole'
sudo nft add rule inet filter input ip saddr @blackhole drop
```

**Пример 2: Использование анонимных наборов для разрешения трафика на определённые порты**

```bash
sudo nft add rule inet filter input tcp dport { 22, 80, 443 } accept
```

### Использование богатых правил (Rich Rules) в firewalld

**Пример 1: Разрешение SSH-доступа только с определённого IP-адреса**

```bash
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.1.10" service name="ssh" accept'
sudo firewall-cmd --reload
```

**Пример 2: Блокировка ICMP (ping) запросов с логированием**

```bash
sudo firewall-cmd --permanent --add-rich-rule='rule protocol value="icmp" log prefix="ICMP drop: " level="info" drop'
sudo firewall-cmd --reload
```

**Пример 3: Использование IP-наборов (IP sets) для управления группами адресов**

```bash
# Создаём IP-набор 'trusted' с типом 'hash:net'
sudo firewall-cmd --permanent --new-ipset=trusted --type=hash:net

# Добавляем IP-адреса в набор 'trusted'
sudo firewall-cmd --permanent --ipset=trusted --add-entry=192.168.1.0/24
sudo firewall-cmd --permanent --ipset=trusted --add-entry=10.0.0.0/8

# Разрешаем доступ к HTTP и HTTPS для IP-адресов из набора 'trusted'
sudo firewall-cmd --permanent --add-rich-rule='rule source ipset=trusted service name="http" accept'
sudo firewall-cmd --permanent --add-rich-rule='rule source ipset=trusted service name="https" accept'

# Перезагружаем firewalld для применения изменений
sudo firewall-cmd --reload
```

### Ограничение скорости (Rate Limiting)

**iptables: Ограничение количества SSH-подключений**

```bash
sudo iptables -A INPUT -p tcp --dport 22 -m state --state NEW -m recent --set
sudo iptables -A INPUT -p tcp --dport 22 -m state --state NEW -m recent --update --seconds 60 --hitcount 4 -j DROP
```

**nftables: Ограничение количества SSH-подключений**

```bash
# Создаём таблицу 'filter' и цепочку 'input'
sudo nft add table inet filter
sudo nft add chain inet filter input { type filter hook input priority 0 \; policy accept \; }

# Добавляем правило, ограничивающее количество новых SSH-соединений
sudo nft add rule inet filter input tcp dport 22 ct state new limit rate 3/minute accept
sudo nft add rule inet filter input tcp dport 22 drop
```

### Логирование отброшенных пакетов в iptables

```bash
sudo iptables -A INPUT -s 192.168.1.100 -j LOG --log-prefix "Dropped packet: "
sudo iptables -A INPUT -s 192.168.1.100 -j DROP
```

## Fail2Ban

**Fail2Ban** — это инструмент с открытым исходным кодом, который автоматически блокирует IP-адреса, проявляющие подозрительную активность (например, множественные попытки подбора паролей). Он анализирует логи сервисов и применяет правила для временной или постоянной блокировки.

**Для чего используется:**

- Защита от брутфорс-атак на SSH, FTP, веб-серверы.
- Блокировка сканеров портов и спам-ботов.
- Снижение нагрузки на сервер за счёт отсеивания вредоносного трафика.

**Принципы работы:**

1. Мониторинг логов (например, `/var/log/auth.log` для SSH).
2. Фильтрация через регулярные выражения — поиск шаблонов неудачных попыток входа.
3. Триггер действия — при превышении лимита попыток IP добавляется в черный список.
4. Блокировка через фаерволл (iptables, ufw, nftables).

**Ключевые сущности:**

- **Jail (тюрьма)** — конфигурационный файл, определяющий правила для сервиса.
- **Filter (фильтр)** — регулярные выражения для поиска атак в логах.
- **Action (действие)** — команды, выполняемые при обнаружении атаки.

### Установка и настройка Fail2Ban

```bash
sudo apt update
sudo apt install fail2ban
sudo systemctl start fail2ban
sudo systemctl enable fail2ban   # автозапуск при загрузке
sudo systemctl status fail2ban   # должен быть "active (running)"
```

**Базовая настройка для защиты SSH:**

Не редактируется `/etc/fail2ban/jail.conf` напрямую. Создаётся свой файл:

```bash
sudo nano /etc/fail2ban/jail.d/custom.conf
```

Секция [sshd] с параметрами:

```ini
[DEFAULT]
bantime = 600          # 10 минут
findtime = 300         # 5 минут
maxretry = 3           # 3 попытки

[sshd]
enabled = true
```

**Пояснение параметров:**

- `maxretry` — количество попыток до блокировки.
- `findtime` — время, за которое считаются попытки.
- `bantime` — длительность блокировки (можно установить -1 для перманентного бана).

**Перезагрузка Fail2Ban:**

```bash
sudo systemctl restart fail2ban
```

### Проверка работы Fail2Ban

Просмотр активных блокировок:

```bash
sudo fail2ban-client status sshd
```

Пример вывода:

```text
Status for the jail: sshd
|- Filter
|  |- Currently failed: 1
|  |- Total failed: 3
|- Actions
   |- Currently banned: 1
   |- Total banned: 1
```

Просмотр правил iptables (цепочка `f2b-sshd`):

```bash
sudo iptables -L -n
```

### Разбан IP-адреса

```bash
sudo fail2ban-client set sshd unbanip <IP-адрес>
# например
sudo fail2ban-client set sshd unbanip 192.168.1.100
```

**Полезные команды:**

- `fail2ban-client status` — список активных jail
- `fail2ban-client status sshd` — статус конкретного jail
- `fail2ban-client set sshd banip <IP>` — заблокировать IP вручную
- `fail2ban-client set sshd unbanip <IP>` — разблокировать IP
- `fail2ban-client reload` — перезагрузить конфигурацию

Больше примеров: [https://github.com/fail2ban/fail2ban/blob/master/config/jail.conf](https://github.com/fail2ban/fail2ban/blob/master/config/jail.conf)

## Современные альтернативы Fail2Ban: CrowdSec

CrowdSec — современная и расширенная альтернатива fail2ban.

**Сходства:**

- Оба инструмента анализируют логи, выявляют подозрительное поведение и блокируют IP-адреса.
- Оба просты в интеграции с различными сервисами (SSH, веб-серверы, базы данных).

**Преимущества CrowdSec:**

- **Краудсорсинг данных** — глобальная база атакующих IP-адресов со всех подключенных инстансов.
- **Современная архитектура** — разделение на движок анализа логов и механизм реагирования.
- **Репутация IP** — учёт репутации IP на основании данных сообщества.

**Преимущества Fail2Ban:**

- Проверен временем, огромное количество доступных правил и сценариев.
- Простота настройки и поддержки, особенно для простых сценариев защиты.

**Рекомендации по выбору:**

- **CrowdSec** — когда нужна защита не только на основе собственных логов, но и от атакующих IP, уже замеченных другими пользователями.
- **Fail2Ban** — для простых, стабильных сценариев, когда не нужны функции краудсорсинга.

## NGFW (Next-Generation Firewall) и WAF (Web Application Firewall)

Традиционные межсетевые экраны обеспечивают безопасность на сетевом и транспортном уровнях (3 и 4 уровни модели OSI). Однако рост сложности атак, направленных на уязвимости прикладного уровня, сделал такие решения недостаточными.

### NGFW (Next-Generation Firewall)

NGFW — следующее поколение межсетевых экранов с глубоким анализом пакетов (DPI), интегрированной системой предотвращения вторжений (IPS), антивирусной защитой, контролем приложений и мониторингом активности пользователей.

**Популярные решения NGFW:**

| Решение | Тип | Описание |
|---------|-----|----------|
| **pfSense** | open-source | Мощный файрвол. Без дополнительных пакетов не является полноценным NGFW. |
| **pfSense Plus** | коммерческий | Полноценный NGFW с глубоким анализом трафика и контролем приложений. |
| **OPNsense + Zenarmor** | open-source | Форк pfSense. После установки плагина Zenarmor становится полноценным NGFW. |
| **Palo Alto Networks NGFW** | коммерческий | Ведущий коммерческий NGFW с глубоким анализом пакетов, интеграцией с облачными сервисами. |
| **Fortinet FortiGate** | коммерческий | Интегрированные функции файрвола, IPS, веб-фильтрации и антивирусной защиты. |

### WAF (Web Application Firewall)

WAF — специализированный файрвол для защиты веб-приложений от атак: SQL-инъекции, межсайтовый скриптинг (XSS), подделка межсайтовых запросов (CSRF) и других угроз уровня приложений. WAF анализирует трафик на уровне HTTP-запросов и ответов.

**Популярные решения WAF:**

| Решение | Тип | Описание |
|---------|-----|----------|
| **ModSecurity** | open-source | Работает с Apache, Nginx, IIS. Использует правила OWASP CRS. Требует тщательной настройки. |
| **NAXSI** | open-source | Легковесный модуль WAF для Nginx. Низкое потребление ресурсов. Прост в настройке. |
| **Cloudflare WAF** | коммерческий, облачный | Интегрирован с CDN. Прост в развёртывании. Эффективная защита от DDoS и атак уровня приложений. |

**Резюме:** Использование NGFW и WAF существенно повышает уровень безопасности инфраструктуры и приложений. Выбор конкретного решения зависит от требований бизнеса, масштаба инфраструктуры и бюджета. Сочетание различных инструментов позволяет построить комплексную защиту от большинства современных угроз.
