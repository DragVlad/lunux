## 1. Модель AAA
Ключевая концепция управления доступом:

- **Идентификация** — кто вы (логин, ID).
- **Аутентификация** — подтверждение личности (пароль, ключ).
- **Авторизация** — что вам можно делать (права доступа).
- *Учёт (Accounting)* — логирование действий (опционально).

> **Пример в Linux:**  
> 1. Вход через SSH → идентификация (логин).  
> 2. Проверка пароля/ключа → аутентификация.  
> 3. Проверка `sudo` → авторизация.  
> 4. Логирование `sudo` → учёт действий.

## 2. Источники идентификации

| Тип | Описание |
|-----|----------|
| **Локальная БД** | Файлы `/etc/passwd`, `/etc/shadow` (для автономных серверов). |
| **LDAP** | Централизованное управление пользователями и группами. |
| **Active Directory (AD)** | Интеграция через SSSD, `winbind`, `realmd` (Kerberos). |
| **RADIUS / TACACS+** | Для сетевого оборудования, VPN, Wi-Fi. |
| **SSO (OIDC/SAML)** | Google, Azure AD, Okta. |
| **PAM-модули** | Кастомные схемы (2FA, FIDO2, OTP). |

## 3. Парольная политика (актуальные требования 2025)

- **Длина:** минимум 14 символов, лучше **≥16**.
- **Сложность:** верх/нижний регистр, цифры, спецсимволы. Запрет простых последовательностей.
- **Проверка утечек:** `haveged`, `hibp-pwned`, `pam_pwquality`.
- **Запрет повтора:** минимум 5–10 предыдущих паролей.
- **Срок действия:**
  - Обычные пользователи: 3–6 мес (без MFA).
  - Привилегированные (root): 45–90 дней.
  - При наличии MFA: до 6–12 мес.
- **Защита от перебора (brute-force):** `pam_tally2`, `fail2ban` (например, блокировка после 5 попыток на 15 мин).
- **Использование фраз-паролей** (20+ символов) вместо коротких сложных.
- **Многофакторность (2FA/MFA)** — обязательно для критических учёток.
- **Для сервисных аккаунтов:** SSH-ключи, API-токены, Kerberos (не пароли).

## 4. Многофакторная аутентификация (2FA/MFA)

### Настройка Google Authenticator для SSH

**Установка:**
```bash
sudo apt install -y libpam-google-authenticator
```

**Генерация TOTP для пользователя:**
```bash
google-authenticator
```
*(отсканируйте QR-код приложением, ответьте `y` на вопросы)*

**Настройка SSH (`/etc/ssh/sshd_config`):**
```yaml
UsePAM yes
KbdInteractiveAuthentication yes
PasswordAuthentication yes   # если нужен пароль + OTP
```

**Настройка PAM (`/etc/pam.d/sshd`):**
После строки `@include common-auth` добавьте:
```python
# two-factor authentication via Google Authenticator
auth   required   pam_google_authenticator.so
```

**Перезапуск SSH:**
```bash
sudo systemctl restart ssh
```

**Для совместной работы с SSH-ключами** (в `/etc/ssh/sshd_config`):
```
AuthenticationMethods publickey,keyboard-interactive
PasswordAuthentication no
```
А в `/etc/pam.d/sshd` закомментируйте `@include common-auth` (иначе получится 3 фактора: ключ+пароль+OTP).

### Корпоративные решения 2FA

| Решение | Тип | Применение |
|---------|-----|-------------|
| YubiKey | Аппаратный (FIDO2/U2F) | SSH, VPN, веб, passwordless |
| Duo Security | Централизованное | SSH, VPN, RDP |
| FreeIPA + OTP | LDAP/AD интеграция | Крупные Linux-среды |
| Okta / Azure AD MFA | Облачные | Корпоративный доступ |

## 5. Контроль сессий пользователей

### Просмотр активных сессий

| Команда | Что показывает |
|---------|----------------|
| `who` | Кто, с какого IP, время входа |
| `w` | Дополнительно: запущенные процессы, IDLE |
| `last` | История входов и перезагрузок |
| `ps aux \| grep sshd` | Все активные SSH-процессы |

### Принудительное завершение сессии

```bash
# Завершить все процессы пользователя
pkill -KILL -u user1

# Завершить конкретную сессию по терминалу
who                  # найти pts/N
pkill -KILL -t pts/1
```

### Ограничение количества сессий

В `/etc/security/limits.conf`:
```bash
# Для конкретного пользователя — не более 1 сессии
user1   hard   maxlogins   1

# Для всех, кроме root — не более 2 сессий
*       hard   maxlogins   2
```

### Логирование всех команд пользователей

Добавить в `/etc/profile`:
```bash
export HISTCONTROL=ignoredups:erasedups
export HISTSIZE=10000
export HISTFILESIZE=20000
export HISTTIMEFORMAT="%Y-%m-%d %H:%M:%S "
shopt -s histappend
PROMPT_COMMAND="history -a; history -n; $PROMPT_COMMAND"
```

**Защита истории от удаления:**
```bash
sudo chattr +a /home/*/.bash_history
```
(теперь файл только для добавления и чтения)

> **Кратко по диагностике:**  
> - Не могу залогиниться → проблема в идентификации или аутентификации (логин/пароль/ключ).  
> - Залогинился, но не хватает прав → проблема в авторизации (группы, `sudo`).
