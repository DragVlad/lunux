## 1. Дискреционная модель доступа (DAC)

Дискреционная модель доступа (DAC) позволяет владельцам файлов и ресурсов самостоятельно управлять доступом к ним. Владелец ресурса может определять, кто из пользователей и групп имеет права на чтение, запись или выполнение его файла или директории.

### Основы теории

- **Объекты** — это ресурсы системы (файлы, директории, устройства)
- **Субъекты** — пользователи или процессы, выполняющие действия над объектами
- **Права** — определяют, какие действия (чтение, запись, выполнение) могут быть выполнены

*Классическая матрица доступа* представляет собой таблицу, где строки — субъекты, столбцы — объекты, а ячейки содержат права доступа.

### Реализация в Linux

В Linux реализована дискреционная модель через права для трёх категорий:
- **Владелец** (user)
- **Группа** (group)
- **Остальные** (others)

#### Просмотр прав доступа
```bash
ls -l example.txt
```

#### Пример вывода
```bash
-rw-r--r-- 1 alice developers 4096 Aug 16 10:00 example.txt
```

Расшифровка:
- `rw-` — владелец (чтение и запись)
- `r--` — группа (только чтение)
- `r--` — остальные (только чтение)

### Числовое представление прав

Таблица соответствия:
- `4` — чтение (r)
- `2` — запись (w)
- `1` — выполнение (x)

#### Пример установки прав 755
```bash
sudo chmod 755 example.txt
```

Что означает 755:
- **Владелец**: 7 (4+2+1) — чтение, запись, выполнение
- **Группа**: 5 (4+0+1) — чтение, выполнение
- **Остальные**: 5 (4+0+1) — чтение, выполнение

### Специальные права доступа

#### SUID (Set User ID)
Программа запускается с правами владельца файла, а не пользователя, который её запустил.

```bash
sudo chmod u+s /usr/bin/someprogram
```

#### SGID (Set Group ID)
Если установлен на директории, все созданные в ней файлы будут принадлежать группе этой директории.

```bash
sudo chmod g+s /some/directory
```

#### Sticky Bit
Разрешает удаление файлов только их владельцам, даже при общих правах на запись.

```bash
sudo chmod +t /some/directory
```

## 2. Posix ACL (Access Control Lists)

### Зачем нужны ACL

Классическая модель (владелец, группа, остальные) недостаточно гибка. Пример: нужно предоставить доступ к файлу пользователям alice и bob, которые состоят в разных группах.

**Решение**: Posix ACL позволяет назначать права конкретным пользователям и группам без создания дополнительных групп.

### Установка ACL в Ubuntu

```bash
sudo apt-get install acl
```

### Примеры использования ACL

#### Просмотр текущих ACL
```bash
getfacl example.txt
```

#### Добавление прав для конкретного пользователя
```bash
sudo setfacl -m u:bob:rw example.txt
```

#### Удаление ACL для пользователя
```bash
sudo setfacl -x u:bob example.txt
```

## 3. Мандатный контроль доступа (MAC)

### Основы MAC

> **MAC** — модель безопасности, при которой правила доступа устанавливаются централизованно и не могут быть изменены пользователями.

**Зачем нужно**: для систем с высокими требованиями к безопасности (военные, государственные системы), где даже администраторы не могут изменить правила доступа.

### Принципы работы

1. **Классификация данных** — каждому объекту присваивается уровень конфиденциальности
2. **Классификация субъектов** — каждому пользователю/процессу присваивается уровень допуска
3. **Разграничение доступа** — доступ определяется сравнением уровней

### SELinux и AppArmor

#### SELinux
Строгие политики безопасности, определяющие действия процессов над объектами.

```bash
sudo setenforce 1  # Включение
sudo setenforce 0  # Отключение
```

#### AppArmor
Использует профили, определяющие разрешённые операции для программ.

```bash
sudo aa-enforce /etc/apparmor.d/usr.bin.someprogram
```

### Преимущества и недостатки MAC

| Преимущества | Недостатки |
|--------------|------------|
| Высокий уровень безопасности | Сложность настройки |
| Централизованное управление | Возможные конфликты с легитимными операциями |

## 4. Управление привилегиями с sudo

### Как работает sudo

`sudo` позволяет выполнять команды от имени другого пользователя (обычно root) без входа в его учётную запись.

**Принцип**:
1. Система проверяет разрешение пользователя на выполнение команды
2. При успехе команда выполняется от имени указанного пользователя
3. Все действия журналируются

### Настройка sudo (файл /etc/sudoers)

**Важно**: редактировать файл только через `visudo`!

```bash
sudo visudo
```

#### Примеры конфигурации

Предоставление пользователю alice прав на выполнение всех команд:
```bash
alice ALL=(ALL) ALL
```

Ограничение привилегий (только перезагрузка):
```bash
bob ALL=(ALL) /sbin/reboot
```

Разрешить пользователю dave только shutdown:
```bash
dave ALL=(ALL) /sbin/shutdown
```

### Логирование действий sudo

Просмотр логов:
```bash
cat /var/log/auth.log | grep sudo
```

Настройка подробного логирования (в /etc/sudoers):
```bash
Defaults logfile="/var/log/sudo.log"
```

### Политика минимизации привилегий

Предоставляйте пользователям только те права, которые необходимы для выполнения их задач.

## 5. PAM (Pluggable Authentication Modules)

### Что такое PAM

> **PAM** — гибкая система настройки аутентификации, авторизации и учёта доступа в Linux.

### Основные конфигурационные файлы PAM

- `/etc/pam.d/common-auth` — настройки аутентификации
- `/etc/pam.d/common-password` — настройки паролей
- `/etc/pam.d/common-session` — настройки сессий

### Примеры настройки PAM

#### Политики сложности паролей

В файл `/etc/pam.d/common-password`:
```bash
password requisite pam_pwquality.so retry=3 minlen=12 dcredit=-1 ucredit=-1 ocredit=-1 lcredit=-1
```

Что означает:
- `minlen=12` — минимальная длина 12 символов
- `dcredit=-1` — минимум 1 цифра
- `ucredit=-1` — минимум 1 заглавная буква
- `lcredit=-1` — минимум 1 строчная буква

#### Блокировка после неудачных попыток

В файл `/etc/pam.d/common-auth`:
```bash
auth required pam_tally2.so deny=5 unlock_time=300
```
Блокировка после 5 неудачных попыток на 5 минут (300 секунд).

### Интеграция с LDAP и Active Directory

#### Настройка LDAP
```bash
sudo apt-get install libpam-ldapd
```
Затем настройте `/etc/nslcd.conf` и `/etc/pam.d/common-auth`.

#### Настройка Active Directory
```bash
sudo apt-get install realmd sssd krb5-user
sudo realm join yourdomain.com -U Administrator
```

## 6. Журналирование и аудит безопасности

### Системные логи

Важные логи находятся в `/var/log`:
```bash
cat /var/log/auth.log
```

### Auditd — система аудита

Установка и запуск:
```bash
sudo apt-get install auditd
sudo systemctl start auditd
```

#### Пример настройки правила аудита

Отслеживание изменений файла `/etc/passwd`:
```bash
sudo auditctl -w /etc/passwd -p wa -k passwd_changes
```

## 7. Контроль доступа к устройствам

### Доступ через /dev

Доступ к устройствам управляется через специальные файлы в директории `/dev`.

### Использование udev

`udev` — подсистема управления динамическими устройствами. Позволяет автоматически настраивать права доступа при подключении устройств.

## Итоговая таблица: Модели доступа

| Модель | Управление | Гибкость | Сложность | Применение |
|--------|------------|----------|-----------|------------|
| **DAC** | Владелец ресурса | Средняя | Низкая | Общее назначение |
| **ACL** | Владелец + расширенные правила | Высокая | Средняя | Сложные сценарии прав |
| **MAC** | Централизованное | Низкая | Высокая | Высокозащищённые системы |
| **sudo** | Централизованное (root) | Высокая | Средняя | Делегирование привилегий |

## Полезные команды (шпаргалка)

```bash
# Права доступа
ls -l <файл>                    # Просмотр прав
chmod 755 <файл>                # Установка прав числом
chmod u+x <файл>                # Добавить выполнение владельцу

# ACL
getfacl <файл>                  # Просмотр ACL
setfacl -m u:пользователь:rw <файл>   # Добавить ACL

# SELinux
getenforce                      # Проверить статус
setenforce 1/0                  # Вкл/Выкл

# sudo
sudo visudo                     # Редактирование sudoers
sudo -l                         # Список доступных команд

# PAM
# Файлы конфигурации в /etc/pam.d/

# Аудит
sudo auditctl -l                # Список правил аудита
sudo ausearch -k <ключ>         # Поиск по ключу
```
