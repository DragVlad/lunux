# Введение в файловую систему Linux

## Определение файловой системы

> **Файловая система** — это метод и структура, которые операционная система использует для организации, хранения и управления данными на дисковых устройствах (жестких дисках, SSD, флеш-накопителях). Это механизм, обеспечивающий упорядочение и контроль над тем, как данные читаются и записываются.

Поддержка различных файловых систем и гибкость в их использовании делает Linux мощным инструментом для администрирования и работы с данными.

---

## Общие принципы работы файловых систем

### Блочная структура

Диск делится на **блочную структуру** для эффективного управления хранением и доступом к данным.

| Термин | Описание |
|--------|----------|
| **Блок** | Минимальная единица хранения (обычно 4 KB / 4096 байт) |
| **Суперблок** | Хранит информацию о ФС: размер блоков, количество блоков, свободное место и т.д. |
| **Группы блоков** | Диск делится на группы для минимизации фрагментации и ускорения доступа |

> [!warning]
> Суперблок — критически важная часть файловой системы. Его повреждение может привести к потере доступа к данным.

### Inodes (индексные дескрипторы)

**Inode** — структура данных, хранящая информацию о файле (кроме имени и содержимого):

- Владелец файла
- Права доступа
- Время создания и модификации
- **Указатели на блоки данных** (прямые и косвенные)

> [!note]
> Каждый файл или каталог имеет уникальный inode. Inode не содержат сами данные, но указывают на блоки, где данные хранятся.

#### Экстенты (Extents)

**Extent** — непрерывный блок данных на диске. Вместо множества указателей на отдельные блоки, inode хранит диапазон блоков.

| Без экстентов | С экстентами |
|---------------|--------------|
| Указатели на блоки 1,2,3,4,5,6 | Один экстент: начальный блок 1, длина 6 |
| Много указателей для больших файлов | Эффективно, компактно |

### Директории

Директории — это **специальные файлы**, содержащие списки имён файлов и соответствующих им inode.

```
Поиск файла: имя файла → директория → inode → блоки данных
```

## Дополнительные возможности файловых систем

### Журналирование

Изменения сначала записываются в **журнал**, затем применяются к основным блокам. Защищает от повреждения данных при сбоях.

### Кеширование

**Page Cache** — кеш в оперативной памяти для часто используемых данных. Значительно ускоряет доступ.

### Сжатие и дедупликация

| Механизм | Описание | Пример (Btrfs) |
|----------|----------|----------------|
| **Сжатие** | Уменьшение размера файлов на диске | zlib, lzo, zstd |
| **Дедупликация** | Устранение избыточных копий данных | `duperemove`, `bedup` |

> Дедупликация устраняет избыточные копии одинаковых данных. Один набор данных хранится один раз, остальные — ссылки.

### Контроль целостности данных

Современные ФС (ZFS, Btrfs) используют **контрольные суммы** для каждого блока данных. При ошибке система может восстановить данные из зеркальной копии или RAID.

## Иерархия файловой системы (FHS)

**Корневая директория** `/` — вершина иерархической файловой структуры. Все файлы и каталоги ведут путь от корня.

> FHS (Filesystem Hierarchy Standard) — стандарт, определяющий структуру каталогов в Unix-подобных ОС. Текущая версия — 3.0 (2015). Для справки: `man hier`.

### Основные каталоги Linux

| Каталог | Назначение |
|---------|------------|
| `/bin` | Основные бинарные файлы (ls, cp, mv) |
| `/boot` | Файлы загрузки (ядро, GRUB) |
| `/dev` | Файлы устройств (диски, терминалы) |
| `/etc` | Конфигурационные файлы системы |
| `/home` | Домашние каталоги пользователей |
| `/lib` | Библиотеки для `/bin` и `/sbin` |
| `/media`, `/mnt` | Точки монтирования внешних носителей |
| `/opt` | Дополнительное ПО |
| `/root` | Домашний каталог root |
| `/sbin` | Системные бинарные файлы (reboot, fdisk) |
| `/srv` | Данные служб (веб-серверы, FTP) |
| `/tmp` | Временные файлы |
| `/usr` | Пользовательские программы и утилиты |
| `/var` | Переменные данные (логи, почта) |

## Типы файлов в Linux

| Тип | Символ `ls -l` | Описание | Пример |
|-----|---------------|----------|--------|
| **Обычный файл** | `-` | Хранение данных | `file.txt`, `image.jpg` |
| **Каталог** | `d` | Организация файловой структуры | `/home`, `/etc` |
| **Символическая ссылка** | `l` | Указывает на другой файл/каталог | `ln -s original link` |
| **Жесткая ссылка** | `-` (счётчик >1) | Ссылка на тот же inode | `ln original hardlink` |
| **Блочное устройство** | `b` | Поблочное чтение/запись | `/dev/sda` |
| **Символьное устройство** | `c` | Побайтовое чтение/запись | `/dev/tty`, `/dev/null` |
| **FIFO (именованный канал)** | `p` | Межпроцессный обмен (очередь) | `mkfifo my_fifo` |
| **Сокет** | `s` | Двунаправленный обмен данными | `/var/run/docker.sock` |

### Особенности жёстких ссылок

- Указывают на один и тот же **inode**
- Удаление оригинала не удаляет данные, пока есть другие ссылки
- Все ссылки равноправны
- Можно создавать **только в пределах одной файловой системы**

```bash
# Создание жёсткой ссылки
ln /path/to/original /path/to/hardlink
```

### Создание символической ссылки

```bash
# Создание символической ссылки
ln -s /path/to/original /path/to/link
```

## Итог

Файловая система Linux — сложный, но хорошо структурированный механизм:

1. **Блочная структура + inodes** — основа хранения данных
2. **FHS** — стандарт иерархии для единообразия во всех дистрибутивах
3. **Восемь типов файлов** — от обычных до сокетов и устройств
4. **Дополнительные возможности** — журналирование, кеширование, сжатие, контроль целостности

> [!tip]
> Команда `ls -l` позволяет определить тип файла по первому символу прав доступа. Команда `man hier` покажет документацию по иерархии файловой системы.
