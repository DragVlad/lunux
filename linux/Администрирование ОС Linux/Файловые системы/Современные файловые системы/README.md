# Современные файловые системы Linux

## EXT4 — стандартная файловая система Linux

**ext4** (Fourth Extended Filesystem) — одна из самых популярных файловых систем в Linux. Является преемником ext3 и была официально включена в ядро Linux версии 2.6.28 в декабре 2008 года.

### Ключевые особенности

| Особенность | Описание |
|-------------|----------|
| **Журналирование** | Отслеживает изменения, уменьшая риск повреждения данных при сбоях |
| **Поддержка больших файлов** | Файлы до 16 ТБ, тома до 1 ЭБ (на практике до 16 ТБ) |
| **Экстенты (Extents)** | Непрерывные блоки данных вместо отдельных указателей |
| **Отложенное выделение** | Оптимизирует расположение данных и уменьшает фрагментацию |
| **Совместимость** | Полная совместимость с ext3/ext2, лёгкое обновление без потери данных |
| **Временные метки** | Точность до наносекунд |

### Преимущества и недостатки

| ✅ Преимущества | ⚠️ Недостатки |
|----------------|----------------|
| Высокая производительность | Ограниченная поддержка RAID (требует ручной настройки выравнивания) |
| Надёжность (журналирование) | Нет встроенной дедупликации и сжатия |
| Широкая поддержка во всех дистрибутивах | Базовые механизмы контроля целостности |
| Простота и стабильность | |

### Типовые случаи использования

- **Рабочие станции** — стандартная ФС для Ubuntu, Debian и др.
- **Серверы и базы данных** — надёжность и производительность
- **Встраиваемые системы** — низкие накладные расходы
- **Системы с ограниченными ресурсами**

## XFS — для больших данных и высокой производительности

**XFS** — высокопроизводительная 64-разрядная журналируемая ФС, изначально разработанная SGI для IRIX. В 2001 году портирована на Linux. С 2014 года — ФС по умолчанию в RHEL 7 и CentOS 7.

### Ключевые особенности

| Особенность | Описание |
|-------------|----------|
| **Журналирование** | Оптимизировано для многопроцессорных систем |
| **Большие файлы** | Файлы до 8 ЭБ, тома до 8 ЭБ |
| **Allocation Groups (AG)** | Разделение на группы для масштабирования на многопроцессорных системах |
| **Дефрагментация на лету** | Поддержка дефрагментации без размонтирования |
| **Гибкое квотирование** | Ограничения на уровне пользователей, групп и ролей |

### Преимущества и недостатки

| ✅ Преимущества | ⚠️ Недостатки |
|----------------|----------------|
| Высокая производительность с большими файлами | **Не поддерживает уменьшение размера тома** |
| Отличная масштабируемость на многопроцессорных системах | Нет встроенного сжатия и дедупликации |
| Надёжность и дефрагментация на лету | Восстановление данных сложнее, чем на ext4 |
| Поддержка очень больших томов | |

### Типовые случаи использования

- **Серверы баз данных** — высокая производительность ввода-вывода
- **Системы хранения данных (NAS/SAN)** — масштабируемость
- **Видеомонтаж и мультимедиа** — работа с большими файлами
- **Научные вычисления и суперкомпьютеры** — большие массивы данных

> [!warning]
> XFS **нельзя уменьшить** в размере. Если вы планируете изменять размер ФС, это важное ограничение.

## Btrfs — следующее поколение с продвинутыми функциями

**Btrfs** (B-Tree File System) — современная ФС, разработка которой началась в Oracle в 2007 году. Включена в ядро Linux с версии 2.6.29 (2009). Используется как основная в openSUSE и Fedora.

### Ключевые особенности

| Особенность | Описание |
|-------------|----------|
| **Copy-on-Write (CoW)** | Данные не перезаписываются, а копируются в новое место |
| **Снимки (Snapshots)** | Мгновенные копии данных, занимающие минимум места |
| **Субтомы (Subvolumes)** | Независимые части ФС для отдельного управления |
| **Сжатие данных** | Алгоритмы zlib, lzo, zstd |
| **Дедупликация** | Устранение дублирующихся блоков данных |
| **Встроенный RAID** | RAID 0, 1, 10, 5, 6 с динамическим управлением |
| **Контроль целостности** | Контрольные суммы для данных и метаданных |

### Преимущества и недостатки

| ✅ Преимущества | ⚠️ Недостатки |
|----------------|----------------|
| Мощные функции управления данными | **RAID 5/6 могут быть нестабильны** |
| Высокая защита данных (CoW + контрольные суммы) | Низкая производительность в некоторых сценариях (БД) |
| Гибкость в управлении томами и RAID | Сложность настройки для новичков |
| Динамическое управление пространством | |

### Типовые случаи использования

- **Рабочие станции** — снимки и сжатие для резервного копирования
- **Файловые серверы и NAS** — управление большими объёмами данных
- **Системы резервного копирования** — инкрементальные копии
- **Виртуализация и контейнеры** — клонирование и снимки

> [!note]
> Btrfs активно развивается, но некоторые функции (особенно RAID 5/6) всё ещё считаются экспериментальными.

## ZFS — надёжность и защита данных (OpenZFS)

**ZFS** (Zettabyte File System) — продвинутая ФС с управлением томами, разработанная Sun Microsystems. Включена в Solaris в 2005 году. В Linux доступна через **OpenZFS**.

### Ключевые особенности

| Особенность | Описание |
|-------------|----------|
| **Copy-on-Write (CoW)** | Целостность данных и простота снимков |
| **Пул хранения** | Объединение устройств в пулы с динамическим выделением |
| **Снимки и клонирование** | Мгновенные копии для резервного копирования |
| **Сжатие данных** | LZ4, gzip и другие алгоритмы |
| **Дедупликация** | Удаление дублирующихся блоков |
| **RAID-Z (Z1/Z2/Z3)** | Устранение проблемы «дыры RAID» |
| **Контрольные суммы** | Для всех данных и метаданных — автоматическое восстановление |
| **Масштабируемость** | ФС до 256 ЗБ, файлы до 16 ЭБ |

### Преимущества и недостатки

| ✅ Преимущества | ⚠️ Недостатки |
|----------------|----------------|
| **Максимальная надёжность** (контрольные суммы, восстановление) | **Высокие требования к RAM** (1 ГБ на 1 ТБ диска) |
| Мощные функции управления (сжатие, дедупликация, снимки) | Сложность настройки |
| Простое управление томами (пулы) | Лицензионные ограничения (не входит в основное ядро Linux) |
| Отличная масштабируемость | |

### Типовые случаи использования

- **Серверы хранения данных (NAS/SAN)** — TrueNAS, FreeNAS
- **Системы виртуализации** — дедупликация и клонирование
- **Резервное копирование** — снимки и быстрая инкрементальность
- **Облачные и масштабируемые системы**
- **Научные вычисления** — огромные объёмы данных

> [!important]
> ZFS требует значительного объёма RAM. При использовании дедупликации требования к памяти могут быть ещё выше. Не устанавливайте ZFS на системы с ограниченной памятью.

## Краткий обзор других современных ФС

| ФС | Назначение | Особенности |
|----|------------|-------------|
| **F2FS** | Flash-Friendly File System | Оптимизирована для флеш-памяти (SSD, eMMC, SD-карты). Минимизация износа, высокая производительность |
| **ReiserFS** | Работа с большим количеством маленьких файлов | Журналируемая, эффективное использование дискового пространства (менее популярна сегодня) |
| **JFS** | Journaled File System (IBM) | Серверная ФС, высокая производительность и надёжность |
| **Nilfs2** | Log-structured файловая система | Непрерывные снимки, откат к любой предыдущей версии |
| **Bcachefs** | Экспериментальная ФС | Кэширование на быстрых устройствах (SSD), сжатие, контроль целостности |

## Userspace файловые системы (FUSE)

**Userspace файловые системы** работают в пространстве пользователя, а не ядра, через **FUSE** (Filesystem in Userspace).

### Как работает FUSE

1. Приложение обращается к файлу → ядро передаёт запрос модулю FUSE
2. Модуль FUSE перенаправляет запрос в демона в пользовательском пространстве
3. Демон обрабатывает запрос (сеть, БД, облако) и возвращает результат

### Преимущества FUSE

| Преимущество | Описание |
|--------------|----------|
| **Безопасность** | Ошибка в ФС не вызывает крах ядра |
| **Упрощённая разработка** | Стандартные языки и инструменты отладки |
| **Гибкость** | Эксперименты без изменения ядра |
| **Совместимость** | Поддержка ФС, не реализованных в ядре |

### Примеры FUSE-файловых систем

| ФС | Назначение |
|----|------------|
| **SSHFS** | Монтирование удалённых директорий через SSH |
| **EncFS** | Шифрование данных «на лету» |
| **NTFS-3G** | Чтение и запись NTFS-разделов |
| **S3FS** | Монтирование Amazon S3 как локальной ФС |

## Типовые проблемы файловых систем

| Проблема | Описание | Решение |
|----------|----------|---------|
| **Фрагментация** | Файлы разбиты на несмежные блоки → снижение производительности | Дефрагментация (XFS, Btrfs) |
| **Повреждение данных** | Сбои питания, ошибки оборудования, баги | Журналирование, контрольные суммы (Btrfs, ZFS) |
| **Поломка структуры ФС** | Невозможность монтирования из-за сбоя | `fsck` (ext4) или встроенные средства (ZFS/Btrfs) |
| **Ограничения размера** | Некоторые ФС не поддерживают большие файлы/тома | Выбор XFS, Btrfs, ZFS |
| **Отсутствие современных функций** | Нет снимков, дедупликации, сжатия | Переход на Btrfs или ZFS |
| **Медленная работа с большими директориями** | Деградация производительности | XFS, Btrfs |
| **Проблемы совместимости** | ФС одной ОС недоступна в другой | FAT32, exFAT или драйверы |
| **Ограничения управления правами** | Нет поддержки сложных ACL | ext4, Btrfs, ZFS (с поддержкой ACL) |

## Рекомендации по выбору ФС

| Сценарий | Рекомендуемая ФС | Почему |
|----------|------------------|--------|
| **Настольный ПК / рабочая станция** | EXT4 или Btrfs | EXT4 — стандарт и простота, Btrfs — снимки для отката |
| **Сервер баз данных** | XFS | Высокая производительность с большими файлами |
| **Файловый сервер / NAS** | ZFS или Btrfs | Защита данных, RAID, сжатие |
| **Корпоративное хранилище** | ZFS | Максимальная надёжность и масштабируемость |
| **Виртуализация / контейнеры** | ZFS или Btrfs | Дедупликация, клонирование, снимки |
| **Система с ограниченной RAM** | EXT4 | Низкие требования к памяти |
| **Встраиваемая система** | EXT4 или F2FS | Низкие накладные расходы или оптимизация под флеш |
| **Резервное копирование** | ZFS или Btrfs | Снимки, инкрементальные копии |
| **Облачное хранилище / монтирование удалённых ресурсов** | FUSE (SSHFS, S3FS) | Работа через сеть без изменения ядра |

## Заключение

Выбор файловой системы зависит от конкретных задач:

- **EXT4** — надёжный стандарт для повседневного использования
- **XFS** — для больших данных и высокой производительности (особенно на RHEL/CentOS)
- **Btrfs** — для продвинутых функций при готовности мириться с возможной нестабильностью
- **ZFS** — для максимальной надёжности и защиты данных (требует ресурсов)
- **FUSE** — для нестандартных сценариев (монтирование облака, шифрование)

> [!tip]
> Для большинства пользователей и серверов общего назначения **EXT4** остаётся наилучшим выбором благодаря своей стабильности, производительности и простоте. Для сред с критическими данными или специфическими требованиями стоит рассмотреть **ZFS** или **Btrfs**.
