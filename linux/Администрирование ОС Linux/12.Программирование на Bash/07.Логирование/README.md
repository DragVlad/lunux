# Логирование

> Логирование в Bash-скриптах — это важный способ отслеживания выполнения скриптов, диагностики проблем и сохранения ключевой информации о ходе выполнения программы. Это особенно полезно для долгосрочных процессов, автоматизации задач, а также для мониторинга систем. Логирование позволяет сохранять выводы скриптов в файлы или отправлять их в системные логи.

## Основные методы логирования в Bash

1. **Логирование в файл** — вывод информации в текстовые файлы.
2. **Использование команды `logger` для системных логов** — запись логов в системный журнал (например, с использованием `syslog`).
3. **Перенаправление стандартного вывода и вывода ошибок** — сохранение информации о ходе выполнения скрипта, а также ошибок.

## Логирование в файл

Вы можете сохранять ключевую информацию из скрипта в отдельный файл, что удобно для последующего анализа.

**Пример записи логов в файл:**

```bash
#!/bin/bash

LOGFILE="/var/log/my_script.log"

# Функция для логирования
log() {
    local message="$1"
    echo "$(date '+%Y-%m-%d %H:%M:%S') : $message" >> "$LOGFILE"
}

# Пример использования функции
log "Начало работы скрипта"
log "Выполняем какую-то команду"

# Логирование ошибки
if ! cp non_existent_file.txt destination.txt 2>> "$LOGFILE"; then
    log "Ошибка при копировании файла"
fi

log "Завершение работы скрипта"
```

**Объяснение:**

- Функция `log` добавляет временную метку к каждому сообщению и записывает его в лог-файл.
- В команде `cp` вывод ошибок перенаправляется в лог-файл с помощью `2>> "$LOGFILE"`. Это сохраняет информацию о возможных ошибках в файл.

**Результат в лог-файле:**

```text
2024-09-25 12:00:01 : Начало работы скрипта
2024-09-25 12:00:02 : Выполняем какую-то команду
2024-09-25 12:00:03 : Ошибка при копировании файла
2024-09-25 12:00:04 : Завершение работы скрипта
```

Для предотвращения переполнения лог-файлов можно настроить ротацию логов, например, с использованием системной утилиты `logrotate`, которая автоматически управляет размером логов, создавая новые файлы и удаляя старые.

## Логирование с помощью команды logger (системные логи)

Команда `logger` позволяет записывать сообщения в системный журнал (обычно в `/var/log/syslog` на большинстве систем Linux) с помощью механизма `syslog`.

**Пример использования logger:**

```bash
#!/bin/bash

logger "Скрипт запущен"

# Команда, выполняющаяся в скрипте
if cp file.txt /backup/; then
    logger "Файл успешно скопирован"
else
    logger "Ошибка при копировании файла"
fi

logger "Скрипт завершен"
```

Это позволяет записывать события в системный лог, который можно просматривать с помощью таких команд, как `tail` или `less`.

**Пример просмотра логов:**

```bash
tail /var/log/syslog
```

**Вывод:**

```text
Sep 25 12:00:01 hostname script.sh[12345]: Скрипт запущен
Sep 25 12:00:02 hostname script.sh[12345]: Файл успешно скопирован
Sep 25 12:00:04 hostname script.sh[12345]: Скрипт завершен
```

**Опции команды logger:**

- `-p` — указывает приоритет сообщения (например, `user.info`, `user.err`)
- `-t` — позволяет указать тег (имя программы) для сообщения в логе
- `-i` — включает ID процесса в лог

## Перенаправление вывода и ошибок

Вы можете перенаправлять стандартный вывод (stdout) и вывод ошибок (stderr) в файлы для ведения журналов. Это полезно для записи всего, что происходит в скрипте, в лог-файлы.

**Пример перенаправления вывода и ошибок в лог-файл:**

```bash
#!/bin/bash

LOGFILE="/var/log/my_script.log"

# Перенаправляем стандартный вывод и вывод ошибок
exec > >(tee -a "$LOGFILE") 2>&1

echo "Начало работы"
ls non_existent_file.txt  # Эта команда вызовет ошибку
echo "Конец работы"
```

**Объяснение:**

- `exec > >(tee -a "$LOGFILE") 2>&1` — перенаправляет стандартный вывод и ошибки в команду `tee`, которая записывает вывод в лог-файл и одновременно отображает его в консоли.
- `2>&1` — перенаправляет стандартный поток ошибок (stderr, дескриптор 2) в стандартный вывод (stdout, дескриптор 1).

**Разделение стандартного вывода и вывода ошибок по разным файлам:**

```bash
#!/bin/bash

exec 1>>/var/log/output.log   # Стандартный вывод
exec 2>>/var/log/error.log    # Вывод ошибок

echo "Это стандартное сообщение"
ls non_existent_file.txt  # Это сообщение об ошибке
```

**Использование tee для одновременного вывода в файл и на экран:**

```bash
#!/bin/bash

LOGFILE="/var/log/my_script.log"

echo "Начало работы" | tee -a "$LOGFILE"
ls non_existent_file.txt | tee -a "$LOGFILE"
echo "Конец работы" | tee -a "$LOGFILE"
```

В этом примере команда `tee` сохраняет все сообщения в лог-файл и выводит их в терминал.

## Продвинутые техники логирования

### Уровни логирования

Можно реализовать уровни логирования (например, `INFO`, `ERROR`, `DEBUG`), чтобы лучше контролировать вывод логов.

```bash
#!/bin/bash

LOGFILE="/var/log/my_script.log"
LOG_LEVEL="INFO"  # Можно менять уровень на ERROR или DEBUG

log() {
    local level="$1"
    local message="$2"
    if [[ "$level" == "$LOG_LEVEL" ]] || [[ "$level" == "ERROR" ]]; then
        echo "$(date '+%Y-%m-%d %H:%M:%S') [$level] : $message" | tee -a "$LOGFILE"
    fi
}

log "INFO" "Скрипт запущен"
log "DEBUG" "Это сообщение для отладки"
log "ERROR" "Произошла ошибка"
log "INFO" "Скрипт завершен"
```

**Использование различных уровней:**

- `INFO` — общая информация о работе
- `DEBUG` — сообщения для отладки
- `ERROR` — сообщения об ошибках

**Результат при LOG_LEVEL="INFO":**

```text
2024-09-25 12:00:01 [INFO] : Скрипт запущен
2024-09-25 12:00:02 [ERROR] : Произошла ошибка
2024-09-25 12:00:03 [INFO] : Скрипт завершен
```

## Ротация логов

Для управления размером лог-файлов и их ротации можно использовать утилиту `logrotate`. Она позволяет автоматически архивировать и удалять старые логи.

**Пример конфигурации logrotate**

Создайте файл конфигурации `/etc/logrotate.d/my_script`:

```text
/var/log/my_script.log {
    daily
    rotate 7
    compress
    missingok
    notifempty
}
```

**Пояснение:**

- `daily` — ротация логов каждый день
- `rotate 7` — хранить 7 предыдущих логов
- `compress` — сжатие старых логов
- `missingok` — не выдавать ошибку, если файла нет
- `notifempty` — не ротировать пустые логи

**Запуск ротации вручную:**

```bash
logrotate -f /etc/logrotate.d/my_script
```

## Итоговые рекомендации

Логирование в Bash-скриптах позволяет отслеживать выполнение программ и диагностировать возможные проблемы. Основные методы включают:

1. **Логирование в файл** — запись вывода и сообщений в текстовые файлы для последующего анализа.
2. **Использование `logger` для системных логов** — интеграция с системным журналом через `syslog`.
3. **Перенаправление вывода и ошибок** — запись стандартного вывода и ошибок в лог-файлы.
4. **Продвинутые техники** — уровни логирования (например, `INFO`, `ERROR`), использование ротации логов через `logrotate`.

Выбор подходящего метода зависит от задач и требований к мониторингу работы скриптов.
