# Ввод данных от пользователя и работа с конфигурацией

## Чтение ввода пользователя

В Bash-скриптах можно организовать взаимодействие с пользователем через **аргументы командной строки** и ввод через команду **`read`**. Эти два метода позволяют получать данные для выполнения скриптов, что делает их более гибкими и интерактивными.

**Основные способы получения данных от пользователя:**

1. **Аргументы командной строки** — параметры, передаваемые скрипту при его запуске.
2. **Команда `read`** — используется для интерактивного ввода данных от пользователя во время выполнения скрипта.

### Аргументы командной строки

Аргументы командной строки передаются в скрипт при его запуске. Эти данные можно использовать для задания параметров или конфигураций.

**Доступ к аргументам командной строки:**

- `$1, $2, ..., $n` — доступ к каждому аргументу по порядку
- `$0` — имя самого скрипта
- `$#` — количество переданных аргументов
- `$@` — список всех аргументов
- `$*` — все аргументы как одна строка

**Пример использования:**

```bash
#!/bin/bash

echo "Имя скрипта: $0"
echo "Первый аргумент: $1"
echo "Второй аргумент: $2"
echo "Всего аргументов: $#"
```

**Запуск скрипта:**

```bash
./script.sh Иван 25
# Вывод:
# Имя скрипта: ./script.sh
# Первый аргумент: Иван
# Второй аргумент: 25
# Всего аргументов: 2
```

### Проверка количества аргументов

Убедиться, что передано нужное количество аргументов:

```bash
#!/bin/bash

if [ $# -lt 2 ]; then
    echo "Ошибка: недостаточно аргументов."
    echo "Использование: $0 имя возраст"
    exit 1
fi

name=$1
age=$2

echo "Привет, $name. Тебе $age лет."
```

### Аргументы с флагами (getopts)

`getopts` — это стандартный способ обработки флагов командной строки, таких как `-a`, `-b`, `-c`.

**Пример использования getopts:**

```bash
#!/bin/bash

while getopts "n:a:" opt; do
    case $opt in
        n) name=$OPTARG ;;
        a) age=$OPTARG ;;
        *) echo "Некорректный параметр"; exit 1 ;;
    esac
done

echo "Имя: $name"
echo "Возраст: $age"
```

**Запуск:**

```bash
./script.sh -n Иван -a 25
# Вывод:
# Имя: Иван
# Возраст: 25
```

### Команда read для интерактивного ввода

Команда `read` позволяет организовать ввод данных от пользователя во время выполнения скрипта.

**Синтаксис:**

```bash
read [опции] переменная
```

**Опции команды read:**

- `-p` — выводит подсказку перед вводом
- `-s` — скрывает ввод (например, для паролей)
- `-n` — ограничивает количество вводимых символов
- `-t` — задает тайм-аут
- `-r` — отключает интерпретацию экранирующих символов

| Описание | Пример |
|----------|--------|
| Простое использование read | `read name; echo "Привет, $name!"` |
| Использование с подсказкой | `read -p "Введите ваше имя: " name` |
| Чтение нескольких значений за один ввод | `read -p "Введите имя и возраст: " name age` |
| Проверка числового ввода | `if [[ $number =~ ^[0-9]+$ ]]; then echo "Число: $number"; fi` |
| Обработка ответов «да/нет» | `case $answer in [Yy]*) echo "Продолжаем...";; [Nn]*) echo "Завершаем...";; esac` |

**Пример проверки числового ввода:**

```bash
#!/bin/bash

while true; do
    read -p "Введите число: " number
    if [[ $number =~ ^[0-9]+$ ]]; then
        echo "Вы ввели число: $number"
        break
    else
        echo "Ошибка: введите корректное число."
    fi
done
```

### Сочетание аргументов командной строки и read

Можно использовать комбинацию аргументов командной строки и ввода через `read`, чтобы скрипт был более гибким и позволял вводить значения как при запуске, так и в процессе выполнения.

```bash
#!/bin/bash

if [ -z "$1" ]; then
    read -p "Введите ваше имя: " name
else
    name=$1
fi

if [ -z "$2" ]; then
    read -p "Введите ваш возраст: " age
else
    age=$2
fi

echo "Привет, $name. Тебе $age лет."
```

### Сводка методов ввода

| Метод | Описание |
|-------|----------|
| **Аргументы командной строки** | Удобный способ передавать данные скрипту при его запуске. Можно проверить количество аргументов, использовать флаги через `getopts` и работать с ними для автоматизации. |
| **Команда `read`** | Позволяет организовать интерактивное взаимодействие с пользователем во время выполнения скрипта. Можно запрашивать данные с подсказками, использовать скрытый ввод для паролей, ограничивать количество символов или задавать тайм-аут. |
| **Комбинация методов** | Позволяет сделать скрипты более гибкими, принимая параметры как из командной строки, так и через пользовательский ввод. |

## Использование флагов

В Bash-скриптах флаги и опции командной строки предоставляют мощный механизм для передачи параметров. Они делают скрипты более гибкими и универсальными, позволяя пользователям указывать настройки или передавать данные в виде аргументов.

Для работы с флагами и опциями в Bash используется встроенная команда `getopts`. Это стандартный инструмент для обработки опций в командной строке, таких как `-a`, `-b`, `-c`, с возможностью указания аргументов для этих опций.

### Основные принципы работы с getopts

`getopts` обрабатывает флаги в формате `-опция` или `-опция аргумент`, где:
- опция — это одиночная буква
- аргумент — это значение, связанное с этой опцией (например, имя файла)

**Синтаксис:**

```bash
getopts "опции" переменная
```

- `"опции"` — строка, где каждая буква представляет поддерживаемую опцию. Если после буквы стоит двоеточие, опция принимает аргумент.
- `переменная` — переменная, в которую сохраняется текущая обрабатываемая опция.

**Пример с флагами без аргументов:**

```bash
#!/bin/bash

while getopts "ab" opt; do
    case $opt in
        a)
            echo "Опция -a была выбрана"
            ;;
        b)
            echo "Опция -b была выбрана"
            ;;
        *)
            echo "Неизвестная опция: -$OPTARG"
            exit 1
            ;;
    esac
done
```

### Обработка опций с аргументами

Некоторые опции могут принимать аргументы. Для этого в строке опций после буквы ставится двоеточие:

```bash
#!/bin/bash

while getopts "f:" opt; do
    case $opt in
        f)
            echo "Вы выбрали опцию -f с аргументом: $OPTARG"
            ;;
        *)
            echo "Неизвестная опция: -$OPTARG"
            exit 1
            ;;
    esac
done
```

### Комбинирование нескольких опций

Можно комбинировать несколько опций с аргументами и без:

```bash
#!/bin/bash

while getopts "n:a:f:" opt; do
    case $opt in
        n)
            echo "Имя: $OPTARG"
            ;;
        a)
            echo "Возраст: $OPTARG"
            ;;
        f)
            echo "Файл: $OPTARG"
            ;;
        *)
            echo "Неизвестная опция: -$OPTARG"
            exit 1
            ;;
    esac
done
```

### Обработка ошибок и отсутствующих аргументов

При обработке опций важно учитывать возможность отсутствия обязательных аргументов. По умолчанию `getopts` выведет сообщение об ошибке и завершит выполнение. Чтобы изменить это поведение, можно использовать перед строкой опций двоеточие.

**Пример обработки ошибки:**

```bash
#!/bin/bash

while getopts ":f:" opt; do
    case $opt in
        f)
            if [ -z "$OPTARG" ]; then
                echo "Опция -f требует аргумент"
                exit 1
            else
                echo "Файл: $OPTARG"
            fi
            ;;
        :)
            echo "Ошибка: опция -$OPTARG требует аргумент"
            exit 1
            ;;
        \?)
            echo "Ошибка: некорректная опция -$OPTARG"
            exit 1
            ;;
    esac
done
```

### Поддержка длинных опций (например, --help)

По умолчанию `getopts` поддерживает только короткие опции. Для поддержки длинных опций в Bash можно использовать парсинг аргументов через цикл.

```bash
#!/bin/bash

while [[ "$1" != "" ]]; do
    case $1 in
        -n | --name )
            shift
            name=$1
            ;;
        -a | --age )
            shift
            age=$1
            ;;
        --help )
            echo "Использование: $0 [-n имя] [-a возраст] [--help]"
            exit 0
            ;;
        * )
            echo "Неверная опция: $1"
            exit 1
    esac
    shift
done

echo "Имя: $name"
echo "Возраст: $age"
```

### Советы по использованию getopts

1. **Документируйте опции**: включайте в скрипты справочные сообщения (например, через `--help`), чтобы пользователи знали, какие флаги и аргументы поддерживаются.
2. **Обрабатывайте ошибки**: обязательно обрабатывайте некорректные опции и отсутствующие аргументы, чтобы скрипт был устойчив к ошибкам ввода.
3. **Используйте shift**: после завершения обработки флагов с `getopts`, с помощью `shift` можно обработать оставшиеся аргументы, такие как имена файлов или другие параметры.
4. **Аргументы по умолчанию**: используйте значения по умолчанию для опций, чтобы скрипт мог работать с минимальными входными данными, если аргументы не переданы.

## Подключение конфигурационных файлов

В Bash-скриптах часто возникает необходимость разделять основной код и конфигурационные данные, такие как параметры настроек, пути, переменные окружения и т.д. Это позволяет сделать код более структурированным и поддерживаемым, а также упрощает изменение настроек без необходимости редактировать сам скрипт.

Для подключения внешних конфигурационных файлов используется команда `source` (или её сокращение — точка `.`). Она выполняет команды, содержащиеся в указанном файле, в текущем контексте скрипта. Это означает, что все переменные и функции из подключаемого файла становятся доступными в основном скрипте.

**Синтаксис:**

```bash
source /путь/к/файлу
# или
. /путь/к/файлу
```

### Пример использования source для подключения конфигурационного файла

**Шаг 1: Создание конфигурационного файла `config.sh`:**

```bash
# Конфигурационные переменные
DB_USER="admin"
DB_PASS="password123"
DB_HOST="localhost"
DB_NAME="my_database"

# Функция для вывода конфигурации
print_config() {
    echo "Пользователь базы данных: $DB_USER"
    echo "Пароль базы данных: $DB_PASS"
    echo "Хост базы данных: $DB_HOST"
    echo "Имя базы данных: $DB_NAME"
}
```

**Шаг 2: Подключение конфигурационного файла в основном скрипте `main_script.sh`:**

```bash
#!/bin/bash

# Подключаем конфигурационный файл
source ./config.sh  # Или . ./config.sh

# Используем переменные из конфигурационного файла
echo "Подключаемся к базе данных на хосте $DB_HOST с пользователем $DB_USER."

# Вызов функции из конфигурационного файла
print_config
```

### Преимущества использования source для подключения конфигурационных файлов

1. **Разделение логики и конфигурации**: основной код программы отделён от конфигурационных данных, что упрощает управление и изменения в настройках.
2. **Многократное использование**: один и тот же конфигурационный файл может быть подключён к нескольким скриптам, что обеспечивает консистентность настроек.
3. **Читаемость и поддерживаемость**: логика программы остаётся чистой и сосредоточенной на бизнес-логике, в то время как все переменные и настройки находятся в одном месте.

### Подключение нескольких конфигурационных файлов

Если есть несколько конфигурационных файлов для различных целей, их можно подключить последовательно:

```bash
#!/bin/bash

# Подключаем первый файл конфигурации
source ./config_database.sh

# Подключаем второй файл конфигурации
source ./config_app.sh

# Используем данные из обоих файлов
echo "Подключаемся к базе данных на $DB_HOST..."
echo "Используем порт $APP_PORT для работы приложения."
```

### Динамическое подключение конфигурационных файлов

Иногда нужно подключить разные конфигурационные файлы в зависимости от переданных параметров или других условий:

```bash
#!/bin/bash

# Получаем имя конфигурационного файла из аргумента командной строки
CONFIG_FILE=$1

# Проверяем, существует ли файл
if [ -f "$CONFIG_FILE" ]; then
    source "$CONFIG_FILE"
else
    echo "Конфигурационный файл $CONFIG_FILE не найден!"
    exit 1
fi

# Используем данные из конфигурационного файла
echo "Пользователь базы данных: $DB_USER"
```

**Запуск:**

```bash
./main_script.sh config_prod.sh
```

### Использование значений по умолчанию

Можно задать значения по умолчанию в основном скрипте, а затем переопределить их из конфигурационного файла:

```bash
#!/bin/bash

# Значения по умолчанию
DB_USER="default_user"
DB_PASS="default_pass"
DB_HOST="localhost"
DB_NAME="default_database"

# Подключаем конфигурационный файл, если он существует
if [ -f ./config.sh ]; then
    source ./config.sh
fi

# Используем переменные
echo "Подключаемся к базе данных на хосте $DB_HOST с пользователем $DB_USER."
```

### Обработка ошибок при подключении конфигурационного файла

Можно добавить проверку того, был ли файл подключен успешно, и обработать ошибки:

```bash
#!/bin/bash

CONFIG_FILE="./config.sh"

if [ -f "$CONFIG_FILE" ]; then
    source "$CONFIG_FILE"
    echo "Конфигурация загружена успешно."
else
    echo "Ошибка: Конфигурационный файл $CONFIG_FILE не найден."
    exit 1
fi
```

### Безопасность при подключении конфигурационных файлов

1. **Права доступа**: убедитесь, что конфигурационные файлы имеют правильные права доступа и не могут быть изменены неавторизованными пользователями.
2. **Избегайте использования непроверенных файлов**: если имя файла конфигурации передаётся как аргумент, проверяйте его существование и правильность формата перед подключением.

### Основные преимущества использования source

- Разделение конфигурационных данных и логики
- Упрощение изменения настроек
- Возможность переиспользования конфигураций в разных скриптах
- Гибкость в зависимости от условий или аргументов командной строки
