# Символические и жесткие ссылки

В файловых системах Unix/Linux ссылки (links) — это механизм, позволяющий обращаться к одному и тому же файлу или каталогу из разных точек файловой иерархии. В Linux существует два типа ссылок: **жесткие ссылки (hard links)** и **символические ссылки (symbolic links, symlinks)**. Они различаются по своей природе, поведению и областям применения.

## Жесткие ссылки (Hard Links)

> Жесткая ссылка — это дополнительное имя (запись в каталоге), указывающее на ту же область данных на диске, что и исходный файл. Все жесткие ссылки на один файл равноправны: после создания любой из них может считаться «оригиналом».

### Принцип работы

В файловой системе Linux каждый файл представлен двумя сущностями:
- **inode** — структура данных, содержащая метаданные файла (размер, права доступа, временные метки, указатели на блоки данных на диске).
- **запись в каталоге (dentry)** — связывает имя файла с его inode.

Жесткая ссылка создает новую запись в каталоге, которая ссылается на тот же inode, что и исходный файл. При удалении одной из записей данные не удаляются, пока существует хотя бы одна ссылка на inode. Счетчик ссылок (link count) в inode уменьшается на 1 при каждом удалении; когда он становится равным нулю, данные освобождаются.

### Особенности жестких ссылок

- **Один inode** — все жесткие ссылки разделяют один inode, а значит, и один набор данных на диске.
- **Изменения видны через все ссылки** — модификация файла через любую ссылку отражается на всех остальных.
- **Невозможность для каталогов** — жесткие ссылки на каталоги запрещены (за исключением `.` и `..` в большинстве файловых систем) во избежание циклических ссылок.
- **Требование к файловой системе** — жесткая ссылка может ссылаться только на файл в той же файловой системе (на том же разделе), поскольку inode уникален только в пределах одной файловой системы.
- **Не различаются от оригинала** — после создания жесткой ссылки невозможно определить, какая запись была «исходной»; все равноправны.

### Создание жестких ссылок

```bash
ln исходный_файл имя_ссылки
```

**Пример:**

```bash
echo "Hello" > file1.txt
ln file1.txt file2.txt
ls -li file1.txt file2.txt
```

Вывод покажет, что оба файла имеют одинаковый номер inode (первая колонка):

```text
123456 -rw-r--r-- 2 user user 6 Jun 15 10:00 file1.txt
123456 -rw-r--r-- 2 user user 6 Jun 15 10:00 file2.txt
```

Число `2` в поле ссылок указывает на наличие двух жестких ссылок на данный inode.

### Когда использовать жесткие ссылки

- Создание нескольких имен для одного файла в пределах одной файловой системы.
- Экономия места — две ссылки не занимают дополнительное дисковое пространство.
- Защита от случайного удаления — пока есть хотя бы одна ссылка, данные сохраняются.
- В системах резервного копирования для создания снапшотов без дублирования данных.

## Символические ссылки (Symbolic Links)

> Символическая ссылка (симлинк, symlink) — это специальный файл, который содержит путь к другому файлу или каталогу. При обращении к символической ссылке операционная система автоматически перенаправляет запрос к целевому объекту.

### Принцип работы

Символическая ссылка — это отдельный файл со своим собственным inode. В отличие от жесткой ссылки, она не ссылается на тот же inode, а хранит в себе строку-путь к целевому объекту. При открытии симлинка ядро читает этот путь и перенаправляет операцию.

### Особенности символических ссылок

- **Отдельный inode** — симлинк имеет собственный inode и тип файла `l` (link).
- **Могут пересекать файловые системы** — симлинк может указывать на файл на другом разделе или даже на удаленной файловой системе (NFS).
- **Могут указывать на каталоги** — симлинки на каталоги разрешены и широко используются.
- **Могут указывать на несуществующие объекты** — симлинк может быть «битым» (dangling link), если целевой файл был удален или перемещен.
- **Размер симлинка** — размер равен длине строки пути, который он хранит.
- **Права доступа** — права доступа к симлинку обычно игнорируются; используются права целевого файла.

### Создание символических ссылок

```bash
ln -s целевой_объект имя_ссылки
```

**Пример:**

```bash
echo "Hello" > original.txt
ln -s original.txt symlink.txt
ls -li original.txt symlink.txt
```

Вывод покажет разные inode, а у symlink.txt тип будет `l`:

```text
123456 -rw-r--r-- 1 user user 6 Jun 15 10:00 original.txt
123457 lrwxrwxrwx 1 user user 12 Jun 15 10:00 symlink.txt -> original.txt
```

### Относительные и абсолютные пути в симлинках

При создании символической ссылки важно указать путь к целевому объекту. Можно использовать как абсолютные, так и относительные пути.

- **Абсолютный путь:** `ln -s /home/user/original.txt symlink.txt` — ссылка будет работать из любого каталога.
- **Относительный путь:** `ln -s original.txt symlink.txt` — ссылка будет работать, если она находится в том же каталоге, что и целевой файл. При перемещении симлинка ссылка может «сломаться».

**Важно:** В относительных путях путь интерпретируется относительно расположения **самой ссылки**, а не текущей рабочей директории.

### Когда использовать символические ссылки

- Создание коротких имен для длинных путей.
- Организация версий (например, `latest` → `app-2.3.1`).
- Ссылки на каталоги (например, `/usr/bin` → `/usr/local/bin`).
- Кросс-файловая система — для связи файлов на разных разделах.
- Перенаправление конфигурационных файлов.
- В системах с динамическим размещением данных (например, логи, кэши).

## Сравнение жестких и символических ссылок

| Характеристика | Жесткая ссылка | Символическая ссылка |
|----------------|----------------|----------------------|
| **Тип файла** | Обычный файл | Специальный файл типа `l` |
| **Inode** | Общий с исходным файлом | Собственный inode |
| **Содержимое** | Указатель на inode | Путь к целевому объекту |
| **Область действия** | Одна файловая система | Любая файловая система |
| **Целевой объект** | Только файлы | Файлы и каталоги |
| **Разрешен для каталогов** | Нет (кроме `.` и `..`) | Да |
| **Битые ссылки** | Невозможны (inode существует или нет) | Возможны (если целевой объект удален) |
| **Отслеживание изменений** | Все ссылки равноправны | При перемещении/переименовании цели ссылка ломается |
| **Размер ссылки** | Размер inode не зависит от имени | Зависит от длины пути |
| **Кроссплатформенность** | Только в той же файловой системе | Может пересекать файловые системы |
| **Права доступа** | Права определяются inode | Права ссылки игнорируются |

## Практические примеры использования

### Пример 1: Симлинк для переключения версий приложений

```bash
# Создание ссылки на активную версию
ln -s /opt/app-2.3.1 /opt/app-current
# При обновлении достаточно поменять ссылку
rm /opt/app-current
ln -s /opt/app-2.4.0 /opt/app-current
```

### Пример 2: Жесткие ссылки для снапшотов

```bash
# Создание снапшота без копирования данных
cp -al /data/current /data/snapshot-2025-01-01
# Теперь snapshot-2025-01-01 — это множество жестких ссылок на текущие файлы
```

### Пример 3: Битый симлинк и его диагностика

```bash
ln -s /nonexistent/path deadlink
ls -l deadlink
# Вывод: lrwxrwxrwx 1 user user 16 Jun 15 10:00 deadlink -> /nonexistent/path

# Проверка существования цели
test -e deadlink && echo "OK" || echo "Broken link"
```

### Пример 4: Поиск жестких ссылок на один inode

```bash
# Поиск всех файлов с тем же inode
stat -c "%i" file.txt
# Полученный inode можно использовать для поиска других ссылок
find /path -inum 123456
```

### Пример 5: Обход символических ссылок при работе с файлами

```bash
# Создать файл и симлинк
echo "data" > real.txt
ln -s real.txt link.txt

# Чтение через симлинк
cat link.txt  # Выводит "data"

# Удаление оригинала
rm real.txt
cat link.txt  # Ошибка: No such file or directory
```

## Рекомендации по использованию

1. **Жесткие ссылки** стоит использовать для:
   - Точечных копий одного файла в пределах одного раздела.
   - Снапшотов и резервных копий без дублирования данных.
   - Ситуаций, где важно, чтобы все имена были равноправны.

2. **Символические ссылки** стоит использовать для:
   - Кросс-файловых систем и ссылок на каталоги.
   - Создания коротких псевдонимов для длинных путей.
   - Организации версий (переключение между версиями ПО).
   - Гибких конфигураций и перенаправлений.

3. **Избегайте**:
   - Циклических симлинков (например, `a -> b` и `b -> a`).
   - Хранения критичных данных только через симлинк (при удалении цели данные теряются).
   - Создания симлинков с абсолютными путями, если каталог планируется переносить.

4. **Диагностика**:
   - Проверка типа файла: `ls -l` или `stat`.
   - Поиск битых симлинков: `find . -type l ! -exec test -e {} \; -print`.
   - Поиск жестких ссылок: `find . -inum <номер_inode>`.
