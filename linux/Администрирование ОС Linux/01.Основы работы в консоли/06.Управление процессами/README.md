# Управление процессами в Linux

## Что такое процесс

> **Процесс** — это экземпляр выполняемой программы. Каждая команда, скрипт или сервис, запущенный в системе, создаёт один или несколько процессов.

В отличие от просто программы (которая лежит на диске), процесс — это активная сущность, имеющая собственное адресное пространство в оперативной памяти, набор файловых дескрипторов и уникальный идентификатор.

---

## Жизненный цикл процесса

Процесс в Linux может находиться в одном из нескольких состояний:

| Состояние | Символ `ps` | Описание |
|-----------|-------------|----------|
| **Running** | `R` | Выполняется или готов к выполнению (в очереди) |
| **Sleeping (Interruptible)** | `S` | Ожидание события (например, ввода с клавиатуры). Можно прервать сигналом |
| **Sleeping (Uninterruptible)** | `D` | Ожидание ввода-вывода (например, записи на диск). Нельзя прервать |
| **Stopped** | `T` | Приостановлен сигналом (например, `Ctrl+Z`) |
| **Zombie** | `Z` | Процесс завершился, но родитель не прочитал код возврата |

> [!note]
> **Zombie-процессы** обычно безвредны и занимают минимум ресурсов (только запись в таблице процессов). Проблема возникает, если родительский процесс «не забирает» детей — тогда таблица процессов может переполниться.

## Просмотр процессов

### Команда `ps` (Process Status)

```bash
# Процессы текущего терминала
ps

# Все процессы системы в расширенном формате
ps aux

# Дерево процессов (кто кого породил)
ps axjf

# Выборка по пользователю
ps -u username
```

**Что означают колонки в `ps aux`:**

| Колонка | Значение |
|---------|----------|
| `USER` | Владелец процесса |
| `PID` | Уникальный идентификатор процесса |
| `%CPU` | Использование процессора |
| `%MEM` | Использование оперативной памяти |
| `VSZ` | Виртуальный размер (KiB) |
| `RSS` | Физическая память (KiB) |
| `TTY` | Терминал, с которым связан процесс |
| `STAT` | Состояние процесса (R, S, D, T, Z) |
| `START` | Время запуска |
| `TIME` | Общее время использования CPU |
| `COMMAND` | Команда запуска |

### Команда `top` (динамический мониторинг)

```bash
top                    # Запуск интерактивного монитора
htop                   # Более удобная версия (требует установки)
```

**Горячие клавиши в `top`:**
- `P` — сортировка по CPU
- `M` — сортировка по памяти
- `k` — завершить процесс (ввести PID)
- `q` — выход

### Команда `pgrep` (поиск по имени)

```bash
pgrep -l nginx        # Найти PID процесса nginx
pgrep -u root bash    # Найти все bash-процессы root
```

## Управление процессами: сигналы

> **Сигнал** — асинхронное уведомление, отправляемое процессу для управления его поведением.

### Основные сигналы

| Сигнал | Номер | Действие по умолчанию | Применение |
|--------|-------|----------------------|------------|
| `SIGTERM` | 15 | Завершение | Вежливая просьба завершиться (можно обработать) |
| `SIGKILL` | 9 | Принудительное завершение | Убить процесс, который не реагирует на `SIGTERM` |
| `SIGHUP` | 1 | Перезагрузка конфигурации | Заставить процесс перечитать конфиг (без остановки) |
| `SIGINT` | 2 | Завершение | Отправляется по `Ctrl+C` |
| `SIGSTOP` | 19 | Остановка процесса | Приостановить выполнение |
| `SIGCONT` | 18 | Продолжить | Возобновить остановленный процесс |

### Отправка сигналов

```bash
# Завершить процесс вежливо
kill PID

# То же самое, но с явным сигналом
kill -15 PID

# Принудительно убить
kill -9 PID

# Отправить SIGHUP (перечитать конфиг)
kill -1 PID

# Убить все процессы пользователя
killall -u username

# Убить по имени (осторожно!)
pkill nginx
```

> [!warning]
> `kill -9` (`SIGKILL`) не даёт процессу шанса корректно завершиться (закрыть файлы, освободить ресурсы). Используйте его только как крайнее средство.

## Фоновый и интерактивный режим

### Запуск в фоне

```bash
# Амперсанд в конце — процесс уходит в фон
sleep 1000 &

# Посмотреть фоновые задачи текущего терминала
jobs
```

**Пример вывода `jobs`:**
```
[1]-  Running    sleep 1000 &
[2]+  Running    nginx &
```

### Перемещение между фоном и передним планом

```bash
# Вернуть задачу №1 на передний план
fg %1

# Переместить задачу в фон (если она уже запущена на переднем плане)
# Сначала приостановить: Ctrl+Z, затем:
bg %1

# Запустить процесс в фоне с перенаправлением вывода
./long_script.sh > output.log 2>&1 &
```

### `nohup` — защита от закрытия терминала

```bash
# Процесс продолжит работу даже после выхода из SSH
nohup ./long_task.sh &

# Вывод по умолчанию идёт в nohup.out
```

## Приоритеты процессов (Nice)

> **Nice value** (значение «доброты») определяет, сколько процессорного времени получит процесс. Чем выше значение (добрее), тем меньше приоритет.

| Диапазон | Значение |
|----------|----------|
| `-20` | Самый высокий приоритет (не рекомендуется обычным пользователям) |
| `0`   | Приоритет по умолчанию |
| `19`  | Самый низкий приоритет (фоновые задачи) |

```bash
# Запустить процесс с низким приоритетом (nice 10)
nice -n 10 ./background_task.sh

# Изменить приоритет уже запущенного процесса
renice +5 -p PID

# Запустить с высоким приоритетом (требует прав root)
sudo nice -n -10 ./critical_task.sh
```

> [!tip]
> Пользователь может **только повышать** nice (делать процесс добрее — менее приоритетным). Понижать (делать агрессивнее) может только `root`.

## Интерактивные инструменты управления

| Инструмент | Описание | Установка |
|------------|----------|-----------|
| `htop` | `top` на стероидах (цвета, управление мышью) | `sudo apt install htop` |
| `atop` | Мониторинг с историей для анализа пиков | `sudo apt install atop` |
| `glances` | Кроссплатформенный мониторинг в реальном времени | `sudo apt install glances` |

**Пример `htop` в действии:**
- F6 — сортировка по выбранной колонке
- F9 — меню отправки сигнала (kill)
- F3 — поиск процесса

## Процессы-демоны

> **Демон** — процесс, работающий в фоне и не привязанный к терминалу. Обычно запускается при загрузке системы и имеет `PPID=1` (родитель — `systemd`).

**Признаки демона:**
- В колонке `TTY` — `?` (нет терминала)
- В колонке `COMMAND` — часто путь в квадратных скобках `[kthreadd]`

```bash
# Список демонов
ps aux | grep -E '^USER|/usr/sbin/'
systemctl list-units --type=service --state=running
```

## Полезные команды (шпаргалка)

```bash
# Просмотр
# Просмотр
ps aux                          # Все процессы
ps axjf                         # Дерево процессов
top / htop                      # Интерактивный монитор
pgrep -l process_name           # Найти PID

# Управление
kill PID                        # SIGTERM (вежливое завершение)
kill -9 PID                     # SIGKILL (принудительное)
pkill process_name              # Убить по имени
killall process_name            # Убить все процессы с именем

# Фоновый режим
command &                       # Запуск в фоне
jobs                            # Список задач терминала
fg %1                           # Вернуть задачу на передний план
bg %1                           # Возобновить фоновую задачу

# Приоритеты
nice -n 10 command              # Запуск с низким приоритетом
renice +5 -p PID                # Понизить приоритет существующего

# systemd - просмотр юнитов
systemctl list-units            # Все активные юниты
systemctl list-units --all      # Все юниты (включая неактивные)
systemctl list-units --type=service      # Только сервисы
systemctl list-units --type=service --state=running  # Только работающие
systemctl list-unit-files       # Все файлы юнитов (включены/выключены)

# systemd - управление сервисами
systemctl status nginx          # Статус сервиса
systemctl start nginx           # Запустить
systemctl stop nginx            # Остановить
systemctl restart nginx         # Перезапустить
systemctl reload nginx          # Перечитать конфиг (без остановки)
systemctl enable nginx          # Автозапуск при загрузке
systemctl disable nginx         # Отключить автозапуск
systemctl mask nginx            # Полная блокировка (не запустится даже вручную)
systemctl unmask nginx          # Снять блокировку
systemctl is-enabled nginx      # Проверить, включен ли автозапуск

# systemd - логи
journalctl -u nginx -f          # Логи в реальном времени
journalctl -u nginx -n 50       # Последние 50 строк
journalctl -u nginx --since today      # Логи за сегодня
journalctl -u nginx --since "2026-06-01" --until "2026-06-08"
```

## Итог

1. **Процесс** — выполняющаяся программа с PID и состоянием (R, S, D, Z)
2. **Сигналы** — основной способ управления: `SIGTERM` (15) для вежливого завершения, `SIGKILL` (9) для принудительного
3. **Фоновый режим** — `&`, `jobs`, `fg`, `bg`, `nohup`
4. **Nice** — управление приоритетом CPU (от -20 до 19)
5. **Демоны** — фоновые процессы, не привязанные к терминалу, управляются через `systemctl`

> [!tip]
> Никогда не убивайте процессы без разбора. Всегда пробуйте `SIGTERM` (обычный `kill`) перед `SIGKILL` (`kill -9`). Некорректно завершённый процесс может оставить после себя мусор (сокеты, временные файлы, блокировки).
