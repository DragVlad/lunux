# Альтернативные варианты установки Linux

По факту, единственным вариантом, который качественно отличается от установки с образа диска (ISO) или развертывания из готового шаблона, — это **установка по сети**.

---

## Загрузка и установка по сети: Netboot и PXE

Рассмотрим два основных термина — **Netboot** и **PXE**. Это технологии, позволяющие загружать операционную систему по сети, но они имеют различия в концепциях и реализации.

---

### Netboot (Network Boot)

> **Netboot** — общий термин, описывающий процесс загрузки ОС через сеть. Может быть реализован различными методами и протоколами: PXE, BOOTP, TFTP, NFS, HTTP и другими.

Основная идея: компьютер загружает ОС или начальный загрузчик (bootloader) с удалённого сервера вместо локального диска.

---

### PXE (Preboot Execution Environment)

> **PXE** — конкретный стандарт и протокол для сетевой загрузки, наиболее распространённый способ реализации Netboot. Определяет, как клиент загружает ОС с помощью DHCP и TFTP.

#### Основные шаги работы PXE

| Шаг | Описание |
|-----|----------|
| **DHCP Discovery** | Клиент отправляет запрос для получения IP-адреса и информации о загрузочном сервере |
| **DHCP Offer** | DHCP-сервер отвечает, предоставляя IP-адрес и путь к TFTP-серверу с загрузочным образом |
| **TFTP Download** | Клиент загружает начальный загрузочный образ с TFTP-сервера |
| **Booting** | Клиент загружает ОС и продолжает процесс установки |

---

## Различия между Netboot и PXE

| Критерий | Netboot | PXE |
|----------|---------|-----|
| **Область применения** | Широкий термин, охватывает все способы сетевой загрузки | Конкретный стандарт и протокол |
| **Протоколы** | BOOTP, RARP, NFS, HTTP, PXE и др. | DHCP + TFTP |
| **Процесс** | Зависит от конкретного метода | Стандартизированный (Discovery → Offer → Download → Boot) |

---

## Примеры использования

### PXE
- Крупные организации — массовая установка ОС на новые компьютеры
- Учебные заведения — централизованное управление компьютерными классами

### Netboot (не-PXE варианты)
- **NFS** — загрузка дисков для Raspberry Pi и подобных устройств
- **BOOTP** — для старых систем, не поддерживающих PXE
- **HTTP Boot** — для современных UEFI-систем, загрузка образов через HTTP

---

## Преимущества сетевой установки

| Преимущество | Описание |
|--------------|----------|
| **Масштабируемость** | Установка на множество компьютеров одновременно без физических носителей |
| **Автоматизация** | Использование скриптов и предварительно настроенных конфигураций |
| **Централизованное управление** | Упрощает обновление и поддержку образов ОС |
| **Снижение затрат** | Экономия на физических носителях и их распространении |

## Пример использования PXE

**Сценарий:** в компании 100 новых компьютеров, на все нужно установить Ubuntu.

### Пошаговая схема

1. **Настройка DHCP-сервера**
   - Выдаёт IP-адреса
   - Указывает на TFTP-сервер с PXE-образом

2. **Настройка TFTP-сервера**
   - Содержит PXE-образ с минимальной ОС

3. **Настройка NFS/HTTP/FTP-сервера**
   - Содержит все установочные файлы Ubuntu

4. **Запуск на клиентах**
   - Клиенты получают IP → загружают PXE-образ → начинают установку

---

## Заключение

Сетевая установка с использованием PXE — мощный инструмент для системных администраторов, позволяющий эффективно и централизованно управлять установкой ОС на множество компьютеров.

> [!tip]
> **Netboot** — широкое понятие, охватывающее любую сетевую загрузку. **PXE** — самый распространённый стандарт, использующий DHCP и TFTP. Выбор зависит от ваших задач: для современных систем с UEFI можно рассмотреть HTTP Boot, для массовых развёртываний в корпоративной среде — классический PXE.
