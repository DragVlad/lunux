# Лекция: Безопасность сервера — введение и основные концепции

## Ограничения лекции

Безопасность — огромная тема. В рамках этого материала мы **не будем** углубляться в:
- Безопасность кластеров (Kubernetes, OpenStack)
- Корпоративные сети и политики (SOC, IAM, SIEM)
- Полную защиту рабочих станций
- Глубокую криптографию

**Фокус лекции**: защита **одиночного сервера** в трёх базовых сценариях:

| Сценарий | Пример | Основные угрозы |
|----------|--------|------------------|
| **Публичный сервер** | VPS, веб-сайт, публичный API | Ботнеты, брутфорс, DDoS, взлом SSH |
| **Приватный с ограниченным доступом** | База данных, VPN-сервер | Атаки через доступные порты, компрометация бэкенда |
| **Изолированный (через bastion-host)** | Внутренняя инфраструктура | Компрометация администраторов, supply chain атаки |

**Ключевые аспекты защиты**:
- Аутентификация и контроль доступа
- Работа с уязвимостями
- Минимизация поверхности атаки
- Шифрование и ограничение привилегий

## Безопасность — это процесс, а не состояние

Одна из самых распространённых ошибок — считать безопасность фиксированным состоянием. В реальности она требует непрерывного внимания.

### Примеры, почему безопасность динамична

1. **Управление уязвимостями**
   - Сервер защищён при установке → через месяц выходят критические обновления → администратор не установил (боится сломать приложение) → через 3 месяца хакеры разрабатывают эксплойт → сервер скомпрометирован

2. **Бесконечный цикл патчей**
   - Разработчики выпускают ПО → хакеры находят уязвимость → выпускается патч → цикл повторяется

3. **Пароли и учётные записи**
   - Пароль может утечь через год
   - Сотрудник использует один пароль везде
   - Уволенный сотрудник сохраняет доступ
   - Сотрудник накапливает привилегии при переходах между отделами

4. **Защита сети**
   - Администратор временно открывает порт и забывает закрыть
   - Случайно включается вход по паролю в SSH
   - Пользователь создаёт проброс порта через NAT "для удобства"

### Выводы

Безопасность требует:
- **Постоянного обновления** — слежение за CVE, установка патчей
- **Мониторинга** — анализ логов, активных подключений
- **Аудитов** — регулярные проверки и пентесты
- **Адаптации** — изменение настроек под новые угрозы

## Почему безопасность критична? Триада CIA

Вся информационная безопасность строится на трёх принципах:

| Принцип | Суть | Примеры угроз |
|---------|------|----------------|
| **Конфиденциальность** | Защита от несанкционированного доступа | Взлом SSH, утечка БД, бэкдоры |
| **Целостность** | Защита от несанкционированного изменения | Подмена данных, внедрение вредоносного кода, ransomware |
| **Доступность** | Обеспечение работоспособности | DDoS, майнинг, удаление данных без бэкапов |

### Реальные примеры

| Принцип | Инцидент | Последствия |
|---------|----------|-------------|
| Конфиденциальность | Equifax (2017) | Утечка 148 млн записей через уязвимость в Apache Struts |
| Целостность | WannaCry (2017) | 500 000+ компьютеров зашифровано, паралич больниц и аэропортов |
| Доступность | Botnet Mirai (2016) | Недоступны Twitter, Netflix, PayPal |

## Модели угроз: типы атакующих

### 1. Скрипт-кидди (Script Kiddies)
*Новички с готовыми инструментами*

| Характеристика | Описание |
|----------------|----------|
| **Цели** | Развлечение, хаос, вандализм, ботнеты |
| **Методы** | Сканеры (Shodan, Nmap), брутфорс, готовые эксплойты (Metasploit) |
| **Опасность** | Автоматизированные атаки на тысячи серверов |

**Защита**: сложные пароли, закрыть парольный SSH, fail2ban, обновления.

### 2. Хактивисты (Hacktivists)
*Идеологически мотивированные атаки*

| Характеристика | Описание |
|----------------|----------|
| **Цели** | Саботаж, публикация данных, "наказание" противников |
| **Методы** | DDoS, дефейс сайтов, утечки, шифрование |
| **Опасность** | Политически или социально значимые проекты |

**Защита**: DDoS-защита (Cloudflare), rate limiting, изоляция сервисов (SELinux).

### 3. Киберпреступники
*Финансово мотивированные атаки*

| Характеристика | Описание |
|----------------|----------|
| **Цели** | Кража данных, выкуп за расшифровку, продажа информации |
| **Методы** | Фишинг, шифровальщики (REvil, WannaCry), SQL-инъекции |
| **Опасность** | Наиболее массовая угроза для большинства серверов |

**Защита**: 2FA, мониторинг входа (auditd, fail2ban), регулярные бэкапы (borg, restic).

### 4. APT-группы (Advanced Persistent Threat)
*Государственные и корпоративные хакеры*

| Характеристика | Описание |
|----------------|----------|
| **Цели** | Кибершпионаж, долгосрочное присутствие, саботаж |
| **Методы** | 0-day уязвимости, spear-phishing, supply chain атаки |
| **Опасность** | Государственные структуры, финансовый сектор, критическая инфраструктура |

**Защита**: контроль соединений (nftables, Snort), IDS/IPS (Suricata, Wazuh), аудит безопасности (Lynis, OpenSCAP).

> **Важно**: Если вам угрожают типы 3 и 4 — создавайте профессиональную ИБ-команду.

## Основные векторы атак

### 1. Социальная инженерия

| Вид | Описание |
|-----|----------|
| **Фишинг** | Поддельные письма для кражи паролей |
| **Вишинг** | Мошенничество по телефону |
| **Фейковые сайты** | Имитация легитимных сервисов |

**Защита**: 2FA, обучение персонала, «доброкачественная паранойя».

### 2. Уязвимости в ПО

| Термин | Значение |
|--------|----------|
| **0-day** | Уязвимость без патча |
| **N-day** | Известная уязвимость с патчем |
| **CVE** | База известных уязвимостей |
| **RCE** | Удалённое выполнение кода |

**Защита**: регулярные обновления, мониторинг CVE, отключение ненужных сервисов.

### 3. Brute-force атаки

**Защита**:
- Отключить вход по паролю → использовать SSH-ключи
- fail2ban, iptables для ограничения попыток
- Сложные уникальные пароли

### 4. DDoS-атаки

| Тип | Примеры |
|-----|---------|
| **Сетевые (Volumetric)** | UDP Flood, ICMP Flood, DNS Amplification |
| **Протокольные (Protocol)** | SYN Flood, Slowloris, Teardrop |
| **Прикладные (Application)** | HTTP Flood, Cache Busting, Slow POST |

**Защита**: Cloudflare, rate limiting (mod_evasive), балансировка нагрузки.

### 5. Вредоносные вложения и загрузки

**Защита**: не запускать файлы из ненадёжных источников, ClamAV, AppArmor/SELinux.

### 6. Supply Chain атаки

*Компрометация зависимостей и пакетов*

**Примеры**: вредоносные NPM-пакеты, заражённые обновления, бэкдоры в Docker-образах.

**Защита**: проверка источников, GPG-подписи репозиториев, изоляция (Docker, chroot).

### 7. Атаки на сеть и перехват трафика

| Вид | Описание |
|-----|----------|
| **MITM** | Подмена данных между сервером и клиентом |
| **DNS-спуфинг** | Подмена DNS-запросов |
| **ARP-спуфинг** | Подмена MAC-адресов в локальной сети |

**Защита**: TLS/VPN, DNSSEC, nftables/iptables, сегментирование (VLAN).

### 8. Атаки через внутреннюю инфраструктуру

**Методы**: боковое перемещение, утечка SSH-ключей, компрометация внутренних API.

**Защита**: сегментация сети (VLAN, Zero Trust), firewalld/nftables, контроль SSH-ключей.

## Цена взлома: стоит ли атаковать вашу систему?

### Взлом — это инвестиция для атакующего

**Факторы сложности атаки**:
- Защищённость системы (брандмауэр, обновления)
- Методы аутентификации (2FA, SSH-ключи)
- Наличие мониторинга
- Сегментация инфраструктуры

### Стоимость атаки vs. потенциальная выгода

| Повышают привлекательность | Снижают привлекательность |
|---------------------------|---------------------------|
| Ценные данные (финансы, клиенты) | Хорошая защита (блокировки, 2FA) |
| Возможность вымогательства | Минимальная поверхность атаки |
| Использование в ботнетах | Регулярные обновления |
| Политическая значимость | Отсутствие ценных данных |

### Как сделать сервер непривлекательной целью?

1. **Минимизация поверхности атаки**
   - Отключить ненужные сервисы и порты
   - Использовать проверенные пакеты
   - Принцип минимального доступа

2. **Сложность эксплуатации**
   - Ограничение входа по IP, VPN
   - 2FA
   - Контроль логов

3. **Скрытие системы**
   - Отключить баннеры с версиями ПО
   - Минимизировать публичную информацию
   - Нестандартные порты для управления

## Оценка рисков и управление ими

### Золотое правило

> Не нужно защищаться от всего подряд. Тратить ресурсы на защиту угроз, которые реально актуальны.

### Оценка рисков: три вопроса

1. **Что представляет ценность?** (данные, сервисы, учётные записи)
2. **Кто может атаковать?** (сканеры, киберпреступники, инсайдеры)
3. **Какова вероятность и последствия?**

### Стратегии управления рисками

| Стратегия | Действие | Пример |
|-----------|----------|--------|
| **Принять** | Угроза маловероятна или ущерб мал | — |
| **Снизить** | Уменьшить вероятность или последствия | Шифрование дисков, бэкапы |
| **Передать** | Использовать внешние сервисы | Облачная DDoS-защита |
| **Избежать** | Убрать сервер из зоны риска | Не держать данные в открытом доступе |

### Минимизация рисков: базовые меры

- Отключить ненужные сервисы и порты
- Использовать актуальные версии ПО
- Включить 2FA
- Регулярно проверять логи
- Делать резервные копии

## Шпаргалка: основные команды и инструменты

```bash
# Межсетевой экран
sudo ufw status                    # Статус UFW
sudo ufw allow 22/tcp              # Разрешить SSH
sudo ufw enable                    # Включить UFW

# Ограничение попыток входа
sudo apt install fail2ban
sudo systemctl enable fail2ban

# Проверка открытых портов
sudo ss -tlnp
sudo netstat -tulpn

# Обновление системы
sudo apt update && sudo apt upgrade -y
sudo apt autoremove

# Мониторинг логов
sudo tail -f /var/log/auth.log     # Логи аутентификации
sudo journalctl -xe                # Системные логи

# Резервное копирование (пример с Borg)
sudo apt install borgbackup
borg init --encryption=repokey /path/to/repo

# Аудит безопасности
sudo apt install lynis
sudo lynis audit system
```

## Итоговые тезисы

1. **Безопасность — это процесс**, а не разовая настройка
2. **Фокус на реальных угрозах** — не защищайтесь от APT, если у вас маленькая компания
3. **Триада CIA**: конфиденциальность, целостность, доступность
4. **Модель угроз** помогает понять, кто и зачем будет вас атаковать
5. **Чем дороже взлом**, тем меньше вероятность, что вас атакуют
6. **Оценка рисков** — баланс между затратами на защиту и реальными угрозами
