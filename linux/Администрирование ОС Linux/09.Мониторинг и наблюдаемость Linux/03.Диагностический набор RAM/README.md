# RAM: мозг и буфер

Если CPU — это сердце, то память — это мозг. Важное правило касательно памяти в Linux:

> **Свободная память в Linux — это потерянная память.**

Если видно, что память используется, это хорошо. Значит, ядро кэширует, буферизует и готово быстро отдать всё нужное обратно, оптимизируя работу системы. Нужно смотреть на `available` как на источник доступной памяти. Это честный прогноз, сколько можно реально выделить под приложения без риска уйти в свопинг.

## free

В любой непонятной ситуации начинается с классической утилиты по анализу памяти:

```bash
free -h
```

```text
              total        used        free      shared  buff/cache   available
Mem:          964Mi       149Mi       119Mi       1.0Mi       696Mi       656Mi
Swap:            0B          0B          0B
```

**Особенности интерпретации:**

Часть памяти резервируется ядром для собственных нужд (хранения структур данных, драйверов) и не отображается как доступная для приложений. Это нормально. На практике для анализа ориентируются на цифры, которые показывает утилита.

## top/htop про память

Обе утилиты помимо загрузки CPU и LA позволяют посмотреть утилизацию памяти.

В `top` строка `KiB Mem` показывает всё то же самое. Чтобы узнать, кто конкретно потребляет память — нажать `M` для сортировки по `%MEM`. В `htop` — клик мышкой или `F6`.

## vmstat

`vmstat` — одна из базовых диагностических команд в Linux, входящая в пакет `procps` или `procps-ng`. Она предназначена для получения краткой, но ёмкой сводки о текущем состоянии системы, охватывая сразу несколько аспектов — процессы, память, swap, I/O, системные события и загрузку CPU.

```bash
vmstat 1 5
```

Команда выводит сводку каждую секунду 5 раз.

**Разбор полей vmstat:**

| Группа | Поле | Описание |
|--------|------|----------|
| **procs (процессы)** | `r` | Количество процессов, ожидающих CPU (run queue). Если больше количества ядер — нагрузка |
| | `b` | Количество процессов в состоянии непрерываемого сна (ожидание I/O). Рост может говорить о проблемах с дисками |
| **memory (память)** | `swpd` | Объём использованной swap-памяти (в КБ) |
| | `free` | Доступная свободная физическая память |
| | `buff` | Буферы, выделенные под блочные устройства |
| | `cache` | Страничный кеш — файловые данные в памяти |
| **swap** | `si` | Swap-in: объём данных, загружаемых из swap в RAM (КБ/сек) |
| | `so` | Swap-out: объём выгружаемых из RAM в swap |
| **Ввод-Вывод (io)** | `bi` | Количество блоков, прочитанных с диска (КБ/сек) |
| | `bo` | Количество блоков, записанных на диск |
| **system** | `in` | Количество аппаратных прерываний в секунду |
| | `cs` | Количество переключений контекста между процессами |
| **cpu** | `us` | Время на пользовательские процессы |
| | `sy` | Время на выполнение ядром системных вызовов |
| | `id` | Idle: процессор свободен |
| | `wa` | Wait I/O: ожидание операций ввода/вывода |
| | `st` | Steal time: «украденное» время у виртуальной машины |

**Как использовать vmstat для диагностики:**

1. **Процессы (r и b):**
   - `r > N_ядер`: CPU — узкое место.
   - `b > 0`: процессы ждут I/O, посмотреть `iostat` или `iotop`.

2. **Память (si/so):**
   - `si` и `so` растут: идёт активный свопинг — не хватает RAM.
   - `swpd` велик: приложение уже «вытеснено» из памяти.

3. **IO (bi/bo):**
   - Высокий `bo`: интенсивная запись — проверить активность логирования, резервных копий.
   - Высокий `bi`: много чтений — возможно, связано с базой данных.

4. **CPU (us/sy/wa):**
   - `us` высокий — активные пользовательские приложения.
   - `sy` высокий — частые системные вызовы, интенсивный ввод-вывод.
   - `wa` высокий — CPU простаивает, ожидая диска или сети.

## Учебные примеры с памятью

### Симуляция утечки памяти в Python

```python
# Постепенно съедаем память
import time

leak = []
while True:
    leak.append(' ' * 10**6)  # Добавляем мегабайт пустой строки
    time.sleep(0.1)
```

В `top` или `htop` видно, как процесс раздувается, `used` растёт, а `available` падает.

### Симуляция активного использования swap

```python
# Съедаем всю RAM, заставляем лезть в swap
import time

chunks = []
try:
    while True:
        chunks.append(bytearray(100 * 1024 * 1024))  # +100 МБ каждый раз
        time.sleep(0.2)
except MemoryError:
    print("Out of memory!")
```

Если swap доступен и есть место, система начнёт его использовать — сбрасывать неиспользуемые страницы памяти на диск. Если swap отсутствует или заполнен — включится OOM killer.

## OOM killer

Когда в системе заканчивается оперативная память и своп, Linux запускает **OOM killer** (Out-Of-Memory Killer). Это встроенный механизм ядра, который спасает систему от полной остановки, убивая самые «прожорливые» процессы.

Ядро не стреляет вслепую — у каждого процесса есть **OOM score**. Чем выше этот счёт — тем больше шансов, что именно этот процесс будет уничтожен.

**На выбор влияют:**
- Сколько памяти потребляет процесс.
- Является ли он root-процессом (root защищён больше).
- Установлены ли флаги защиты (например, `oom_score_adj`).
- Запущен ли процесс сессией пользователя или системной службой.

**Как узнать, кто попал под раздачу:**

```bash
dmesg | grep -i 'killed process'
```

Пример вывода:

```text
Out of memory: Kill process 12345 (python) score 987 or sacrifice child
Killed process 12345 (python) total-vm:123456kB, anon-rss:100000kB, file-rss:500kB, shmem-rss:0kB
```

## swappiness

Параметр `swappiness` определяет, насколько охотно ядро будет выгружать данные из оперативной памяти в swap. Значение — от 0 до 100:

```bash
cat /proc/sys/vm/swappiness
```

- `60` (значение по умолчанию) — ядро начинает активно использовать swap при малейшем намёке на нехватку RAM. Нормально для серверов с предсказуемыми нагрузками.
- `10` — ядро будет держаться за оперативку до последнего и свопить только в крайнем случае. Подходит для приложений, чувствительных к задержкам.
- `0` — почти не используем swap вообще. **Это не значит, что swap отключён**. Просто система будет избегать его максимально долго.

**Изменение swappiness:**

```bash
# временно (до перезагрузки)
sudo sysctl vm.swappiness=10

# на длительный срок
sudo nano /etc/sysctl.conf
vm.swappiness = 10
```

## Современные альтернативы

| Инструмент | Особенности |
|------------|-------------|
| [smem](https://github.com/giampaolo/smem) | Учитывает shared memory, показывает Proportional Set Size (PSS) — точнее, чем ps или top |
| [ps_mem](https://github.com/pixelb/ps_mem) | Простой скрипт — быстро показывает реальное потребление памяти |
| [btop++](https://github.com/aristocratos/btop) | Графика, интерфейс, детальный breakdown по памяти, swap и cache |
| [glances](https://nicolargo.github.io/glances/) | Универсальный агент. Мониторинг в браузере, API, веб-дашборд |
| [meminfo-top](https://github.com/pixelb/meminfo-top) | Специализирован для чтения `/proc/meminfo` в реальном времени |
| [dstat](https://github.com/dagwieers/dstat) | Расширенный `vmstat` с графическим выводом и цветами |
| [atop](https://www.atoptool.nl/) | Подробный отчёт по ресурсам, включая swap, CPU, сеть, процессы |
| [netdata](https://www.netdata.cloud/) | Агент с веб-интерфейсом, показывает в реальном времени всю систему |
| [collectl](https://sourceforge.net/projects/collectl/) | Системный монитор с логированием. Удобен для анализа истории |
