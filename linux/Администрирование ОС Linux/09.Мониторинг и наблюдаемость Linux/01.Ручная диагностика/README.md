# Ручная диагностика Linux: источники системных метрик

Прежде чем погрузиться в мир больших систем мониторинга, таких как Zabbix или Prometheus, необходимо научиться "говорить" с системой напрямую. Это те самые команды, которые вводятся в консоль, когда есть только SSH-доступ и несколько минут, чтобы найти виновника проблемы.

## Откуда берутся метрики в Linux

Большинство системных метрик в Linux доступны напрямую из виртуальных файловых систем `/proc` и `/sys`, которые предоставляются ядром. Эти каталоги не содержат обычных файлов в привычном понимании: они являются интерфейсами к внутренним структурам ядра, отображающими текущие значения (из рантайма) в текстовом виде.

- `/proc/` — отражает текущее состояние процессов и подсистем ядра (CPU, память, прерывания и др.)
- `/sys/` — предоставляет доступ к устройствам, драйверам и параметрам ядра в виде иерархии (часто используется для настройки)

## Файл /proc/stat

Файл `/proc/stat` содержит статистику использования CPU и ряд других общесистемных счётчиков.

```bash
cat /proc/stat
```

```text
cpu  2615 149 1750 21618 317 0 167 0 0 0
cpu0 2615 149 1750 21618 317 0 167 0 0 0
intr 86600 47 9 0 0 4572 0 0 0 0 0 0 0 160 ….
ctxt 853714
btime 1749980299
processes 19489
procs_running 1
procs_blocked 0
softirq 209021 0 18169 76 17013 32801 0 1 0 0 140961
```

Это последовательность счётчиков, увеличивающихся с момента загрузки. Мониторинговые программы вычитают предыдущие значения из текущих, чтобы получить загрузку за интервал.

| Поле | Описание |
|------|----------|
| **CPU** | Суммарная информация по всем ядрам CPU с числовыми значениями в джиффи (jiffies). Порядок значений (первые 10 полей):<br>1. `user` — время в режиме пользователя<br>2. `nice` — пользовательский режим с nice<br>3. `system` — время в режиме ядра<br>4. `idle` — время простоя<br>5. `iowait` — ожидание ввода-вывода<br>6. `irq` — обслуживание аппаратных прерываний<br>7. `softirq` — обслуживание программных прерываний<br>8. `steal` — "украденное" время на виртуальных машинах<br>9. `guest` — время на выполнение гостевых ОС<br>10. `guest_nice` — как guest, но с приоритетом nice |
| **CPU0** | То же самое, но только для первого логического ядра |
| **INTR** | Информация об аппаратных прерываниях. Первое число — общее количество прерываний |
| **ctxt** | Количество переключений контекста между процессами |
| **btime** | Момент загрузки системы в формате Unix-времени |
| **processes** | Количество созданных процессов с момента загрузки системы |
| **procs_running / procs_blocked** | Текущие состояния процессов: `procs_running` — число процессов в run queue; `procs_blocked` — число процессов, ожидающих ввода-вывода |
| **softirq** | Статистика по software interrupts (таймеры, сетевые события, задачи от kernel thread) |

**Что важно запомнить:**
- `/proc/stat` — ключевой источник данных для метрик CPU.
- Используется большинством систем мониторинга (Prometheus, Zabbix, collectd и др.).
- Метрики не являются "готовыми процентами" — их нужно вычислять через дельты.

```text
%idle  = Δ idle / Δ total
%user  = Δ user / Δ total
```

Различные локальные утилиты для наблюдения за системой (`top`, `htop`, `vmstat`, `sar`, `node_exporter`) читают эту информацию (и ряд других файлов из псевдофайловых систем), рассчитывают разницы, преобразуют форматы и выдают в удобном для восприятия виде.

## Load Average

Файл `/proc/loadavg` содержит информацию о **средней нагрузке на систему** за последние 1, 5 и 15 минут, а также сведения о состоянии очереди процессов и PID последнего запущенного процесса.

```bash
cat /proc/loadavg
```

```text
0.25 0.70 1.30 2/100 20749
```

**Рассмотрим каждое поле подробнее:**

| Поле | Значение в примере | Что означает |
|------|-------------------|--------------|
| 1 | `0.25` | Load average за последнюю минуту |
| 2 | `0.70` | Load average за последние 5 минут |
| 3 | `1.30` | Load average за последние 15 минут |
| 4 | `2/100` | 2 — количество текущих активных процессов (в R и D состояниях); 100 — общее число процессов в системе |
| 5 | `20749` | PID последнего запущенного процесса |

Load Average (LA) показывает **среднее количество процессов**, которые находятся в одном из двух состояний:
1. `R` (running) — процесс выполняется на CPU или готов к выполнению.
2. `D` (uninterruptible sleep) — процесс "спит", ожидая завершения операций ввода/вывода.

Важно: в отличие от CPU utilization, Load Average учитывает не только реальную нагрузку на CPU, **но и процессы, ожидающие ресурсов**, в частности дисковый ввод/вывод.

**Интерпретация значений LA:**

- LA ≈ N, где N — количество ядер → **CPU полностью загружен**, но не перегружен.
- LA > N — **очереди на CPU**: процессов больше, чем ядер.
- LA ≪ N — **CPU простаивает**, запас по вычислениям есть.

| Система | Кол-во ядер | LA | Что это значит |
|---------|-------------|----|----------------|
| 4-ядерная VM | 4 | 3.8 | Почти полная загрузка, но без очереди |
| 4-ядерная VM | 4 | 6.2 | Перегрузка: процессы ждут CPU |
| 8-ядерный сервер | 8 | 1.0 | Система в расслабленном состоянии |

**Важные замечания:**
- LA — это **скользящее среднее**, а не моментальный снимок.
- Высокий LA не всегда связан с CPU — может быть признаком I/O-зависимости.
- Мониторинг и алертинг по LA требуют корреляции с количеством ядер и метриками CPU + I/O.

**Примерные выводы на основе анализа LA:**
- Высокий LA + низкий CPU utilization → вероятно, I/O-задержки.
- Высокий LA + высокий %user CPU → перегрузка CPU.
- Пиковый LA на 1 минуту → кратковременный всплеск нагрузки.
- Рост по всем трём (1, 5, 15 минут) → устойчивое ухудшение состояния.

## Память: /proc/meminfo

Файл `/proc/meminfo` — один из важнейших источников информации о состоянии оперативной памяти в Linux. Это **виртуальный файл**, автоматически обновляемый ядром.

```bash
cat /proc/meminfo
```

```text
MemTotal:         988244 kB
MemFree:          204220 kB
MemAvailable:     689444 kB
Buffers:           46676 kB
Cached:           551180 kB
…
```

**Ключевые поля:**

| Поле | Что означает |
|------|--------------|
| `MemTotal` | Общий объём оперативной памяти |
| `MemFree` | Свободная (неиспользуемая) память. Обычно **маленькая** — это нормально для Linux |
| `MemAvailable` | **Оценка реально доступной памяти**: сколько ещё можно выделить под приложения без выхода в swap. Самая важная метрика |
| `Buffers` | Память под буферы блочных устройств |
| `Cached` | Память под кэш файлов (Page Cache) |
| `SwapTotal` | Объём файла/раздела подкачки |
| `SwapFree` | Свободно в swap. Если swap активно используется — возможна нехватка RAM |
| `SwapCached` | Данные, недавно выгруженные в swap, но всё ещё хранимые в RAM |

`MemFree` ≠ свободная память. Это скорее "не занятая ни подо что" память. В Linux почти вся неиспользуемая работающими процессами память используется под кэш — это не проблема, а фоновая автоматическая оптимизация производительности.

Главная метрика для оценки доступности памяти — `MemAvailable`. Именно она говорит, есть ли ещё запас памяти для запуска новых процессов без использования swap.

**Рекомендации для мониторинга:**
- Метрика `MemAvailable` должна собираться и анализироваться — именно она отражает реальное состояние доступности и занятости памяти.
- Метрика `SwapUsed` (или `SwapFree`) даёт повод начать расследование, кто потребляет память.

**Диаграмма распределения физической памяти:**

В Linux большая часть памяти занята под кэш (`Cached`) — это нормально, так как ядро использует неиспользуемую RAM под буферизацию и ускорение операций. Реально используемой приложениями памяти (`Used (apps)`) гораздо меньше. Это объясняет, почему `MemFree` может быть низким, но система всё ещё далека от нехватки памяти.

## Процессы: /proc/<PID>/

Для каждого процесса, запущенного в системе, ядро создаёт собственную директорию в каталоге `/proc/<PID>/`.

### /proc/<PID>/status

Файл, содержащий сводную информацию о процессе:
- текущее состояние (работает, спит, завершён и т.д.)
- UID и GID процесса
- потребление памяти (VmSize, VmRSS, VmData, VmStk, VmExe и др.)
- флаги, родительский PID и прочее

```bash
cat /proc/19424/status
```

```text
Name:    bash
Umask:   0002
State:   S (sleeping)
Tgid:    19424
Ngid:    0
Pid:     19424
PPid:    19423
...
```

### /proc/<PID>/io

Содержит статистику ввода-вывода (в байтах):

```bash
cat /proc/19424/io
```

```text
rchar: 509754
wchar: 14076
syscr: 1144
syscw: 317
read_bytes: 626688
write_bytes: 0
cancelled_write_bytes: 0
```

| Поле | Значение | Расшифровка |
|------|----------|-------------|
| rchar | 509754 байт | Сколько байт прочитано через системные вызовы |
| wchar | 14076 байт | Сколько байт записано пользователем через вызовы write() |
| syscr | 1144 | Сколько системных вызовов чтения сделал процесс |
| syscw | 317 | Сколько вызовов записи сделал процесс |
| read_bytes | 626688 байт | Сколько байт реально прочитано с диска |
| write_bytes | 0 | Сколько байт реально записано на диск |
| cancelled_write_bytes | 0 | Сколько записей было отменено |

### /proc/<PID>/stat

Машиночитаемый файл со множеством числовых параметров: время в user/system mode, число тиков на процессоре, информация о приоритетах, позиция в очереди планирования и др. Используется в большинстве утилит, собирающих CPU-статистику.

**Как это используется в мониторинге:**

Мониторинг-агенты (node_exporter, collectd, custom-скрипты) часто сканируют `/proc/`, перебирая все PID и обрабатывая интересующие файлы. На основе этих данных можно:
- определить самые ресурсоёмкие процессы (по CPU, памяти, IO)
- отследить "утечки" памяти по росту VmRSS или VmSize
- построить персональный "top" или отчёт о подозрительной активности
- выявить "зависшие" процессы, застрявшие в IO (State: D)

## Диск и I/O: /proc/diskstats

Файл `/proc/diskstats` — один из главных источников **низкоуровневой статистики по работе блочных устройств** (дисков, SSD, виртуальных томов).

```bash
cat /proc/diskstats
```

```text
8   0 sda 523040 189 20284310 382912 221098 130409 13991234 481232 0 281720 864144
```

**Интерпретация значений:**

| Поле | Значение | Что это значит |
|------|----------|----------------|
| reads completed | 523040 | Количество завершённых операций чтения |
| sectors read | 20284310 | Сколько секторов было прочитано |
| read_time (мс) | 382912 | Время, затраченное на чтение |
| writes completed | 221098 | Количество завершённых операций записи |
| sectors written | 13991234 | Сколько секторов было записано |
| write_time (мс) | 481232 | Время, затраченное на запись |
| IO time | 864144 | Общее время, когда устройство было занято операциями |

**На основе этих счётчиков строятся показатели:**

- **IOPS (Input/Output Operations per Second)**: `iops = (delta_reads + delta_writes) / delta_time`
- **Пропускная способность (throughput)**: `bytes/sec = delta_sectors * 512 / delta_time` (если сектор 512 байт)
- **Время ожидания и обслуживания** (await): `await = total_time / completed_ops`
- **Загрузка диска (%util)** — доля времени, когда хотя бы одна операция была в обработке. Если util ≈ 100%, диск — узкое место.

Кроме `/proc/diskstats`, есть `/sys/block/<dev>/stat` с похожей информацией.

## Сеть: /proc/net/dev

Файл `/proc/net/dev` — ключевой источник информации о состоянии сетевых интерфейсов в Linux.

```bash
cat /proc/net/dev
```

```text
Inter-|   Receive                                                |  Transmit
 face |bytes    packets errs drop fifo frame compressed multicast|bytes    packets errs drop fifo colls carrier compressed
  eth0: 1234567  1234    0    0    0     0          0         0  7654321  5678    0    0    0     0       0          0
```

**Основные поля:**

| Группа | Поле | Описание |
|--------|------|----------|
| Receive | bytes | Общий объём полученных данных (в байтах) |
| Receive | packets | Количество полученных пакетов |
| Receive | errs | Количество ошибок (например, CRC) |
| Receive | drop | Количество отброшенных пакетов |
| Transmit | bytes | Общий объём переданных данных |
| Transmit | packets | Количество переданных пакетов |
| Transmit | errs | Количество ошибок при передаче |
| Transmit | drop | Количество отброшенных пакетов при передаче |

**На основе этих данных строятся метрики:**

- **Throughput (пропускная способность, текущий трафик)**: изменение поля bytes за 1 секунду даёт байт/с.
- **PPS (Packets Per Second)**: оценка динамики входящих/исходящих пакетов.
- **Сетевые ошибки**: рост errs или drop — сигнал проблем с каналом, оборудованием или перегрузкой.

**Практическое применение:**
- Если график bytes стабильно приближается к физическому лимиту интерфейса (например, 1 Gbps ≈ 125 MB/s), это сигнал о **перегрузке канала**.
- Если errs или drop начинают расти — стоит проверить настройки duplex/speed, кабель или заменить NIC.
- Для балансировки нагрузки анализ pps помогает определить, когда нужно масштабировать или ограничивать трафик.

## Температура и электропитание

Мониторинг аппаратных параметров реализован через виртуальную файловую систему `/sys`.

**Температура CPU и чипсета:**

```bash
cat /sys/class/thermal/thermal_zone*/temp
```

Значение — в тысячных долях градуса Цельсия (например, 42000 = 42.0°C).

**Скорость вентиляторов:**

```bash
cat /sys/class/hwmon/hwmon*/fan*_input
```

Возвращает скорость вращения вентилятора в об/мин.

**Энергопитание и батарея (для ноутбуков):**

```bash
ls /sys/class/power_supply/
# Например, BAT0/capacity, BAT0/status, AC/online
```

Помимо этого можно отслеживать SMART-данные дисков и целостность аппаратных рейдов.

## Логи системы

Мониторинг — это не только метрики, но и **логи событий**, особенно системного и ядра. Источники данных, такие как syslog или журнал ядра (`dmesg`), критически важны. Они могут содержать информацию о таких событиях, как ошибки ядра, аварийные завершения процессов, сбои оборудования, что по умолчанию не отражается в метриках, но логируется системой.

Например, ядро может логировать, что произошёл **OOM Kill** (механизм Out-Of-Memory Killer уничтожил процесс из-за нехватки памяти) — и эту информацию можно увидеть только в логе `/var/log/kern.log` или `dmesg`. Мониторинг может быть настроен на обнаружение таких сообщений с помощью скриптов или лог-агентов, так как событие типа OOM Kill — явный индикатор проблемы.
