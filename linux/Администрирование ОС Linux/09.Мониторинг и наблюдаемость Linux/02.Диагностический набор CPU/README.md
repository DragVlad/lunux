# CPU: сердце системы

Нагрузка на CPU в Linux — это не одна метрика, а целый набор показателей, каждый из которых рассказывает о своей части происходящего.

## Load Average

Load Average — это набор из трех метрик (за 1, 5 и 15 минут), которые можно наблюдать совместно с другими значениями с помощью нескольких утилит.

### uptime

Команда `uptime` помимо Load Average показывает, сколько времени система работает с момента последнего перезапуска.

```bash
uptime
```

```text
 12:34:56 up 10 days,  3:45,  2 users,  load average: 0.25, 0.70, 1.30
```

### top и htop

`top` и `htop` — классические инструменты для анализа ресурсов, в первую очередь нагрузки на CPU.

`top` — это старая добрая классика. Работает, много ресурсов не потребляет, но интерфейс может показаться олдскульным.

`htop` — цветной и интерактивный аналог с поддержкой мыши, различными режимами и меню. Требует установки отдельно.

**В top:**

Запускается командой `top`. Нажатие `1` показывает нагрузку по каждому ядру. В верхней панели отображаются основные категории использования процессорного ресурса:

- `%us` — сколько CPU уходит на пользовательские процессы (веб-серверы, бэкенды, скрипты).
- `%sy` — нагрузка на ядро: системные вызовы, драйверы.
- `%wa` — ожидание ввода-вывода (диски, сетевые файловые системы).
- `%id` — idle (простой). Чем больше — тем лучше.

**Управление в top:**

| Действие | Клавиша |
|----------|---------|
| Переключение режима отображения памяти | `m` |
| Сортировка по использованию памяти | `M` |
| Сортировка по использованию CPU | `P` |
| Сортировка по времени работы | `T` |
| Выбор отображаемых полей | `f` |
| Режим дерева процессов | `V` |
| Фильтрация по пользователю | `u` → ввод имени |
| Завершение процесса | `k` → ввод PID и сигнала |
| Изменение интервала обновления | `d` → ввод секунд |

**В htop:**

- Цветные полоски CPU / RAM / Swap в реальном времени.
- Режим дерева процессов (клавиша `t` или `F5`).
- Фильтрация по команде, PID, пользователю (`F3` и `F4`).
- Сортировка по любой метрике (клик или `F6`).
- Конфигурация и сохранение настроек (`F2`).

## mpstat

`mpstat` входит в пакет `sysstat` и показывает статистику по каждому ядру процессора.

```bash
mpstat -P ALL 1 5
```

Эта команда покажет статистику по каждому ядру, обновляя данные раз в секунду пять раз подряд. Это особенно полезно, когда приложение перегружает лишь одно ядро (например, однопоточные программы).

**Основные поля mpstat:**

- `%usr` — процент времени, когда CPU занят пользовательскими процессами.
- `%sys` — нагрузка от ядра: драйверы, системные вызовы.
- `%iowait` — сколько времени CPU проводит в ожидании I/O-операций.
- `%idle` — свободное время процессора.

### Пример: симуляция загрузки одного ядра

```python
# Однопоточная нагрузка на одно ядро
while True:
    pass
```

Сохраняется в файл `burn_one_cpu.py` и запускается:

```bash
python3 burn_one_cpu.py &
```

После этого с помощью `mpstat` видно, как загрузка одного ядра стремится к 100%.

## sar

`sar` — инструмент для просмотра исторической статистики. Позволяет анализировать нагрузку, которая была в прошлом.

```bash
sar -u -f /var/log/sysstat/sa15
```

Показывает загрузку CPU за 15-е число.

`sar` — часть пакета `sysstat`, который пишет логи в фоновом режиме. Обычно собирает метрики каждые 10 минут. Позволяет просмотреть:
- Загрузку CPU по времени.
- Занятость дисков и I/O wait.
- Память, swap, сеть и Load Average.

**Настройка sysstat:**

```bash
sudo apt install -y sysstat
sudo nano /etc/default/sysstat

# Исправить:
ENABLED="true"

sudo systemctl enable --now sysstat
ls -l /var/log/sysstat/
sar -u -f /var/log/sysstat/sa$(date +%d)
```

## Примеры эмуляции нагрузки

Для экспериментов с искусственной нагрузкой на CPU можно использовать следующие скрипты.

### Загрузка всех ядер (многопоточная)

Создаёт по одному бесконечному процессу на каждое ядро.

```python
# Многопоточная нагрузка на все ядра
import multiprocessing

def load():
    while True: pass

if __name__ == "__main__":
    for _ in range(multiprocessing.cpu_count()):
        multiprocessing.Process(target=load).start()
```

### Рост Load Average

Создаёт много процессов, которые коротко висят в run queue.

```python
import multiprocessing
import time

def block():
    for _ in range(1000000):
        _ = sum(i*i for i in range(10))  # маленькая математика
    time.sleep(0.1)

if __name__ == "__main__":
    for _ in range(100):
        multiprocessing.Process(target=block).start()
```

### Нагрузка в kernel space (%sy)

Интенсивная работа с файловой системой и системными вызовами.

```python
import multiprocessing
import os
import time

def hammer():
    while True:
        for _ in range(1000):
            os.stat("/tmp")      # sys call
            os.getpid()          # sys call
            os.urandom(10)       # sys call
        time.sleep(0.01)

if __name__ == "__main__":
    for _ in range(50):
        p = multiprocessing.Process(target=hammer)
        p.start()
```

## Диагностика проблем

| Симптом | Вероятная причина | Действие |
|---------|-------------------|----------|
| **Высокий %us** | Пользовательские процессы потребляют CPU | Открыть `top`/`htop`, сортировка по `P`, найти виновника. Проверить код на неэффективность, зацикленность, GC в Java/Python |
| **Высокий %sy** | Нагрузка на ядро | Причины: сетевая активность, дисковая активность. Использовать `iostat`, `iotop`, `ss`, `perf top` |
| **Высокий %wa** | CPU ждёт ввода-вывода | I/O — узкое место. Использовать `iostat`, `fio`, `blktrace` для поиска проблемы |
| **Высокий Load Average, но высокий %idle** | Процессы не CPU ждут, а чего-то другого (диск, сеть) | Смотреть на %wa и iowait |

**Итог:** Метрика %CPU — только вершина айсберга. Без контекста она не даёт полной картины. Для понимания проблемы нужно смотреть на I/O, память, процессы и логи.
