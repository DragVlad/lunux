# Хранение данных в Linux: дисковые разделы

Наша сегодняшняя лекция посвящена обзору различных доступных вариантов хранилищ. Любая информационная система обеспечивает как минимум одну из сфер работы с данными — передачу, хранение или обработку. Сегодня мы затрагиваем сферу **хранения данных**.

---

## Дисковые разделы

Опуская технические детали подключения дисков (SATA, SCSI, SSD, HDD, NVME), вы получаете физическое хранилище некоторого объёма. Для начала его использования нужно создать **раздел**.

> **Дисковые разделы** — это логические сегменты на физическом диске, используемые для организации и управления данными.

### Схемы разделов: MBR vs GPT

| Характеристика | MBR | GPT |
|----------------|-----|-----|
| **Возраст** | IBM, 1983 год | UEFI, 1990-е годы |
| **Максимальный размер диска** | до 2 ТБ | до 9,4 зеттабайт |
| **Максимальное количество разделов** | 4 первичных (можно расширенные/логические) | до 128 |
| **Структура** | Один сектор в начале диска | Копии таблицы в начале и конце диска |
| **Отказоустойчивость** | Нет встроенной защиты | CRC-контроль + резервные копии |
| **Идентификация** | Нет | GUID (глобальный уникальный идентификатор) |

> [!tip]
> При установке новых систем или обновлении аппаратуры **рекомендуется использовать GPT** для максимальной производительности и надёжности.

## Обозначение дисков и разделов в Linux

В Linux каждый раздел воспринимается как отдельное **блочное устройство**. С точки зрения ОС нет разницы между работой с физическим диском или его разделом.

| Тип устройства | Обозначение | Пример |
|----------------|-------------|--------|
| Физический диск | `/dev/sdX` | `/dev/sda`, `/dev/sdb` |
| Раздел диска | `/dev/sdXN` | `/dev/sda1`, `/dev/sda2` |

> [!note]
> Для NVME-дисков обозначения выглядят как `/dev/nvme0n1`, `/dev/nvme0n1p1` и т.д.

## Практический пример работы с разделами

Предположим, у нас есть диск `/dev/sdc` объёмом 10 ГБ. Создадим на нём три раздела: 2 ГБ, 3 ГБ и 5 ГБ.

### Создание GPT-разделов

```bash
# Инициализация диска с GPT
sudo parted /dev/sdc mklabel gpt

# Создание разделов
sudo parted -a optimal /dev/sdc mkpart primary ext4 0% 2GB
sudo parted -a optimal /dev/sdc mkpart primary ext4 2GB 5GB
sudo parted -a optimal /dev/sdc mkpart primary ext4 5GB 10GB

# Создание файловых систем
sudo mkfs.ext4 /dev/sdc1
sudo mkfs.ext4 /dev/sdc2
sudo mkfs.ext4 /dev/sdc3

# Просмотр результата
lsblk /dev/sdc
```

### Полная очистка диска (перед созданием MBR)

```bash
# Запись нулей на весь диск
sudo dd if=/dev/zero of=/dev/sdc bs=4M status=progress

# Альтернативы:
# sudo shred -v -n 1 /dev/sdc
# sudo wipefs --all /dev/sdc
```

### Создание MBR-разделов

```bash
# Инициализация диска с MBR
sudo parted /dev/sdc mklabel msdos

# Создание разделов (команды те же)
sudo parted -a optimal /dev/sdc mkpart primary ext4 0% 2GB
sudo parted -a optimal /dev/sdc mkpart primary ext4 2GB 5GB
sudo parted -a optimal /dev/sdc mkpart primary ext4 5GB 10GB

# Создание файловых систем
sudo mkfs.ext4 /dev/sdc1
sudo mkfs.ext4 /dev/sdc2
sudo mkfs.ext4 /dev/sdc3
```

## Монтирование разделов

Создадим каталоги и смонтируем разделы:

```bash
# Создание точек монтирования
sudo mkdir -p /var/www/mysite
sudo mkdir -p /opt/myapp
sudo mkdir -p /var/mydatabase

# Монтирование разделов
sudo mount /dev/sdc1 /var/www/mysite
sudo mount /dev/sdc2 /opt/myapp
sudo mount /dev/sdc3 /var/mydatabase

# Проверка
df -h
```

---

## Автоматическое монтирование через /etc/fstab

Добавьте строки в `/etc/fstab` для автоматического монтирования при загрузке:

```bash
sudo nano /etc/fstab
```

```
/dev/sdc1	/var/www/mysite	ext4	defaults	0 2
/dev/sdc2	/opt/myapp	ext4	defaults	0 2
/dev/sdc3	/var/mydatabase	ext4	defaults	0 2
```

### Поля /etc/fstab

| Поле | Описание |
|------|----------|
| 1 | Устройство (или UUID/LABEL) |
| 2 | Точка монтирования |
| 3 | Тип файловой системы |
| 4 | Опции монтирования (`defaults`, `ro`, `noexec` и др.) |
| 5 | Дамп (0 — отключён) |
| 6 | Порядок проверки fsck (0 — не проверять, 1 — корневая ФС, 2 — остальные) |

## Монтирование по UUID

> **UUID** — уникальный идентификатор раздела, остаётся постоянным даже при изменении имени устройства.

### Получение UUID

```bash
blkid /dev/sdc1
# Пример вывода: /dev/sdc1: UUID="12345678-1234-1234-1234-1234567890ab" TYPE="ext4"
```

### Использование в /etc/fstab

```
UUID=12345678-1234-1234-1234-1234567890ab /var/www/mysite ext4 defaults 0 2
```

---

## Монтирование по метке (LABEL)

### Присвоение метки

```bash
sudo e2label /dev/sdc1 mysite
sudo e2label /dev/sdc2 myapp
sudo e2label /dev/sdc3 mydatabase
```

### Использование в /etc/fstab

```
LABEL=mysite	/var/www/mysite	ext4	defaults	0 2
LABEL=myapp	/opt/myapp	ext4	defaults	0 2
LABEL=mydatabase	/var/mydatabase	ext4	defaults	0 2
```

## Основные команды для работы с дисками и разделами

| Команда | Назначение |
|---------|------------|
| `lsblk /dev/sda` | Просмотр разделов на диске |
| `fdisk /dev/sda` | Интерактивное управление разделами |
| `parted /dev/sda` | Более мощный инструмент (поддерживает GPT) |
| `mkfs.ext4 /dev/sda1` | Создание файловой системы ext4 |
| `mount /dev/sda1 /mnt` | Монтирование раздела |
| `umount /mnt` | Отмонтирование |
| `blkid` | Просмотр UUID и другой информации |
| `df -h` | Просмотр смонтированных ФС и использования места |

---

## Итог

Работа с дисковыми разделами в Linux — фундаментальный навык. Ключевые моменты:

1. **GPT предпочтительнее MBR** для современных систем
2. Разделы — это блочные устройства, с ними работают те же инструменты, что и с целыми дисками
3. Для автоматического монтирования используется `/etc/fstab`
4. Для надёжности лучше использовать **UUID** или **LABEL**, а не имена устройств (`/dev/sda1`)

> [!warning]
> Перед работой с дисками убедитесь, что выбран правильный диск — операции необратимы. Всегда делайте резервные копии важных данных.
