# Кратко о Ceph

> **Ceph** — это программно-определяемая распределённая файловая система с открытым исходным кодом, лишённая узких мест и единых точек отказа. Представляет собой легко масштабируемый до петабайтных размеров кластер узлов, обеспечивающий хранение, репликацию данных и распределение нагрузки для высокой доступности и надёжности.

Система **бесплатна** (разработчики могут предоставлять платную поддержку). Специального оборудования не требуется, но для production-среды рекомендуется мощное оборудование и тщательное планирование.

> [!important]
> При выходе из строя диска, узла или группы узлов Ceph не только сохранит данные, но и **автоматически восстановит утраченные копии** на других узлах. Восстановление происходит без секунды простоя и прозрачно для клиентов.

---

## Поддерживаемые протоколы

Ceph поддерживает все три основных типа хранения данных в одном кластере:

| Тип хранения | Компонент | Интерфейс | Применение |
|--------------|-----------|-----------|------------|
| **Объектное** | RADOS Gateway (RGW) | S3 / OpenStack Swift | Объектное хранение, совместимое с AWS S3 |
| **Блочное** | RBD (RADOS Block Device) | Блочные устройства | Подключение как обычных дисков (снапшоты, клонирование) |
| **Файловое** | CephFS | POSIX-совместимая ФС | Распределённая файловая система |

## Особенности Ceph

| Особенность | Описание |
|-------------|----------|
| **Масштабируемость** | От нескольких до тысяч узлов без потери производительности. Автоматическое распределение и балансировка данных |
| **Отказоустойчивость** | Автоматическая репликация и восстановление. Алгоритм CRUSH — нет единой точки отказа |
| **Производительность** | Высокая параллельность операций. Erasure Coding для экономии места при сохранении надёжности |
| **Гибкость** | Поддержка трёх типов хранилища. Совместимость с S3 и Swift API |

## Преимущества и недостатки

### ✅ Преимущества

| Преимущество | Описание |
|--------------|----------|
| **Открытый исходный код** | Свободное использование, возможность модификации |
| **Масштабируемость и гибкость** | Лёгкое расширение кластера, поддержка разных типов данных |
| **Отказоустойчивость** | Автоматическое восстановление при сбоях, репликация и Erasure Coding |
| **Интеграция** | Поддержка Kubernetes (через Rook), OpenStack и облачных платформ |

### ⚠️ Недостатки

| Недостаток | Описание |
|------------|----------|
| **Сложность управления** | Требует значительных знаний и опыта. Высокий порог вхождения |
| **Ресурсоёмкость** | Потребляет много RAM и CPU. Требуется быстрая сеть |
| **Затраты на оборудование** | Для оптимальной производительности нужно высокопроизводительное оборудование |

**Ключевые компоненты:**
- **MON** (Monitor) — хранит карту кластера
- **MGR** (Manager) — метрики и дашборд
- **OSD** (Object Storage Daemon) — хранит данные и обрабатывает репликацию
- **RGW** (RADOS Gateway) — шлюз для S3/Swift API

## Сравнение: Ceph vs альтернативы

| Характеристика | Ceph | MinIO | GlusterFS |
|----------------|------|-------|-----------|
| **Типы хранения** | Объектное + блочное + файловое | Только объектное | Только файловое |
| **S3-совместимость** | ✅ (RGW) | ✅ (нативная) | ❌ |
| **Масштабируемость** | Петабайты, тысячи узлов | Десятки узлов | Сотни узлов |

| **Интеграция с K8s** | ✅ (Rook) | ✅ | ⚠️ (ограниченная) |

## Итог

Ceph — мощнейшее решение для организации **масштабируемого и отказоустойчивого** хранилища **единым кластером** для трёх типов данных одновременно:

1. **Объектное хранилище** (S3 / Swift) — для облачных приложений
2. **Блочное хранилище** (RBD) — для виртуализации и баз данных
3. **Файловое хранилище** (CephFS) — для традиционных файловых систем

> [!warning]
> Ceph — не для новичков и не для одного сервера. Это решение для крупных инфраструктур, где нужна высокая доступность и масштабируемость. Для простых задач лучше подойдут MinIO (S3) или традиционные NFS/Samba.

**Когда выбирать Ceph:**
- ✅ Петобайтные масштабы данных
- ✅ Нужны все три типа хранения в одном кластере
- ✅ Есть команда опытных администраторов
- ✅ Высокие требования к отказоустойчивости

**Когда Ceph не нужен:**
- ❌ Небольшой объём данных (террабайты)
- ❌ Нет опыта работы с распределёнными системами
- ❌ Ограниченные ресурсы (RAM, CPU, сеть)
