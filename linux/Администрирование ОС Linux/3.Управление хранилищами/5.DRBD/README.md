# Распределённые реплицируемые блочные устройства (DRBD)

**DRBD** (Distributed Replicated Block Device) — это программный инструмент для создания высокодоступных и отказоустойчивых систем хранения данных на базе Linux. В отличие от ранее рассмотренных протоколов, это «чисто линуксовая фишка».

> DRBD позволяет зеркалировать данные между двумя или более серверами, обеспечивая высокую доступность данных при сбоях одного из узлов. Это достигается путём синхронизации данных на уровне блочного устройства.

DRBD — это, по сути, **сетевое RAID-зеркалирование** (RAID 1 по сети). Блоки на входе → блоки на выходе.

---

## Основные характеристики DRBD

| Характеристика | Описание |
|----------------|----------|
| **Блочное зеркалирование** | Синхронизация данных между серверами на уровне блочного устройства |
| **Высокая доступность** | При сбое одного сервера, другой берёт на себя работу |
| **Синхронная репликация** | Данные записываются на оба узла одновременно (надёжно, но выше задержка) |
| **Асинхронная репликация** | Данные сначала на основной узел, затем с задержкой на резервный (быстрее, но риск потери данных) |

---

## Основные компоненты DRBD

| Компонент | Роль |
|-----------|------|
| **Primary Node** (основной узел) | Активно обрабатывает запросы к блочному устройству |
| **Secondary Node** (резервный узел) | Поддерживает реплику данных от основного узла |
| **DRBD Device** | Виртуальное блочное устройство (например, `/dev/drbd0`) |

---

## Как работает DRBD

1. **Инициализация и конфигурация** — установка, создание конфигурационных файлов, запуск сервисов
2. **Синхронизация данных** — по сети в синхронном или асинхронном режиме
3. **Failover** — при сбое основного узла резервный становится основным

## Практический пример настройки DRBD

### Схема
- Два сервера: `slurm-linux-1` (192.168.250.10) и `slurm-linux-2` (192.168.250.11)
- Используемый раздел: `/dev/sdc1` (10 ГБ)

### Шаг 1: Установка DRBD (на обоих серверах)

```bash
sudo add-apt-repository ppa:linbit/linbit-drbd9-stack
sudo apt update
sudo apt install drbd-utils drbd-dkms
```

### Шаг 2: Подготовка дискового раздела (на обоих серверах)

```bash
# Инициализация диска с GPT
sudo parted /dev/sdc mklabel gpt

# Создание раздела 10 ГБ
sudo parted -a optimal /dev/sdc mkpart primary ext4 0% 10GB
```

### Шаг 3: Создание конфигурационных файлов (на обоих серверах)

```bash
# Резервное копирование оригинального конфига
sudo mv /etc/drbd.d/global_common.conf /etc/drbd.d/global_common.conf.original
```

**Файл `/etc/drbd.d/global_common.conf`:**

```
global {
  usage-count yes;
}
common {
  net {
    protocol C;        # Синхронная репликация
  }
}
```

**Файл `/etc/drbd.d/r0.res`:**

```
resource "r0" {
  device minor 1;
  disk "/dev/sdc1";
  meta-disk internal;

  on "slurm-linux-1" {
    node-id 0;
  }
  on "slurm-linux-2" {
    node-id 1;
  }
  connection {
    host "slurm-linux-1" address 192.168.250.10:7789;
    host "slurm-linux-2" address 192.168.250.11:7789;
  }
}
```

> [!note]
> Протокол `C` означает синхронную репликацию: данные считаются записанными только после подтверждения от обоих узлов.

### Шаг 4: Инициализация и запуск (на обоих серверах)

```bash
sudo drbdadm create-md r0
sudo systemctl start drbd
sudo systemctl enable drbd
sudo systemctl status drbd
```

### Шаг 5: Назначение первичного узла (только на одном сервере, один раз)

```bash
sudo drbdadm primary --force r0
sudo drbdadm status
```

**Результат:**
```
r0 role:Primary
  disk:UpToDate
  slurm-linux-2 role:Secondary
    disk:UpToDate
```

### Шаг 6: Просмотр статистики

```bash
# Краткий статус
sudo drbdadm status r0 --verbose --statistics

# Детальная информация о событиях
sudo drbdsetup events2 --now r0

# Просмотр созданного устройства
ls -l /dev/drbd/by-res/r0/
```

### Шаг 7: Создание ФС и монтирование (только на primary узле)

```bash
# Создание файловой системы
sudo mkfs.ext4 /dev/drbd1

# Точка монтирования
sudo mkdir /mnt/drbd

# Монтирование
sudo mount /dev/drbd1 /mnt/drbd

# Проверка
lsblk
```

## Тестирование переключения (Failover)

### Шаг 1: Создание тестовых данных на primary узле

```bash
cd /mnt/drbd/
sudo wget https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.10.3.tar.xz
```

### Шаг 2: Наблюдение за репликацией (на secondary узле)

```bash
sudo watch -n 1 drbdadm status r0 --verbose --statistics
```
Следите за значениями `written` (записано) и `received` (получено).

### Шаг 3: Штатное переключение

**На primary узле (slurm-linux-1):**
```bash
# Размонтирование
sudo umount /mnt/drbd

# Переключение в secondary
sudo drbdadm secondary r0
```

**На secondary узле (slurm-linux-2):**
```bash
# Переключение в primary
sudo drbdadm primary --force r0

# Проверка статуса
drbdadm status

# Монтирование устройства
sudo mount /dev/drbd1 /mnt/drbd

# Проверка данных
ls -l /mnt/drbd/
```

> [!tip]
> Данные сохранились! Файл ядра, скачанный на первом узле, доступен на втором после переключения.

## Основные команды DRBD

| Команда | Назначение |
|---------|------------|
| `drbdadm create-md r0` | Создание метаданных для ресурса |
| `drbdadm up r0` | Поднять ресурс |
| `drbdadm down r0` | Остановить ресурс |
| `drbdadm primary r0` | Сделать узел основным |
| `drbdadm secondary r0` | Сделать узел резервным |
| `drbdadm status r0` | Показать статус ресурса |
| `drbdadm status --verbose --statistics` | Детальная статистика |
| `drbdsetup events2 --now r0` | События в реальном времени |
| `cat /proc/drbd` | Классический просмотр статуса |

---

## Режимы репликации

| Протокол | Описание | Задержка | Надёжность |
|----------|----------|----------|------------|
| **A** (Async) | Асинхронный — данные на primary, затем фоном на secondary | Низкая | Средняя |
| **B** (Semi-sync) | Полусинхронный — подтверждение после записи на primary и отправки на secondary | Средняя | Высокая |
| **C** (Sync) | Синхронный — подтверждение после записи на оба узла | Высокая | Максимальная |

> [!important]
> Для production-систем с критичными данными рекомендуется использовать **протокол C**.

---

## Итог

DRBD — мощное решение для организации отказоустойчивых систем хранения на уровне блочных устройств:

1. **RAID 1 по сети** — полное зеркалирование данных между серверами
2. **Автоматический failover** — при сбое основного узла
3. **Прозрачность для приложений** — работает как обычное блочное устройство
4. **Три режима репликации** — от асинхронного до синхронного

> [!warning]
> DRBD не заменяет резервное копирование. Он защищает от отказа оборудования, но не от логических ошибок, случайного удаления или вирусов. Для полноценной защиты данных требуется комбинация: DRBD (отказоустойчивость) + резервные копии (защита от ошибок).
