# Что такое ядро и из чего оно состоит

Кратко — это основная часть операционной системы Linux. Ядро управляет всеми ресурсами компьютера и предоставляет программный интерфейс для взаимодействия с аппаратным обеспечением.

Говоря языком аналогий: если сравнивать ОС с автомобилем, то ядро — это двигатель и ходовая часть. Ядро Linux является основным элементом операционной системы, обеспечивая базовые функции, необходимые для работы пользовательских программ и приложений. Оно обеспечивает абстракцию от аппаратного обеспечения, что позволяет программам работать на различных аппаратных платформах без изменений исходного кода.

Ядро предоставляет разработчикам абстракции вида процесс, область памяти, файл на диске, сетевой сокет и так далее. При этом не важно, какое железо находится под капотом (при условии, что ОС его поддерживает). Разработчику не нужно переписывать прикладное ПО при изменении модели или типа жёсткого диска или процессора. В худшем случае потребуется пересобрать тот же самый исходный код под другую архитектуру процессора.

## Основные функции ядра в Linux

1. **Управление процессами** — отвечает за создание, управление и завершение процессов в системе.
2. **Управление памятью** — управление виртуальной памятью, выделение и освобождение памяти приложений.
3. **Управление файловой системой** — обеспечивает доступ к файлам и каталогам, управляет файловыми операциями, такими как чтение, запись и выполнение.
4. **Управление устройствами** — управляет вводом-выводом и взаимодействием с устройствами, такими как жёсткие диски, сетевые карты, USB-устройства и другие периферийные устройства.
5. **Сетевые возможности** — отвечает за сетевое взаимодействие, включая поддержку протоколов TCP/IP, маршрутизацию, фильтрацию трафика, сетевые устройства.

## Из чего состоит ядро

Ядро Linux состоит из нескольких основных компонентов, каждый из которых выполняет определённые функции:

1. **Драйверы устройств (Device Drivers)** — обеспечивают поддержку и взаимодействие с аппаратным обеспечением компьютера. Драйверы устройств позволяют ядру взаимодействовать с жёсткими дисками, сетевыми картами, USB-устройствами, графическими картами и другими периферийными устройствами.

2. **Файловые системы (File Systems)** — включают различные типы файловых систем, такие как *ext4*, *Btrfs*, *XFS* и другие, а также систему виртуальной файловой системы (VFS), которая является абстракцией над ними и обеспечивает унифицированный доступ к каждой из них. Файловые системы предоставляют методы для организации и хранения данных на диске.

3. **Системные вызовы (System Calls)** — интерфейсы, которые позволяют пользователям и приложениям взаимодействовать с ядром, запрашивая его функции и услуги. Системные вызовы позволяют создавать, управлять и завершать процессы, работать с файлами, управлять памятью.

4. **Подсистемы ядра (Kernel Subsystems)** — ядро Linux включает различные подсистемы, такие как управление памятью, планирование задач, управление процессами, сетевая подсистема, виртуализация и многое другое. Каждая подсистема отвечает за определённые аспекты функционирования операционной системы.

## Архитектура ядра

Архитектура ядра Linux представляет собой монолитную архитектуру с модульной системой.

1. **Монолитная архитектура:**
   - В основе монолитной архитектуры лежит единый исполняемый модуль (ядро), который включает в себя все основные функции операционной системы.
   - В Linux множество функций реализовано внутри ядра, что делает его компактным и быстрым в выполнении.
   - Этот подход позволяет эффективно управлять процессами, памятью, файловой системой, устройствами и сетью, так как все функции находятся в одном адресном пространстве.

2. **Модульная система:**
   - Помимо монолитной части, ядро Linux поддерживает модульную архитектуру, которая позволяет динамически загружать и выгружать драйверы и другие модули в ядро по мере необходимости.
   - Это позволяет гибко управлять функциональностью ядра, активируя только те модули, которые действительно требуются для работы конкретной системы.
   - Модульная система упрощает обновление ядра, так как не требуется пересборка всего ядра при добавлении или изменении функциональности.

## Практические примеры

### Определение версии загруженного ядра

После загрузки системы ядро функционирует. Для просмотра используемой версии ядра применяется команда:

```bash
uname -r
```

Флаг `-r` означает «ревизия», то есть версия. При использовании флага `-a` отображается полная информация о имени машины, запущенном ядре, дате сборки, аппаратной платформе (x86-64) и дистрибутиве:

```bash
uname -a
```

### Расположение ядра на диске

Файл ядра в бинарном виде обычно находится в каталоге `/boot` вместе с конфигурационными файлами загрузчика:

```bash
ls -la /boot
```

Основные файлы:
- **vmlinuz** — сжатое ядро Linux, готовое для загрузки в оперативную память. Во время загрузки загрузчик (например, GRUB) распаковывает это сжатое ядро в память и запускает его.
- **initrd.img** — сжатый образ начальной RAM-дисковой системы (initrd). Это временная корневая файловая система, которая загружается в оперативную память в начале загрузки системы перед монтированием основной файловой системы. Содержит необходимые драйверы и утилиты.
- **config-версия** — содержит конфигурацию ядра, использованную при его компиляции. Включает опции поддержки устройств, файловых систем, сетевых протоколов и другие параметры.

### Модули ядра

Файлы модулей ядра находятся в каталоге `/lib/modules`. Каждая версия ядра имеет свой собственный подкаталог:

```bash
ls /lib/modules/
```

### Конфигурация ядра

Конфигурация ядра существует в двух видах:

1. **Текущая конфигурация** находится в виртуальной файловой системе `/proc` по пути `/proc/sys/`:

```bash
ls /proc/sys/
```

Пример вывода:
```
debug  dev  fs  kernel  net  vm
```

2. **Классический конфигурационный файл** расположен в `/etc/sysctl.conf` и предназначен для переопределения системных настроек ядра по умолчанию:

```bash
cat /etc/sysctl.conf
```

`/proc/sys` — это виртуальная файловая система, предоставляющая интерфейс для доступа и управления системными параметрами ядра в реальном времени. Каждый параметр представлен в виде файла или каталога.

Основные категории параметров в `/proc/sys`:

- **kernel** — параметры, связанные с ядром Linux (параметры планировщика, памяти, сети)
- **net** — параметры сети (TCP/IP параметры, маршрутизация, настройки сетевых интерфейсов)
- **vm** — параметры управления виртуальной памятью (размер страницы, настройки подкачки)
- **fs** — параметры файловой системы (ограничения inode, параметры монтирования)
- **debug** — параметры отладки

#### Примеры настройки параметров

**Параметр vm/swappiness** — определяет, насколько часто ядро будет использовать область подкачки вместо оперативной памяти. Значение по умолчанию — 60.

```bash
# Просмотр текущего значения
cat /proc/sys/vm/swappiness

# Установка более агрессивной стратегии использования области подкачки
echo 10 > /proc/sys/vm/swappiness
```

**Параметр fs/file-max** — определяет максимальное количество файловых дескрипторов, которые могут быть открыты системой.

```bash
# Установка максимального количества файловых дескрипторов в 100000
echo 100000 > /proc/sys/fs/file-max
```

**Параметр kernel/pid_max** — определяет максимальное число PID (идентификаторов процессов).

```bash
# Установка максимального количества PID в 100000
echo 100000 > /proc/sys/kernel/pid_max
```

> Изменения, внесённые непосредственно через `/proc/sys`, применяются немедленно, но не сохраняются после перезагрузки системы. Для постоянного сохранения изменений используется конфигурационный файл `sysctl.conf`.

### Просмотр загруженных модулей

Команда `lsmod` отображает список загруженных модулей ядра:

```bash
lsmod
```

Пример вывода:
```
Module                  Size  Used by
btrfs                1300000  0
tls                    45000  0
ext4                  650000  1
usb_storage            70000  1
```

- **Module** — название модуля
- **Size** — размер модуля в байтах
- **Used by** — количество экземпляров модуля, используемых другими модулями или системой

### Получение информации о модуле

Команда `modinfo` позволяет узнать подробности о конкретном модуле:

```bash
modinfo btrfs
```

```bash
modinfo tls
```

### Загрузка и выгрузка модулей вручную

**Удаление модуля с помощью rmmod:**

```bash
sudo rmmod module_name
```

При попытке удалить модуль, от которого зависят другие, возникает ошибка:
```
ERROR: Module <name> is in use by ....
```

Для принудительного удаления используется флаг `-f`, однако это не рекомендуется:

```bash
sudo rmmod -f module_name
```

**Использование modprobe** — более предпочтительный способ, так как эта команда автоматически проверяет зависимости и выгружает зависимые модули:

```bash
# Загрузка модуля
sudo modprobe module_name

# Выгрузка модуля (с зависимостями)
sudo modprobe -r module_name
```

Пример:
```bash
sudo modprobe usb_storage
sudo modprobe -r usb_storage
```

### Автозагрузка модулей

Для автоматической загрузки модулей при старте системы используется файл `/etc/modules`. По умолчанию он пуст. Для добавления модуля в автозагрузку необходимо вписать его имя в этот файл:

```bash
echo "my_module" | sudo tee -a /etc/modules
```

Для более гибкой настройки существует каталог `/etc/modprobe.d/`. Файлы в этом каталоге должны иметь расширение `.conf`. Они позволяют настраивать параметры загрузки модулей, управлять зависимостями и указывать модули, которые должны быть загружены или не загружены.

**Пример файла `/etc/modprobe.d/my_module.conf`:**

```bash
# Загружаем модуль my_module автоматически при запуске системы
my_module
```

**Пример настройки параметров модуля `/etc/modprobe.d/my_module_params.conf`:**

```bash
# Установка параметра для модуля my_module
options my_module my_option=value
```

Просмотр содержимого каталога `/etc/modprobe.d/`:

```bash
ls /etc/modprobe.d/
```

Пример вывода:
```
alsa-base.conf
blacklist.conf
droid-nvram.conf
intel-microcode-blacklist.conf
iwlwifi.conf
```

### Блокировка модулей (черный список)

Функция внесения модуля в чёрный список применяется, когда модуль конфликтует с другим модулем, заменяется другим модулем или является нежелательным по другим причинам.

Самый простой способ внести модуль в чёрный список — добавить его в файл `/etc/modprobe.d/blacklist.conf`:

```bash
echo "blacklist modulename" | sudo tee -a /etc/modprobe.d/blacklist.conf
```

Пример содержимого файла `blacklist.conf`:

```bash
# Блокировка конфликтующего модуля
blacklist evbug
blacklist pcspkr
```
