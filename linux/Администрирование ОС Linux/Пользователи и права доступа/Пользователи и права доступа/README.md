## Управление пользователями и правами доступа в Linux (Ubuntu)



## 1. Пользователи и группы: фундамент управления доступом

В Ubuntu, как и в любом дистрибутиве Linux, **пользователи** и **группы** — это основные сущности для управления доступом к ресурсам системы.

[!note]
**Ключевая идея:** Каждый процесс в Linux запускается от имени определённого пользователя и группы, что определяет, к каким файлам и устройствам он может обращаться.

### Создание и управление пользователями

**Создание пользователя**

Для создания нового пользователя используется команда `useradd`. Например, чтобы создать пользователя `alice`:

```bash
sudo useradd -m alice
```

> Опция `-m` создаёт домашний каталог для пользователя (`/home/alice`).

**Установка пароля**

После создания пользователя ему необходимо установить пароль:

```bash
sudo passwd alice
```

### Управление группами

Группы упрощают управление правами доступа. Файл (или директория) может быть привязан к определённой группе — все члены этой группы получат одинаковые права на ресурс.

> *Пример:* Несколько пользователей работают над одним проектом. Создайте группу `project`, добавьте в неё всех участников и настройте права так, чтобы только члены группы могли изменять файлы проекта.

**Создание группы и добавление пользователя:**

```bash
sudo groupadd developers
sudo usermod -aG developers alice
```

> Опция `-aG` добавляет пользователя в указанную группу **без удаления** его из других групп.

## 2. Процесс создания пользователя: что происходит под капотом

Когда в Ubuntu создаётся новый пользователь с помощью `useradd`, система выполняет несколько ключевых действий:

1. **Запись в файл `/etc/passwd`**
   - Присваиваются уникальный идентификатор (UID) и идентификатор основной группы (GID).
   - Добавляется строка с именем, UID, GID, домашним каталогом, shell по умолчанию.

   Пример для пользователя `alice`:
   ```
   alice:x:1001:1001::/home/alice:/bin/bash
   ```
   > Символ `x` указывает, что пароль хранится в зашифрованном виде в `/etc/shadow`.

2. **Создание домашнего каталога**
   - При указании опции `-m` создаётся `/home/alice`.
   - В каталог копируются стандартные файлы из `/etc/skel` (например, `.bashrc`, `.profile`).

3. **Запись в файл `/etc/shadow`**
   - Хранится зашифрованный пароль, «соль» (salt), срок действия пароля и другие данные.

4. **Запись в файл `/etc/group`**
   - Создаётся запись о группе (если она новая). Пользователь добавляется в соответствующую группу.

5. **Создание файлов конфигурации пользователя**
   - В домашнем каталоге появляются файлы начальных настроек окружения (`.bashrc`, `.profile` и т.д.).

## 3. Установка пароля и хеширование

Пароль устанавливается командой `passwd`. После ввода он **шифруется** и записывается в `/etc/shadow`.

> Как работает хеширование: пароль преобразуется с использованием алгоритма (например, SHA-512) с добавлением случайной «соли» (salt) для защиты от атак по радужным таблицам.

Пример записи в `/etc/shadow` для `alice`:
```
alice:$6$randomsalt$encryptedpassword:18536:0:99999:7:::
```

- `$6$` — алгоритм SHA-512.
- `randomsalt` — соль.
- `encryptedpassword` — результат хеширования.

## 4. Файлы конфигурации пользователей

| Файл | Назначение | Пример содержимого |
| :--- | :--- | :--- |
| **`/etc/passwd`** | Информация о пользователях (без паролей) | `alice:x:1001:1001:,,,:/home/alice:/bin/bash` |
| **`/etc/shadow`** | Зашифрованные пароли и политики | `alice:$6$randomsalt$...:18536:0:99999:7:::` |
| **`/etc/group`** | Информация о группах | `developers:x:1002:alice,bob` |

### Структура записи в `/etc/passwd`

| Поле | Значение |
| :--- | :--- |
| Имя пользователя | `alice` |
| Пароль (зашифрован) | `x` (указывает на `/etc/shadow`) |
| UID | `1001` |
| GID | `1001` |
| Информация о пользователе | `,,,` |
| Домашний каталог | `/home/alice` |
| Shell по умолчанию | `/bin/bash` |

---

## 5. Вход пользователя в систему и понятие сеанса

Когда пользователь вводит учётные данные, система проверяет пароль по `/etc/shadow`. После успешной аутентификации:

1. Запускается **пользовательская сессия**.
2. Устанавливаются переменные окружения: `HOME`, `SHELL`, `PATH` и другие.
3. Пользователь получает доступ к своему рабочему окружению.

[!tip]
**Важно:** Каждый сеанс (сессия) изолирован от других. Переменные окружения одного пользователя не влияют на другого без явного разрешения.
