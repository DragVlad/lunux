## 1. Выбор минимального образа ОС

### Основной принцип

> Чем меньше сервисов работает на сервере, тем меньше потенциальных точек входа для злоумышленников.

**Минимальный образ ОС** — это версия дистрибутива, содержащая только базовые компоненты, необходимые для работы системы. В нём отсутствуют дополнительные пакеты, графический интерфейс, ненужные сервисы и библиотеки.

### Сравнение минимального и обычного образов

| Параметр | Минимальный образ | Обычный образ |
|----------|-------------------|---------------|
| **Размер** | 100–500 МБ | Гигабайты |
| **Состав пакетов** | Только базовые утилиты | Полный набор (GUI, офисные пакеты) |
| **Безопасность** | Повышенная (меньше поверхность атаки) | Возможны уязвимости в лишних компонентах |
| **Производительность** | Высокая (меньше фоновых процессов) | Больше потребления ресурсов |
| **Гибкость** | Полностью кастомизируемый | Предустановленные компоненты |

### Что входит в минимальный образ

**Есть:**
- Ядро Linux
- Базовые утилиты (`bash`, `coreutils`, `grep`, `sed`, `awk`)
- Базовые сетевые инструменты (`ip`, `ping`, `netstat`)
- Минимальная пакетная система (`apt`, `dnf`, `yum`, `apk`)

**Нет:**
- Графического интерфейса (X11, GNOME, KDE)
- Лишних сервисов (Bluetooth, принтеры, звуковые драйверы)
- Интерпретаторов (python, perl, ruby) — если не указано при установке

### Примеры минимальных образов

| Дистрибутив | Варианты минимальной установки |
|-------------|--------------------------------|
| Ubuntu/Debian | `ubuntu-minimal`, netinstall, debootstrap |
| CentOS/RHEL | Minimal ISO, kickstart |
| Контейнеры | Alpine Linux, distroless образы |

## 2. Отключение лишних сервисов

### Проверка активных сервисов

```bash
# Список запущенных сервисов
systemctl list-units --type=service --state=running
```

### Проверка открытых портов

```bash
# Какие порты и на каких интерфейсах слушают сервисы
ss -tulnp
```

**Что означают поля:**
- `-t` — TCP порты
- `-u` — UDP порты
- `-l` — только слушающие (listening)
- `-n` — не преобразовывать в имена
- `-p` — показать процесс

### Отключение сервисов

```bash
# Остановить и отключить автозагрузку
systemctl disable --now <имя_сервиса>

# Примеры
systemctl disable --now cups.service      # Отключение печати
systemctl disable --now avahi-daemon      # Отключение автообнаружения устройств
```

### Разница между disable и mask

| Команда | Что делает | Можно ли запустить вручную |
|---------|------------|---------------------------|
| `systemctl disable` | Удаляет симлинки автозагрузки | ✅ Да |
| `systemctl mask` | Создаёт ссылку на `/dev/null` | ❌ Нет |

```bash
# Маскирование сервиса (полная блокировка)
systemctl mask cups.service

# Снять маску
systemctl unmask cups.service
```

**Рекомендация**: для критических сервисов, которые не должны запускаться ни при каких обстоятельствах, используйте `mask`.

### Удаление ненужных пакетов

```bash
# Удаление пакетов с очисткой конфигов
apt remove --purge telnet cups avahi-daemon rpcbind

# Автоматическое удаление зависимостей
apt autoremove
```

> **Совет**: сначала отключите сервисы и протестируйте систему (включая перезагрузку), затем удаляйте пакеты.

### Модули ядра

Модули ядра также могут быть использованы для атак. Проверьте список загруженных модулей и отключите ненужные:

```bash
lsmod                     # Список загруженных модулей
modprobe -r <модуль>      # Выгрузить модуль
```

## 3. Сканирование портов с помощью nmap

**nmap** (Network Mapper) — инструмент для сканирования сети и проверки доступных сервисов.

### Базовые команды

```bash
# Полное сканирование всех портов (1-65535) без ICMP
nmap -sSV -p- -Pn <IP_сервера>

# Поиск всех активных хостов в сети
nmap -sn 192.168.1.0/24

# Определение версий сервисов в сети
nmap -sV 192.168.1.0/24
```

**Опции:**
- `-sSV` — определение версий сервисов
- `-p-` — все порты (1-65535)
- `-Pn` — не отправлять ICMP-запросы
- `-sn` — ping-сканирование (без проверки портов)
- `-sV` — определение версий

> **Важно**: После настройки фаервола обязательно проверьте себя — запустите nmap с другой машины и убедитесь, что открытых портов не осталось.

## 4. Уязвимости и обновление системы

### Основная аксиома

> Ни одно сложное программное обеспечение не может разрабатываться без ошибок. Ошибки → уязвимости.

**Уязвимость (Vulnerability)** — слабое место в ПО, которое может быть использовано злоумышленником.

### Типы уязвимостей

| Тип | Описание | Пример |
|-----|----------|--------|
| **RCE** (Remote Code Execution) | Удалённое выполнение кода | CVE-2021-44228 (Log4Shell) |
| **Privilege Escalation** | Повышение привилегий до root | CVE-2021-3156 (sudo Baron Samedit) |
| **Authentication Bypass** | Обход аутентификации | CVE-2022-40684 (Fortinet) |

### Базы данных уязвимостей

| База | Описание | Ссылка |
|------|----------|--------|
| **CVE** | Уникальный идентификатор уязвимости | cve.mitre.org |
| **NVD** | Национальная база с метриками риска | nvd.nist.gov |
| **BID** | Bugtraq ID (глубокий анализ) | securityfocus.com |

### CVSS (Common Vulnerability Scoring System)

Оценка критичности уязвимости по шкале от 0 до 10:

| CVSS | Оценка | Пример |
|------|--------|--------|
| 0.0 – 3.9 | Низкий риск | Локальный DoS |
| 4.0 – 6.9 | Средний риск | Кража данных при особых условиях |
| 7.0 – 8.9 | Высокий риск | RCE без привилегий |
| 9.0 – 10.0 | Критический риск | RCE с root-доступом |

### Процесс исправления уязвимостей

1. Анализ уязвимости
2. Разработка патча
3. Публикация Security Advisory
4. Распространение патча в дистрибутивы
5. Обновление NVD и CVE

### История из реальной жизни

> **WannaCry (2017)**: вирус заразил тысячи серверов через уязвимость CVE-2017-0144 в SMB. Microsoft выпустила патч за **2 месяца** до атаки, но многие компании не обновились.

### Алгоритм работы с обновлениями

```
1. Сканирование системы → сохранить результат
2. Установка обновлений → перезагрузка
3. Повторное сканирование
4. Сравнение результатов "до" и "после"
5. Если уязвимости остались → искать пути решения
```

### Обновление системы

```bash
# Установка обновлений
apt upgrade -y
apt dist-upgrade -y

# Перезагрузка (важно для обновления ядра)
reboot
```

## 5. Сканирование уязвимостей с Trivy

**Trivy** — мощный универсальный сканер безопасности от Aqua Security.

### Основные возможности

- Сканирование контейнерных образов
- Проверка файловых систем
- Анализ Git-репозиториев
- Интеграция с Kubernetes
- Сканирование IaC (Infrastructure as Code)

### Установка Trivy (Ubuntu/Debian)

```bash
sudo apt-get install -y wget gnupg
wget -qO - https://aquasecurity.github.io/trivy-repo/deb/public.key | gpg --dearmor | sudo tee /usr/share/keyrings/trivy.gpg > /dev/null
echo "deb [signed-by=/usr/share/keyrings/trivy.gpg] https://aquasecurity.github.io/trivy-repo/deb generic main" | sudo tee -a /etc/apt/sources.list.d/trivy.list
sudo apt-get update
sudo apt-get install -y trivy
```

### Сканирование файловой системы

```bash
# Сканирование с выводом только HIGH и CRITICAL уязвимостей
trivy fs --scanners vuln --severity HIGH,CRITICAL /

# Только количество уязвимостей
trivy fs --scanners vuln --severity HIGH,CRITICAL / 2>/dev/null | grep Total

# Вывод в JSON (для автоматизации)
trivy fs --scanners vuln --severity HIGH,CRITICAL --format json --output report.json /
```

### Пример результата сканирования

Trivy показывает:
- Конкретный пакет с уязвимостью
- Текущую версию
- CVE номер
- Краткое описание
- Версию, в которой уязвимость исправлена

### Ложные срабатывания (False Positive)

> **False Positive** — ситуация, когда сканер обнаруживает уязвимость там, где её на самом деле нет.

**Причины:**
1. Ошибка в базе CVE
2. Вендор исправил уязвимость без изменения версии пакета
3. Особенности конфигурации системы
4. Формат данных для разных дистрибутивов

### Пример: обновление ядра

```bash
# Проверка текущего ядра
uname -r

# Удаление старого ядра (например, 5.15.0-71-generic)
sudo apt-get purge linux-image-5.15.0-71-generic

# Очистка зависимостей
sudo apt-get autoremove --purge

# Проверка /boot после удаления
ls -l /boot/

# Повторное сканирование
trivy fs --scanners vuln --severity HIGH,CRITICAL / 2>/dev/null
```

## Шпаргалка: основные команды

```bash
# ===== Управление сервисами =====
systemctl list-units --type=service --state=running    # Запущенные сервисы
systemctl disable --now <service>                      # Остановить и отключить
systemctl mask <service>                               # Полная блокировка
systemctl unmask <service>                             # Снять блокировку

# ===== Сеть и порты =====
ss -tulnp                                              # Просмотр открытых портов
nmap -sSV -p- -Pn <IP>                                 # Сканирование портов
nmap -sn 192.168.1.0/24                                # Поиск хостов в сети

# ===== Управление пакетами =====
apt remove --purge <package>                           # Удалить с конфигами
apt autoremove                                         # Удалить зависимости
apt upgrade -y                                         # Обновить пакеты
apt dist-upgrade -y                                    # Обновить с зависимостями

# ===== Информация о системе =====
uname -r                                               # Версия ядра
lsmod                                                  # Загруженные модули
ls -l /boot/                                           # Файлы загрузчика
```

## Итоговые тезисы

1. **Начинайте с минимального образа** — меньше компонентов = меньше поверхность атаки
2. **Отключайте всё, что не используется** — если сервис не нужен, замаскируйте его
3. **Проверяйте себя извне** — используйте nmap для проверки открытых портов
4. **Обновления критически важны** — WannaCry атаковал системы, которые не установили патч
5. **Сканируйте систему регулярно** — Trivy помогает находить уязвимости в пакетах
6. **Удаляйте старое ядро** — старые пакеты могут создавать ложные срабатывания
7. **Безопасность — это процесс** — однократная настройка не гарантирует защиту
