# Защита данных при хранении

Защита данных, хранящихся на сервере или на локальном диске, является важной задачей, поскольку в случае физического доступа злоумышленника к серверу или носителю информации обычные права доступа не обеспечивают достаточной защиты.

Главное решение проблемы — **шифрование данных**, которое делает невозможным чтение данных без ключа шифрования, даже если физический носитель попал в чужие руки.

> **Шифрование** — это математическое преобразование данных, при котором информация преобразуется так, чтобы её было невозможно прочитать без специального **ключа**. Ключ – это секретный набор символов, похожий на пароль, используемый для обратного преобразования (расшифровки) данных. Без этого ключа зашифрованные данные выглядят как набор случайных символов.
>
> Шифрование в Linux обычно реализуется на двух уровнях:
>
> - **На уровне блок-устройств** (например, LUKS): При записи данных на диск информация блок за блоком преобразуется с помощью математических алгоритмов (AES, Serpent и др.) в нечитаемую форму, а при чтении обратно расшифровывается с помощью секретного ключа. Без ключа прочитать диск невозможно, даже если диск физически похищен.
>
> - **На уровне файловой системы или отдельных файлов** (eCryptfs, fscrypt, GnuPG): Информация шифруется перед сохранением в файлы или каталоги, и расшифровывается только при доступе. Ключ шифрования, который может храниться отдельно, либо выводиться из пароля, обеспечивает секретность информации и защищает данные даже в случае компрометации устройства.
>
> Таким образом, шифрование в Linux — это всегда преобразование с помощью криптографических алгоритмов, где безопасность зависит от надежности ключа и алгоритма шифрования. Чем сложнее ключ и надёжнее алгоритм, тем труднее злоумышленнику получить доступ к защищенным данным.
>
> На практике чаще всего используют шифрование целых дисков (LUKS) для защиты от кражи устройств и шифрование каталогов или отдельных файлов (Fscrypt или GPG), если нужна дополнительная гибкость.

### Шифрование дисков (LUKS / dm-crypt)

**LUKS (Linux Unified Key Setup)** – это стандарт шифрования на уровне блок-устройств в Linux. Он использует механизм ядра **dm-crypt**, обеспечивая прозрачное и безопасное шифрование данных.

С технической стороны, LUKS представляет собой слой между физическим диском и файловой системой. Он шифрует данные перед записью на диск и расшифровывает их при чтении. Данные шифруются блоками с помощью математического преобразования и секретного ключа, который хранится в специальном защищённом заголовке на диске. Этот заголовок зашифрован и требует ввода пароля или специального файла-ключа при запуске системы.

При правильном вводе пароля ядро Linux открывает зашифрованный раздел как обычное блочное устройство (например, `/dev/mapper/securedata`). С этого момента система работает с устройством прозрачно: все данные автоматически шифруются при записи и расшифровываются при чтении. Без ключа заголовок недоступен, а диск выглядит как набор случайных данных, что надёжно защищает информацию при физической краже устройства.

LUKS хранит ключи шифрования в специальной структуре данных, которая называется **LUKS-заголовок (LUKS header)**. Он расположен в начале зашифрованного раздела и содержит всю необходимую информацию для расшифровки данных: зашифрованные мастер-ключи, параметры шифрования и метаданные.

Важной особенностью LUKS является защита ключей от брутфорса (перебора). Когда вводится пароль (или используется ключевой файл), LUKS не расшифровывает данные напрямую. Вместо этого:

- Сначала пароль обрабатывается с использованием ключевой функции деривации (PBKDF2, Argon2).
- К паролю применяется многократное (тысячи и десятки тысяч раз) хеширование с солью, чтобы усложнить перебор и замедлить попытки брутфорса.
- Полученный из пароля промежуточный ключ используется для расшифровки специального защищённого слота, в котором уже лежит основной мастер-ключ, которым и шифруются данные на диске.

Таким образом, даже если злоумышленник украдёт диск и попытается подобрать пароль методом перебора, скорость взлома будет очень низкой (буквально несколько попыток в секунду даже на мощном оборудовании). Благодаря этой архитектуре, LUKS надёжно защищает данные от взлома методом перебора.

**Преимущества LUKS:**

- Универсальность: работает с любыми файловыми системами. ФС создается поверх него как поверх любого блочного устройства.
- Производительность: шифрует целыми блоками, что быстрее. Работа с ним как с блочным устройством (как и в случае LVM) почти не вызывает просадки производительности.
- Безопасность: ключи управления хранятся в специальном заголовке LUKS, зашифрованном и защищённом от brute-force.

#### Примеры работы с LUKS

**Создание шифрованного раздела:**

```bash
# создаем раздел
sudo parted -s /dev/sdc mklabel gpt mkpart primary 0% 100%

# формируем раздел под LUKS (это потребует время)
echo -n "YourStrongPassword" | sudo cryptsetup luksFormat /dev/sdc1 -

# либо вместо пароля можно использовать ключевой файл
sudo cryptsetup luksFormat /dev/sdc1 /path/to/keyfile
```

**Открытие (подключение) раздела:**

```bash
echo -n "YourStrongPassword" | sudo cryptsetup luksOpen /dev/sdc1 cryptdisk -
```

Это создаст виртуальное устройство `/dev/mapper/cryptdisk`. После этого создаётся файловая система и монтируется устройство:

```bash
sudo mkfs.ext4 /dev/mapper/cryptdisk
sudo mount /dev/mapper/cryptdisk /mnt

# просмотр статуса
sudo cryptsetup status cryptdisk
```

**Закрытие раздела:**

```bash
sudo umount /mnt
sudo cryptsetup close cryptdisk
```

После этого данные недоступны без ключа.

**Когда использовать LUKS?**

- Защита от физической кражи диска или сервера.
- Защита серверов, VPS, ноутбуков.

### Шифрование на уровне файловой системы (eCryptfs)

**eCryptfs** — это «стековая» файловая система, обеспечивающая прозрачное шифрование отдельных файлов и каталогов в Linux. В отличие от LUKS, eCryptfs шифрует не целиком диск или раздел, а только указанные файлы и папки, работая поверх существующей файловой системы. Это выглядит следующим образом:

- Выбирается каталог, который нужно зашифровать.
- eCryptfs накладывает поверх него специальный слой, который шифрует каждый файл отдельно перед записью на физический диск и расшифровывает при чтении в оперативную память.
- eCryptfs реализует дополнительный уровень абстракции между приложениями пользователя и физической файловой системой на диске:
  - При записи файла в зашифрованный каталог eCryptfs шифрует его в памяти и затем записывает на диск уже в зашифрованном виде.
  - При чтении файла eCryptfs берёт его с диска в зашифрованном виде, расшифровывает в оперативной памяти и отдаёт уже в исходном виде.
  - Для пользователя это прозрачно и выглядит как обычный каталог, но на диске данные всегда находятся в зашифрованном виде.
- Файлы хранятся на диске в зашифрованном виде и выглядят как набор случайных символов. При доступе с правильным ключом содержимое видно и редактируется как обычно.

**Схема ключей eCryptfs:**

eCryptfs шифрует каждый файл индивидуально с помощью специального ключа. Чтобы работать с файлами прозрачно (не запрашивать пароль для каждого файла отдельно), eCryptfs использует двухуровневую схему ключей:

- При настройке eCryptfs задаётся **пароль** (passphrase).
- Из этого пароля создаётся **ключ шифрования (File Encryption Key, FEK)**, которым и шифруются сами файлы.
- FEK хранится не в открытом виде, а шифруется с помощью второго ключа — **Master Encryption Key (MEK)**.
- Сам **мастер-ключ** хранится в файле на диске, но он также зашифрован паролем пользователя. Этот защищённый файл называется: `~/.ecryptfs/wrapped-passphrase`
- Этот файл («wrapped-passphrase») — ключевой момент защиты. Без пароля его невозможно использовать.

**Процесс расшифровки данных** при логине в систему или монтировании eCryptfs:

1. Вводится пароль (тот самый, изначальный).
2. Пароль используется для расшифровки файла wrapped-passphrase и извлечения FEK-ключа.
3. Получив FEK, eCryptfs может прозрачно шифровать и расшифровывать файлы «на лету».

**Как обеспечивается безопасность:**

- Ключ никогда не хранится в открытом виде на диске.
- Пароль тоже не хранится явно, он используется только для расшифровки зашифрованного промежуточного ключа («wrapped-passphrase»).
- Если злоумышленник украдёт диск, то без пароля он получит только бесполезный файл wrapped-passphrase, который не сможет использовать.

eCryptfs особенно удобен для шифрования личных данных (например, домашнего каталога), поскольку не требует изменения структуры дисков или создания отдельных разделов. Данные шифруются и расшифровываются «на лету». В отличие от LUKS, он шифрует отдельные файлы и каталоги, а не весь диск целиком.

#### Примеры работы с eCryptfs

**Установка:**

```bash
sudo apt update
sudo apt install -y ecryptfs-utils
```

**Создание директорий:**

- `/opt/.securedata` — здесь будут храниться зашифрованные файлы.
- `/securedata` — здесь данные будут доступны прозрачно.

```bash
sudo mkdir /opt/securedata-encrypted
sudo mkdir /securedata
```

**Монтирование в первый раз:**

```bash
sudo mount -t ecryptfs /opt/securedata-encrypted /securedata
```

При первом запуске появятся вопросы:
- Выбор tspi или Passphrase — **Passphrase**
- **Passphrase**: ввод пароля
- **Cipher**: выбор алгоритма шифрования (по умолчанию, при выборе ничего не выбирая, будет применен AES)
- **Key bytes**: выбор длины ключа шифрования
- **Enable plaintext passthrough**: позволяет использовать незашифрованные файлы внутри монтирования. Выбирается N (по умолчанию), чтобы файлы всегда шифровались
- **Filename Encryption**: шифровать ли имена файлов?

После ввода параметров каталог будет смонтирован.

**Проверка монтирования:**

```bash
mount | grep ecryptfs
```

**Проверка шифрования:**

```bash
ls -l /securedata
ls -l /opt/securedata-encrypted
echo "secret data" | sudo tee /securedata/secret.txt
cat /securedata/secret.txt

# просмотр зашифрованного хранилища
ls -l /opt/securedata-encrypted
cat /opt/securedata-encrypted/secret.txt
```

**Безопасное закрытие доступа к данным:**

```bash
sudo umount /securedata
ls -l /securedata
ls -l /opt/securedata-encrypted
```

После этого `/securedata` станет пустым, а файлы будут безопасно храниться в `/opt/securedata-encrypted`.

### Когда использовать eCryptfs?

- Защита личных данных на сервере (home-каталоги).
- Когда нужно зашифровать отдельные папки без изменения структуры дисков.

### Сравнение LUKS и eCryptfs

| LUKS (dm-crypt) | eCryptfs |
|----------------|----------|
| Шифрование целых дисков или разделов | Шифрование отдельных файлов/папок |
| Универсально, любые ФС | Работает поверх существующих ФС |
| Отличная производительность | Снижение производительности |
| Идеален для защиты от физической кражи | Удобен для персональных данных |

**Рекомендация:**

- Для серверов, VPS, облачной инфраструктуры идеально подходит LUKS.
- Для пользовательских данных, персональной информации, домашних каталогов – eCryptfs.

### Альтернативные решения для защиты данных на Linux

Помимо распространенных решений (LUKS, eCryptfs), в Linux доступны и другие средства для защиты данных путём шифрования на уровне разделов, файловых систем или отдельных файлов.

**EncFS** — простое шифрование каталогов и отдельных файлов. EncFS создаёт шифрованную директорию и монтирует её как обычную файловую систему, шифруя данные «на лету».
- Файловая система, аналог eCryptfs, но проще в использовании.
- Шифрует файлы в отдельной директории на уровне пользователя.
- Удобно использовать для шифрования облачных хранилищ (например, Dropbox).
- **Плюс:** простота, лёгкость настройки.
- **Минус:** слабее защита метаданных и производительность ниже, чем у eCryptfs.

**Cryptomator** — современная альтернатива EncFS. Ориентирована на прозрачное и простое шифрование файлов перед отправкой в облака (Google Drive, Dropbox и др.).
- Ориентирована на облачное хранение данных.
- Простое графическое приложение, доступное для всех платформ.
- Удобен, когда надо безопасно хранить данные в облаках (Dropbox, Google Drive).
- **Преимущество:** файлы шифруются индивидуально, удобны при синхронизации.

**Fscrypt** — современная встроенная в ядро Linux технология для прозрачного шифрования файлов и каталогов.
- Современное решение для прозрачного шифрования файлов в Linux.
- Встроено в ядро Linux с 4.1 версии.
- Быстрее и удобнее eCryptfs, активно развивается.
- Хорошо подходит для шифрования домашних каталогов, папок пользователей, особенно на SSD.
- Используется в Android и Chrome OS по умолчанию.
- Высокая производительность.

> **Fscrypt vs eCryptfs:** Fscrypt позиционируется как более современная и производительная альтернатива eCryptfs, но пока полностью не вытеснила её по следующим причинам:
>
> - **Поддержка дистрибутивами:** eCryptfs давно интегрирован во многие дистрибутивы и включен по умолчанию (например, в Ubuntu до недавнего времени), в то время как fscrypt — это более новый механизм, который требует дополнительных действий для настройки и включения.
> - **Совместимость:** eCryptfs шифрует файлы поверх любой существующей файловой системы как отдельный слой, а fscrypt требует встроенной поддержки со стороны файловой системы (например, ext4, f2fs). Поэтому eCryptfs более универсален, а fscrypt доступен не на всех файловых системах.
> - **Гибкость использования:** eCryptfs монтируется поверх текущей файловой системы и удобен, когда требуется быстрое включение или отключение шифрования без переформатирования. Fscrypt же требует предварительной настройки на уровне файловой системы и её подготовки.
>
> На практике, fscrypt — перспективная замена eCryptfs, так как он быстрее, проще и лучше интегрирован в ядро Linux. Однако на текущий момент eCryptfs продолжает использоваться за счёт простоты и удобства в некоторых сценариях.

**VeraCrypt** — кроссплатформенное решение, наследник TrueCrypt, позволяет создавать шифрованные контейнеры или целые диски.
- Поддерживает шифрование с использованием AES, Twofish, Serpent и комбинаций этих алгоритмов.
- Удобен для переноса зашифрованных данных между ОС (Linux, Windows, MacOS).
- **Плюсы:** удобный интерфейс, переносимость контейнеров.
- **Минусы:** производительность ниже, чем у LUKS.
- Идеален, когда нужно переносить данные между разными ОС.

**ZFS Encryption** — встроенная возможность шифрования данных в файловой системе ZFS. Подходит для надёжного хранения больших объемов данных, сочетая высокую производительность с удобным шифрованием целых datasets.

**GnuPG (GPG)** — это свободная реализация стандарта OpenPGP, предназначенная для шифрования и подписания данных, файлов и электронной почты.
- Классическое решение для ручного шифрования файлов и почты.
- Поддерживает асимметричное шифрование (публичный и приватный ключ).
- Используется чаще для защиты отдельных файлов, резервных копий и электронной почты.
- **Минус:** менее удобно для автоматического использования, не прозрачное.

### Резюме по выбору решения

- Для простой защиты каталогов или облачного хранилища: **Cryptomator, EncFS**
- Для надёжной защиты разделов дисков: **VeraCrypt, LUKS**
- Для прозрачного, встроенного шифрования без дополнительных слоёв: **Fscrypt**
- Для больших хранилищ с продвинутыми возможностями: **ZFS encryption**
