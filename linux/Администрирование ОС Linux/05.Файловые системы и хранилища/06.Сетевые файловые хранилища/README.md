# Сетевые хранилища и доступ к файлам

Мы поговорили о различных простых способах организации локальных хранилищ. Теперь перейдём к сетевым вариантам.

В Linux существует несколько механизмов для сетевого доступа к файлам:

| Протокол | Назначение | Особенности |
|----------|------------|-------------|
| **NFS** | Монтирование удалённых ФС | Работает как локальный диск через TCP/IP |
| **SMB/CIFS** | Взаимодействие с Windows | Интеграция с Windows-сетями |
| **SSHFS** | Безопасный доступ по SSH | Шифрование, аутентификация через SSH |
| **FTP/SFTP** | Передача файлов | SFTP — безопасная версия через SSH |
| **WebDAV** | Управление файлами через HTTP | Расширение HTTP/HTTPS |

В рамках лекции рассмотрим два самых распространённых решения — **SMB** и **NFS**.

---

## SMB / CIFS

**SMB** (Server Message Block) и **CIFS** (Common Internet File System) — протоколы для совместного использования файлов и ресурсов по сети. CIFS является расширением SMB. Широко используются в Windows, а в Linux реализованы через **Samba**.

### Основные функции

- Совместное использование файлов
- Доступ к сетевым принтерам
- Поддержка сетевых ресурсов
- Безопасность и контроль доступа

### Версии протокола SMB и их безопасность

| Версия | Особенности | Статус в Linux |
|--------|-------------|----------------|
| **SMB1 (CIFS)** | Базовые функции, уязвим (EternalBlue) | ❌ Не рекомендуется |
| **SMB2** | Улучшенная производительность и безопасность | ✅ Поддерживается (Samba 3.0+) |
| **SMB3.0** | Шифрование трафика, многопоточность | ✅ Поддерживается (Samba 4.0+) |
| **SMB3.1.1** | Улучшенное шифрование, защита от атак | ✅ Поддерживается (Samba 4.5.0+) |

### Аутентификация

| Протокол | Уровень безопасности | Использование |
|----------|---------------------|---------------|
| **NTLM** | Низкий (хеши паролей) | SMB1, SMB2 |
| **Kerberos** | Высокий (билетная система) | SMB2, SMB3 |

### Шифрование

- **SMB 3.0+** поддерживает шифрование трафика
- Использование сертификатов защищает от атак "man-in-the-middle"

> [!note]
> Детальная настройка файлового хранилища с помощью Samba остаётся для практического занятия.

## NFS (Network File System)

NFS — протокол для удалённого доступа к файловым системам, разработан Sun Microsystems. Позволяет клиентам монтировать удалённые ФС как локальные диски.

### Основные особенности

- **Прозрачность** — работа с удалёнными файлами как с локальными
- **Кроссплатформенность** — Linux, Unix, Windows (с доп. инструментами)
- **Модель клиент-сервер** — сервер экспортирует ресурсы, клиенты монтируют

### Версии NFS и их безопасность

| Версия | Транспорт | Особенности | Безопасность |
|--------|-----------|-------------|--------------|
| **NFSv2** | UDP | Базовые операции, ограничения по размеру файлов | ❌ Нет шифрования |
| **NFSv3** | TCP | Большие файлы, асинхронные операции | ❌ Нет шифрования (только UID/GID) |
| **NFSv4** | TCP | Stateful, интеграция с Kerberos, ACL | ✅ Kerberos, шифрование |
| **NFSv4.1** | TCP | pNFS (параллельный доступ), масштабируемость | ✅ Улучшенная |
| **NFSv4.2** | TCP | Гибридные ФС, большие файлы | ✅ Актуальная |

### Проблемы безопасности (NFSv3 и ниже)

- Отсутствие шифрования трафика
- Аутентификация только по UID/GID (должны совпадать на сервере и клиенте)
- Не рекомендуется для использования в незащищённых сетях

### Рекомендации

> [!important]
> Для безопасного использования NFS применяйте **NFSv4 с Kerberos**. NFSv3 и более старые версии не стоит использовать в сетях с потенциальными угрозами.

## iSCSI и сетевые диски

Прежде чем говорить об iSCSI, важно понять концепцию **SAN** (Storage Area Network).

> **SAN** — специализированная высокоскоростная сеть для подключения серверов и устройств хранения данных. Обеспечивает высокопроизводительный, масштабируемый и надёжный доступ к хранилищам.

### SAN vs NAS

| Характеристика | SAN | NAS |
|----------------|-----|-----|
| **Уровень доступа** | Блочный (как локальный диск) | Файловый |
| **Протоколы** | Fibre Channel, iSCSI, FCoE | NFS, SMB, FTP |
| **Производительность** | Очень высокая | Средняя |
| **Цена** | Высокая | Низкая / средняя |

### Типы SAN

| Тип | Транспорт | Скорость | Стоимость |
|-----|-----------|----------|-----------|
| **Fibre Channel** | Оптоволокно | 1-128 Gbps | Высокая |
| **iSCSI** | Ethernet (IP-сети) | 1-25 Gbps | Низкая / средняя |
| **FCoE** | Ethernet (поверх FC) | Высокая | Средняя |

## iSCSI (Internet Small Computer Systems Interface)

Протокол для передачи команд SCSI по IP-сетям. Позволяет использовать сетевые ресурсы хранения, как если бы они были локальными дисками.

### Основные компоненты

| Компонент | Роль |
|-----------|------|
| **iSCSI Initiator** | Клиент, инициирующий запросы к хранилищу |
| **iSCSI Target** | Устройство хранения, принимающее запросы |

### Принцип работы

1. **Установка соединения** — Initiator подключается к Target по IP или DNS
2. **Передача команд** — SCSI-команды инкапсулируются в TCP/IP пакеты
3. **Управление сессиями** — поддержка нескольких соединений (отказоустойчивость, балансировка)

### Безопасность iSCSI

| Механизм | Описание |
|----------|----------|
| **CHAP** | Аутентификация клиента и сервера через случайные числа и хеши |
| **Mutual CHAP** | Двусторонняя аутентификация (инициатор и таргет) |
| **IPSec** | Шифрование трафика (iSCSI сам не шифрует) |

> [!tip]
> iSCSI обычно используется в **выделенной сети хранения** (отдельная VLAN), изолированной от основного трафика. Это позволяет создать SAN «на коленке», используя обычное сетевое оборудование.

### Примеры использования SAN

- **Виртуализация** — управление хранилищем для ВМ
- **Резервное копирование** — централизованное хранение бэкапов
- **Базы данных** — высокая производительность ввода-вывода
- **Обработка больших данных** — масштабируемое хранилище

## Сравнение протоколов

| Протокол | Уровень | Типичное использование | Шифрование | Аутентификация |
|----------|---------|------------------------|------------|----------------|
| **NFSv3** | Файловый | Unix/Linux сети | ❌ | UID/GID |
| **NFSv4** | Файловый | Безопасные Unix-сети | ✅ (опционально) | Kerberos |
| **SMB 3.0+** | Файловый | Смешанные сети (Windows + Linux) | ✅ | NTLM/Kerberos |
| **iSCSI** | Блочный | SAN, виртуализация, БД | через IPSec | CHAP/Mutual CHAP |

---

## Итог

1. **NFS** — простой и быстрый доступ для Unix-систем, но для безопасности нужна версия 4 с Kerberos
2. **SMB/CIFS (Samba)** — стандарт для интеграции с Windows, начиная с SMB 3.0 поддерживает шифрование
3. **iSCSI** — позволяет создать недорогую SAN на стандартном Ethernet-оборудовании, но требует отдельной сети и настройки безопасности

> [!note]
> Детальная настройка Samba, NFS и iSCSI вынесена в практические занятия. Здесь мы рассмотрели концепции и ключевые отличия протоколов.
