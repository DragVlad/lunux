# Первичная настройка системы Linux

После установки Linux следующий логический шаг — начальная настройка. Этот этап можно разбить на две стадии:

1. **Общие меры** — применяются ко всем свежеустановленным системам
2. **Специфическая настройка** — под конкретный класс задач (веб-сервер, БД, кластер контейнеризации)

> [!important]
> В рамках учебной программы мы рассматриваем действия так, словно они выполняются вручную — для лучшего понимания. В реальной жизни это **обязательно** должно автоматизироваться (Puppet, Ansible), иначе цена поддержки будет слишком высокой.

---

## Базовые действия после установки

### 1. Обновление системы

Особенно важно, если система публично доступна из интернета. Для внутреннего контура можно повременить, но оставлять систему **без обновлений не рекомендуется в любом случае**.

```bash
# Debian / Ubuntu
sudo apt update && sudo apt upgrade -y

# RHEL / CentOS
sudo yum update -y
```

---

### 2. Настройка временной зоны

Если все сервера и команда в одном часовом поясе — выбирайте его. Если распределены по миру — выберите нейтральный вариант. **По умолчанию рекомендуется UTC.**

```bash
sudo timedatectl set-timezone Europe/Moscow
# или
sudo timedatectl set-timezone UTC
```

---

### 3. Создание нового пользователя

**Не рекомендуется** эксплуатировать систему с пользователями по умолчанию. Создайте новых, настройте права, заблокируйте или удалите автоматически созданных.

```bash
# Создание пользователя
sudo adduser new_user

# Добавление в группу администраторов
sudo usermod -aG sudo new_user     # Debian/Ubuntu
sudo usermod -aG wheel new_user    # RHEL/CentOS
```

---

### 4. Настройка SSH

Базовые меры защиты основного канала удалённого управления. **Актуально, если система публично доступна из интернета.**

#### Измените порт SSH (с 22 на нестандартный)

```bash
sudo nano /etc/ssh/sshd_config
# Измените: Port 22 → Port 2222
```

#### Запретите вход root по SSH

```bash
PermitRootLogin no
```

#### Включите аутентификацию по ключам, отключите вход по паролю

```bash
PubkeyAuthentication yes
PasswordAuthentication no
```

#### Примените изменения

```bash
sudo systemctl stop ssh.socket
sudo systemctl disable ssh.socket
sudo systemctl restart sshd
```

---

### 5. Настройка файрвола

Оптимально, если сервера защищены отдельным специализированным решением. Если нет — используйте встроенные средства.

| Дистрибутив | Инструмент | Команды |
|-------------|------------|---------|
| Debian/Ubuntu | **UFW** | `sudo ufw allow 2222/tcp`<br>`sudo ufw enable` |
| RHEL/CentOS | **firewalld** | `sudo firewall-cmd --permanent --add-port=2222/tcp`<br>`sudo firewall-cmd --reload` |

> [!note]
> Наибольшей гибкостью обладает классический `iptables` (или `nftables`), но для простых случаев удобнее использовать надстройки.

---

### 6. Автоматические обновления

Автоматическая установка обновлений несёт некоторый риск нарушения стабильности, но **число проблем от отсутствия обновлений на порядки больше**.

#### Debian / Ubuntu

```bash
sudo apt install unattended-upgrades -y
sudo dpkg-reconfigure --priority=low unattended-upgrades
```

#### RHEL / CentOS

```bash
sudo yum install yum-cron -y
sudo systemctl enable yum-cron
sudo systemctl start yum-cron
```

> [!tip]
> Процесс обновления можно совместить с внутренним контролем, тестированием и созданием снапшотов для отката.

---

## Резюме

| Действие | Приоритет | Автоматизация |
|----------|-----------|---------------|
| Обновление системы | **Высокий** | `unattended-upgrades` / `yum-cron` |
| Настройка timezone | Средний | Ansible / Puppet |
| Создание пользователя | **Высокий** | Cloud-init / Ansible |
| Настройка SSH | **Высокий** (для публичных серверов) | Ansible / Puppet |
| Файрвол | Средний | Ansible / Puppet |

> [!important]
> Все перечисленные меры в реальной инфраструктуре **должны быть автоматизированы**. Ручное выполнение подходит только для обучения или единичных серверов.
