# Cloud-init: автоматизация инициализации виртуальных машин

**Cloud-init** — это мощный инструмент для инициализации и конфигурации виртуальных машин в облачных средах. Он используется для автоматизации задач, которые обычно выполняются вручную после развёртывания новой ВМ.

> Cloud-init — проект с открытым исходным кодом, предоставляющий метод инициализации облачных ВМ на основании метаданных от провайдера. Поддерживается AWS, Azure, Google Cloud, OpenStack и другими платформами.

---

## Основные функции

1. **Инициализация сетевого интерфейса** — настройка IP-адресов, шлюзов и DNS-серверов
2. **Управление учётными записями** — создание пользователей, добавление SSH-ключей
3. **Установка программного обеспечения** — через `apt`, `yum` и другие пакетные менеджеры
4. **Выполнение пользовательских скриптов** — для произвольных задач настройки
5. **Настройка хранилищ** — монтирование дополнительных дисков

---

## Как работает Cloud-init

| Этап | Описание |
|------|----------|
| **Получение метаданных** | При запуске ВМ запрашивает метаданные и пользовательские данные у провайдера |
| **Обработка данных** | Cloud-init выполняет соответствующие действия по настройке |
| **Выполнение этапов** | Последовательная инициализация: сеть → пакеты → скрипты |
| **Запись логов** | Все действия сохраняются для диагностики |

### Основные этапы инициализации

1. **Initialization (init)** — обработка метаданных
2. **Network Configuration** — настройка сетевых интерфейсов
3. **Config Modules** — управление пользователями, установка пакетов, запуск скриптов
4. **Final Modules** — очистка временных файлов, перезагрузка сервисов

## Пример конфигурационного файла (YAML)

```yaml
#cloud-config
hostname: my-server
fqdn: my-server.example.com
manage_etc_hosts: true

users:
  - name: ubuntu_super_admin
    ssh_authorized_keys:
      - ssh-rsa AAAAB3NzaC1yc2EAAAABIwAAAQE...

package_update: true
packages:
  - nginx
  - git

runcmd:
  - echo "Welcome to my-server!" > /var/www/html/index.html
  - systemctl restart nginx
```

## Преимущества и недостатки

| Преимущества | Недостатки |
|--------------|------------|
| **Автоматизация** — снижает ручную настройку | **Сложность освоения** для начинающих |
| **Скорость** — быстрое развёртывание | **Сложность отладки** — менее очевидно, чем bash/Ansible |
| **Консистентность** — одинаковые конфигурации | **Ошибки конфигурации** — могут привести к неверной настройке |
| **Кроссплатформенность** — поддержка всех крупных облачных провайдеров | |

## Отладка Cloud-init

### 1. Проверка логов

| Файл | Содержимое |
|------|------------|
| `/var/log/cloud-init.log` | Основной лог Cloud-init |
| `/var/log/cloud-init-output.log` | Вывод команд и скриптов |
| `/var/log/cloud-init-per-instance` | Логи для каждого запуска |

### 2. Проверка состояния

```bash
cloud-init status
```

### 3. Повторный запуск всех этапов

```bash
sudo cloud-init clean
sudo cloud-init init
sudo cloud-init modules --mode=config
sudo cloud-init modules --mode=final
```

Только этап `final`:

```bash
sudo cloud-init modules --mode=final
```

### 4. Отладочный режим

Создайте файл `/etc/cloud/cloud.cfg.d/05_logging.cfg`:

```yaml
log:
  level: DEBUG
```

### 5. Валидация YAML

Используйте `yamllint` или онлайн-валидаторы для проверки синтаксиса.

> [!tip]
> Перед добавлением сложных скриптов в Cloud-init выполните их вручную на тестовом экземпляре.

## Примеры использования

| Сценарий | Применение |
|----------|------------|
| **AWS EC2** | Автоматическая установка веб-сервера, настройка безопасности, развёртывание приложения |
| **OpenStack** | Управление пользователями, ключами, пользовательские скрипты |

## Вывод

Cloud-init — мощный инструмент, значительно облегчающий развёртывание и управление облачными серверами, обеспечивая высокий уровень автоматизации и консистентности.

> [!note]
> Cloud-init также можно использовать с виртуальными машинами VirtualBox — для этого требуется дополнительная настройка метаданных.
