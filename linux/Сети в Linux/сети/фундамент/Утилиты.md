# Утилиты ping, traceroute, tcpdump

## Святая сетевая троица

| Утилита | Основное назначение |
|---------|---------------------|
| **ping** | Проверка достижимости узла и измерение задержек (RTT) |
| **traceroute / tracepath / mtr** | Трассировка маршрута до узла |
| **tcpdump** | Захват и анализ сетевого трафика |

---

## 1. ping

### Протоколы
**ICMP** (IPv4) или **ICMPv6** (IPv6)

### Принцип работы
- Отправляет **ICMP Echo Request**
- Ожидает **ICMP Echo Reply**
- Измеряет **RTT** (*Round Trip Time* – время туда и обратно)

### Особенности
- Работает напрямую поверх IP (без TCP/UDP)
- Иногда запрещён на файрволах (шутка: *«в аду отдельный чанк для их админов»*)

### Параметры

| Параметр | Описание |
|----------|----------|
| `-c N` | Количество запросов (N штук) |
| `-s M` | Размер данных в запросе (M байт) |
| `-D` | Проставлять timestamp (Unixtime) для каждого запроса |
| `-I <intf/IP>` | Указать интерфейс или IP-адрес для отправки |
| `-O` | Явно показывать запросы без ответа |
| `-i K` | Интервал между запросами (K секунд) |
| `-a` | Пинг с бипом через динамик |

### Примеры команд

```bash
# Базовый пинг (бесконечный, до Ctrl+C)
ping google.com

# 4 пакета, размер данных 100 байт
ping -c 4 -s 100 8.8.8.8

# Пинг с указанием интерфейса
ping -I eth0 192.168.1.1

# С timestamp и звуковым сигналом
ping -D -a google.com
```

## 2. traceroute / tracepath / mtr

### Общий принцип работы
- Отправляет серию запросов с **увеличивающимся TTL** (Time To Live)
- Узел, у которого TTL истекает, возвращает **ICMP Time Exceeded**
- По этим сообщениям определяется каждый промежуточный узел

### Протоколы, которые может использовать
| Протокол | Примечание |
|----------|------------|
| ICMP | Классический вариант |
| TCP | Шлёт данные на предопределённый порт (33434-33534) |
| UDP | По умолчанию во многих реализациях |

### traceroute vs tracepath vs mtr

| Утилита | Особенности | Права |
|---------|-------------|-------|
| **traceroute** | Классическая трассировка, много параметров | Некоторые аргументы требуют root |
| **tracepath** | Упрощённый вариант, определяет MTU | Работает от обычного пользователя |
| **mtr** | Интерактивный режим, постоянное обновление, красивый вывод | Работает от обычного пользователя |

### MTR (Младший брат traceroute)

**Параметры:**
| Параметр | Описание |
|----------|----------|
| `-T` | Использовать TCP |
| `-U` | Использовать UDP |
| `-P` | Указать порт |
| `-I` | Указать интерфейс |
| `-a` | Указать IP-адрес источника |

**Преимущества mtr:**
- Удобное отображение информации
- Постоянная, а не разовая отправка проверок
- Возможность выбирать протоколы и порты

### Примеры команд

```bash
# Классическая трассировка
traceroute google.com

# TCP-трассировка на порт 443
traceroute -T -p 443 google.com

# tracepath (не требует root)
tracepath google.com

# MTR в интерактивном режиме
mtr google.com

# MTR с TCP на порт 80
mtr -T -P 80 google.com

# MTR с указанием интерфейса
mtr -I eth0 yandex.ru
```

## ⚠️ Важные предупреждения

> **Звёздочки (`*`) и `no reply` ещё не означают, что есть проблемы**
> 
> **Потери на промежуточных узлах ещё не означают, что есть проблемы**
> 
> **Большие задержки на промежуточных узлах ещё не означают, что есть проблемы**

**Почему?**
- Узел может быть настроен не отвечать на определённые типы запросов (ICMP rate-limiting)
- Ответы могут приходить с более низким приоритетом, чем реальный трафик
- Асимметрия маршрутов (обратный путь отличается от прямого)
- Промежуточный узел "загружен" обработкой диагностических запросов, но нормально проходит пользовательский трафик

## 3. tcpdump

### Что это?
Утилита для сбора и анализа трафика, проходящего через узел.

### Особенности
- Анализирует **любые** протоколы (не только TCP)
- Требует **sudo** (или root-прав)

### Параметры

| Параметр | Описание |
|----------|----------|
| `-i` | Выбрать интерфейс для прослушивания |
| `-v` / `-vv` / `-vvv` | Детализированный вывод (чем больше v, тем детальнее) |
| `host` | Фильтр по IP-адресу (src/dst) |
| `port` | Фильтр по номеру порта |
| `ip` / `udp` / `tcp` / `icmp` / `icmp6` / `proto N` | Фильтр по протоколу |
| `and` / `or` / `not` | Логические операторы в фильтрах |
| `-w` | Сохранить дамп в файл |
| `-r` | Прочитать дамп из файла |
| `-U` | Пакетная запись (важно для pipe) |
| `-s0` | Захватывать пакет целиком (без обрезания) |

### Базовый синтаксис фильтров
```
tcpdump [options] [expression]
```

### Примеры команд

```bash
# Просмотр всего трафика на интерфейсе eth0
sudo tcpdump -i eth0

# Фильтр по хосту (десять пакетов)
sudo tcpdump -c 10 host 192.168.1.1

# Фильтр по порту
sudo tcpdump port 443

# Фильтр по протоколу и порту
sudo tcpdump tcp port 22

# Сложный фильтр (источник, назначение, порт)
sudo tcpdump src host 10.0.0.1 and dst port 80

# Показать только ICMP (пинги)
sudo tcpdump icmp

# Сохранить дамп в файл
sudo tcpdump -i eth0 -w capture.pcap

# Прочитать файл дампа
tcpdump -r capture.pcap

# Более детальный вывод
sudo tcpdump -i eth0 -v

# Вывод в HEX и ASCII (максимальная детализация)
sudo tcpdump -i eth0 -X
```

## 4. Продвинутая техника: tcpdump через SSH + Wireshark

```bash
# Захват удалённого трафика и открытие в локальном Wireshark
ssh host 'sudo tcpdump -U -s0 not port 22 -w -' | wireshark -k -i -
```

**Как это работает:**
1. `ssh host` – подключение к удалённому серверу
2. `sudo tcpdump -U -s0 not port 22` – захват всего, кроме SSH-трафика (чтобы не зациклиться)
3. `-w -` – вывод дампа в stdout
4. `| wireshark -k -i -` – передача в локальный Wireshark для реального времени

## 6. Краткая шпаргалка (команды)

```bash
# === PING ===
ping -c 4 8.8.8.8                         # 4 пакета
ping -s 1400 -c 10 google.com             # 1400 байт данные
ping -I eth1 192.168.1.1                  # через конкретный интерфейс

# === TRACEROUTE ===
traceroute yandex.ru
traceroute -T -p 443 google.com           # TCP на 443 порт
tracepath 1.1.1.1                         # без прав root
mtr --report google.com                   # однократный отчёт mtr

# === TCPDUMP ===
sudo tcpdump -i eth0 -c 100               # 100 пакетов на eth0
sudo tcpdump port 53                      # DNS-трафик (UDP/TCP)
sudo tcpdump 'tcp[tcpflags] & (tcp-syn) != 0'  # все TCP SYN-пакеты
sudo tcpdump -s0 -w dump.pcap             # сохранить всё в файл
tcpdump -r dump.pcap | head               # прочитать сохранённый дамп
```
