# Конспект: Стек протоколов TCP/IP

## 1. Соответствие уровней TCP/IP и OSI

| TCP/IP (уровень) | OSI (уровни) | Примеры протоколов |
|------------------|--------------|---------------------|
| **Прикладной** (Application) | 7 (Прикладной), 6 (Представления), 5 (Сеансовый) | HTTP, SMTP, FTP, Telnet, SSH, SMB, NFS, RTSP, BGP, OSPF, DHCP, DNS, NTP, SNMP |
| **Транспортный** (Transport) | 4 (Транспортный) | TCP, UDP, SCTP, QUIC, SPX, GRE |
| **Сетевой** (Internet/Network) | 3 (Сетевой) | IPv4, IPv6, ICMP, IGMP, OSPF, RIP, ARP |
| **Канальный/Физический** (Link/Physical) | 2 (Канальный), 1 (Физический) | Ethernet, Token ring, PPP, MPLS, Wi-Fi, Bluetooth, электрические провода, оптоволокно, радиосвязь, ИК-излучение |

> **Примечание:** В модели TCP/IP уровни Представления (6) и Сеансовый (5) OSI в явном виде не выделяются — их функции берёт на себя Прикладной уровень.

## 2. Уровни TCP/IP подробно

### 2.1 Прикладной уровень (Application)
**Область действия** – приложения на конечных устройствах.

**Функции и примеры протоколов:**
| Протокол | Назначение |
|----------|------------|
| HTTP / HTTPS | Веб-серфинг, передача гипертекста |
| SSH | Удалённое управление, защищённый доступ |
| DNS | Преобразование доменных имён в IP-адреса |
| DHCP | Автоматическая выдача IP-конфигураций |
| SMTP | Отправка электронной почты |
| NTP | Синхронизация времени |
| BGP | Маршрутизация между автономными системами (AS) |
| OSPF | Динамическая маршрутизация внутри AS |
| SNMP | Мониторинг и управление сетевыми устройствами |

---

### 2.2 Транспортный уровень (Transport)
**Область действия** – сокеты (порты + IP) на конечных устройствах.

| Протокол | Особенности |
|----------|--------------|
| **TCP** | Надёжный, с установлением соединения, контроль доставки, упорядочивание пакетов |
| **UDP** | Ненадёжный, без установления соединения, быстрый, без гарантий доставки |
| **SCTP** | Сочетает черты TCP/UDP, используется в сигнализации (VoIP, SS7) |
| **QUIC** | Современный протокол поверх UDP (HTTP/3), с шифрованием и уменьшенными задержками |

> **Шутка про UDP:** «Я знаю замечательную шутку про UDP, но боюсь, что она до вас не дойдет».  
> **Шутка про TCP:** «Я знаю отличную шутку про TCP, но если она до вас не дойдет, то я повторю...»

---

### 2.3 Сетевой уровень (Internet)
**Область действия** – конечные устройства взаимодействия (сквозная доставка).

| Протокол | Назначение |
|----------|------------|
| **IPv4** | Основной протокол адресации и маршрутизации (32 бита) |
| **IPv6** | Следующее поколение (128 бит), решает проблему исчерпания адресов |
| **ICMP** | Диагностика (ping, traceroute), сообщения об ошибках |
| **IGMP** | Управление групповой многоадресной рассылкой (multicast) |
| **ARP** | Преобразование IP → MAC-адресов (внутри одного широковещательного домена) |

> **Шутка про ICMP** (обыгрывается невозможность просто так отправлять ICMP-пакеты без специальных привилегий).  
> **Шутка про ARP:** «Была еще одна шутка, про ARP. Кто-нибудь её знает? Расскажите!..» (ARP работает широковещательными запросами «кто имеет IP X?»).

---

### 2.4 Канальный и физический уровень
**Область действия** – ближайший маршрутизатор (или коммутатор).

| Тип | Примеры |
|-----|----------|
| **Канальный** (L2) | Ethernet, PPP, MPLS, Token ring |
| **Физический** (L1) | Витая пара, оптоволокно, радиоканал, ИК-порт, Bluetooth, Wi-Fi |

---

## 3. Путь пакета в TCP/IP (анимация жизни пакета)

1. **Прикладной уровень** создаёт данные (например, HTTP-запрос).  
2. **Транспортный уровень** нарезает данные на **сегменты/датаграммы** (для TCP/UDP), добавляет порты отправителя/получателя.  
3. **Сетевой уровень** инкапсулирует сегмент в **пакет** (добавляет IP-адреса источника/назначения).  
4. **Канальный уровень** инкапсулирует пакет в **кадр** (frame) – добавляет MAC-адреса и контрольную сумму.  
5. **Физический уровень** передаёт биты в среду.  

На каждом промежуточном узле (маршрутизаторе/коммутаторе) пакет разбирается только до нужного уровня (обычно до сетевого), а затем снова инкапсулируется для передачи дальше.

> **Термины:**  
> - Segment/Datagram – данные транспортного уровня  
> - Packet – данные сетевого уровня  
> - Frame – данные канального уровня

## 4. Примеры команд для диагностики TCP/IP (в дополнение к OSI)

| Уровень | Команда (Linux/macOS) | Команда (Windows) | Что делает |
|---------|----------------------|-------------------|-------------|
| **Прикладной** | `curl -v http://example.com` | `curl -v http://example.com` | Просмотр HTTP-обмена |
| | `dig google.com` | `nslookup google.com` | DNS-запрос |
| | `ssh user@host` | `ssh user@host` | Подключение по SSH |
| **Транспортный** | `ss -tulpn` | `netstat -an` | Список открытых портов и соединений |
| | `nc -zv localhost 22` | `Test-NetConnection localhost -Port 22` (PowerShell) | Проверка доступности порта |
| **Сетевой** | `ip route show` | `route print` | Таблица маршрутизации |
| | `ping 8.8.8.8` | `ping 8.8.8.8` | ICMP-эхо-запрос (L3) |
| | `traceroute google.com` | `tracert google.com` | Трассировка маршрута (ICMP или UDP) |
| **Канальный** | `arp -a` | `arp -a` | ARP-таблица (IP→MAC) |
| | `ip neigh` | `netsh interface ip show neighbors` | Таблица соседей (NDP для IPv6) |
| **Физический** | `ethtool eth0` | `Get-NetAdapter -Name "Ethernet"` | Статус линка, скорость, дуплекс |
| | `ip link show` | `Get-NetAdapterStatistics` | Статистика ошибок передачи |

## 5. Главные особенности TCP/IP (по презентации)

1. **Реально работающий стек** – на практике почти весь интернет построен на TCP/IP, а не на OSI.  
2. **Промежуточные сетевые узлы** *должны* обрабатывать данные не выше сетевого уровня, но *фактически* иногда забираются до прикладного (например, прокси-серверы, балансировщики, DPI).  
3. **Только конечные хосты** должны обрабатывать данные на всех уровнях (принцип сквозной связности). Однако на практике этот принцип **нарушается** (NAT, файрволы, прокси).  
4. **«Соткан из костылей»** – множество надстроек, заплаток и расширений из-за исторического развития и отсутствия изначально продуманной эталонной модели.

## 6. Сравнение OSI и TCP/IP

| Характеристика | OSI | TCP/IP |
|----------------|-----|--------|
| **Уровней** | 7 | 4 (или 5, если разделять канальный/физический) |
| **Тип** | Концептуальная (эталонная) | Практическая (рабочая) |
| **Использование** | Теоретическое, для обучения | Реальный интернет, сети |
| **Разработка** | ISO (международный стандарт) | DoD / IETF |
| **Статус** | Почти не используется «как есть» | Доминирует во всём мире |
